# Write GDD

## 目标

把概念和玩法方向整理成结构化的游戏设计文档。

## 何时使用

- 项目需要正式的设计文档
- 现有设计笔记比较零散

## 工作流

1. 收集概念与系统输入
2. 按结构组织文档章节
3. 标出缺失的设计决策
4. 把实现计划交给 `plan-production`

## 输出要求

- 结构化 GDD 草稿
- 缺失决策
- 开放风险
- 下一步交接对象

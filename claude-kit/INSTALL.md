# Install the Claude kit (agents, skills, tools) of the Roblox Dev Mastery Vault

What it is: Roblox specialist agents (including `rbx-builder`, the single entry point for "make me a Roblox game"), their skills, the `kbq` and `vault-find` search tools and a Rojo/Luau project template. Everything resolves paths at run time; nothing is user-specific.

Default scope is vault + kit + assets (a plain Enter or no answer); "just the vault" and "vault + kit" stay available.

## Steps
1. Find this folder: it is `claude-kit/` in the vault clone (`$CLAUDES_VAULT`, else `~/Obsidian/claudes-vault`, else `%USERPROFILE%\Obsidian\claudes-vault`). If the vault is not cloned yet, run the vault runbook (`SETUP-FOR-CLAUDE.md` at the vault root, or START-HERE.txt on the share) first; it calls this installer for you.
2. Run the installer for the OS (idempotent; no admin, no sudo, no prompts):
   - macOS/Linux/Git Bash: `bash <vault>/claude-kit/install.sh`
   - Windows: `powershell -NoProfile -ExecutionPolicy Bypass -File "<vault>\claude-kit\install.ps1"`
3. What it does (do this by hand only if the script cannot run):
   - Create `~/.claude/claude-kit/vault-mode/.claude/{skills,agents}` (the on-demand store: NOT read by normal Claude sessions) and `~/.claude/claude-kit/tools` if missing.
   - Copy `agents/*.md` to `~/.claude/claude-kit/vault-mode/.claude/agents/`, each `skills/<name>/` folder to `~/.claude/claude-kit/vault-mode/.claude/skills/<name>/` EXCEPT the five always-on ones listed in `mode/always-on.txt` (rbx-load, rbx-unload, rbx-update, rbx-check, rbx-uninstall), which go to `~/.claude/skills/<name>/`; `mode/CLAUDE.md` (the mode rules), `mode/always-on.txt` and `mode/cold/` (the cold area, read only through `[cold:topic/file]` pointers) to `~/.claude/claude-kit/vault-mode/`, everything in `tools/` to `~/.claude/claude-kit/tools/` and everything in `systems/` to `~/.claude/claude-kit/systems/`.
   - If `~/.claude/claude-kit/installed.tsv` shows an OLDER install (kit skills/agents directly in `~/.claude/skills` and `/agents`), run `python ~/.claude/claude-kit/tools/vault-mode.py migrate` (the installer does it): unchanged kit files move to `~/.claude/claude-kit/backup/mode-migration-<time>/`, your own skills, agents and CLAUDE.md are untouched, `migrate --revert` undoes it.
   - Kit wins: a target file that differs from the kit version is replaced by the kit version, with no question. Your version is first copied to `~/.claude/claude-kit/backup/<date>/<relpath>` (nothing is lost). No `.new` files are written any more. Your skills with other names are never touched or removed; the installer prints a one-line list of the ones that look similar to a kit skill ("kit versions will be used"), and the kit entry points (rbx, rbx-workflow, rbx-mentor, rbx-idea-quick, game-dev-*) carry the line "When a kit skill and another installed skill cover the same job, use the kit skill."
4. Set nothing global: do not edit `settings.json` (the one exception is the user-approved hook merge: `install.sh --with-hooks` / `install.ps1 -WithHooks`, never run by default, which adds the two `/rbx-low-usage` hooks and the `rbx-mentor` suggestion hook; each is backed up first, idempotent and removable with `--remove-hooks` / `-RemoveHooks`), environment variables, shell profiles, MCP configuration or permissions. Do not install software. Do not write inside the vault.
5. Check (cheap): the installer prints `claude-kit: installed N new, updated N, unchanged N, replaced-yours N` (plus, when N > 0, a line naming the backup folder). Then confirm `~/.claude/claude-kit/vault-mode/.claude/agents/rbx-builder.md` exists and, if python exists, `bash ~/.claude/claude-kit/tools/pyrun ~/.claude/claude-kit/tools/kbq.py where` prints a VAULT path (if it prints an empty VAULT, set nothing; tell the user the vault is not cloned yet).

Do not install them unless the user asked. Test it safely with `-DryRun` / `--dry-run` and a temporary `CLAUDE_CONFIG_DIR`.
7. Final message to the user: the installer line from step 5, then END your final report with the completion block from STEP 6 of SETUP-FOR-CLAUDE.md in the vault root ("The Roblox Dev Mastery Vault is now set up.", grouped slash commands, how it works, and "Built and maintained by Roman (GitHub: romangigliotti123-arch)"). Tell them the kit is OFF by default and that `/rbx-load` in their Roblox project folder turns on Roblox dev mode (`/rbx-unload` turns it off); no restart is needed for /rbx-load itself.

## Trust model: what installing and updating means (read once)
- **Installing runs code from this repository** (Python, bash, PowerShell scripts) with your user rights, no admin. It writes under `~/.claude/claude-kit`, five small commands in `~/.claude/skills`, the vault folder and `<vault>/Assets`. It sends nothing anywhere: it only reads from github.com, raw.githubusercontent.com and the website over HTTPS. The one exception is `/rbx-learn` notes, which are secret- and personal-data-scanned and pushed only from a computer that already has write access to the inbox repo.
- **An update can do what the installer can do.** `/rbx-update` (and the optional logon task) fetches the vault and kit and runs the new installer and tools, so whoever controls github.com/romangigliotti123-arch (or a repository `repos.json` lists) controls the next update. Nothing is signed; Git commit ids are the only pin. Keep the logon task off if that is too much trust, and preview before you update: `/rbx-check` lists the commits and the scripts that changed; `git -C <vault> diff --stat HEAD origin/main` and `git -C <vault> diff HEAD origin/main -- claude-kit/tools claude-kit/install.sh claude-kit/install.ps1` show the code itself.
- **What limits the damage**: sources must be HTTPS under that account (plus GitHub's download hosts and the site; `VAULT_ALLOWED_OWNERS` / `VAULT_ALLOW_HOSTS` widen this on purpose); asset zips are SHA-256 checked before extraction (this catches corruption and a swapped file on the way, it does not prove who published the list) and are refused when an entry leaves `Assets/`, when there are too many entries or too many bytes; extra repository shards can write only inside the folders their `mount` lists; `.claude/vault-mode.json` of a project can only make `/rbx-unload` remove files inside that project's `.claude`; your edited files are backed up before the kit replaces them; hooks (`--with-hooks`) and mods (`--with-mods`, they run inside Claude Code) are never installed unless you ask; the learning inbox is untrusted and never read as knowledge.
- **Not covered**: a compromised GitHub account, a malicious kit release, or a hostile local program. The mode text in `CLAUDE.md` is instructions for Claude, not a sandbox; Claude Code's own permission prompts remain your last line.
- **Verify**: the installer prints the kit commit; compare with the commit list at github.com/romangigliotti123-arch/vault-kit-01. Remove everything with `/rbx-uninstall`.

## Update
The sync scripts (`win-sync-setup.ps1`, `mac-sync-setup.sh`, `linux-sync-setup.sh`) make the vault update at every logon/login (no 15-minute polling) and on demand (`vault-update.ps1` / `vault-update.sh` in the vault root, or `/rbx-update`); each update runs a self-healing `git fetch` + fast-forward (blocked by local changes: they are saved to `local-changes-<timestamp>.patch` and the vault is reset to the latest, automatically), then `kit-refresh.ps1` / `kit-refresh.sh` (runs the installer quietly, so installed skills refresh by themselves) and then `tools/assets-sync.py` (fills `<vault>/Assets`). A computer set up before that change needs its sync script run once more. By hand: run step 2 again. Files the user edited are replaced by the kit version after a backup (see step 3).

Your own work is safe: `Games/` (per-game communities and `Games/_Reusable`), `My Research/` (default output folder of the research skill), any folder containing `PROTECTED-RESEARCH.md` and every untracked file you created are never deleted by `/rbx-update` (git-excluded; the update prints `N of your own files kept`); only edits to tracked (generated) files are patched and reset. `My Research` is a reserved name: the main vault never ships files there. Two commands: `/rbx-update` (safe, keeps everything of yours) and `/rbx-clean` (exact copy of the main vault, still keeps My Research; prints a dry run, asks once, backs up what it removes). One-liners: `vault-update.ps1 -Clean [-Yes] [-IncludeMine]` / `bash vault-update.sh --clean [--yes] [--include-mine]` (`-IncludeMine` also deletes My Research, only when you type it).

## Check commands
- `/rbx-check`: is a newer vault or kit out? Read-only (git fetch, compare, changelog of up to 10 commits, changed kit skills), then offers `/rbx-update`.
- `/rbx-list`: everything the kit installed (skills, agents, mods), one line each, plus the /rbx pack pointer.
- `/rbx-setup`: table of the software the setup uses (git, Python, Claude Code, Studio and Studio MCP, Rokit + Luau tools, Rojo, Blender + Blender MCP, uv, Obsidian ...), required vs optional, exact install command per OS; installs only after your yes. Setup runs it automatically at the end. By hand: `python tools/setup-check.py`.

- Mods: `/rbx-subagent-hud` shows the master agent and its subagents (done count, time estimate, click a subagent to see its prompt); `/rbx-graph` shows the vault graph (kit mods installed with the kit via `claude plugin`; they only show in the terminal and desktop app, not in Remote Control or mobile). The installer registers the local marketplace `roblox-vault-kit-mods` (`claude-kit/mods` in the vault) and installs `rbx-subagent-hud` and `rbx-graph` when the `claude` CLI is on PATH (idempotent); without it, it prints `/plugin marketplace add <path>`, `/plugin install <mod>@roblox-vault-kit-mods`, `/reload-plugins` for you to run in a session. `/rbx-uninstall` removes them first.
- The installer's last line is always `>>> Type /rbx-load in a Roblox project folder to use the kit (then /rbx-list shows everything it contains).`.

## Remove
**To remove: `/rbx-uninstall`.** It shows a plan first, asks for a yes, copies your games (`Games/`, `Games/_Reusable`, `My Research/`) to `~/Roblox Games` and checks the copy, removes the hooks, then deletes the kit and the vault folder. By hand instead: delete the files listed in `~/.claude/claude-kit/installed.tsv` (first column, relative to `~/.claude/`) and the `~/.claude/claude-kit/` folder. Only do this if the user asks.

3b. The kit refresh also sends notes queued by `/rbx-learn` to the public vault-learnings inbox (`learn.py flush --quiet`): silent when nothing is queued, offline, or without write access (notes stay queued; `learn.py pr` is the explicit opt-in way to contribute from a fork). Skip with env `CLAUDE_LEARN_SKIP=1`.

## From skills/rbx-update/SKILL.md :: 4b. The kit refresh also (a) refreshes folders that have Rob

4b. The kit refresh also (a) refreshes folders that have Roblox dev mode loaded (`/rbx-load`), and (b) moves an OLDER always-on kit install (vault skills/agents directly in `~/.claude/skills` and `/agents`) into the on-demand store with a backup, printing `vault-mode: moved N vault skills ...`. Your own skills, agents and CLAUDE.md are not touched.
4d. UI mockups notice (one time per install): a `NOTICE FOR THE USER (show this): UI mockups now default to automatic design-first ...` line = show it as ONE line before the final `Your vault is up to date as of ...` line, which stays the LAST line of the report. `/rbx-mockup on|off|status` changes the mode (tools/ui_pref.py).
4c. Command rename (one time): output containing `NOTICE FOR THE USER ... commands renamed` = copy that notice into your report word for word (old name -> new name). The installer removed the OLD generic command names of this vault and installed the vault-suffixed ones; your own skills with those old names were left alone. Undo: `kit-rename.py migrate --revert` (in `<config>/claude-kit/tools`). Do not run any old name again.
4e. Kept vault files (UP): output containing `NOTICE FOR THE USER ... N locally changed vault files kept; incoming versions saved; review with ...` = show that ONE line before the final `Your vault is up to date as of ...` line (which stays LAST). The update never overwrites or deletes a vault file the user edited: it keeps theirs and saves the incoming version in `<config>/claude-kit/state/conflicts/<path>.vault-new`. Review: `python <config>/claude-kit/tools/kit-conflicts.py list|diff PATH|accept PATH|keep PATH` (accept takes the incoming file and backs the user's up; keep stops reporting that version). Do not accept or keep for the user without being asked. `vault-mode.py status` prints `kept vault files: N` while any are unresolved. The user's own rules go in `<config>/claude-kit/state/overrides/local-rules.md` (never conflicts). Learn queue, hiccup ledger and preferences live in `<config>/claude-kit/state/` and are never touched by an update.

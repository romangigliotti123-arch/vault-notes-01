# claude-kit (the manager toolkit of the Roblox Dev Mastery Vault)

Built and maintained by Roman (GitHub: romangigliotti123-arch)

Say one sentence on any computer and a Claude agent designs and builds a Roblox game for you, using the vault, the Roblox skills and your downloaded assets. It never asks you questions: if your idea is vague it makes assumptions, writes them down, and carries on.

## What to run (in your Roblox project folder: start Claude, type `/load-rbxdev-vault`, then these)
The vault kit is installed but switched OFF by default: a normal Claude session loads nothing from it. In your Roblox project folder type `/load-rbxdev-vault` (Roblox dev mode: the vault skills, agents, art-direction, placement, lighting and visual-QA rules, reference images, learn step) and `/unload-rbxdev-vault` to turn it off again. Always available: `/load-rbxdev-vault`, `/unload-rbxdev-vault`, `/update-rbxdev-vault`, `/update-check-rbxdev-vault`, `/uninstall-rbxdev-vault`. Session-only alternative that writes nothing into the project: `claude --add-dir ~/.claude/claude-kit/vault-mode`, then `/load-rbxdev-vault`. Auto-load for Roblox project folders (opt-in, nothing adds it for you): `python ~/.claude/claude-kit/tools/vault-mode.py autoload-snippet` prints a SessionStart hook for settings.json.
- `/game-idea-rbxdev-vault [genre]` : one short idea that fits what is working on Roblox right now (live charts and trend sources, date-stamped, plus vault benchmarks), with the 30 s / 5 min / session loop, a solo buildable scope using kit systems and /rbx skills, and its critic idea score; say "start it" to hand it to `/game-dev-workflow`.
- `/game-dev-workflow` : the flagship flow. Asks only for your game idea, elaborates it from the vault, rates it 1.00-10.00, writes a build plan (skills, agents, models, budget), asks "Ready to build?", then it acts as a manager: spawns specialist workers (pack skills, kit agents) with master prompts filled from the vault, verifies their reports, proposes the next best jobs and ends with a playtest. Side commands, each also usable alone: `/game-dev-ads` (ads plan), `/game-dev-update` (update roadmap and patch notes), `/game-dev-playtest` (bug and feel report), `/game-dev-thumbnail` (icon/thumbnail prompts and images with the newest Nano Banana model from your own API key). Sub-skills: `/game-dev-rate`, `/game-dev-plan`, `/game-dev-art-direction` (art bible before building: palette, one UI style kit shipped as a Luau StyleKit, layout rules, lighting preset, model rules, juice list), `/game-dev-placement-qa` (the placement gate: every model created, inserted or moved is measured in Studio for pivot and size, grounded, upright, facing, overlap, anchoring and connections, auto-fixed and re-verified; a full-map scan must pass before a game is called done), `/game-dev-visual-qa` (the visual gate: screenshots of the running game, a layout-overlap check at phone/tablet/desktop, a 7-item rubric, up to 3 fix rounds; a game is never called done unless it passes, otherwise its status is "playable prototype, visuals not polished" with a polish backlog). They read the newest vault notes every run (pull, freshness line, live check).
- **Your games stay in the vault.** `/game-dev-workflow` is the single entry for every game: the first run asks your experience level and game type once; each game gets its own protected community `Games/<game>/` in the vault (`GAME.md` hub with stage, numbers and next tasks, `design`, `decisions`, `systems`, `playtests/`, `weekly/`, `critic/`, all linked into the KB so Obsidian shows one cluster per game). Run it again any time: it detects the real stage from evidence (idea > prototype > playtest > launch > growth > live-ops) and resumes. Judgement: before a stage advances or anything is called done, an independent critic (`/game-dev-critic`, agent `game-critic-rbxdev-vault`) scores 10 hit-versus-flop factors with evidence, separates "works" from "good" and says GOOD / NOT YET / BAD with the top 3 fixes; NOT YET blocks. Also: `/game-dev-weekly` (paste Creator Dashboard numbers, get the week's plan), `/game-dev-launch-kit` (thumbnails, ads, update calendar, checklists), `/game-dev-harvest` (save reusable systems to `Games/_Reusable/`, found first by `vault-find --type reusable`), `/contribute-rbxdev-vault` (optional: bundle one for the vault owner). `Games/` is never touched or shipped by `/update-rbxdev-vault` or `/update-clean-rbxdev-vault`.
- `/game-dev-benchmark` : measure the vault itself. `scorecard.py` turns every gate result of a game (visual, placement, lighting, critic, any new gate) into a 0-100 scorecard with the top 3 problems and fixes, a history CSV and a before/after compare; 3 standard test games (obby, tycoon, tower defense) let any vault version be compared on the same task; `vault_cost.py` estimates what load mode costs a session (tokens, install time, heaviest skills); `learn_stats.py` reports how much the learning loop is used. Protocol: `skills/game-dev-benchmark/references/protocol.md`.
- `/roblox-architecture-choice` : picks the structure of a Roblox system (plain module, OOP, components, ECS, state store, object pool) by evidence, with Luau examples; `roblox-luau-style` now has a lifecycle and leak-cleanup section, `roblox-code-rate` a severity-ranked sharp-edges checklist plus the generated-vs-tested evidence ladder (and a `code-quality/gate.json` that game-dev-benchmark scores), and `roblox-monetization-audit` / `game-dev-rate` a fair-or-pressure ethics column. Ideas adapted from excaldev/ro-engineer (MIT); reference copies live in the vault under `Imported/ro-engineer`.
- `/game-dev-tune` : bounded metric loop for balance, optimise and polish work. Pick ONE number and a read-only evaluator, baseline it, change one thing per experiment, keep only strict improvements, revert the rest, log every run in `Games/<slug>/tune/<run-id>/` (`tune_check.py` validates the ledger: baseline row, strict improvement, unchanged evaluator, budget, gates still passing). The loop idea comes from Karpathy's autoresearch (no licence file in that repo, so idea only, own words); the unbounded never-stop mode is not adopted.
- **Code gates, Fix loop, smallest complete change (adapted from the video "9 Claude Skills I Use Every Single Day", ideas only, nothing installed).** `game-dev-critic/scripts/code_gates.py <project> --write Games/<slug>` is the one runner of the scored code gates: comment-scan (CM1-3), scope-scan (SC1-5: orphan modules, TODO stubs, kit systems rebuilt by hand, unused exports, oversized files), security-scan (`static_scan.py --gate`, SEC1-5: client-trusted remotes, hardcoded keys and webhooks, server code in ReplicatedStorage, DataStore and receipt safety, backdoor patterns), bugfix ledgers (FL1) and tune ledgers (TN1-6). Policy: every finding is SCORED and never blocks (the scans are heuristics and give false hits); NOT RUNNING them does block the verdict: the critic must run them itself, otherwise it cannot return GOOD (`playable prototype, code gates not run`; the verdict file carries `codegates: ran`, which `games.py advance` needs; verdict files from before count as not run). The standing rules sit in the load-mode rules (two bullets), the builder, engineer, reviewer and critic agents, and the workflow and manager steps. `game-dev-playtest` has the Fix loop (reproduce first: a red check before any edit, the same check green after, ledger `Games/<slug>/bugfix/<id>.md`); `roblox-luau-style` has the Smallest complete change ladder (reuse a kit system or Roblox built-in before new code); the manager builds the core loop alone in wave 1. Credits: Ponytail and Unlazy (smallest change, stubs), Vibe Security (security gate), Matt Pocock's diagnosing-bugs and pstack / Poteto mode by Lauren Tan (fix loop, core loop first), all MIT, re-written in our own words.
- **No code comments by default.** Every agent and skill that writes code follows one rule (`roblox-luau-style`, Comments; also in the load-mode rules): no comments, except one line that says WHY something non-obvious is done (engine quirk, ordering, replication timing, physics ownership), never WHAT. Type annotations and `--!` directives stay. All shipped Luau (StyleKit, templates, systems, skill-pack scripts, the generated Placement and Lighting modules) was stripped to match; `game-dev-critic/scripts/comment_scan.py` counts stray comments per file and writes a scored, never blocking `comment-scan/gate.json` that game-dev-benchmark picks up.
- `/learn-rbxdev-vault` : the self-improving part. After an agent VERIFIES something non-obvious (a fix, a gotcha, a corrected assumption) it records a small note (`tools/learn.py add`); the note is scanned for secrets, personal data and instruction-like text, queued on your computer and sent by `/update-rbxdev-vault` to the public inbox repo `vault-learnings` (CC0). Nothing in that inbox is trusted: the vault owner's `/curate-rbxdev-vault` runs fixed rules over it and promotes accepted notes to `learned/<topic>/` in the vault, which every agent checks first (`vault-find.py "<problem>" --type learned`). Without write access your notes stay queued; `learn.py pr` (opt-in) opens a pull request from your fork.
- `/mentor-rbxdev-vault` : a co-pilot with the combined knowledge of every creator in both vaults; it works alongside you on any job and suggests the right skill, agent, note or creator method at each step, and answers "what would <creator> do" (agent `mentor-rbxdev-vault`; reads `CAPABILITIES.md` and `Mentor/Combined-Brain.md` first).
- `/low-usage-mode-rbxdev-vault` : keeps Claude in low usage mode for every message and session until `/low-usage-mode-rbxdev-vault off` (cheapest model that fits, at most one subagent, short replies, small tool output; each reply starts with "low usage mode enabled."). `/low-usage-mode-rbxdev-vault status` reports it. It asks once before adding its two hooks to `~/.claude/settings.json` (backup first); see `skills/low-usage-mode-rbxdev-vault/references/`.
- `/manager-mode-rbxdev-vault` : makes any Claude session act as a manager that delegates to right-sized workers (haiku/sonnet/opus), briefs and checks them, and respects a usage cap you set; `/manager-mode-rbxdev-vault install-presets` adds the worker presets.

## What to say instead
- `make me a Roblox game: <your idea>` (for example: `make me a Roblox game: a pet-collecting obby for kids`)
- `use the vault to build <your idea>`
- `give me game ideas that would do well` (ideas only, scored; no build)
- `make me a Roblox game` (no idea: it picks the best-scoring small one)

## What you get
A folder `<game-name>/` in the current directory with:
- `docs/GDD.md` (scored concepts, core loop, first 30 seconds, retention, monetisation plan, economy numbers, ad plan, assumptions), `docs/TASKS.md`, `docs/SELF-REVIEW.md`, `docs/research-notes.md` (every claim cites a vault note)
- a Rojo project (`default.project.json`, `src/server`, `src/client`, `src/shared`) with the core loop, data saving (ProfileStore, Apache-2.0), responsive UI and monetisation hooks written in Luau
- `docs/THIRD-PARTY.md` (libraries and licenses) and `docs/ASSET-IMPORT.md` (which downloaded models/sounds to import and how)
- a final report: how to open it in Roblox Studio (Rojo sync, or paste), what is untested, the next three tasks

It does not publish, spend Robux, or invent asset/pass ids (those are `0` until you create them in Creator Hub). Studio playtests are only run if the Roblox Studio MCP is available; otherwise everything is files and marked untested.

## Install
Normally automatic: the vault setup (SETUP-FOR-CLAUDE.md, or the sync scripts) runs it, and the vault update (at every logon/login, or on demand with `/update-rbxdev-vault` / `vault-update.ps1` / `vault-update.sh`) runs `kit-refresh.sh` / `kit-refresh.ps1` after the pull, so a kit update published to the vault reaches every computer by itself (quiet; one log line only when something changed). The same step syncs `<vault>/Assets` from the public vault-assets GitHub repositories (`tools/assets-sync.py`; sources in `repos.json`), and the reference screenshots (`tools/refs-sync.py`). By hand: `bash claude-kit/install.sh` (macOS/Linux) or `powershell -NoProfile -ExecutionPolicy Bypass -File claude-kit\install.ps1` (Windows). Writes only to `~/.claude/agents`, `~/.claude/skills`, `~/.claude/claude-kit`. Kit wins: a file you edited is replaced by the kit version after your original is copied to `~/.claude/claude-kit/backup/<date>/`; skills of yours with other names are untouched (similar ones are listed, and the kit skill is used when both cover the same job). See INSTALL.md.

Your own work is safe: `My Research/` (default output folder of the research skill), any folder containing `PROTECTED-RESEARCH.md` and every untracked file you created are never deleted by `/update-rbxdev-vault` (git-excluded; the update prints `N of your own files kept`); only edits to tracked (generated) files are patched and reset. `My Research` is a reserved name: the main vault never ships files there. Two commands: `/update-rbxdev-vault` (safe, keeps everything of yours) and `/update-clean-rbxdev-vault` (exact copy of the main vault, still keeps My Research; prints a dry run, asks once, backs up what it removes). One-liners: `vault-update.ps1 -Clean [-Yes] [-IncludeMine]` / `bash vault-update.sh --clean [--yes] [--include-mine]` (`-IncludeMine` also deletes My Research, only when you type it).

## Needs
- The vault on the computer (a git clone of the public vault repository) and, for assets, `<vault>/Assets` (the setup and every vault update sync it from the public vault-assets GitHub repositories; first run downloads about 2.7 GB).
- Optional: Python 3 (for `kbq.py`; without it the agents use grep), Rokit tools for static checks (`rokit install` in the template folder), Roblox Studio with the Rojo plugin to open the result. To let Claude drive Studio (write scripts, playtest, read Output) run the opt-in `tools/studio-setup.ps1` (Windows) / `tools/studio-setup.sh` (macOS) or use `/roblox-studio-connect`; you sign in to Studio and switch on "Enable Studio as MCP server" yourself.

Hooks (opt-in, never automatic): `bash claude-kit/install.sh --with-hooks` / `--remove-hooks` or `install.ps1 -WithHooks` / `-RemoveHooks` install the two low-usage-mode-rbxdev-vault hooks and the mentor-rbxdev-vault suggestion hook (on each prompt it runs `vault-find` and adds the top 3 matches, at most about 300 tokens, silent when nothing matches, no network; mute with the file `~/.claude/state/mentor-hook.off`).

Switch light/full view only (no update, offline): `/light-mode-on-rbxdev-vault`, `/light-mode-off-rbxdev-vault`, or `vault-update.ps1 -SetView light|full` / `bash vault-update.sh --set-view light|full`.

How the mode works: the installer puts the kit's skills and agents in `~/.claude/claude-kit/vault-mode/.claude/{skills,agents}` (not read by normal sessions); `/load-rbxdev-vault` (tools/vault-mode.py) copies them into the current folder's `.claude/`, lists them in `.claude/vault-mode.json`, hides them from git (`.git/info/exclude`) and prints `Roblox dev mode on: N skills, M agents, ...`; `/unload-rbxdev-vault` removes exactly those files (a file you changed is kept; a skill or agent of yours with the same name is skipped and yours wins); `/update-rbxdev-vault` refreshes every loaded folder and moves an older always-on install into the store (backup + manifest, idempotent, `vault-mode.py migrate --revert` undoes it). `/rbx-subagent-hud` and `/graph-rbxdev-vault` are Claude Code plugins (they load in every session), so they are opt-in: `install.sh --with-mods` / `install.ps1 -WithMods`.

To remove everything and keep only your games: `/uninstall-rbxdev-vault` (dry-run plan first, asks for a yes; copies `Games/`, `Games/_Reusable` and `My Research/` to `~/Roblox Games` and verifies the copy, removes hooks, the kit and the vault folder; `--keep-dir DIR`, `--keep-edited`).

Command names (changed 2026-11-04): every command and agent of this vault that has a generic name carries the vault's name, in the form `<verb>-<slug>-vault` (slug `rbxdev`: `/update-rbxdev-vault`, `/load-rbxdev-vault`, `/uninstall-rbxdev-vault`, `/mentor-rbxdev-vault`, `/graph-rbxdev-vault`, ...). That keeps them from clashing with another vault's commands or with your own skills. Roblox-specific names (`game-dev-*`, `roblox-*`, `make-roblox-game`, `/rbx`) are unchanged. The table is `~/.claude/claude-kit/tools/vault-names.json` (and `COMMANDS-RENAMED.txt` after a migration). If the kit was installed before this change, the first update (`kit-rename.py`, run by the installer) removes the old generic names the kit had installed (backup, only unchanged files, undo with `kit-rename.py migrate --revert`; a skill of yours with the same old name is left alone with a warning), refreshes the folders where the mode is loaded, and prints a one-time `NOTICE FOR THE USER ... commands renamed` line. The same mechanism removes skills and agents that were merged into another one (2026-11-04 prune, legacy names: the `removed` list in `vault-names.json`; notice `commands merged`): `roblox-ad-thumbnail-brief` is now part of `roblox-thumbnail-brief`, and the agents `roblox-builder`, `roblox-tester`, `roblox-ad-creative-planner`, `roblox-analytics-reviewer` are part of `roblox-luau-engineer`, `roblox-playtest-runner`, `roblox-launch-marketing-manager`, `roblox-game-doctor`. Commands you must type yourself (they are not in Claude's skill list, to save context): `/update-clean-rbxdev-vault`, `/uninstall-rbxdev-vault`, `/curate-rbxdev-vault`, `/contribute-rbxdev-vault`, `/light-mode-on-rbxdev-vault`, `/light-mode-off-rbxdev-vault`, `/list-rbxdev-vault`, `/setup-check-rbxdev-vault`, `/low-usage-mode-rbxdev-vault`.

Commands: `/update-check-rbxdev-vault` (is a newer vault/kit out; read-only, offers /update-rbxdev-vault), `/setup-check-rbxdev-vault` (software table with install commands; installs only after your yes). `/list-rbxdev-vault` lists everything installed (skills, agents, mods). `/rbx-subagent-hud` shows the master agent and its subagents (done count, time estimate, click a subagent to see its prompt); `/graph-rbxdev-vault` shows the vault graph (kit mods, opt-in because plugins load in every session: `install.sh --with-mods` / `install.ps1 -WithMods`; they only show in the terminal and desktop app, not in Remote Control or mobile). Precedence: when a kit skill and another installed skill cover the same job, the kit skill is used.

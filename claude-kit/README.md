# claude-kit (the manager toolkit of the Roblox Dev Mastery Vault)

Built and maintained by Roman (GitHub: romangigliotti123-arch)

Say one sentence on any computer and a Claude agent designs and builds a Roblox game for you, using the vault, the Roblox skills and your downloaded assets. It never asks you questions: if your idea is vague it makes assumptions, writes them down, and carries on.

## What to run (start a new Claude session in any folder first)
- `/game-idea [genre]` : one short idea that fits what is working on Roblox right now (live charts and trend sources, date-stamped, plus vault benchmarks), with the 30 s / 5 min / session loop, a solo buildable scope using kit systems and /rbx skills, and its critic idea score; say "start it" to hand it to `/game-dev-workflow`.
- `/game-dev-workflow` : the flagship flow. Asks only for your game idea, elaborates it from the vault, rates it 1.00-10.00, writes a build plan (skills, agents, models, budget), asks "Ready to build?", then it acts as a manager: spawns specialist workers (pack skills, kit agents) with master prompts filled from the vault, verifies their reports, proposes the next best jobs and ends with a playtest. Side commands, each also usable alone: `/game-dev-ads` (ads plan), `/game-dev-update` (update roadmap and patch notes), `/game-dev-playtest` (bug and feel report), `/game-dev-thumbnail` (icon/thumbnail prompts and images with the newest Nano Banana model from your own API key). Sub-skills: `/game-dev-rate`, `/game-dev-plan`, `/game-dev-art-direction` (art bible before building: palette, one UI style kit shipped as a Luau StyleKit, layout rules, lighting preset, model rules, juice list), `/game-dev-visual-qa` (the visual gate: screenshots of the running game, a layout-overlap check at phone/tablet/desktop, a 7-item rubric, up to 3 fix rounds; a game is never called done unless it passes, otherwise its status is "playable prototype, visuals not polished" with a polish backlog). They read the newest vault notes every run (pull, freshness line, live check).
- **Your games stay in the vault.** `/game-dev-workflow` is the single entry for every game: the first run asks your experience level and game type once; each game gets its own protected community `Games/<game>/` in the vault (`GAME.md` hub with stage, numbers and next tasks, `design`, `decisions`, `systems`, `playtests/`, `weekly/`, `critic/`, all linked into the KB so Obsidian shows one cluster per game). Run it again any time: it detects the real stage from evidence (idea > prototype > playtest > launch > growth > live-ops) and resumes. Judgement: before a stage advances or anything is called done, an independent critic (`/game-dev-critic`, agent `game-critic`) scores 10 hit-versus-flop factors with evidence, separates "works" from "good" and says GOOD / NOT YET / BAD with the top 3 fixes; NOT YET blocks. Also: `/game-dev-weekly` (paste Creator Dashboard numbers, get the week's plan), `/game-dev-launch-kit` (thumbnails, ads, update calendar, checklists), `/game-dev-harvest` (save reusable systems to `Games/_Reusable/`, found first by `vault-find --type reusable`), `/vault-contribute` (optional: bundle one for the vault owner). `Games/` is never touched or shipped by `/vault-update` or `/vault-update-clean`.
- `/vault-mentor` : a co-pilot with the combined knowledge of every creator in both vaults; it works alongside you on any job and suggests the right skill, agent, note or creator method at each step, and answers "what would <creator> do" (agent `vault-mentor`; reads `CAPABILITIES.md` and `Mentor/Combined-Brain.md` first).
- `/low-usage-mode` : keeps Claude in low usage mode for every message and session until `/low-usage-mode off` (cheapest model that fits, at most one subagent, short replies, small tool output; each reply starts with "low usage mode enabled."). `/low-usage-mode status` reports it. It asks once before adding its two hooks to `~/.claude/settings.json` (backup first); see `skills/low-usage-mode/references/`.
- `/manager-mode` : makes any Claude session act as a manager that delegates to right-sized workers (haiku/sonnet/opus), briefs and checks them, and respects a usage cap you set; `/manager-mode install-presets` adds the worker presets.

## What to say instead
- `make me a Roblox game: <your idea>` (for example: `make me a Roblox game: a pet-collecting obby for kids`)
- `use the vault to build <your idea>`
- `give me game ideas that would do well` (ideas only, scored; no build)
- `make me a Roblox game` (no idea: it picks the best-scoring small one)

## What you get
A folder `<game-name>/` in the current directory with:
- `docs/GDD.md` (scored concepts, core loop, first 30 seconds, retention, monetisation plan, economy numbers, ad plan, assumptions), `docs/TASKS.md`, `docs/SELF-REVIEW.md`, `docs/research-notes.md` (every claim cites a vault note)
- a Rojo project (`default.project.json`, `src/server`, `src/client`, `src/shared`) with the core loop, data saving (ProfileStore, Apache-2.0), responsive UI and monetisation hooks written in Luau
- `docs/THIRD-PARTY.md` (libraries and licenses) and `docs/ASSET-IMPORT.md` (which downloaded models/sounds to import and how)
- a final report: how to open it in Roblox Studio (Rojo sync, or paste), what is untested, the next three tasks

It does not publish, spend Robux, or invent asset/pass ids (those are `0` until you create them in Creator Hub). Studio playtests are only run if the Roblox Studio MCP is available; otherwise everything is files and marked untested.

## Install
Normally automatic: the vault setup (SETUP-FOR-CLAUDE.md, or the sync scripts) runs it, and the vault update (at every logon/login, or on demand with `/vault-update` / `vault-update.ps1` / `vault-update.sh`) runs `kit-refresh.sh` / `kit-refresh.ps1` after the pull, so a kit update published to the vault reaches every computer by itself (quiet; one log line only when something changed). The same step syncs `<vault>/Assets` from the host share (`tools/assets-sync.py`). By hand: `bash claude-kit/install.sh` (macOS/Linux) or `powershell -NoProfile -ExecutionPolicy Bypass -File claude-kit\install.ps1` (Windows). Writes only to `~/.claude/agents`, `~/.claude/skills`, `~/.claude/claude-kit`. Kit wins: a file you edited is replaced by the kit version after your original is copied to `~/.claude/claude-kit/backup/<date>/`; skills of yours with other names are untouched (similar ones are listed, and the kit skill is used when both cover the same job). See INSTALL.md.

Your own work is safe: `My Research/` (default output folder of the research skill), any folder containing `PROTECTED-RESEARCH.md` and every untracked file you created are never deleted by `/vault-update` (git-excluded; the update prints `N of your own files kept`); only edits to tracked (generated) files are patched and reset. `My Research` is a reserved name: the main vault never ships files there. Two commands: `/vault-update` (safe, keeps everything of yours) and `/vault-update-clean` (exact copy of the main vault, still keeps My Research; prints a dry run, asks once, backs up what it removes). One-liners: `vault-update.ps1 -Clean [-Yes] [-IncludeMine]` / `bash vault-update.sh --clean [--yes] [--include-mine]` (`-IncludeMine` also deletes My Research, only when you type it).

## Needs
- The vault on the computer (Tailscale to the host PC, or GitHub login) and, for assets, `<vault>/Assets` (the setup and every vault update sync it from the host share; first run downloads about 2.7 GB).
- Optional: Python 3 (for `kbq.py`; without it the agents use grep), Rokit tools for static checks (`rokit install` in the template folder), Roblox Studio with the Rojo plugin to open the result. To let Claude drive Studio (write scripts, playtest, read Output) run the opt-in `tools/studio-setup.ps1` (Windows) / `tools/studio-setup.sh` (macOS) or use `/roblox-studio-connect`; you sign in to Studio and switch on "Enable Studio as MCP server" yourself.

Hooks (opt-in, never automatic): `bash claude-kit/install.sh --with-hooks` / `--remove-hooks` or `install.ps1 -WithHooks` / `-RemoveHooks` install the two low-usage-mode hooks and the vault-mentor suggestion hook (on each prompt it runs `vault-find` and adds the top 3 matches, at most about 300 tokens, silent when nothing matches, no network; mute with the file `~/.claude/state/mentor-hook.off`).

Switch light/full view only (no update, offline): `/light-mode-on`, `/light-mode-off`, or `vault-update.ps1 -SetView light|full` / `bash vault-update.sh --set-view light|full`.

To remove everything and keep only your games: `/uninstall` (dry-run plan first, asks for a yes; copies `Games/`, `Games/_Reusable` and `My Research/` to `~/Roblox Games` and verifies the copy, removes hooks, the kit and the vault folder; `--keep-dir DIR`, `--keep-edited`).

Commands: `/update-check` (is a newer vault/kit out; read-only, offers /vault-update), `/setup-check` (software table with install commands; installs only after your yes). `/kit-list` lists everything installed (skills, agents, mods). `/hud` shows the workflow agent tree and turn progress; `/graph` shows the vault graph (kit mods installed with the kit via `claude plugin`; they only show in the terminal and desktop app, not in Remote Control or mobile). Precedence: when a kit skill and another installed skill cover the same job, the kit skill is used.

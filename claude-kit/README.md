# claude-kit (the manager toolkit of the Roblox Dev Mastery Vault)

Built and maintained by Roman (GitHub: romangigliotti123-arch)

## Quick start

**HOW TO START USING**
- Start a new Claude session in your vault folder (for example `~/Obsidian/claudes-vault`); that folder has everything loaded.

**HOW TO SEE SKILLS AND AGENTS**
- Type `/rbx-list` in that session, or `/` then `rbx-`.

**THE TWO MODS (ALREADY INSTALLED)**
- Type `/reload-plugins` once; they run in the vault folder only. Remove: `/plugin`, or the installer's `--no-mods`.

**HOW TO MAKE A GAME IDEA**
- `/rbx-ideas` finds one fresh idea (reply `another`, `build it` or `plan`); `/rbx-idea-creator` starts from yours.

**HOW TO BUILD A GAME**
- `/rbx-workflow` builds a game stage by stage; resume with "I want to work on <game name>".

**HOW TO UPDATE**
- Type `/rbx-update` (works from any session).

**NOT SURE WHICH SKILL?**
- Just describe what you want; Claude offers the right skill and you reply yes.

More details: `MANUAL-READ.md` in the vault folder (or the site's `/manual` page).

Say one sentence on any computer and a Claude agent designs and builds a Roblox game for you, using the vault, the Roblox skills and your downloaded assets. It never asks you questions: if your idea is vague it makes assumptions, writes them down, and carries on.

## What to run (start Claude in the vault folder, then these)
The vault folder (your clone, for example `~/Obsidian/claudes-vault`) is permanently loaded: the installer and every `/rbx-update` write the vault skills, agents, art-direction, placement, lighting and visual-QA rules and reference-image pointers into its own `.claude/` (hidden from git together with `Games/` and `Models/`). Load the vault by starting a Claude session in that folder; there is no load or unload command. A normal Claude session in any other folder loads nothing from the vault. Always available everywhere: `/rbx-update`, `/rbx-check`, `/rbx-uninstall`.
- `/rbx-ideas [genre]` : Claude reads a dated market brief and random seeds, a maker that never sees a rubric invents ONE strange idea, a separate judge (`rbx-idea-judge`, a bored 12-year-old) says what is good, bad and where a kid quits, the maker edits (up to 3 rounds), and a short dot-point card is shown (hook, first 30 s, D1 and week-1 return plan, money, build ease 1-10, category); reply `build it` to create `Games/<slug>/` with a seeded README, `another` or `plan`. `/rbx-idea-creator <your idea>` does the same starting from YOUR idea; with no idea it asks a few multiple-choice questions (category first).
- `/rbx-idea-quick [genre]` : one short idea that fits what is working on Roblox right now (live charts and trend sources, date-stamped, plus vault benchmarks), with the 30 s / 5 min / session loop, a solo buildable scope using kit systems and /rbx skills, and its critic idea score; say "start it" to hand it to `/rbx-workflow`.
- `/rbx-workflow` : the flagship flow. Asks only for your game idea, elaborates it from the vault, rates it 1.00-10.00, writes a build plan (skills, agents, models, budget), asks "Ready to build?", then it acts as a manager: spawns specialist workers (pack skills, kit agents) with master prompts filled from the vault, verifies their reports, proposes the next best jobs and ends with a playtest. Side commands, each also usable alone: `/rbx-ads` (ads plan), `/rbx-game-update` (update roadmap and patch notes), `/rbx-playtest` (bug and feel report), `/rbx-thumbnail` (icon/thumbnail prompts and images with the newest Nano Banana model from your own API key). Sub-skills: `/rbx-rate`, `/rbx-plan`, `/rbx-art` (art bible before building: palette, one UI style kit shipped as a Luau StyleKit, layout rules, lighting preset, model rules, juice list), `/rbx-placement` (the placement gate: every model created, inserted or moved is measured in Studio for pivot and size, grounded, upright, facing, overlap, anchoring and connections, auto-fixed and re-verified; a full-map scan must pass before a game is called done), `/rbx-visual` (the visual gate: screenshots of the running game, a layout-overlap check at phone/tablet/desktop, a 7-item rubric, up to 3 fix rounds; a game is never called done unless it passes, otherwise its status is "playable prototype, visuals not polished" with a polish backlog). They read the newest vault notes every run (pull, freshness line, live check).
- **Your games live in your project folder.** `/rbx-workflow` is the single entry for every game: the first run asks your experience level and game type once; each game gets `Games/<game>/` in the vault folder (the loaded folder; git-excluded, so updates never touch it; never HOME or `~/.claude`) with a `README.md` resume file (say "work on <game>" in any new chat started in the vault folder: Claude reads it and answers "Got it"), `GAME.md` (stage, numbers, next tasks), `design`, `decisions`, `systems`, `playtests/`, `weekly/`, `critic/`. Run it again any time: it detects the real stage from evidence (idea > prototype > playtest > launch > growth > live-ops) and resumes. Judgement: before a stage advances or anything is called done, an independent critic (`/rbx-critic`, agent `rbx-judge`) scores 10 hit-versus-flop factors with evidence, separates "works" from "good" and says GOOD / NOT YET / BAD with the top 3 fixes; NOT YET blocks. Also: `/rbx-weekly` (paste Creator Dashboard numbers, get the week's plan), `/rbx-launch-kit` (thumbnails, ads, update calendar, checklists), `/rbx-harvest` (save reusable systems to `Games/_Reusable/`, found first by `vault-find --type reusable`). `Games/` is never touched or shipped by `/rbx-update` or `/rbx-clean`.
- **Models library.** `Models/` in the vault folder (next to `Games/`, git-excluded, never touched by an update) keeps the few best reusable 3D models: Claude runs `models.py find <words>` before building a model and saves a new one only if it passes the strict admission rules (quality >= 8/10 with the visual and placement gates passed, generic across 3+ genres, theme-able by parameters, self-contained, original or CC0, no duplicates, max 40 models and 6 per category). Instructions: `Models/README.md`; tool: `tools/models.py`.
- `/rbx-bench` : measure the vault itself. `scorecard.py` turns every gate result of a game (visual, placement, lighting, critic, any new gate) into a 0-100 scorecard with the top 3 problems and fixes, a history CSV and a before/after compare; 3 standard test games (obby, tycoon, tower defense) let any vault version be compared on the same task; `vault_cost.py` estimates what load mode costs a session (tokens, install time, heaviest skills). Protocol: `skills/rbx-bench/references/protocol.md`.
- `/rbx-arch` : picks the structure of a Roblox system (plain module, OOP, components, ECS, state store, object pool) by evidence, with Luau examples; `rbx-luau` now has a lifecycle and leak-cleanup section, `rbx-code-rate` a severity-ranked sharp-edges checklist plus the generated-vs-tested evidence ladder (and a `code-quality/gate.json` that rbx-bench scores), and `rbx-monetize-audit` / `rbx-rate` a fair-or-pressure ethics column. Ideas adapted from excaldev/ro-engineer (MIT); reference copies live in the vault under `Imported/ro-engineer`.
- `/rbx-tune` : bounded metric loop for balance, optimise and polish work. Pick ONE number and a read-only evaluator, baseline it, change one thing per experiment, keep only strict improvements, revert the rest, log every run in `Games/<slug>/tune/<run-id>/` (`tune_check.py` validates the ledger: baseline row, strict improvement, unchanged evaluator, budget, gates still passing). The loop idea comes from Karpathy's autoresearch (no licence file in that repo, so idea only, own words); the unbounded never-stop mode is not adopted.
- **Research round 2 (INT, 2026-11-05; ideas adapted in our own words, nothing installed, no hooks).** (1) Agent audit: all 17 agents set `model` and `effort`; the read-only roles (rbx-reviewer, rbx-judge, rbx-verifier, rbx-auditor) carry `disallowedTools` for Edit and NotebookEdit (rbx-verifier also Write); `omitClaudeMd` is deliberately unused, because the vault rules reach a subagent through its brief only if the brief carries them; recommendation only. (2) Evidence before claims: one mode rule, plus `rbx-critic/scripts/evidence_scan.py <report.md>` (EV1-EV3: hedge words, claims without a command and output, a subagent success claim without a diff check), run by `code_gates.py --report <final report>`; scored like the other gates, never a block ([cold:rbx-critic/evidence.md]). (3) Token-triggered checks: `static_scan.py <project> --triggers` maps code tokens (OnServerEvent, PlayerAdded, CharacterAdded, Touched, LoadAnimation, DataStore calls, loops that fire remotes, connections with no cleanup) to the SE-n checks of rbx-code-rate in severity order TR1-TR4 (exploits and data loss, crashes, leaks, performance), also run by `code_gates.py`. (4) Rulings, DONE WHEN and spec-before-style: `Ruling: what - why - cost if wrong` in decisions.md, one checkable DONE WHEN line whose command output is printed in CRITERIA, spec compliance judged before style ([cold:rbx-workflow/rulings.md]). (5) Scanner leads need a TRUE-POSITIVE / FALSE-POSITIVE verdict with an evidence line before a fix loop acts; mutation testing of the Systems tests is an optional one-off, not a rule ([cold:rbx-playtest/fp-verdict.md]). (6) The built-in Studio MCP is the first choice in rbx-studio and /rbx-setup (Windows config `cmd.exe /c %LOCALAPPDATA%\Roblox\mcp.bat`; `script_grep`/`search_game_tree` before reading scripts, `multi_edit` instead of rewriting), the older Rust server only a fallback; NOT yet tested live in Studio. Credits: Superpowers (MIT) for verification and rulings; Trail of Bits skills (CC-BY-SA) and a public Luau optimiser skill (no licence) as ideas only.
- **Code gates, Fix loop, smallest complete change (adapted from the video "9 Claude Skills I Use Every Single Day", ideas only, nothing installed).** `rbx-critic/scripts/code_gates.py <project> --write Games/<slug>` is the one runner of the scored code gates: comment-scan (CM1-3), scope-scan (SC1-5: orphan modules, TODO stubs, kit systems rebuilt by hand, unused exports, oversized files), security-scan (`static_scan.py --gate`, SEC1-5: client-trusted remotes, hardcoded keys and webhooks, server code in ReplicatedStorage, DataStore and receipt safety, backdoor patterns), bugfix ledgers (FL1) and tune ledgers (TN1-6). Policy: every finding is SCORED and never blocks (the scans are heuristics and give false hits); NOT RUNNING them does block the verdict: the critic must run them itself, otherwise it cannot return GOOD (`playable prototype, code gates not run`; the verdict file carries `codegates: ran`, which `games.py advance` needs; verdict files from before count as not run). The standing rules sit in the load-mode rules (two bullets), the builder, engineer, reviewer and critic agents, and the workflow and manager steps. `rbx-playtest` has the Fix loop (reproduce first: a red check before any edit, the same check green after, ledger `Games/<slug>/bugfix/<id>.md`); `rbx-luau` has the Smallest complete change ladder (reuse a kit system or Roblox built-in before new code); the manager builds the core loop alone in wave 1. Credits: Ponytail and Unlazy (smallest change, stubs), Vibe Security (security gate), Matt Pocock's diagnosing-bugs and pstack / Poteto mode by Lauren Tan (fix loop, core loop first), all MIT, re-written in our own words.
- **No code comments by default.** Every agent and skill that writes code follows one rule (`rbx-luau`, Comments; also in the load-mode rules): no comments, except one line that says WHY something non-obvious is done (engine quirk, ordering, replication timing, physics ownership), never WHAT. Type annotations and `--!` directives stay. All shipped Luau (StyleKit, templates, systems, skill-pack scripts, the generated Placement and Lighting modules) was stripped to match; `rbx-critic/scripts/comment_scan.py` counts stray comments per file and writes a scored, never blocking `comment-scan/gate.json` that rbx-bench picks up.
- `/rbx-mockup` : UI mockup mode, `on|off|status`. Default OFF = AUTOMATIC DESIGN-FIRST: before any UI is built, Claude designs every button (default/hover/pressed/disabled) and each screen layout itself (`rbx-ui-mockup`: a local HTML/CSS design sheet with tokens, phone + desktop frames and real Roblox font names, rendered to PNG by a headless Chrome/Edge that is already installed, else HTML only), exports the exact rectangles, colours, text and font sizes as a spec, builds from it, compares the built UI numerically and iterates (max 3 rounds); report line `UI design: done (auto|figma|manual) / skipped: <reason>` (advisory). If your Claude has the Figma connector enabled it is used; if not, ONE line says Figma isn't connected and how to connect it (the vault never asks for or stores Figma tokens). ON = a MANUAL package for making mockups yourself with Nano Banana 2.1 on the Gemini website (`ui-mockup/`: prompts, reference images, numbered steps, checklist; nothing waits for the images). The setup asks one yes/no question about it; the default is no. Tools: `skills/rbx-ui-mockup/scripts/{ui_design,ui_spec,ui_compare,ui_assets,ui_mock}.py` (stdlib, no network), `tools/ui_pref.py` (preference file `claude-kit/ui-mockup.json`).
- `/rbx-ui-prototype` : turns a UI mockup picture (a Gemini or Nano Banana image, or any screenshot you drop in the game folder) into ONE self-contained HTML prototype in `Games/<slug>/ui/prototype/index.html` that you open in a browser (double-click): working buttons with hover, press and disabled states and squish animations, navigation between every screen, tabs and modals, fake coin and gem counters, inventory and equip, toasts, keyboard shortcuts, a device switcher (Phone, Tablet, Desktop) with a rotate button (key R) that turns phone and tablet between portrait and landscape, screens that reflow per orientation, and a safe-area overlay per orientation, a Roblox constraints list, a visible 'not buildable as-is' note and a fidelity panel (what was matched from the image and what was guessed). Only things Roblox UI can build are used. It also writes `spec.json` and `handoff.md` (each component mapped to a Frame/ImageButton/UICorner/UIStroke/Scale tree) for `/rbx-ui`, and `scripts/proto_check.py` verifies the page (one file, no network, required parts) before Claude says it is done. Say: `prototype this mockup`. It is a stand-in, never the game; `rbx-visual` runs only after the real build.
- Thumbnail click psychology (inside `/rbx-thumbnail`, no new command): candidates from any source (`gen_image.py`, manual Nano Banana, user-supplied; a Blender render source is optional: see the next paragraph) are scored by LOOKING at them against a rubric of 3 gates and 13 weighted checks (max 46, pass 32; weights and the pass bar are labelled assumptions, grounded in an evidence-graded A/B/C table of click-psychology principles and Roblox's own thumbnail rules). `skills/rbx-thumbnail/scripts/thumb_score.py` does the arithmetic, ranks 2-5 variants, checks the file (16:9 or square, 1920x1080, under 3 MB, icon at least 512) and writes the advisory gate `thumb-score/gate.json`; the launch and publish steps report `thumbnail: scored <score>/<max> (variants N)` or `thumbnail: skipped: <reason>` (shown in the critic's launch verdict and the scorecard, never blocking). After a Roblox thumbnail personalization test (2-5 thumbnails, hold 7 days or more) decide the winner by hand with the rule in the cold protocol file. Fair-promise guard: a thumbnail must match the first minute of play. Heavy text lives in `mode/cold/rbx-thumbnail/`.
- Optional Blender renders (inside `/rbx-thumbnail`, no new command, needs your own free Blender, nothing is installed or downloaded): `skills/rbx-thumbnail/scripts/blender_gfx.py detect|gen|check|run` writes a GPL-2.0-or-later bpy script for a hero icon, character portrait, action pose, text-less scene or palette variants (3-point light with a contrasting rim, 1920x1080 or 1024 square, flat-colour override for untextured Studio exports), refuses scripts that import os/subprocess/socket or call eval/exec/open, and renders headless into `<project>/renders/` with timeouts and sample caps; the PNGs are scored like any other candidate. UNTESTED LIVE (no Blender on the build host). Details in `mode/cold/rbx-thumbnail/blender.md`.
- `/rbx-mentor` : a co-pilot with the combined knowledge of every creator in both vaults; it works alongside you on any job and suggests the right skill, agent, note or creator method at each step, and answers "what would <creator> do" (agent `rbx-coach`; reads `CAPABILITIES.md` and `Mentor/Combined-Brain.md` first).
- `/rbx-low-usage` : keeps Claude in low usage mode for every message and session until `/rbx-low-usage off` (cheapest model that fits, at most one subagent, short replies, small tool output; each reply starts with "low usage mode enabled."). `/rbx-low-usage status` reports it. It asks once before adding its two hooks to `~/.claude/settings.json` (backup first); see `skills/rbx-low-usage/references/`.
- `/rbx-manager` : makes any Claude session act as a manager that delegates to right-sized workers (haiku/sonnet/opus), briefs and checks them, and respects a usage cap you set; `/rbx-manager install-presets` adds the worker presets.

- `make me a Roblox game: <your idea>` (for example: `make me a Roblox game: a pet-collecting obby for kids`)

- `give me game ideas that would do well` (ideas only, scored; no build)

## What you get
A folder `<game-name>/` in the current directory with:
- `docs/GDD.md` (scored concepts, core loop, first 30 seconds, retention, monetisation plan, economy numbers, ad plan, assumptions), `docs/TASKS.md`, `docs/SELF-REVIEW.md`, `docs/research-notes.md` (every claim cites a vault note)
- a Rojo project (`default.project.json`, `src/server`, `src/client`, `src/shared`) with the core loop, data saving (ProfileStore, Apache-2.0), responsive UI and monetisation hooks written in Luau
- `docs/THIRD-PARTY.md` (libraries and licenses) and `docs/ASSET-IMPORT.md` (which downloaded models/sounds to import and how)
- a final report: how to open it in Roblox Studio (Rojo sync, or paste), what is untested, the next three tasks

It does not publish, spend Robux, or invent asset/pass ids (those are `0` until you create them in Creator Hub). Studio playtests are only run if the Roblox Studio MCP is available; otherwise everything is files and marked untested.

## Install
Normally automatic: the vault setup (SETUP-FOR-CLAUDE.md, or the sync scripts) runs it, and the vault update (at every logon/login, or on demand with `/rbx-update` / `vault-update.ps1` / `vault-update.sh`) runs `kit-refresh.sh` / `kit-refresh.ps1` after the pull, so a kit update published to the vault reaches every computer by itself (quiet; one log line only when something changed). The same step syncs `<vault>/Assets` from the public vault-assets GitHub repositories (`tools/assets-sync.py`; sources in `repos.json`), and the reference screenshots (`tools/refs-sync.py`). By hand: `bash claude-kit/install.sh` (macOS/Linux) or `powershell -NoProfile -ExecutionPolicy Bypass -File claude-kit\install.ps1` (Windows). Writes only to `~/.claude/agents`, `~/.claude/skills`, `~/.claude/claude-kit`. The vault owns every file it installs: an update overwrites each one with the new version (no keep files, no conflicts, no notices) and removes files that left the vault. What is yours: the `Games/` and `Models/` folders of your project and anything outside the vault's own paths; install, update, load, unload and sync never touch them. Only tiny settings (the `/rbx-mockup` choice) live in `~/.claude/claude-kit/state/` and are never deleted. Old leftovers there from earlier versions (learnings-queue, hiccups, conflicts, overrides, thumbnails) are ignored; delete them by hand if you like. See INSTALL.md.

`/rbx-update` ends with a `Vault: <folder> | Kit: <folder>` line showing where the vault and kit are on your computer.

Your own work is safe: `My Research/` (default output folder of the research skill), any folder containing `PROTECTED-RESEARCH.md` and every untracked file you created are never deleted by `/rbx-update` (git-excluded); only edits to tracked (generated) files are patched and reset. `My Research` is a reserved name: the main vault never ships files there. Two commands: `/rbx-update` (safe, keeps everything of yours) and `/rbx-clean` (exact copy of the main vault, still keeps My Research; prints a dry run, asks once, backs up what it removes). One-liners: `vault-update.ps1 -Clean [-Yes] [-IncludeMine]` / `bash vault-update.sh --clean [--yes] [--include-mine]` (`-IncludeMine` also deletes My Research, only when you type it).

## Needs
- The vault on the computer (a git clone of the public vault repository) and, for assets, `<vault>/Assets` (the setup and every vault update sync it from the public vault-assets GitHub repositories; first run downloads 1.02 GB of zips).
- Optional: Python 3 (for `kbq.py`; without it the agents use grep), Rokit tools for static checks (`rokit install` in the template folder), Roblox Studio with the Rojo plugin to open the result. To let Claude drive Studio (write scripts, playtest, read Output) run the opt-in `tools/studio-setup.ps1` (Windows) / `tools/studio-setup.sh` (macOS) or use `/rbx-studio`; you sign in to Studio and switch on "Enable Studio as MCP server" yourself.

Hooks (opt-in, never automatic): `bash claude-kit/install.sh --with-hooks` / `--remove-hooks` or `install.ps1 -WithHooks` / `-RemoveHooks` install the two rbx-low-usage hooks and the rbx-mentor suggestion hook (on each prompt it runs `vault-find` and adds the top 3 matches, at most about 300 tokens, silent when nothing matches, no network; mute with the file `~/.claude/state/mentor-hook.off`).

Switch light/full view only (no update, offline): `/rbx-light-on`, `/rbx-light-off`, or `vault-update.ps1 -SetView light|full` / `bash vault-update.sh --set-view light|full`.

How the mode works: the installer puts the kit's skills and agents in `~/.claude/claude-kit/vault-mode/.claude/{skills,agents}` (not read by normal sessions). The **cold area** (`mode/cold/<topic>/<file>.md` in the kit, `~/.claude/claude-kit/vault-mode/cold/` after install) holds bulk the skills rarely need (sources and attribution, worked examples, long evidence, trigger phrases cut from descriptions); skills carry one-line pointers `[cold:topic/file] <when to read it>`, `python ~/.claude/claude-kit/tools/vault-mode.py cold [topic[/file]]` prints it, and the cold area is never copied into a folder. The installer and every update (internal tool `tools/vault-mode.py load --project <vault>`) copy the store's skills and agents into the VAULT FOLDER's `.claude/` (overwritten each time: the vault owns them), list them in `.claude/vault-mode.json`, hide them together with `Games/` and `Models/` from git (`.git/info/exclude`) and save the vault rules (short dot-point replies ending in Done / You / Next lines) as a marked block in the vault folder's `.claude/CLAUDE.md`, so a Claude session started in the vault folder has everything and no load or unload command exists; folders that an older kit had loaded are cleaned once (`Vault copies removed from N old project folders (your Games/ and Models/ there were left in place). Start sessions in <vault path> instead.`); `/rbx-update` also moves an older always-on install into the store (backup + manifest, idempotent, `vault-mode.py migrate --revert` undoes it). `/rbx-subagent-hud` and `/rbx-graph` are Claude Code plugins (they load in every session), so they are opt-in: `install.sh --with-mods` / `install.ps1 -WithMods`.

To remove everything and keep only your games: `/rbx-uninstall` (dry-run plan first, asks for a yes; copies `Games/`, `Games/_Reusable` and `My Research/` to `~/Roblox Games` and verifies the copy, removes hooks, the kit and the vault folder; `--keep-dir DIR`, `--keep-edited`).

Command names (changed 2026-11-05): every command, agent and mod of this vault is named `rbx-<short-name>` (`/rbx-update`, `/rbx-check`, `/rbx-uninstall`, `/rbx-mentor`, `/rbx-graph`, `/rbx-plan`, ...; the router is `/rbx`). Type `/rbx-` and autocomplete lists every vault command. The one short prefix keeps them from clashing with another vault's commands or with your own skills. The table is `~/.claude/claude-kit/tools/vault-names.json` (and `COMMANDS-RENAMED.txt` after a migration). If the kit was installed before this change (the long `...-rbxdev-vault` names of 2026-11-04, the original unsuffixed names, or the long `game-dev-*` / `roblox-*` names), the first update (`kit-rename.py`, run by the installer) removes the old-named files the kit had installed (backup, only unchanged files, undo with `kit-rename.py migrate --revert`; a skill or agent of yours with the same old name is left alone with a warning), refreshes the folders where the mode is loaded, and prints a one-time `NOTICE FOR THE USER ... commands renamed` line. The same mechanism removes skills and agents that were merged into another one (2026-11-04 prune, legacy names: the `removed` list in `vault-names.json`; notice `commands merged`): `roblox-ad-thumbnail-brief` is now part of `rbx-thumb-brief`, and the agents `roblox-builder`, `roblox-tester`, `roblox-ad-creative-planner`, `roblox-analytics-reviewer` are part of `rbx-engineer`, `rbx-tester`, `rbx-marketer`, `rbx-doctor`. Commands you must type yourself (they are not in Claude's skill list, to save context): `/rbx-clean`, `/rbx-uninstall`, `/rbx-light-on`, `/rbx-light-off`, `/rbx-list`, `/rbx-setup`, `/rbx-low-usage`.

Commands: `/rbx-check` (is a newer vault/kit out; read-only, offers /rbx-update), `/rbx-setup` (software table with install commands; installs only after your yes). `/rbx-list` lists everything installed (skills, agents, mods). `/rbx-subagent-hud` shows the master agent and its subagents (done count, time estimate, click a subagent to see its prompt); `/rbx-graph` replies with the link to the vault graph site (kit mods, installed by default for the vault folder only (project scope), so they apply only to sessions started there, and register hooks; turn them off with `/plugin` or `install.sh --no-mods` / `install.ps1 -NoMods`; they only show in the terminal and desktop app, not in Remote Control or mobile). Precedence: when a kit skill and another installed skill cover the same job, the kit skill is used.

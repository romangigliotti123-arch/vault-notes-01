# claude-kit (the manager toolkit of the Roblox Dev Mastery Vault)

Built and maintained by Roman (GitHub: romangigliotti123-arch)

Say one sentence on any computer and a Claude agent designs and builds a Roblox game for you, using the vault, the Roblox skills and your downloaded assets. It never asks you questions: if your idea is vague it makes assumptions, writes them down, and carries on.

## What to run (in your Roblox project folder: start Claude, type `/rbx-load`, then these)
The vault kit is installed but switched OFF by default: a normal Claude session loads nothing from it. In your Roblox project folder type `/rbx-load` (Roblox dev mode: the vault skills, agents, art-direction, placement, lighting and visual-QA rules, reference images, learn step) and `/rbx-unload` to turn it off again. Always available: `/rbx-load`, `/rbx-unload`, `/rbx-update`, `/rbx-check`, `/rbx-uninstall`. In your home or config folder `/rbx-load` loads for that session only (nothing is written; a project folder gives the full persistent mode). Session-only alternative that writes nothing into the project: `claude --add-dir ~/.claude/claude-kit/vault-mode`, then `/rbx-load`. Auto-load for Roblox project folders (opt-in, nothing adds it for you): `python ~/.claude/claude-kit/tools/vault-mode.py autoload-snippet` prints a SessionStart hook for settings.json.
- `/rbx-idea-quick [genre]` : one short idea that fits what is working on Roblox right now (live charts and trend sources, date-stamped, plus vault benchmarks), with the 30 s / 5 min / session loop, a solo buildable scope using kit systems and /rbx skills, and its critic idea score; say "start it" to hand it to `/rbx-workflow`.
- `/rbx-workflow` : the flagship flow. Asks only for your game idea, elaborates it from the vault, rates it 1.00-10.00, writes a build plan (skills, agents, models, budget), asks "Ready to build?", then it acts as a manager: spawns specialist workers (pack skills, kit agents) with master prompts filled from the vault, verifies their reports, proposes the next best jobs and ends with a playtest. Side commands, each also usable alone: `/rbx-ads` (ads plan), `/rbx-game-update` (update roadmap and patch notes), `/rbx-playtest` (bug and feel report), `/rbx-thumbnail` (icon/thumbnail prompts and images with the newest Nano Banana model from your own API key). Sub-skills: `/rbx-rate`, `/rbx-plan`, `/rbx-art` (art bible before building: palette, one UI style kit shipped as a Luau StyleKit, layout rules, lighting preset, model rules, juice list), `/rbx-placement` (the placement gate: every model created, inserted or moved is measured in Studio for pivot and size, grounded, upright, facing, overlap, anchoring and connections, auto-fixed and re-verified; a full-map scan must pass before a game is called done), `/rbx-visual` (the visual gate: screenshots of the running game, a layout-overlap check at phone/tablet/desktop, a 7-item rubric, up to 3 fix rounds; a game is never called done unless it passes, otherwise its status is "playable prototype, visuals not polished" with a polish backlog). They read the newest vault notes every run (pull, freshness line, live check).
- **Your games live in your project folder.** `/rbx-workflow` is the single entry for every game: the first run asks your experience level and game type once; each game gets `Games/<game>/` in the loaded project folder (never the vault clone or HOME) with a `README.md` resume file (say "work on <game>" in any new chat of that folder: Claude reads it and answers "Got it"), `GAME.md` (stage, numbers, next tasks), `design`, `decisions`, `systems`, `playtests/`, `weekly/`, `critic/`. Run it again any time: it detects the real stage from evidence (idea > prototype > playtest > launch > growth > live-ops) and resumes. Judgement: before a stage advances or anything is called done, an independent critic (`/rbx-critic`, agent `rbx-judge`) scores 10 hit-versus-flop factors with evidence, separates "works" from "good" and says GOOD / NOT YET / BAD with the top 3 fixes; NOT YET blocks. Also: `/rbx-weekly` (paste Creator Dashboard numbers, get the week's plan), `/rbx-launch-kit` (thumbnails, ads, update calendar, checklists), `/rbx-harvest` (save reusable systems to `Games/_Reusable/`, found first by `vault-find --type reusable`), `/rbx-contribute` (optional: bundle one for the vault owner). `Games/` is never touched or shipped by `/rbx-update` or `/rbx-clean`.
- `/rbx-bench` : measure the vault itself. `scorecard.py` turns every gate result of a game (visual, placement, lighting, critic, any new gate) into a 0-100 scorecard with the top 3 problems and fixes, a history CSV and a before/after compare; 3 standard test games (obby, tycoon, tower defense) let any vault version be compared on the same task; `vault_cost.py` estimates what load mode costs a session (tokens, install time, heaviest skills); `learn_stats.py` reports how much the learning loop is used. Protocol: `skills/rbx-bench/references/protocol.md`.
- `/rbx-arch` : picks the structure of a Roblox system (plain module, OOP, components, ECS, state store, object pool) by evidence, with Luau examples; `rbx-luau` now has a lifecycle and leak-cleanup section, `rbx-code-rate` a severity-ranked sharp-edges checklist plus the generated-vs-tested evidence ladder (and a `code-quality/gate.json` that rbx-bench scores), and `rbx-monetize-audit` / `rbx-rate` a fair-or-pressure ethics column. Ideas adapted from excaldev/ro-engineer (MIT); reference copies live in the vault under `Imported/ro-engineer`.
- `/rbx-tune` : bounded metric loop for balance, optimise and polish work. Pick ONE number and a read-only evaluator, baseline it, change one thing per experiment, keep only strict improvements, revert the rest, log every run in `Games/<slug>/tune/<run-id>/` (`tune_check.py` validates the ledger: baseline row, strict improvement, unchanged evaluator, budget, gates still passing). The loop idea comes from Karpathy's autoresearch (no licence file in that repo, so idea only, own words); the unbounded never-stop mode is not adopted.
- **Research round 2 (INT, 2026-11-05; ideas adapted in our own words, nothing installed, no hooks).** (1) Agent audit: all 17 agents set `model` and `effort`; the read-only roles (rbx-reviewer, rbx-judge, rbx-verifier, rbx-auditor) carry `disallowedTools` for Edit and NotebookEdit (rbx-verifier also Write); `omitClaudeMd` is deliberately unused, because the vault rules reach a subagent through its brief only if the brief carries them; recommendation only. (2) Evidence before claims: one mode rule, plus `rbx-critic/scripts/evidence_scan.py <report.md>` (EV1-EV3: hedge words, claims without a command and output, a subagent success claim without a diff check), run by `code_gates.py --report <final report>`; scored like the other gates, never a block ([cold:rbx-critic/evidence.md]). (3) Token-triggered checks: `static_scan.py <project> --triggers` maps code tokens (OnServerEvent, PlayerAdded, CharacterAdded, Touched, LoadAnimation, DataStore calls, loops that fire remotes, connections with no cleanup) to the SE-n checks of rbx-code-rate in severity order TR1-TR4 (exploits and data loss, crashes, leaks, performance), also run by `code_gates.py`. (4) Rulings, DONE WHEN and spec-before-style: `Ruling: what - why - cost if wrong` in decisions.md, one checkable DONE WHEN line whose command output is printed in CRITERIA, spec compliance judged before style ([cold:rbx-workflow/rulings.md]). (5) Scanner leads need a TRUE-POSITIVE / FALSE-POSITIVE verdict with an evidence line before a fix loop acts; mutation testing of the Systems tests is an optional one-off, not a rule ([cold:rbx-playtest/fp-verdict.md]). (6) The built-in Studio MCP is the first choice in rbx-studio and /rbx-setup (Windows config `cmd.exe /c %LOCALAPPDATA%\Roblox\mcp.bat`; `script_grep`/`search_game_tree` before reading scripts, `multi_edit` instead of rewriting), the older Rust server only a fallback; NOT yet tested live in Studio. Credits: Superpowers (MIT) for verification and rulings; Trail of Bits skills (CC-BY-SA) and a public Luau optimiser skill (no licence) as ideas only.
- **Code gates, Fix loop, smallest complete change (adapted from the video "9 Claude Skills I Use Every Single Day", ideas only, nothing installed).** `rbx-critic/scripts/code_gates.py <project> --write Games/<slug>` is the one runner of the scored code gates: comment-scan (CM1-3), scope-scan (SC1-5: orphan modules, TODO stubs, kit systems rebuilt by hand, unused exports, oversized files), security-scan (`static_scan.py --gate`, SEC1-5: client-trusted remotes, hardcoded keys and webhooks, server code in ReplicatedStorage, DataStore and receipt safety, backdoor patterns), bugfix ledgers (FL1) and tune ledgers (TN1-6). Policy: every finding is SCORED and never blocks (the scans are heuristics and give false hits); NOT RUNNING them does block the verdict: the critic must run them itself, otherwise it cannot return GOOD (`playable prototype, code gates not run`; the verdict file carries `codegates: ran`, which `games.py advance` needs; verdict files from before count as not run). The standing rules sit in the load-mode rules (two bullets), the builder, engineer, reviewer and critic agents, and the workflow and manager steps. `rbx-playtest` has the Fix loop (reproduce first: a red check before any edit, the same check green after, ledger `Games/<slug>/bugfix/<id>.md`); `rbx-luau` has the Smallest complete change ladder (reuse a kit system or Roblox built-in before new code); the manager builds the core loop alone in wave 1. Credits: Ponytail and Unlazy (smallest change, stubs), Vibe Security (security gate), Matt Pocock's diagnosing-bugs and pstack / Poteto mode by Lauren Tan (fix loop, core loop first), all MIT, re-written in our own words.
- **No code comments by default.** Every agent and skill that writes code follows one rule (`rbx-luau`, Comments; also in the load-mode rules): no comments, except one line that says WHY something non-obvious is done (engine quirk, ordering, replication timing, physics ownership), never WHAT. Type annotations and `--!` directives stay. All shipped Luau (StyleKit, templates, systems, skill-pack scripts, the generated Placement and Lighting modules) was stripped to match; `rbx-critic/scripts/comment_scan.py` counts stray comments per file and writes a scored, never blocking `comment-scan/gate.json` that rbx-bench picks up.
- `/rbx-learn` : the self-improving part. After an agent VERIFIES something non-obvious (a fix, a gotcha, a corrected assumption) it records a small note (`tools/learn.py add`); the note is scanned for secrets, personal data and instruction-like text, queued on your computer and sent by `/rbx-update` to the public inbox repo `vault-learnings` (CC0). Nothing in that inbox is trusted: the vault owner's `/rbx-curate` runs fixed rules over it and promotes accepted notes to `learned/<topic>/` in the vault, which every agent checks first (`vault-find.py "<problem>" --type learned`). Without write access your notes stay queued; `learn.py pr` (opt-in) opens a pull request from your fork. Hiccups are logged live: every failed gate, retry, tool error or user correction goes into a local per-user ledger with a concrete prevention (`learn.py hiccup add`) and the agent tells you in one line, `Hiccup: <what> -> prevention: <what>`; the next steps and games read the ledger as a pre-flight (`learn.py hiccup apply`) and the done-step retro (`learn.py hiccup retro`) closes it. The critic compares the game's logs with the ledger (unreported hiccups are scored, never blocking; `rbx-bench` shows hiccups per game), sharing is opt-in (`learn.py hiccup share on`), and a hiccup that recurs 3 times becomes a promotion candidate that only the vault owner approves. No tool edits a shipped skill.
- `/rbx-mockup` : UI mockup mode, `on|off|status`. Default OFF = AUTOMATIC DESIGN-FIRST: before any UI is built, Claude designs every button (default/hover/pressed/disabled) and each screen layout itself (`rbx-ui-mockup`: a local HTML/CSS design sheet with tokens, phone + desktop frames and real Roblox font names, rendered to PNG by a headless Chrome/Edge that is already installed, else HTML only), exports the exact rectangles, colours, text and font sizes as a spec, builds from it, compares the built UI numerically and iterates (max 3 rounds); report line `UI design: done (auto|figma|manual) / skipped: <reason>` (advisory). If your Claude has the Figma connector enabled it is used; if not, ONE line says Figma isn't connected and how to connect it (the vault never asks for or stores Figma tokens). ON = a MANUAL package for making mockups yourself with Nano Banana 2.1 on the Gemini website (`ui-mockup/`: prompts, reference images, numbered steps, checklist; nothing waits for the images). The setup asks one yes/no question about it; the default is no. Tools: `skills/rbx-ui-mockup/scripts/{ui_design,ui_spec,ui_compare,ui_assets,ui_mock}.py` (stdlib, no network), `tools/ui_pref.py` (preference file `claude-kit/ui-mockup.json`).
- Thumbnail click psychology (inside `/rbx-thumbnail`, no new command): candidates from any source (`gen_image.py`, manual Nano Banana, user-supplied; a Blender render source is optional: see the next paragraph) are scored by LOOKING at them against a rubric of 3 gates and 13 weighted checks (max 46, pass 32; weights and the pass bar are labelled assumptions, grounded in an evidence-graded A/B/C table of click-psychology principles and Roblox's own thumbnail rules). `skills/rbx-thumbnail/scripts/thumb_score.py` does the arithmetic, ranks 2-5 variants, checks the file (16:9 or square, 1920x1080, under 3 MB, icon at least 512) and writes the advisory gate `thumb-score/gate.json`; the launch and publish steps report `thumbnail: scored <score>/<max> (variants N)` or `thumbnail: skipped: <reason>` (shown in the critic's launch verdict and the scorecard, never blocking). After a Roblox thumbnail personalization test (2-5 thumbnails, hold 7 days or more) `tools/thumb_record.py add|decide|summary` keeps your own results ledger in `claude-kit/state/thumbnails/` (survives updates) and shows which features win per genre once enough data exists; sharing a redacted per-genre tally is opt-in (`thumb_record.py share on`, no game names) and goes through the normal `learn.py flush`. Fair-promise guard: a thumbnail must match the first minute of play. Heavy text lives in `mode/cold/rbx-thumbnail/`.
- Optional Blender renders (inside `/rbx-thumbnail`, no new command, needs your own free Blender, nothing is installed or downloaded): `skills/rbx-thumbnail/scripts/blender_gfx.py detect|gen|check|run` writes a GPL-2.0-or-later bpy script for a hero icon, character portrait, action pose, text-less scene or palette variants (3-point light with a contrasting rim, 1920x1080 or 1024 square, flat-colour override for untextured Studio exports), refuses scripts that import os/subprocess/socket or call eval/exec/open, and renders headless into `<project>/renders/` with timeouts and sample caps; the PNGs are scored like any other candidate. UNTESTED LIVE (no Blender on the build host). Details in `mode/cold/rbx-thumbnail/blender.md`.
- `/rbx-mentor` : a co-pilot with the combined knowledge of every creator in both vaults; it works alongside you on any job and suggests the right skill, agent, note or creator method at each step, and answers "what would <creator> do" (agent `rbx-coach`; reads `CAPABILITIES.md` and `Mentor/Combined-Brain.md` first).
- `/rbx-low-usage` : keeps Claude in low usage mode for every message and session until `/rbx-low-usage off` (cheapest model that fits, at most one subagent, short replies, small tool output; each reply starts with "low usage mode enabled."). `/rbx-low-usage status` reports it. It asks once before adding its two hooks to `~/.claude/settings.json` (backup first); see `skills/rbx-low-usage/references/`.
- `/rbx-manager` : makes any Claude session act as a manager that delegates to right-sized workers (haiku/sonnet/opus), briefs and checks them, and respects a usage cap you set; `/rbx-manager install-presets` adds the worker presets.

## What to say instead
- `make me a Roblox game: <your idea>` (for example: `make me a Roblox game: a pet-collecting obby for kids`)
- `use the vault to build <your idea>`
- `give me game ideas that would do well` (ideas only, scored; no build)
- `make me a Roblox game` (no idea: it picks the best-scoring small one)

## What you get
A folder `<game-name>/` in the current directory with:
- `docs/GDD.md` (scored concepts, core loop, first 30 seconds, retention, monetisation plan, economy numbers, ad plan, assumptions), `docs/TASKS.md`, `docs/SELF-REVIEW.md`, `docs/research-notes.md` (every claim cites a vault note)
- a Rojo project (`default.project.json`, `src/server`, `src/client`, `src/shared`) with the core loop, data saving (ProfileStore, Apache-2.0), responsive UI and monetisation hooks written in Luau
- `docs/THIRD-PARTY.md` (libraries and licenses) and `docs/ASSET-IMPORT.md` (which downloaded models/sounds to import and how)
- a final report: how to open it in Roblox Studio (Rojo sync, or paste), what is untested, the next three tasks

It does not publish, spend Robux, or invent asset/pass ids (those are `0` until you create them in Creator Hub). Studio playtests are only run if the Roblox Studio MCP is available; otherwise everything is files and marked untested.

## Install
Normally automatic: the vault setup (SETUP-FOR-CLAUDE.md, or the sync scripts) runs it, and the vault update (at every logon/login, or on demand with `/rbx-update` / `vault-update.ps1` / `vault-update.sh`) runs `kit-refresh.sh` / `kit-refresh.ps1` after the pull, so a kit update published to the vault reaches every computer by itself (quiet; one log line only when something changed). The same step syncs `<vault>/Assets` from the public vault-assets GitHub repositories (`tools/assets-sync.py`; sources in `repos.json`), and the reference screenshots (`tools/refs-sync.py`). By hand: `bash claude-kit/install.sh` (macOS/Linux) or `powershell -NoProfile -ExecutionPolicy Bypass -File claude-kit\install.ps1` (Windows). Writes only to `~/.claude/agents`, `~/.claude/skills`, `~/.claude/claude-kit`. Your edits win: a vault file you edited is never overwritten or deleted by an update; the incoming version is saved as `~/.claude/claude-kit/state/conflicts/<path>.vault-new` and ONE update line says how to review it (`tools/kit-conflicts.py list|diff|accept|keep`). What your use produces (learn queue, hiccup ledger, preferences, your rules in `state/overrides/local-rules.md`) lives in `~/.claude/claude-kit/state/` and no update touches it. Skills of yours with other names are untouched (similar ones are listed, and the kit skill is used when both cover the same job). See INSTALL.md.

`/rbx-load` also prints an index of every skill and agent so they work in the same chat with no restart (type `/reload-skills` for the slash commands), and `/rbx-update` ends with a `Vault: <folder> | Kit: <folder>` line showing where the vault and kit are on your computer.

Your own work is safe: `My Research/` (default output folder of the research skill), any folder containing `PROTECTED-RESEARCH.md` and every untracked file you created are never deleted by `/rbx-update` (git-excluded; the update prints `N of your own files kept`); only edits to tracked (generated) files are patched and reset. `My Research` is a reserved name: the main vault never ships files there. Two commands: `/rbx-update` (safe, keeps everything of yours) and `/rbx-clean` (exact copy of the main vault, still keeps My Research; prints a dry run, asks once, backs up what it removes). One-liners: `vault-update.ps1 -Clean [-Yes] [-IncludeMine]` / `bash vault-update.sh --clean [--yes] [--include-mine]` (`-IncludeMine` also deletes My Research, only when you type it).

## Needs
- The vault on the computer (a git clone of the public vault repository) and, for assets, `<vault>/Assets` (the setup and every vault update sync it from the public vault-assets GitHub repositories; first run downloads about 2.7 GB).
- Optional: Python 3 (for `kbq.py`; without it the agents use grep), Rokit tools for static checks (`rokit install` in the template folder), Roblox Studio with the Rojo plugin to open the result. To let Claude drive Studio (write scripts, playtest, read Output) run the opt-in `tools/studio-setup.ps1` (Windows) / `tools/studio-setup.sh` (macOS) or use `/rbx-studio`; you sign in to Studio and switch on "Enable Studio as MCP server" yourself.

Hooks (opt-in, never automatic): `bash claude-kit/install.sh --with-hooks` / `--remove-hooks` or `install.ps1 -WithHooks` / `-RemoveHooks` install the two rbx-low-usage hooks and the rbx-mentor suggestion hook (on each prompt it runs `vault-find` and adds the top 3 matches, at most about 300 tokens, silent when nothing matches, no network; mute with the file `~/.claude/state/mentor-hook.off`).

Switch light/full view only (no update, offline): `/rbx-light-on`, `/rbx-light-off`, or `vault-update.ps1 -SetView light|full` / `bash vault-update.sh --set-view light|full`.

How the mode works: the installer puts the kit's skills and agents in `~/.claude/claude-kit/vault-mode/.claude/{skills,agents}` (not read by normal sessions). The **cold area** (`mode/cold/<topic>/<file>.md` in the kit, `~/.claude/claude-kit/vault-mode/cold/` after install) holds bulk the skills rarely need (sources and attribution, worked examples, long evidence, trigger phrases cut from descriptions); skills carry one-line pointers `[cold:topic/file] <when to read it>`, `python ~/.claude/claude-kit/tools/vault-mode.py cold [topic[/file]]` prints it, and `/rbx-load` never copies it into a project. `/rbx-load` (tools/vault-mode.py) copies them into the current folder's `.claude/`, lists them in `.claude/vault-mode.json`, hides them from git (`.git/info/exclude`) and prints `Roblox dev mode on: N skills, M agents, ...`; `/rbx-unload` removes exactly those files (a file you changed is kept; a skill or agent of yours with the same name is skipped and yours wins); `/rbx-update` refreshes every loaded folder and moves an older always-on install into the store (backup + manifest, idempotent, `vault-mode.py migrate --revert` undoes it). `/rbx-subagent-hud` and `/rbx-graph` are Claude Code plugins (they load in every session), so they are opt-in: `install.sh --with-mods` / `install.ps1 -WithMods`.

To remove everything and keep only your games: `/rbx-uninstall` (dry-run plan first, asks for a yes; copies `Games/`, `Games/_Reusable` and `My Research/` to `~/Roblox Games` and verifies the copy, removes hooks, the kit and the vault folder; `--keep-dir DIR`, `--keep-edited`).

Command names (changed 2026-11-05): every command, agent and mod of this vault is named `rbx-<short-name>` (`/rbx-update`, `/rbx-load`, `/rbx-uninstall`, `/rbx-mentor`, `/rbx-graph`, `/rbx-plan`, ...; the router is `/rbx`). Type `/rbx-` and autocomplete lists every vault command. The one short prefix keeps them from clashing with another vault's commands or with your own skills. The table is `~/.claude/claude-kit/tools/vault-names.json` (and `COMMANDS-RENAMED.txt` after a migration). If the kit was installed before this change (the long `...-rbxdev-vault` names of 2026-11-04, the original unsuffixed names, or the long `game-dev-*` / `roblox-*` names), the first update (`kit-rename.py`, run by the installer) removes the old-named files the kit had installed (backup, only unchanged files, undo with `kit-rename.py migrate --revert`; a skill or agent of yours with the same old name is left alone with a warning), refreshes the folders where the mode is loaded, and prints a one-time `NOTICE FOR THE USER ... commands renamed` line. The same mechanism removes skills and agents that were merged into another one (2026-11-04 prune, legacy names: the `removed` list in `vault-names.json`; notice `commands merged`): `roblox-ad-thumbnail-brief` is now part of `rbx-thumb-brief`, and the agents `roblox-builder`, `roblox-tester`, `roblox-ad-creative-planner`, `roblox-analytics-reviewer` are part of `rbx-engineer`, `rbx-tester`, `rbx-marketer`, `rbx-doctor`. Commands you must type yourself (they are not in Claude's skill list, to save context): `/rbx-clean`, `/rbx-uninstall`, `/rbx-curate`, `/rbx-contribute`, `/rbx-light-on`, `/rbx-light-off`, `/rbx-list`, `/rbx-setup`, `/rbx-low-usage`.

Commands: `/rbx-check` (is a newer vault/kit out; read-only, offers /rbx-update), `/rbx-setup` (software table with install commands; installs only after your yes). `/rbx-list` lists everything installed (skills, agents, mods). `/rbx-subagent-hud` shows the master agent and its subagents (done count, time estimate, click a subagent to see its prompt); `/rbx-graph` replies with the link to the vault graph site (kit mods, opt-in because plugins load in every session: `install.sh --with-mods` / `install.ps1 -WithMods`; they only show in the terminal and desktop app, not in Remote Control or mobile). Precedence: when a kit skill and another installed skill cover the same job, the kit skill is used.

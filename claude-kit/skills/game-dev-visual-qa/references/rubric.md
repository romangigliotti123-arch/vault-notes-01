# Visual rubric V1-V7 (the gate scores these; pass = every item >= 7, no open hard fail)

Score from the screenshots and the `ui_overlap` output, not from the code or the plan. Cite the screenshot file and what is visible in it for every score. 7 = a stranger would not call it unfinished; 9 = could sit beside front-page Roblox games. A hard fail caps the item at 4 until fixed. No evidence for an item = 5 and the word `judgment`. Sources for every rule: `Roblox/roblox-kb/ui-ux-design.md`, `building-art-and-assets.md`, `building-and-level-design.md`, `vfx-and-particles.md`, `player-psychology-and-game-feel.md`, `sound-and-music.md`.

| Item | 3 (fail) looks like | 7 (pass) looks like | Hard fails (cap 4) |
|---|---|---|---|
| **V1 UI consistency** | each panel styled differently; flat rectangles; mixed fonts | one component set: same corner radius, stroke, shadow, font, text scale, palette and icon style on every panel, button and popup; `ui-kit-consistency-checker` dominant value >= 80% per field | two or more panel styles in one HUD; panels are bare flat colour rectangles with no stroke, corner, gradient, shadow or icon; default font mixed with a custom one |
| **V2 Layout and overlap** | text on text; banner under the HUD; popups stacked; UI at the edge of the screen | zero findings from `ui_overlap` at phone, tablet and desktop; every element anchored and in Scale; popups queued one at a time; HUD leaves the centre and the touch zones free | any text over text, text over an unrelated panel, an element hidden behind another, an off-screen element, two popups at once, a button in the thumbstick or jump zone, any overlap with Roblox chat or the top bar |
| **V3 Readability and hierarchy** | small or low-contrast text; everything the same weight; wall of text | one focal element per screen state; key numbers large; text >= 14 px on phone, contrast >= 4.5:1 (3:1 for text >= 24 px), icon paired with label; max 2 font sizes per panel | text under 12 px at phone size; low-contrast finding; instructions only as a paragraph; goal not readable within 2 s |
| **V4 Models and world** | grey or beige blocks; flat 2D sprites; one colour; floating objects | hero objects (what the player collects, rides, fights or looks at most) are multi-part or mesh models with 3+ materials, rounded or bevelled shapes, details (eyes, fins, trim) and a contact shadow; ground and props vary in size, colour and angle; a limited palette repeated on purpose; terrain or water has shape and a tuned colour | a hero object is a single bare primitive (Block, Ball, Cylinder, Cone, WedgePart) or a flat sprite or decal in a 3D scene; default grey Plastic surfaces on 50% or more of the visible world; a repeated tile or prop with no variation; objects floating with no shadow or support; world still the grey-green baseplate look |
| **V5 Lighting and atmosphere** | default sky and flat light | an applied preset: Lighting (Ambient, OutdoorAmbient, Brightness, ClockTime, shadows), Atmosphere, Sky, ColorCorrection, Bloom, optional SunRays or DepthOfField; water and terrain tuned to the palette; focal object lit | no Atmosphere and no ColorCorrection, or the default skybox, in the screenshots |
| **V6 Effects and juice** | things happen silently; popups pop in and out | every key event (collect, reward, hit, spawn, purchase, level-up, error, panel open and close) has at least two of: particle burst, tween (pop, squash, slide, fade), sound, camera or UI reaction; sounds from real assets; effects fade out; one screenshot caught mid-effect | a key event with no feedback at all; UI shown or hidden with no tween; a popup that stays on screen with no timeout or dismiss; effect left running after its event |
| **V7 First 30 seconds** | looks like a template or debug build | the spawn screenshot reads as a finished game: title or goal visible, HUD tidy, world lit and styled, no debug text or placeholder names, the first action clear, the first reward fires with feedback | debug or placeholder text on screen; default baseplate or spawn pad; a popup covering the first action; nothing visible to do |

## Prerequisite P0: placement gate
Before any item is scored, the placement gate must be `pass` for the same build (`Games/<slug>/placement-qa/gate.json`, skill `game-dev-placement-qa`: every model in the map has a sane pivot and size, rests on its surface, is upright, faces its target, overlaps nothing, is anchored and lines up with its neighbours). `visual_gate.py --write` adds a reason and fails while it is missing or failing. V4 hard fails "objects floating with no shadow or support" and "repeated tile with no variation" are judged on a placement-clean map, so a floating model is fixed by the placement gate, not argued about here.
## How to run the checks
- V1: `/rbx ui-kit-consistency-checker` or `ui_scan.luau` (dominant value per field) plus the screenshots side by side.
- V2: `scripts/ui_overlap.luau` (rect checks at phone 844x390, tablet 1180x820, desktop 1920x1080), then look at the `render` preview screenshot at phone size. Findings are leads: open each one; a finding you cannot justify is a defect.
- V3: `ui_overlap` small-text and low-contrast rules plus a blur test (squint at the screenshot at 25% size: can you still find the goal and the main number?).
- V4: list the hero objects, then inspect each in Studio (`inspect_instance`, part count, classes, materials) and in a close-up screenshot. Fill all hero objects flat black in your head: is the silhouette recognisable (`building-art-and-assets`)?
- V5: read the Lighting service and its children (`inspect_instance`); compare the screenshot to the preset in `art-direction.md`.
- V6: `rg -n "ParticleEmitter|TweenService|:Emit\(|Sound" src` per key event against the juice list in `art-direction.md`; one screenshot taken during an effect.
- V7: the spawn screenshot, then the screenshot after the first reward, with a stopwatch from join if Studio MCP is present.

## Reference compare (optional, any item scoring <= 7)
If `<claude config dir>/claude-kit/reference-path.txt` exists (line 1 = folder with `INDEX.md`), grep `INDEX.md` for the item's category or tag, Read 3-6 matching references next to your own screenshot of the same screen, and add 3-5 concrete differences (spacing, stroke, palette count, icon style, lighting, effects) to the defect list; cite the reference paths in the report. File absent = skip silently (written by `claude-kit/tools/refs-sync.py` during setup and `/update-rbxdev-vault`). Third-party frames, see NOTICE.md in that folder. Comparison only: never copy or trace a reference, never copy one into the game or repo.

## Screenshots the gate needs (>= 6 distinct files)
Viewports: `desktop` (real capture) and `phone` (the `ui_overlap` preview rendered at phone size, or a Device Emulator capture). Moments: `spawn` (first frame after join), `action` (mid core loop with the HUD busy: most panels visible, a popup open), `effect` (during a particle or tween). Name files `<viewport>-<moment>[-n].png`; keep them under `Games/<slug>/visual-qa/r<round>/`.

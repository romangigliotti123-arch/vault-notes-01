# rbx-uninstall

Removes the kit (agents, skills, tools, hooks, auto-sync job, the vault folder with its `.rbx/claude-kit`, the 3 stub skills and the pointer file) and keeps only the user's games. Python 3 only: `scripts/uninstall.py` (config dir: `$CLAUDE_CONFIG_DIR`, else `~/.claude`). The stub in `~/.claude/skills/rbx-uninstall` ran `where.py`, which printed `VAULT <folder>` and `KIT <folder>`; this file's folder is `<KIT>/vault-mode/.claude/skills/rbx-uninstall`.

1. Run the plan (changes nothing): `python "<KIT>/vault-mode/.claude/skills/rbx-uninstall/scripts/uninstall.py"` (use `python3`/`py` if `python` is missing). Add `--vault DIR` if it says it cannot find the vault or finds several. Run it FROM OUTSIDE the vault folder: make the user's home folder the working directory (for example `cd ~ &&` in front) and keep the absolute path of the script, because a session whose working directory is inside the vault folder keeps that folder locked on Windows, so it could not be deleted at the end. The plan on screen is SHORT (under 2 KB): what is rescued where, what is removed (counts), how many kit files the user really edited, the CLAUDE.md result and the exact confirm command. The complete file lists are in the file named on the line "Full file lists: ..." (open it only if the user asks for details).
2. Show the user the plan in plain words: where your folders are rescued to (default: the PARENT folder of the vault folder, i.e. `Games/`, `Models/`, `My-Skills/`, `My-Agents/` and `My Research/` next to it, never overwriting: an existing name becomes `<name> (<vault folder name>)`; change with `--keep-dir DIR`), what will be removed, kit files they edited (only real content changes count: a changed line ending is not an edit, and the downloaded reference clone and state files are not edits; edited ones are backed up to `<keep-dir>/_edited-kit-files` (default: `<parent> / <vault folder name> uninstall backups`), or left in place with `--keep-edited`), and what is NOT touched (credentials, other skills/agents/settings, MCP servers, Rokit/Luau tools, projects under `$ROBLOX_PROJECTS`, which stay in place). The backups folder is a sibling of the vault folder, so deleting the vault folder by hand never deletes the user's files.
3. Ask: "Remove everything except your games? yes/no". Do NOT continue without an explicit yes in the chat. Never pass `--yes` on your own.
4. After the yes, run the same command with `--yes` (plus the same other flags), again from outside the vault folder. It copies the games first and checks the copy byte for byte, removes hooks (settings.json backed up), the kit mods that are really installed (only real failures are printed), the kit's own marker block in `~/.claude/CLAUDE.md` if there is one (a copy of the file is saved first; nothing else in it is touched), deletes the kit, then the vault, and the skill itself last. If the copy check fails nothing is deleted. If the vault folder itself is still held by this Claude session (its working directory is inside), everything inside it is removed and the script starts a hidden cleanup helper and prints ONE line: "The folder is in use by this session; it will be deleted automatically a few seconds after you close this Claude session (or delete it yourself: <path>)". Relay that line to the user as it is: they close the session and nothing else is needed; the helper deletes only that exact folder, never the backups folder, and logs to `_uninstall-cleanup.log` in the backups folder.
5. Report the summary it prints: where the games are now, anything left, `CLAUDE.md` lines that mention the kit (list them, never edit them; only the kit's own marker block was removed in step 4, with its backup path). To reinstall later: follow the website setup (`SETUP-FOR-CLAUDE.md`) or the vault README.

Never delete anything by hand around this script. Never run it on a vault path the user did not confirm.

# Scribe v2.6.1 - Persistent, typed, auto-replicated player data built on ProfileStore

[Open](https://devforum.roblox.com/t/scribe-v261-persistent-typed-auto-replicated-player-data-built-on-profilestore/4738905) | Roblox DevForum | 110 views | 2026-07-15

## Summary
Documentation/release page for Scribe v2.6.1, a Roblox player-data library built on ProfileStore. Covers typed accessor trees from a template, replication without RemoteEvents, declarators (Int, Enum, Big, Flags, etc.), migrations, monetization/gifting, leaderboards, diagnostics, and version history with upgrade notes.

## Tips
- [page](https://devforum.roblox.com/t/scribe-v261-persistent-typed-auto-replicated-player-data-built-on-profilestore/4738905) **[[ab-testing-and-experiments]]** Not applicable; omit.
- [page](https://devforum.roblox.com/t/scribe-v261-persistent-typed-auto-replicated-player-data-built-on-profilestore/4738905) **[[monetisation-gamepasses]]** Check ownership with Data.Owns(player, "VIP") before offering a pass so gifted or Roblox Plus players are not asked to re-buy it.
- [page](https://devforum.roblox.com/t/scribe-v261-persistent-typed-auto-replicated-player-data-built-on-profilestore/4738905) **[[pricing]]** Show per-player prices via Data.ObserveProductInfo, since Roblox Plus subscribers pay 10 to 20% less and regional pricing can be 30% of list.
- [page](https://devforum.roblox.com/t/scribe-v261-persistent-typed-auto-replicated-player-data-built-on-profilestore/4738905) **[[scripting-and-performance]]** Serialise Vector3, CFrame and Color3 as packed buffers (12, 13 and 4 bytes) rather than JSON tables (CFrame about 200 bytes as JSON).
- [page](https://devforum.roblox.com/t/scribe-v261-persistent-typed-auto-replicated-player-data-built-on-profilestore/4738905) **[[data-persistence]]** Make migrations fail closed: if any migration step throws, do not stamp or save, so half-migrated profiles never persist.
- [page](https://devforum.roblox.com/t/scribe-v261-persistent-typed-auto-replicated-player-data-built-on-profilestore/4738905) **[[data-persistence]]** Enable a wipe guard (WipeGuardPolicy = "Block") to hold saves when top-level keys vanish or payload collapses, persisting the last good snapshot.
- [page](https://devforum.roblox.com/t/scribe-v261-persistent-typed-auto-replicated-player-data-built-on-profilestore/4738905) **[[data-persistence]]** Set SaveInterval no lower than 15 seconds; autosave intervals are capped at 300 seconds in v2.6.0.
- [page](https://devforum.roblox.com/t/scribe-v261-persistent-typed-auto-replicated-player-data-built-on-profilestore/4738905) **[[data-persistence]]** Name your own ProfileStoreIndex so test builds never share live DataStore storage.
- [page](https://devforum.roblox.com/t/scribe-v261-persistent-typed-auto-replicated-player-data-built-on-profilestore/4738905) **[[anti-exploit-and-security]]** Route client mutations through named, validated, rate-limited commands; handlers only run once the profile is Ready.
- [page](https://devforum.roblox.com/t/scribe-v261-persistent-typed-auto-replicated-player-data-built-on-profilestore/4738905) **[[data-persistence]]** Use AwaitBudget when migrating from several stores so per-player reads stay within DataStore request budget and don't throttle.
- [page](https://devforum.roblox.com/t/scribe-v261-persistent-typed-auto-replicated-player-data-built-on-profilestore/4738905) **[[monetisation-devproducts]]** Pass an IdempotencyKey on purchases and use Client.RequestOnce so retried commands or purchases apply at most once.
- [page](https://devforum.roblox.com/t/scribe-v261-persistent-typed-auto-replicated-player-data-built-on-profilestore/4738905) **[[monetisation-other]]** Roblox has no native gift-a-gamepass flow; sell a developer product that grants the recipient a saved perk.
- [page](https://devforum.roblox.com/t/scribe-v261-persistent-typed-auto-replicated-player-data-built-on-profilestore/4738905) **[[client-server-and-remotes]]** Let client writes be optimistic UI only; server operations always win, so authoritative changes must go through commands.
- [page](https://devforum.roblox.com/t/scribe-v261-persistent-typed-auto-replicated-player-data-built-on-profilestore/4738905) **[[analytics-metrics]]** Use Scribe.GetStatus and OnIssue to watch health state (Healthy, Degraded, Outage) and error logs in production.
- [page](https://devforum.roblox.com/t/scribe-v261-persistent-typed-auto-replicated-player-data-built-on-profilestore/4738905) **[[common-mistakes]]** Do not write Scribe values with assignment (data.Coins = 5); it is a type error and only shadows the accessor.
- [page](https://devforum.roblox.com/t/scribe-v261-persistent-typed-auto-replicated-player-data-built-on-profilestore/4738905) **[[common-mistakes]]** Do not mix a mixed-version deploy: protocol changes in v2.0.0 and schema hash changes in v2.1.0 and v2.4.0 require deploying server and client together.
- [page](https://devforum.roblox.com/t/scribe-v261-persistent-typed-auto-replicated-player-data-built-on-profilestore/4738905) **[[common-mistakes]]** Do not combine Scribe.ServerOnly and Scribe.Shared on one field; it is a startup error. Pairing Session with either is allowed.

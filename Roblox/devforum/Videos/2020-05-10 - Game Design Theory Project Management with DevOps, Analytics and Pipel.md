# Game Design Theory: Project Management with DevOps, Analytics and Pipelines for Successful Games and Productive Teams

[Open](https://devforum.roblox.com/t/game-design-theory-project-management-with-devops-analytics-and-pipelines-for-successful-games-and-productive-teams/568057) | Roblox DevForum | 171 views | 2020-05-10

## Summary
Web article by TechSpectrum on applying DevOps thinking to Roblox game teams: cooperation via shared standards, production/testing pipelines with Trello/Jira/ClickUp staging and changelogs, automated checks on assets, and using analytics (MongoDB Atlas/Stitch/Charts) with segmented data while avoiding decisions made on data alone.

## Tips
- [page](https://devforum.roblox.com/t/game-design-theory-project-management-with-devops-analytics-and-pipelines-for-successful-games-and-productive-teams/568057) **[[development-process-and-speed]]** Standardise asset requirements (hit parts, poly count, style) in a documented guide so modelers' output plugs into code without rework.
- [page](https://devforum.roblox.com/t/game-design-theory-project-management-with-devops-analytics-and-pipelines-for-successful-games-and-productive-teams/568057) **[[development-process-and-speed]]** Build a drag-and-drop framework so artists can add content themselves while programmers work on new features.
- [page](https://devforum.roblox.com/t/game-design-theory-project-management-with-devops-analytics-and-pipelines-for-successful-games-and-productive-teams/568057) **[[version-control-and-tooling]]** Track production with a project board (ClickUp, Trello or Jira) using pre-filled checklist cards per asset, with Completed and Live columns.
- [page](https://devforum.roblox.com/t/game-design-theory-project-management-with-devops-analytics-and-pipelines-for-successful-games-and-productive-teams/568057) **[[updates-live-ops]]** Write a changelog of completed tasks before moving them to Live, and publish fixed bugs in the changelog for the community.
- [page](https://devforum.roblox.com/t/game-design-theory-project-management-with-devops-analytics-and-pipelines-for-successful-games-and-productive-teams/568057) **[[testing-debugging-and-qa]]** Automate checks: script that previews every sword on fake characters, damages test enemies, and flags duplicate or missing prices.
- [page](https://devforum.roblox.com/t/game-design-theory-project-management-with-devops-analytics-and-pipelines-for-successful-games-and-productive-teams/568057) **[[testing-debugging-and-qa]]** Recruit a group of experienced players to reproduce bugs step by step so developers can fix them quickly.
- [page](https://devforum.roblox.com/t/game-design-theory-project-management-with-devops-analytics-and-pipelines-for-successful-games-and-productive-teams/568057) **[[testing-debugging-and-qa]]** Set up a bug staging process with documented guidelines so bugs are easier to find, track and identify.
- [page](https://devforum.roblox.com/t/game-design-theory-project-management-with-devops-analytics-and-pipelines-for-successful-games-and-productive-teams/568057) **[[analytics-metrics]]** Chart average cash by level bracket (1-10, 11-20, etc.) and sales per weapon to see real economy health before changing it.
- [page](https://devforum.roblox.com/t/game-design-theory-project-management-with-devops-analytics-and-pipelines-for-successful-games-and-productive-teams/568057) **[[analytics-metrics]]** Filter analytics to exclude exploiters and players inactive for 15-30 days, and keep timestamps on all data.
- [page](https://devforum.roblox.com/t/game-design-theory-project-management-with-devops-analytics-and-pipelines-for-successful-games-and-productive-teams/568057) **[[analytics-metrics]]** Use analytics only as far as budget allows, since analytics services can cost significantly.
- [page](https://devforum.roblox.com/t/game-design-theory-project-management-with-devops-analytics-and-pipelines-for-successful-games-and-productive-teams/568057) **[[playtesting-and-feedback]]** Do not decide from data alone; watch players and test with multiple people before releases to find design flaws and misleading visuals.
- [page](https://devforum.roblox.com/t/game-design-theory-project-management-with-devops-analytics-and-pipelines-for-successful-games-and-productive-teams/568057) **[[playtesting-and-feedback]]** Do not dismiss vocal complaints outright, but verify them against data before acting on them.
- [page](https://devforum.roblox.com/t/game-design-theory-project-management-with-devops-analytics-and-pipelines-for-successful-games-and-productive-teams/568057) **[[mindset-and-strategy]]** Treat players as paying customers who deserve respect; do not lash out at them when they ask about updates.
- [page](https://devforum.roblox.com/t/game-design-theory-project-management-with-devops-analytics-and-pipelines-for-successful-games-and-productive-teams/568057) **[[development-process-and-speed]]** Plan with the team before building: agree on scope, standards and handoffs rather than jumping straight into content production.
- [page](https://devforum.roblox.com/t/game-design-theory-project-management-with-devops-analytics-and-pipelines-for-successful-games-and-productive-teams/568057) **[[updates-live-ops]]** Keep update schedules reliable and communicate delays, since inconsistent update timing made the fan base fall off in the example.

# Docs: projects / version-history

[Open](https://create.roblox.com/docs/projects/version-history.md) | Roblox Creator Docs | 0 views | 2026-10-28

## Summary
Roblox Creator Docs page on Version History in Studio: adding version notes to saves and publishes, searching/filtering versions, generating publish notes from saved notes, and restoring a place to a previous version via Studio or the Creator Dashboard.

## Tips
- [page](https://create.roblox.com/docs/projects/version-history) **[[version-control-and-tooling]]** Add version notes to every save (File > Save to Roblox with Notes, Ctrl+Alt+S / Cmd+Option+S) to create searchable development checkpoints.
- [page](https://create.roblox.com/docs/projects/version-history) **[[version-control-and-tooling]]** Write version notes consistently; publish notes are auto-drafted only from notes logged between publishes, so gaps produce no summary.
- [page](https://create.roblox.com/docs/projects/version-history) **[[version-control-and-tooling]]** Add notes to pre-existing versions to make them searchable; older versions lack the metadata fields and cannot be filtered.
- [page](https://create.roblox.com/docs/projects/version-history) **[[development-process-and-speed]]** Use Version History as a rollback point: restoring to a known good state creates a new version rather than overwriting history.
- [page](https://create.roblox.com/docs/projects/version-history) **[[common-mistakes]]** Restoring a place does not publish it. For a live game, open the restored place, publish it, and restart servers so players get the change.
- [page](https://create.roblox.com/docs/projects/version-history) **[[community-and-discord]]** Write publish notes that describe what changed for players, since version notes are required when publishing.

## Tools
Roblox Studio Version History widget (Window > Version History), Creator Dashboard Version History

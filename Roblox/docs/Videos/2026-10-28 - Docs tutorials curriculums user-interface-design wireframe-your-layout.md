# Docs: tutorials / curriculums / user-interface-design / wireframe-your-layouts

[Open](https://create.roblox.com/docs/tutorials/curriculums/user-interface-design/wireframe-your-layouts.md) | Roblox Creator Docs | 0 views | 2026-10-28

## Summary
Roblox official curriculum page on wireframing UI layouts. Covers visual hierarchy by information category (objective top, blaster middle, player state sides), blocking UI with basic shapes across mobile and PC using core UI and touch controls, and building user flows for each task and device.

## Tips
- [page](https://create.roblox.com/docs/tutorials/curriculums/user-interface-design/wireframe-your-layouts) **[[ui-ux-design]]** Wireframe layouts before building in Studio so you can find pain points and fix designs before investing time in them.
- [page](https://create.roblox.com/docs/tutorials/curriculums/user-interface-design/wireframe-your-layouts) **[[ui-ux-design]]** Group UI elements from the same category together so players know where to look for what they need.
- [page](https://create.roblox.com/docs/tutorials/curriculums/user-interface-design/wireframe-your-layouts) **[[ui-ux-design]]** Display UI contextually per workflow instead of showing too many categories at once to avoid clutter.
- [page](https://create.roblox.com/docs/tutorials/curriculums/user-interface-design/wireframe-your-layouts) **[[ui-ux-design]]** Use art style to visually emphasise your intended interaction order when many UI elements compete for attention.
- [page](https://create.roblox.com/docs/tutorials/curriculums/user-interface-design/wireframe-your-layouts) **[[ui-ux-design]]** Disable unneeded Roblox core UI (backpack, etc.) to free screen space for custom UI when gameplay doesn't need it.
- [page](https://create.roblox.com/docs/tutorials/curriculums/user-interface-design/wireframe-your-layouts) **[[ui-ux-design]]** Block in UI with basic grayscale shapes so you can iterate quickly and keep the eye on information, not background colour.
- [page](https://create.roblox.com/docs/tutorials/curriculums/user-interface-design/wireframe-your-layouts) **[[ui-ux-design]]** Design one adaptive layout that accounts for core UI and touch controls rather than maintaining separate UI versions per device.
- [page](https://create.roblox.com/docs/tutorials/curriculums/user-interface-design/wireframe-your-layouts) **[[ui-ux-design]]** Reserve space for mobile touch controls (virtual thumbstick bottom-left, jump bottom-right) even on PC layouts.
- [page](https://create.roblox.com/docs/tutorials/curriculums/user-interface-design/wireframe-your-layouts) **[[ui-ux-design]]** Place interactive elements in thumb-reachable zones; areas far from bottom corners are uncomfortable or impossible on mobile and tablet.
- [page](https://create.roblox.com/docs/tutorials/curriculums/user-interface-design/wireframe-your-layouts) **[[ui-ux-design]]** Test layouts against varied 3D backgrounds to keep on-screen UI clear and legible.
- [page](https://create.roblox.com/docs/tutorials/curriculums/user-interface-design/wireframe-your-layouts) **[[ui-ux-design]]** Test layouts on mobile, tablet, laptop and TV screen sizes that players actually use.
- [page](https://create.roblox.com/docs/tutorials/curriculums/user-interface-design/wireframe-your-layouts) **[[ui-ux-design]]** Build user flows covering every player action, including quitting mid-round, leaving while joining, and brief disconnects.
- [page](https://create.roblox.com/docs/tutorials/curriculums/user-interface-design/wireframe-your-layouts) **[[ui-ux-design]]** Test layouts with multiple player types, since what developers want players to do often differs from what players want to do.
- [page](https://create.roblox.com/docs/tutorials/curriculums/user-interface-design/wireframe-your-layouts) **[[ui-ux-design]]** Limit each flow chart to one primary task to keep it readable and actionable.
- [page](https://create.roblox.com/docs/tutorials/curriculums/user-interface-design/wireframe-your-layouts) **[[ui-ux-design]]** Create separate user flows per input device (touch, gamepad, mouse) to find device-specific pain points.

# "Claude + Blender: MCP servers, bpy scripting, headless Blender, procedural and AI-assisted modelling"

Back to [[blender-README]] | [[blender-playbook]]

Sources establish how Claude-driven Blender automation works in practice: MCP servers (the addon-based blender-mcp using execute_blender_code, and sandraschi/blender-mcp, which runs fresh headless processes per call) plus plain headless bpy batch scripts. Key pitfalls: on Windows, shell=True quoting and inherited stdio stdin cause hangs (fixed in v0.11.0 via list-form args and stdin=DEVNULL). Integrations (PolyHaven, Sketchfab) are off by default and fail with 'Unknown command type'. Clearing scenes can reset addon flags. Blender 4.x/5.x API changes break old snippets (Principled inputs, 4.4 slotted actions). Headless scripts need --python-exit-code 1. Many sources are manual Blender or Roblox export guides with no Claude content, and none cover Claude-to-Roblox export end to end.

## Key points
- **[SINGLE-SOURCE]** [SINGLE-SOURCE] sandraschi/blender-mcp runs Blender headless per call (no persistent connection, no addon, no live instance): `blender --background --factory-startup --python <temp_script.py>`, stdout/stderr captured, temp file deleted. No shared state between runs; a running UI cannot be inspected. *(multiple-sources, high)* [[sources/gh-sandraschi-blender-mcp-f-docs-BLENDER_COMMS.md|gh-sandraschi-blender-mcp-f-docs-BLENDER_COMMS.md]] [[sources/gh-sandraschi-blender-mcp-f-docs-blender-GUI_MODE.md|gh-sandraschi-blender-mcp-f-docs-blender-GUI_MODE.md]]
- **[OUTDATED/UNSURE]** [OUTDATED/UNSURE] That server exposes 41 portmanteau tools (one tool per domain taking an `operation` string, e.g. blender_rigging(operation='list_bones')), built on FastMCP, and requires Blender on PATH or BLENDER_EXECUTABLE. Its docs are inconsistent on tool counts (50/19 categories vs 37/16). *(multiple-sources, medium)* [[sources/gh-sandraschi-blender-mcp-f-docs-blender-TOOL_REFERENCE.md|gh-sandraschi-blender-mcp-f-docs-blender-TOOL_REFERENCE.md]] [[sources/gh-sandraschi-blender-mcp-f-CLAUDE.md|gh-sandraschi-blender-mcp-f-CLAUDE.md]] [[sources/gh-sandraschi-blender-mcp-f-docs-BLENDER_COMMS.md|gh-sandraschi-blender-mcp-f-docs-BLENDER_COMMS.md]] [[sources/gh-sandraschi-blender-mcp-f-mcpb-packaging-README.md|gh-sandraschi-blender-mcp-f-mcpb-packaging-README.md]]
- **[OUTDATED/UNSURE]** [OUTDATED/UNSURE] Windows hang bug 1: _test_blender_functionality pre-quoted paths and used shell=True; cmd.exe mangled the command, causing a ~2 min stall and a misleading 'Blender not found'. Running as an argument list without a shell takes 1.9s. *(single-source, high)* [[sources/gh-sandraschi-blender-mcp-i2|gh-sandraschi-blender-mcp-i2]]
- **[OUTDATED/UNSURE]** [OUTDATED/UNSURE] Windows hang bug 2: under stdio MCP, spawned Blender inherits the protocol stdin pipe and deadlocks until the 60s timeout (error -32001). Fix is stdin=DEVNULL in both subprocess.run and asyncio.create_subprocess_exec; the maintainer shipped it in v0.11.0 (commit 066a2be). *(multiple-sources, high)* [[sources/gh-sandraschi-blender-mcp-i3|gh-sandraschi-blender-mcp-i3]] [[sources/gh-sandraschi-blender-mcp-i2|gh-sandraschi-blender-mcp-i2]]
- **[OUTDATED/UNSURE]** [OUTDATED/UNSURE] The reporter claims the official Blender Lab MCP server has the identical stdin bug, fixed by the same one-liner (120s timeout to 4s). This is a reporter claim only. *(single-source, low)* [[sources/gh-sandraschi-blender-mcp-i3|gh-sandraschi-blender-mcp-i3]]
- **[SINGLE-SOURCE]** [SINGLE-SOURCE] In the addon-based blender-mcp, PolyHaven/Sketchfab integrations are off by default; their tools are unregistered and calls return 'Unknown command type', which looks like a version mismatch. Preflight with get_polyhaven_status()/get_sketchfab_status() and enable the checkbox in the BlenderMCP sidebar (N key). *(single-source, high)* [[sources/gh-elithril-blender-kiln-f-plugin-references-sourcing-strategy.md|gh-elithril-blender-kiln-f-plugin-references-sourcing-strategy.md]]
- **[SINGLE-SOURCE]** [SINGLE-SOURCE] Clearing the scene with bpy.ops.wm.read_homefile(use_empty=True) resets integration flags stored as scene properties, so later assets in a batch fail silently with 'Unknown command type'. Instead delete objects and then zero-user datablocks (meshes, materials, images, node_groups, armatures) via execute_blender_code. *(single-source, high)* [[sources/gh-elithril-blender-kiln-f-plugin-references-batch-mode.md|gh-elithril-blender-kiln-f-plugin-references-batch-mode.md]]
- **[OFFICIAL]** [OFFICIAL] For headless batch bpy, use `blender --background --factory-startup --python-exit-code 1 --python script.py -- args`. Without --python-exit-code 1, Blender exits 0 when the script raises, so verify the exit code and that the output file exists (measured on 5.0.1). *(single-source, high)* [[sources/gh-elithril-blender-kiln-f-plugin-references-animation.md|gh-elithril-blender-kiln-f-plugin-references-animation.md]] [[sources/gh-elithril-blender-kiln-f-plugin-references-export-targets.md|gh-elithril-blender-kiln-f-plugin-references-export-targets.md]]
- **[OUTDATED/UNSURE]** [OUTDATED/UNSURE] API drift breaks older (and LLM-generated) snippets: Blender 4.x renamed Principled inputs (Transmission Weight, Subsurface Weight, Sheen Weight, Emission Color/Strength), and 4.4+ slotted actions make action.fcurves.new fail with AttributeError. Use keyframe_insert and walk layers/strips/channelbag. *(single-source, high)* [[sources/gh-elithril-blender-kiln-f-plugin-references-texturing-strategy.md|gh-elithril-blender-kiln-f-plugin-references-texturing-strategy.md]] [[sources/gh-elithril-blender-kiln-f-plugin-references-characters.md|gh-elithril-blender-kiln-f-plugin-references-characters.md]]
- **[SINGLE-SOURCE]** [SINGLE-SOURCE] For textures, prefer the addon's download_polyhaven_asset and set_texture over hand-built node graphs, which often get colorspaces wrong. Sketchfab needs a free API token; download_sketchfab_model accepts target_size. *(single-source, medium)* [[sources/gh-elithril-blender-kiln-f-plugin-references-texturing-strategy.md|gh-elithril-blender-kiln-f-plugin-references-texturing-strategy.md]] [[sources/gh-elithril-blender-kiln-f-plugin-references-sourcing-strategy.md|gh-elithril-blender-kiln-f-plugin-references-sourcing-strategy.md]]
- **[SINGLE-SOURCE]** [SINGLE-SOURCE] AI-assisted material workflow: classify faces geometrically in bmesh (z_ratio, normal.z thresholds) into material zones, take a viewport screenshot so Claude names the zones, the user validates, then search PolyHaven per zone. *(single-source, medium)* [[sources/gh-elithril-blender-kiln-f-plugin-references-texturing-strategy.md|gh-elithril-blender-kiln-f-plugin-references-texturing-strategy.md]]
- **[OUTDATED/UNSURE]** [OUTDATED/UNSURE] Reference-image modelling guidance: measure silhouettes and palette instead of eyeballing, inventory details from 3x crops, state or ask for real scale, check attachment with BVH distance (>0.5 mm gap means floating), and cap correction at two rounds (IoU plus band-width gaps >8%). *(single-source, medium)* [[sources/gh-elithril-blender-kiln-f-plugin-references-reference-fidelity.md|gh-elithril-blender-kiln-f-plugin-references-reference-fidelity.md]]
- **[SINGLE-SOURCE]** [SINGLE-SOURCE] Blender's official MCP work (Blender Lab) uses a server outside Blender, an add-on inside, and a chat LLM client. The add-on is separate from core and not on the extensions site, and its docs example uses llama.cpp rather than Claude. *(single-source, medium)* [[sources/yt-kDKQmp80o8I|yt-kDKQmp80o8I]]
- **[OUTDATED/UNSURE]** [OUTDATED/UNSURE] Generic bpy fundamentals appear in tutorials (bmesh.new, verts.new, ensure_lookup_table, face winding, library load/link, world node setup). Tutorials are 2023-2024 and do not involve Claude. *(multiple-sources, high)* [[sources/yt-N3U2noAHgBo|yt-N3U2noAHgBo]] [[sources/yt-BSsjSj0iOaE|yt-BSsjSj0iOaE]] [[sources/yt-xz9Tn6rUzzg|yt-xz9Tn6rUzzg]] [[sources/yt-jT2EbqMfKU8|yt-jT2EbqMfKU8]]

## Techniques
- **[SINGLE-SOURCE]** **[SINGLE-SOURCE] Headless Blender via argument list**: Build argv [blender, '--background', '--factory-startup', '--python', script, '--'] and call subprocess.run without shell=True. [[sources/gh-sandraschi-blender-mcp-i2|gh-sandraschi-blender-mcp-i2]]
- **[SINGLE-SOURCE]** **[SINGLE-SOURCE] stdin=DEVNULL for stdio MCP servers**: Pass stdin=DEVNULL to both subprocess.run and asyncio.create_subprocess_exec so Blender doesn't inherit the JSON-RPC pipe. [[sources/gh-sandraschi-blender-mcp-i3|gh-sandraschi-blender-mcp-i3]] [[sources/gh-sandraschi-blender-mcp-i2|gh-sandraschi-blender-mcp-i2]]
- **[SINGLE-SOURCE]** **[SINGLE-SOURCE] Safe inter-asset scene clear**: Via execute_blender_code remove all objects, then purge zero-user datablocks, avoiding read_homefile. [[sources/gh-elithril-blender-kiln-f-plugin-references-batch-mode.md|gh-elithril-blender-kiln-f-plugin-references-batch-mode.md]]
- **[SINGLE-SOURCE]** **[SINGLE-SOURCE] Integration preflight**: Call get_polyhaven_status()/get_sketchfab_status() and show the message if disabled. [[sources/gh-elithril-blender-kiln-f-plugin-references-sourcing-strategy.md|gh-elithril-blender-kiln-f-plugin-references-sourcing-strategy.md]]
- **[SINGLE-SOURCE]** **[SINGLE-SOURCE] Geometric face classification for materials**: Use bmesh z_ratio and normal.z thresholds to set face.material_index, then bm.to_mesh. [[sources/gh-elithril-blender-kiln-f-plugin-references-texturing-strategy.md|gh-elithril-blender-kiln-f-plugin-references-texturing-strategy.md]]
- **[OFFICIAL]** **[OFFICIAL] Batch exit-code checking**: Use --python-exit-code 1, then check the exit code and that the output file exists. [[sources/gh-elithril-blender-kiln-f-plugin-references-export-targets.md|gh-elithril-blender-kiln-f-plugin-references-export-targets.md]]
- **[OFFICIAL]** **[OFFICIAL] Decimation via modifier**: Add DECIMATE modifier in COLLAPSE mode with ratio=target/current faces, then apply (approximate). [[sources/gh-elithril-blender-kiln-f-plugin-references-topology-rules.md|gh-elithril-blender-kiln-f-plugin-references-topology-rules.md]]
- **[OFFICIAL]** **[OFFICIAL] Reload-on-save dev loop**: Use VS Code Blender Development extension or a watcher add-on that reruns the script on save, with a scene-clean helper. [[sources/yt-t3YWMAJURIw|yt-t3YWMAJURIw]] [[sources/yt-_0srGXAzBZE|yt-_0srGXAzBZE]]

## Disagreements
- **Architecture of Blender MCP servers: persistent addon vs fresh headless process**: sandraschi server: no socket/addon, fresh headless process per run, no shared state [[sources/gh-sandraschi-blender-mcp-f-docs-BLENDER_COMMS.md|gh-sandraschi-blender-mcp-f-docs-BLENDER_COMMS.md]] | Addon-based blender-mcp: live Blender with scene-property state, execute_blender_code, and integrations toggled in the sidebar [[sources/gh-elithril-blender-kiln-f-plugin-references-batch-mode.md|gh-elithril-blender-kiln-f-plugin-references-batch-mode.md]] [[sources/gh-elithril-blender-kiln-f-plugin-references-sourcing-strategy.md|gh-elithril-blender-kiln-f-plugin-references-sourcing-strategy.md]] Note: These are different projects, not a conflict; guidance such as the scene-clear and preflight advice applies only to the addon-based one.

## Gaps
- No source covers Claude-driven export from Blender to Roblox (FBX/glTF settings, scale, cages) in an automated flow; the Roblox export sources are manual-only.
- No evidence on Roblox-specific constraints (triangle limits, mesh validation) applied through bpy or MCP.
- Little first-party documentation on the Anthropic/Claude side. The Blender Lab MCP example uses llama.cpp.
- The key addon claims (integrations off, scene-clear, API drift) rest on a single repo or skill docs and lack independent verification.
- No benchmarks of AI-generated modelling quality beyond the single-source reference-image fidelity workflow.

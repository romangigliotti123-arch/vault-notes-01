# web-70689b6bd0

Personal-use research note. Brief quotes only, with attribution; see the original at the URL above.

## Summary
DevForum thread (Dec 2021): user's Blender mesh split into 200+ parts imports misaligned and resized when re-importing into Roblox with rescale unchecked. Community reply: set FBX export scale to 0.01, apply all transforms (Ctrl+A), and answer Yes to import with location data. Thread is anecdotal and brief; no official Roblox guidance.

## Claims
- c1: Blender models import into Roblox very large when exported as FBX at default scale; reply suggests FBX export scale 0.01 instead of 1. *(experience, medium; roblox-export-settings)*
- c2: Unapplied transforms cause misalignment: apply All Transformations (Ctrl+A) to all selected parts before export. *(experience, medium; common-mistakes-fixes)*
- c3: When importing, answering Yes to the prompt about importing with location data keeps parts positioned as in Blender. *(experience, medium; roblox-import-pipeline)*
- c4: Re-importing a split mesh piece-by-piece with rescale unchecked caused parts to misalign and resize; OP reported this symptom. *(experience, high; common-mistakes-fixes)*
- c5: Suggested workaround: weld the imported parts so one cannot be accidentally moved, avoiding re-imports. *(opinion, low; creator-workflows)*

## Numbers
- n1: **FBX export scale suggested**: 0.01 (default 1) Community reply to scaling issue; not verified by the poster
- n2: **Mesh part count**: over 200 parts OP's plane split into 200+ parts requiring two imports

## Techniques
- t1: **Scale down on FBX export**: Set export scale to 0.01 in Blender FBX exporter instead of 1, then import into Roblox.
- t2: **Apply all transforms before export**: Select all parts, press Ctrl+A, choose All Transformations, then export.
- t3: **Import with location data**: In the Roblox import dialog, answer Yes to import with location data so parts keep positions.
- t4: **Weld split parts**: Weld imported parts together to prevent accidental movement that forces re-import.

# web-41fc623715

Personal-use research note. Brief quotes only, with attribution; see the original at the URL above.

## Summary
DevForum announcement and Q&A on Open Cloud Assets API expansion (Oct 2025): uploads of .rbxm models/animations and Roblox meshes enabled, FBX/glTF model upload via API, 3D Importer for standard formats, plugin upload not supported by API key, models uploaded as packages, and legacy Upload.ashx/UploadNewMesh/UploadNewAnimation endpoints deprecated. Little Blender-specific content.

## Claims
- c1: From 2025-10-23 the Open Cloud Assets API accepts .rbxm models and animations plus Roblox-formatted meshes, mainly to re-upload data previously downloaded from Roblox APIs or Studio. *(doc, high; open-cloud-automation)*
- c2: Standard 3D formats should go through the Studio 3D Importer, or be uploaded as Models via Assets API using FBX or glTF. *(doc, high; open-cloud-automation)*
- c3: Roblox says externally edited .rbxm or mesh files may fail to upload or function because Studio adds extra processing; no guarantee for external tools. *(doc, high; roblox-import-pipeline)*
- c4: Plugins cannot be uploaded with an Open Cloud API key; user-cookie Assets API upload is the only route for now, with no timeline. *(doc, high; open-cloud-automation)*
- c5: All new models uploaded via the API are created as packages; configurable behaviour was in progress with no timeline. *(doc, high; open-cloud-automation)*
- c6: Legacy endpoints Upload.ashx, ide/publish/UploadNewMesh and UploadNewAnimation were slated for deprecation (announced as 3 months, then set to 1 week on 2026-03-02). *(doc, high; open-cloud-automation)*
- c7: Animations shared between accounts should use Animation Sharing (connections/groups/experiences) rather than re-uploading via third-party tools. *(doc, medium; open-cloud-automation)*
- c8: Initially .rbxmx was reported unsupported (400 'Creating Model from a model/x-rbxmx file is not supported yet'); the correct MIME type is model/x-rbxm, and the service determines the format. *(experience, medium; open-cloud-automation)*
- c9: A glTF/GLB sample file with vertex colours uploads through the Assets API as expected; import settings changes need the 3D Importer. *(demo, medium; texturing-baking-uv)*
- c10: A user reported FBX collision meshes misaligned on upload despite aligning in Blender; no fix given in thread, and a Roblox importer engineer said it was unrelated to the API change. *(experience, low; common-mistakes-fixes)*
- c11: Roblox staff said API parity: processes working with Upload.ashx should work with the Open Cloud Assets API. *(doc, medium; open-cloud-automation)*
- c12: Rojo-style plugin upload depends on cookie auth, so cookie-based upload support must remain for tools like Rojo's upload command. *(opinion, medium; open-cloud-automation)*

## Numbers
- n1: **Legacy endpoint deprecation window**: 3 months, later 1 week notice (2026-03-02) Announced 2025-10-23; reminder posted 2026-03-02 saying deprecation in 1 week
- n2: **Source date**: 2025-10-23 Original announcement date of rbxm/mesh upload support

## Techniques
- t1: **Migrate legacy uploads to Assets API**: Replace Upload.ashx/UploadNewMesh/UploadNewAnimation calls with Open Cloud Assets API using an API key. Use FBX or glTF for models; re-upload rbxm only if it came from Roblox. Use Animation Sharing for cross-account animation use.

# off-dev_4656414

Personal-use research note. Brief quotes only, with attribution; see the original at the URL above.

## Summary
Roblox staff post on Avatar Joint Upgrade (AJU) Phase 2. Default-setting games now get AnimationConstraint/BallSocketConstraint joints instead of Motor6D. Opt-out is StarterPlayer.AvatarJointUpgrade = Disabled, temporary, with Phase 3 forced migration targeted by end of 2026. Advises against editing RigAttachment/Attachment CFrame for procedural animation; use .Transform multiplied in PreSimulation. Does not cover Blender, bpy, or asset export.

## Claims
- c1: Phase 2 of AJU applies to all games with StarterPlayer.AvatarJointUpgrade set to 'Default', replacing Motor6D with AnimationConstraint and BallSocketConstraint. *(doc, high; rigging-animation)*
- c2: Games can temporarily opt out by setting StarterPlayer.AvatarJointUpgrade to Disabled and republishing; described as a temporary safety net. *(doc, high; rigging-animation)*
- c3: Phase 3 (full forced migration for all games) is targeted by end of year 2026. *(doc, medium; rigging-animation)*
- c4: Do not modify RigAttachment.CFrame or Attachment0.CFrame for procedural animation; constantly moving RigAttachments can hurt performance and Animation Retargeting. *(doc, high; rigging-animation)*
- c5: Recommended approach for procedural joint changes: multiply AnimationConstraint.Transform inside RunService.PreSimulation, since .Transform is reset each frame by the animation compositor. *(doc, high; rigging-animation)*
- c6: Skip procedural Transform updates when animator.EvaluationThrottled is true (LOD throttling). *(doc, medium; rigging-animation)*
- c7: Setting C0 on the server for replication is discouraged; evaluate procedural animation locally on client and sync via Attributes or UnreliableRemoteEvent. *(doc, high; rigging-animation)*
- c8: Scripts checking instance:IsA('Motor6D') will not detect AnimationConstraints; setting C0, C1, Part0, or Part1 on an AnimationConstraint throws an error because it relies on Attachments. *(doc, high; rigging-animation)*
- c9: For look-at or reach-toward-goal behavior, the post recommends IKControl instead of manual joint manipulation. *(opinion, medium; rigging-animation)*
- c10: Developers hitting AJU breakage are asked to comment on the thread with exactly what broke before the final forced migration. *(doc, high; automation-and-creator-workflows)*
- c11: Nothing in the post covers Blender, bpy, blender-mcp, FBX/glTF export, scale, or mesh/texture limits. *(doc, high; other)*

## Numbers
- n1: **Phase 3 target**: end of 2026 
- n2: **StarterPlayer.AvatarJointUpgrade values**: Default / Disabled 

## Techniques
- t1: **Procedural joint offset via Transform**: In RunService.PreSimulation, skip if animator.EvaluationThrottled; else set neck.Transform = computeNeckRotation() * neck.Transform. Do not edit RigAttachment CFrame.
- t2: **Client-local procedural animation with replicated data**: Replicate target via custom Attribute or UnreliableRemoteEvent; compute Transform locally on each client rather than setting C0 on server.

### Code: Migrated procedural neck offset under AJU (post's 'After' example)
```lua
RunService.PreSimulation:Connect(function()
	-- run after Animation applies the Transform
	if not animator.EvaluationThrottled then -- skip this frame if Animation is throttled by LOD
		neck.Transform = computeNeckRotation() * neck.Transform
	end
end)
```

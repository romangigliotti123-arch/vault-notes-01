## Summary
Official Blender Python API tips: terminal use, copying operator/data paths, debug_wm operator logging, external script execution and module reload, headless background runs, embedded interpreters, bundled-Python version matching, bpy-as-module builds, and WITH_PYTHON_SAFETY. Generic; no Claude, blender-mcp, or Roblox content.

## Claims
- c1: Run Blender headless for non-interactive scripts: blender --background --python myscript.py, optionally with a .blend file first to supply data. *(doc, high; bpy-scripting-headless)*
- c2: Ctrl-C in the terminal (Ctrl-Break on Windows) stops a runaway script; full tracebacks print to the terminal even when Blender shows no report. *(doc, high; bpy-scripting-headless)*
- c3: Running with --debug-wm or setting bpy.app.debug_wm=True logs every operator call to the terminal, not only REGISTER-flagged ones shown in Info editor. *(doc, high; bpy-scripting-headless)*
- c4: Ctrl-C over any menu item or button copies its bpy.ops command; Copy Data Path from context menu gives the path to a setting. *(doc, high; bpy-scripting-headless)*
- c5: External script can be run from a Blender text block via exec(compile(...)); or imported as a module and reloaded with importlib.reload before calling main(). *(doc, high; bpy-scripting-headless)*
- c6: Mid-script inspection via code.interact(local=locals()) or IPython.embed(); Blender has no built-in Python debugger. *(doc, high; bpy-scripting-headless)*
- c7: Bundled Python must match system Python major.minor version for extensions to work; mismatched versions cannot be mixed. *(doc, high; bpy-scripting-headless)*
- c8: Blender can be built as a Python module (bpy) for external IDEs; this requires a special CMake build option, not stock release builds. *(doc, medium; bpy-scripting-headless)*
- c9: Accessing freed data can crash Blender; CMake option WITH_PYTHON_SAFETY turns it into Python exceptions at about 2x slower data access, so it is off in releases. *(doc, high; common-mistakes-fixes)*
- c10: Source is generic Blender Python API tips; it does not mention Claude, blender-mcp, Roblox, or FBX/glTF export settings. *(doc, high; other)*

## Numbers
- n1: **debug overhead**: 2x slower WITH_PYTHON_SAFETY data access cost
- n2: **Python version**: major.minor must match example: 3.6 cannot pair with Blender built for 3.7

## Techniques
- t1: **Headless batch run**: Run blender --background --python script.py, optionally with a .blend file; write output as image, saved blend/export, or text. Re-run on a timer for a live viewer.
- t2: **Reload module and call main**: import module, importlib.reload(module), then call main() with args to test settings quickly without restarting Blender.

### Code: Run a script headless in Blender, optionally against a .blend file
```sh
blender --background --python myscript.py
blender myscene.blend --background --python myscript.py
```

### Code: Reload and call a function in a module script during iteration
```python
import myscript
import importlib

importlib.reload(myscript)
myscript.main()
```

# off-dev_4358192

Personal-use research note. Brief quotes only, with attribution; see the original at the URL above.

## Summary
Roblox DevForum staff post (Feb 12, 2026; updated Mar 13, 2026) announcing Studio Beta then Client Beta of In-Experience Accessory Auto-Setup via AvatarCreationService. Converts raw clothing/accessory meshes into Roblox-ready wearables. Does not mention Blender, bpy, or Blender-to-Roblox export; relevance to the Blender pipeline is indirect.

## Claims
- c1: Accessory Auto-Setup for in-experience items expands last year's Auto-Setup for IEC Bodies to clothing and accessories; built on the same system as Auto Setup in Studio. *(doc, high; avatar-ugc-accessories)*
- c2: Supported item types include shirts, pants, shoulder accessories, and hats; layered clothing and rigid accessories are both covered. *(doc, high; avatar-ugc-accessories)*
- c3: Known issue: rigid accessories (hats, back items) must be submitted to AutoSetupAvatarAsync together with a body model so attachment points are computed relative to the character frame. *(doc, high; avatar-ugc-accessories)*
- c4: Outputs are EditableMesh and EditableImage, allowing texture or geometry edits after setup. *(doc, high; avatar-ugc-accessories)*
- c5: Flow: define AutoSetupParams entries (AccessoryType, IsLayered, Instance), call AutoSetupAvatarAsync on the server, then retrieve a HumanoidDescription via LoadGeneratedAvatarAsync. *(doc, high; automation-and-creator-workflows)*
- c6: Combined with PromptCreateAvatarAsync, generated accessories can be purchased and saved to a player's inventory from inside the experience. *(doc, high; automation-and-creator-workflows)*
- c7: To enable Studio Beta: File > Beta Features > enable In-Experience Avatar Auto-Setup, then restart Studio. *(doc, high; automation-and-creator-workflows)*
- c8: Beta limitation: all input mesh and texture assets must be owned by the same user or group as the experience. *(doc, high; automation-and-creator-workflows)*
- c9: Client Beta (Mar 13, 2026 update) enables these APIs to run in live experiences, not only in Studio. *(doc, high; other)*
- c10: Source does not mention Blender, bpy, blender-mcp, or any Blender export step; the pipeline it describes starts from models already in Studio. *(doc, high; claude-blender-ai)*

## Numbers
- n1: **Studio Beta announcement date**: 2026-02-12 Initial DevForum post date
- n2: **Client Beta update date**: 2026-03-13 Update enabling APIs in live experiences

## Techniques
- t1: **Layered accessory setup**: Create accessory table with AccessoryType=Shirt and IsLayered=true, Instance=model of MeshParts, pass in Accessories array with Body model to AutoSetupAvatarAsync on server.
- t2: **Rigid accessory pairing**: Submit body model and rigid accessory (hat, back item) in the same AutoSetupAvatarAsync call so attachment points resolve correctly.

### Code: Define accessory and call AutoSetupAvatarAsync on server (from source example)
```lua
local shirtAccessory = {
	AccessoryType = Enum.AccessoryType.Shirt,
	IsLayered = true,
	Instance = shirtModel, -- Your Model containing MeshParts
}
local accessories = {shirtAccessory}
local success, generationId = pcall(function()
	return AvatarCreationService:AutoSetupAvatarAsync(player, {
		Body = bodyModel,
		Accessories = accessories
	})
end)
```

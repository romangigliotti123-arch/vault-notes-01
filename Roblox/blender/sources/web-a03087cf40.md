# web-a03087cf40

Personal-use research note. Brief quotes only, with attribution; see the original at the URL above.

## Summary
Roblox doc on the alpha Photo-to-avatar APIs (AvatarCreationService). Covers session request, selfie-to-2D preview, full 3D avatar generation as HumanoidDescription, and in-game publishing. Nothing on Blender, bpy, blender-mcp, FBX/glTF export, or the Blender-to-Roblox pipeline; off-topic for the requested subject.

## Claims
- c1: Roblox photo-to-avatar generation is in alpha per the doc; it is a Roblox in-experience feature, not a Blender pipeline. *(doc, high; other)*
- c2: Flow: RequestAvatarGenerationSessionAsync (server) -> PromptSelectAvatarGenerationImageAsync (selfie fileId) -> GenerateAvatar2DPreviewAsync -> GenerateAvatarAsync -> LoadGeneratedAvatarAsync -> Players.CreateHumanoidModelFromDescription. *(doc, high; avatar-ugc-accessories)*
- c3: Session dictionary provides SessionId, Allowed2DGenerations, Allowed3DGenerations, SessionTime (max seconds); waitTime lets game inform player of queue delay. *(doc, high; avatar-ugc-accessories)*
- c4: Generated mesh and texture assets are EditableMesh and EditableImage objects; edits must be mirrored on server and client to stay in sync for publish. *(doc, high; avatar-ugc-accessories)*
- c5: Finished avatars are published in-experience via AvatarCreationService:PromptCreateAvatarAsync. *(doc, high; avatar-ugc-accessories)*

## Summary
Official Blender Python API overview. Covers the embedded interpreter, bpy/mathutils access, running scripts (Run Script, console, blender --python file.py), startup and add-on loading, and class registration (register/unregister, bl_ prefix, bpy.types subclasses). Nothing on Roblox, MCP, or export. Only tangential to bpy scripting.

## Claims
- c1: Scripts run with 'blender --python /path/script.py' execute directly; classes they register stay live in Blender after execution. *(doc, high; bpy-scripting-headless)*
- c2: Direct script execution makes later unregistering harder; doc recommends importing scripts as modules instead. *(doc, high; bpy-scripting-headless)*
- c3: Edits via bpy.data are applied to Blender's internal data directly; running in the interactive console updates the 3D Viewport. *(doc, high; bpy-scripting-headless)*
- c4: Blender-required module entry points are register() and unregister(); the if __name__ == '__main__' guard lets a script be run from the text editor for testing. *(doc, high; bpy-scripting-headless)*
- c5: Operators cannot be instantiated directly; they are run via bpy.ops.<category>.<name>() after registration. *(doc, high; bpy-scripting-headless)*
- c6: Since Blender 4.4, a RenderEngine subclass must call the Blender-defined parent __init__ before accessing data, or it fails with 'couldn't create bpy_struct object'. *(doc, high; bpy-scripting-headless)*
- c7: Python integration is limited to Panel, Menu, Operator, PropertyGroup, KeyingSet and RenderEngine; mesh modifiers, object types and shader nodes require C/C++ per this doc. *(doc, high; other)*
- c8: Add-ons must include blender_manifest.toml with metadata such as name, author, tags and project link. *(doc, high; bpy-scripting-headless)*
- c9: Property groups must be registered lowest-first, and unregister must mirror register; a PointerProperty to an unregistered class raises a registration error. *(doc, high; bpy-scripting-headless)*

## Numbers
- n1: **Minimum Blender version for mandatory RenderEngine parent __init__ call**: 4.4 

## Techniques
- t1: **Run script from CLI**: Run 'blender --python my_script.py' to execute a file. Use the register/unregister module pattern with an __main__ guard so classes can be toggled and unregistered cleanly.

### Code: Run a Python file with Blender from the command line (direct execution).
```sh
blender --python /home/me/my_script.py
```

### Code: Direct bpy data edit: move vertex 0 of object 'Cube' along +X.
```python
import bpy
bpy.data.objects["Cube"].data.vertices[0].co.x += 1.0
```

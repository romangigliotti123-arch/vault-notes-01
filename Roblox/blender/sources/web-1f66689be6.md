## Summary
Roblox emote spec doc: an emote is an Animation object with AnimationId set to an asset ID. Requirements: under 10 s, standard R15 rig, root joint stays near start, speed capped, sourced from CurveAnimation, and must pass Community Standards. Says nothing about Blender, Claude, or bpy; low relevance to the Blender pipeline topic.

## Claims
- c1: Emote upload requires only an Animation object with AnimationId set to the animation asset ID; no meshes or textures needed. *(doc, high; avatar-ugc-accessories)*
- c2: Emotes must be less than 10 seconds long. *(doc, high; avatar-ugc-accessories)*
- c3: Animation data must reference a standard R15 rig; advanced R15 rig emotes are in closed beta. *(doc, high; rigging-animation)*
- c4: Animation must be sourced from a CurveAnimation; conversion covered in Import emotes page. *(doc, high; rigging-animation)*
- c5: Root joint cannot drift too far from starting position; per-frame movement speed is capped to prevent teleport abuse; violations may fail validation. *(doc, high; avatar-ugc-accessories)*
- c6: Emotes must meet Roblox Community Standards and Marketplace policies. *(doc, high; automation-and-creator-workflows)*
- c7: Source page does not mention Blender, Claude, blender-mcp, or bpy; it is only Roblox emote spec docs, so it gives no Blender-specific workflow. *(doc, high; claude-blender-ai)*

## Summary
Roblox docs on collisions: touch events, collision groups, filtering, and MeshPart CollisionFidelity options (Box, Hull, Default, PreciseConvexDecomposition). Only the mesh collision section relates to the Blender-to-Roblox pipeline; nothing on Claude, blender-mcp, bpy, or export settings.

## Claims
- c1: MeshPart and PartOperation inherit BasePart collision events and filtering; their CollisionFidelity property sets how closely the physical bounds match the visual mesh. *(doc, high; mesh-texture-limits)*
- c2: CollisionFidelity options, lowest to highest fidelity and cost: Box, Hull, Default, PreciseConvexDecomposition. *(doc, high; mesh-texture-limits)*
- c3: Box suits small or non-interactive objects. Hull is a convex hull for objects with shallow indentations. Default approximates concavity for semi-detailed interaction. *(doc, high; mesh-texture-limits)*
- c4: PreciseConvexDecomposition is the most precise but not 1:1 with the visual mesh. It has the highest performance cost and takes the engine longer to compute. *(doc, high; mesh-texture-limits)*
- c5: To see collision fidelity in Studio, enable 'Collision fidelity' in the Visualization Options widget at the upper right of the 3D viewport. *(doc, high; mesh-texture-limits)*
- c6: Register collision groups in a single script, since script execution order isn't guaranteed and multiple scripts can cause a race condition. *(doc, high; automation-and-creator-workflows)*
- c7: Set CanTouch to false on objects that don't need collision events, as a performance optimization. *(doc, high; automation-and-creator-workflows)*
- c8: Touched and TouchEnded fire only from physical simulation, not when Position or CFrame is set so parts intersect. *(doc, high; other)*

## Techniques
- t1: **Choose mesh CollisionFidelity**: Select a MeshPart and set CollisionFidelity to Box, Hull, Default, or PreciseConvexDecomposition to balance accuracy against physics cost. Check the result with Collision fidelity visualization in Studio.

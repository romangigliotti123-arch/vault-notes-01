## Summary
Roblox overview of Studio 3D tools: interface panels, assets vs packages, basic parts vs imported mesh (MeshPart) from Blender/Maya, basic vs PBR textures, materials, terrain and lighting. Gives no bpy, blender-mcp, export settings, scale, or limits. Only peripheral value for the Blender pipeline topic.

## Claims
- c1: Source is a generic Roblox Studio 3D art overview; it does not mention blender-mcp, bpy scripting, Claude, or a Blender-to-Roblox export procedure. *(doc, high; other)*
- c2: Roblox says custom meshes are created in third-party apps like Blender or Maya, then imported into Studio and represented as MeshPart. *(doc, high; mesh-texture-limits)*
- c3: Roblox has two texture types: single-image basic textures and advanced PBR textures that react dynamically to lighting. *(doc, high; mesh-texture-limits)*
- c4: Loading many unique PBR textures at once can hurt performance; reuse one PBR texture set and vary tint via alpha-channel masks in base colors. *(doc, high; mesh-texture-limits)*
- c5: Textures are purely visual and never affect physical properties; materials do affect physical properties. *(doc, high; mesh-texture-limits)*
- c6: Roblox recommends using terrain rather than parts for outdoor environments to ensure performance and expected lighting behavior. *(doc, medium; mesh-texture-limits)*
- c7: Roblox recommends most developers work with Packages (like Unity Prefabs) over plain assets, since packages propagate changes to all copies. *(doc, high; automation-and-creator-workflows)*
- c8: Selling avatar items on the Marketplace requires following specific avatar specifications plus policies; details are on separate Avatar and Marketplace pages not included here. *(doc, medium; avatar-ugc-accessories)*
- c9: Studio's Texture Generator and Material Generator create textures and materials from natural-language prompts; these are built-in, not Blender tools. *(doc, high; other)*

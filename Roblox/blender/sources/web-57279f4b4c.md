# web-57279f4b4c

Personal-use research note. Brief quotes only, with attribution; see the original at the URL above.

## Summary
Roblox Open Cloud Assets API guide: upload/update assets via HTTP (curl) instead of Studio import. Covers supported types and limits (20 MB per call, FBX/glTF/GLB models upload as packages, only FBX content updatable), API key and OAuth permissions, create/update/operation-status requests, and using uploaded assets in Studio.

## Claims
- c1: Assets API lets you upload and update assets with a single HTTP request rather than manually importing in Studio; also manages metadata, versions/rollback, and operation status. *(doc, high; automation-and-creator-workflows)*
- c2: Model uploads accept .fbx, .gltf, .glb, .rbxm, .rbxmx and import as a Model container with one or more MeshParts. *(doc, high; blender-roblox-export-import)*
- c3: Docs recommend the Studio Importer for custom 3D models: it offers 3D preview, error checking and many import settings, which the API lacks. *(doc, high; blender-roblox-export-import)*
- c4: Models uploaded via API are created as packages; find them in Toolbox under Inventory > My Packages (or Creations > Group Packages for group-owned). *(doc, high; blender-roblox-export-import)*
- c5: Updating asset content is currently supported only for .fbx files, and each update creates a new version. *(doc, high; blender-roblox-export-import)*
- c6: Raw Mesh asset type accepts only content downloaded from the Asset Delivery API (model/x-file-mesh-data); not updatable. Use the Importer for meshes otherwise. *(doc, high; mesh-texture-limits)*
- c7: Decal/Image uploads (.png, .jpeg, .bmp, .tga) must be smaller than 8000x8000 pixels and cannot be updated via the API. *(doc, high; mesh-texture-limits)*
- c8: Animation assets upload as .rbxm/.rbxmx; files edited outside Roblox Studio might not upload or function. Same warning for model rbxm files. *(doc, high; rigging-animation)*
- c9: API key needs 'assets' in Access Permissions plus Read/Write operations on the selected game; key goes in the x-api-key header on all endpoints. Group assets require group permissions. *(doc, high; automation-and-creator-workflows)*
- c10: Create/Update return an operation path; poll Get Operation to get either a response with assetId and moderationState or a status explaining failure. *(doc, high; automation-and-creator-workflows)*
- c11: Use an uploaded asset via rbxassetid:// plus assetId in Properties, or Content.fromAssetId() for Content-typed properties like Decal.ColorMapContent. *(doc, high; automation-and-creator-workflows)*
- c12: OAuth 2.0 third-party use needs asset:read and asset:write scopes and is Beta; update endpoints are also beta and may change. *(doc, high; automation-and-creator-workflows)*

## Numbers
- n1: **max file size per call**: 20 MB one asset created or updated per call
- n2: **max image dimensions**: <8000x8000 px Decal/Image upload
- n3: **audio duration limit**: 7 minutes audio upload
- n4: **audio uploads per month**: 100 ID-verified / 10 unverified audio via API
- n5: **video limits**: 5 min, 4096x2160, 3.75 GB, 20 uploads/day 13+ and ID-verified; mp4/mov

## Techniques
- t1: **Upload exported FBX via Create Asset**: POST https://apis.roblox.com/assets/v1/assets with x-api-key header; form 'request' JSON (assetType Model, displayName, description, creationContext.creator userId or groupId) and form fileContent=@file.fbx;type=model/fbx.
- t2: **Update FBX content as new version**: PATCH /assets/v1/assets/{assetId} with request JSON (assetType, assetId, creationContext, expectedPrice) and fileContent; add ?updateMask=description%2CdisplayName to also change metadata.
- t3: **Poll operation status**: GET /assets/v1/operations/{operationId} with x-api-key; wait for done:true, then read response.assetId and moderationResult.

### Code: Create a Model asset from an FBX via Open Cloud
```bash
curl --location 'https://apis.roblox.com/assets/v1/assets' \
--header 'x-api-key: ${ApiKey}' \
--form 'request="{
  \"assetType\": \"Model\",
  \"displayName\": \"Name\",
  \"description\": \"This is a description\",
  \"creationContext\": {\"creator\": {\"userId\": \"${userId}\"}}
}"' \
--form 'fileContent=@"/filepath/model.fbx";type=model/fbx'
```

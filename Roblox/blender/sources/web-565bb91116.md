# web-565bb91116

Personal-use research note. Brief quotes only, with attribution; see the original at the URL above.

## Summary
Roblox doc on authoring cage meshes in Blender for Studio's WrapTarget/WrapLayer deformation. Covers _OuterCage/_InnerCage naming, shared UVs, coarse cage shells, FBX Unit Scale export, and 3D Importer Uses Cages. Avatar cages should use Roblox templates. No blender-mcp, bpy, or Claude content.

## Claims
- c1: Cage meshes must be authored in a third-party tool such as Blender or Maya, then imported into Studio; the doc uses Blender. *(doc, high; blender-roblox-export-import)*
- c2: Target mesh naming: render mesh name plus _OuterCage suffix (e.g. Cube_OuterCage) imports as WrapTarget. *(doc, high; blender-roblox-export-import)*
- c3: Layered mesh needs both _InnerCage and _OuterCage (e.g. Shirt_InnerCage, Shirt_OuterCage); together they import as WrapLayer. *(doc, high; blender-roblox-export-import)*
- c4: Export render mesh and cages together as one .fbx or .gltf; Studio imports cages from both formats equally. *(doc, high; blender-roblox-export-import)*
- c5: For FBX, set Apply Scalings to FBX Unit Scale so model keeps scale in Studio. *(doc, high; blender-roblox-export-import)*
- c6: In 3D Importer, enable Uses Cages; if not auto-enabled, naming is wrong and the file should be re-exported after fixing names. *(doc, high; blender-roblox-export-import)*
- c7: Cage must sit just outside the render surface and fully enclose it, staying as close as possible; create cages after finalizing render mesh topology/UVs. *(doc, high; mesh-texture-limits)*
- c8: Cage is a coarse shell: example avatar head render mesh up to 12,000 vertices vs cage of 335 vertices. *(doc, high; mesh-texture-limits)*
- c9: Cage meshes must share identical UV layout across target and layered cages; Roblox pairs layered mesh to target by UV. Geometry may change, UVs may not. *(doc, high; mesh-texture-limits)*
- c10: Do not add or delete cage vertices after setup, or change UVs; this breaks vertex pairing and causes import errors or wrong deformation. *(doc, high; mesh-texture-limits)*
- c11: Avatar bodies (targets) and marketplace clothing (layered) must share a common Roblox cage; do not create your own cages for avatars or layered accessories. *(doc, high; avatar-ugc-accessories)*
- c12: For avatar/layered accessory cages, use Roblox downloadable cage templates or the Avatar Setup tool to auto-generate a Roblox-supported cage. *(doc, high; avatar-ugc-accessories)*
- c13: Success check: Explorer shows WrapTarget under MeshPart for outer-cage-only; WrapLayer under MeshPart when both cages present. *(doc, high; blender-roblox-export-import)*
- c14: Page does not cover blender-mcp, bpy scripting, or Claude integration; no Claude/AI workflow content present. *(doc, high; other)*

## Numbers
- n1: **avatar head render vertices**: up to 12,000 
- n2: **avatar head cage vertices**: 335 
- n3: **cube loop cuts in example**: 10 per axis 

## Techniques
- t1: **Name cages for importer detection**: Name render mesh X; duplicate and suffix _OuterCage for target, or add _InnerCage and _OuterCage for layer. Export FBX/glTF together, enable Uses Cages in 3D Importer.
- t2: **Duplicate-and-shrink cage**: Duplicate render mesh, decimate to coarse shell, adjust just outside surface, keep UVs identical to target cage.

## Quotes (brief, for attribution)
> Export the render mesh and its cages together as a single .fbx or .gltf file. Studio imports cages from both formats equally.  (create.roblox.com)

Personal-use research note. Brief quotes only, with attribution; see the original at the URL above.

## Summary
Roblox creator docs overview of emotes: full-body Animation objects referenced by AnimationId asset ID. Lists three creation workflows (Animation Capture, Animation Editor, third-party plugins like Moon Animator) and requires compliance with emote specs, Community Standards, and Marketplace policies. Points to import docs for generating asset IDs. Little Blender-specific content; no bpy, blender-mcp, or FBX details.

## Claims
- c1: Emotes are full body Animation objects; the AnimationId property is set to the asset ID of the animation sequence. *(doc, high; avatar-ugc-accessories)*
- c2: Emote animations can be created in Studio via Animation Capture (video to keyframes), Animation Editor (manual rig animation), or third-party plugins such as Moon Animator. *(doc, high; automation-and-creator-workflows)*
- c3: Emotes must meet Roblox emote specifications, Community Standards, and Marketplace policies before upload. *(doc, high; avatar-ugc-accessories)*
- c4: Keyframe sequences are converted to uploadable Marketplace animations via the Import emotes Generate asset ID step. *(doc, medium; automation-and-creator-workflows)*

# web-ec54006323

Personal-use research note. Brief quotes only, with attribution; see the original at the URL above.

## Summary
DevForum thread (2023-2024) where a user's rigged Blender FBX (Freddy model, 39k tris, parts each under 10k) broke apart on Roblox 3D Importer import. Helpers suggested OBJ export, Asset Manager "Insert With Location", and proper weight painting. The OP's reported fix was automatic weights plus cleanup (in Unreal). A helper advised rigging rigid parts with empty groups at weight 1, then joining and separating by material. No confirmed fix for the Roblox FBX case; thread auto-closed.

## Claims
- c1: Rigged Freddy FBX (39k tris, parts each under 10k, transforms applied, origins at 0) imported via 3D Importer came in with all parts scattered; no fix confirmed in thread. *(experience, high; roblox-import-pipeline)*
- c2: Helper says FBX often has location and rotation problems in Studio; OBJ export of same meshes positioned correctly. Not verified by the OP. *(opinion, medium; roblox-import-pipeline)*
- c3: Meshes did not appear in Asset Manager for the OP, so the suggested 'Insert With Location' path was unavailable. *(experience, medium; roblox-import-pipeline)*
- c4: Textures were not carried over from Blender; OP applied them manually in Roblox. *(experience, high; roblox-import-pipeline)*
- c5: Helper believes Roblox decimates a single large mesh on import, so import parts separately rather than as one mesh. *(opinion, low; roblox-mesh-limits)*
- c6: Parenting meshes to bones with default empty groups was not enough for OP; automatic weights plus manual weight cleanup at stiff joints fixed robotic deformation (Unreal project). *(experience, medium; rigging-animation)*
- c7: For robotic parts, assign each rigid part's vertices to one bone at weight 1 instead of automatic weights, which avoids weight-transition cleanup. *(opinion, medium; rigging-animation)*
- c8: Deforming parts (e.g. hand casings) should use automatic weights or hand painting, not rigid bone assignment. *(opinion, medium; rigging-animation)*
- c9: Join segments per bone before rigging, then join whole model and separate by material after rigging, so the rig still works. *(experience, medium; creator-workflows)*
- c10: Ctrl-J join then Edit mode P 'separate by material' reduced a ~100-mesh model to about 10 meshes, simplifying texturing and performance. *(experience, medium; creator-workflows)*
- c11: Applying transforms and setting origins to 0 in Blender did not fix the FBX scatter for this model. *(experience, high; common-mistakes-fixes)*
- c12: Exporting with 'Only selected objects' and scaling down did not change the broken import; scale was not the cause here. *(experience, medium; common-mistakes-fixes)*
- c13: Proposed round trip: import meshes, rig in Roblox, export rig to Blender, animate, re-import animations. Unverified in thread. *(opinion, low; rigging-animation)*

## Techniques
- t1: **Join then separate by material**: Ctrl-J join all meshes, Edit mode, select all, P > separate by material. Yields one mesh per material, fewer parts in Roblox.
- t2: **Rigid bone parenting with empty groups**: Select a joined segment in Edit mode, A to select all, add vertex group for the bone, Assign at weight 1. Repeat per segment; test motion.
- t3: **Automatic weights plus cleanup**: Parent deforming meshes with automatic weights, then weight-paint stiff joints so they move rigidly rather than stretch.
- t4: **Insert With Location from Asset Manager**: Open Asset Manager, Meshes, select meshes, right-click, Insert With Location. Suggested by helper; failed for OP because meshes were absent.
- t5: **OBJ export for placement**: Export meshes as OBJ instead of FBX to avoid location and rotation shifts. Helper's suggestion; OP reported OBJ placed correctly but loses rig.

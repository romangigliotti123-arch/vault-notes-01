## Summary
Blender Python API gotchas for meshes: Edit-Mode data sync (obj.data stale until exiting Edit-Mode; fixes: exit edit mode, BMesh.to_mesh, bmesh.from_edit_mesh), and the three face access methods (MeshPolygon, MeshLoopTriangle, BMFace) with guidance on creating, editing and exporting. Relevant only tangentially to Roblox pipeline; no Roblox content.

## Claims
- c1: Scripts reading obj.data in Edit-Mode get mesh data out of sync with the edit mesh, since Edit-Mode data is written back only on exiting Edit-Mode. *(doc, high; bpy-scripting-headless)*
- c2: Exporters accessing obj.data in Edit-Mode may see stale data; fixes are exit Edit-Mode, call BMesh.to_mesh, or use bmesh.from_edit_mesh. *(doc, high; bpy-scripting-headless)*
- c3: Since Blender 2.63 n-gons are supported; mesh.polygons replaces mesh.faces in Object-Mode, and mesh.loop_triangles gives triangulated faces. *(doc, high; bpy-scripting-headless)*
- c4: MeshPolygon is poor for creating/editing geometry, MeshLoopTriangle is read-only and should not be used for editing (it tessellates n-gons), and BMFace is best for create and manipulate. *(doc, high; bpy-scripting-headless)*
- c5: For exporting, MeshPolygon is most direct; loop triangles are encouraged only for formats without n-gon support; BMesh adds overhead because it is not Object-Mode native storage. *(doc, high; bpy-scripting-headless)*
- c6: Scripts that run in Edit-Mode can silently export stale geometry; exit Edit-Mode or flush with to_mesh before exporting. *(doc, medium; common-mistakes-fixes)*

## Numbers
- n1: **n-gon support start**: Blender 2.63 Since 2.63 n-gons are supported, changing face access API

## Techniques
- t1: **Edit-Mode sync fix**: Exit Edit-Mode before running, or call bmesh.types.BMesh.to_mesh to write edit data back, or use bmesh.from_edit_mesh to operate on edit data directly.
- t2: **Choose face access by task**: Create/edit with BMesh faces; export with mesh.polygons if format supports n-gons, else mesh.loop_triangles.

Personal-use research note. Brief quotes only, with attribution; see the original at the URL above.

## Summary
Blender manual page on rendering from the command line. Covers background rendering (-b) for remote/headless use without X server, single-frame rendering (-f), output path and format override (-o, -F), animation rendering (-a, -s, -e, -t threads), and the rule that argument order matters. Not about Roblox, MCP, or bpy scripting directly.

## Claims
- c1: blender -b runs Blender without UI, so rendering needs no display and can run over a remote shell such as SSH. *(doc, high; bpy-scripting-headless)*
- c2: Arguments are executed in order; -f or -a must be the last arguments, otherwise output/format settings after them are ignored. *(doc, high; bpy-scripting-headless)*
- c3: Command-line arguments are case sensitive: -F (format) and -f (frame) are different options. *(doc, high; bpy-scripting-headless)*
- c4: blender -b file.blend -f 10 renders only frame 10; -f -2 renders the second-last frame. *(doc, high; bpy-scripting-headless)*
- c5: blender -E help lists available render engines; -E CYCLES selects Cycles. *(doc, high; bpy-scripting-headless)*

## Numbers
- n1: **threads**: -t 2 uses two threads example animation render flag
- n2: **frame range**: -s 10 -e 500 start and end frame flags in animation example

## Techniques
- t1: **Headless batch render**: Run blender -b file.blend -o //path -F OPEN_EXR -f N, or -a for full animation, from SSH; put -f/-a last.

### Code: Render frame 10 headless
```sh
blender -b file.blend -f 10
```

### Code: Render frames 10-500 with Cycles, 2 threads
```sh
blender -b file.blend -E CYCLES -s 10 -e 500 -t 2 -a
```

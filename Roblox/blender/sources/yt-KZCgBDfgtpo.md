# yt-KZCgBDfgtpo

Personal-use research note. Brief quotes only, with attribution; see the original at the URL above.

## Summary
Victor Stepanov's 38-min Blender Python tutorial (Jan 2023) builds a bpy script that brainstorms reverse key lighting setups: it creates a camera, empty and area light rig, loops light power, empty Z rotation and camera Z, renders PNGs, and saves per-image JSON metadata that can reload a chosen setup. Nothing on Roblox, blender-mcp, or the Roblox export pipeline.

## Claims
- c1: [1:00] Tutorial's scene uses a Poly Haven floor texture and a barrel model; the light rig is generated by the script, not authored by hand. *(demo, high; other)*
- c2: [5:37] Script renders with Cycles at half resolution and low samples (about 50 or lower) to speed up brainstorm iterations. *(demo, high; claude-blender-ai)*
- c3: [4:12] Helper code tags every object it creates with a 'brainstorm' name tag and only deletes objects carrying that tag on each re-run, leaving user objects intact. *(demo, high; claude-blender-ai)*
- c4: [9:51] Image filenames embed a timestamp (hour, minute, second) and the PNG is written to a temp output folder in the home directory. *(demo, high; automation-and-creator-workflows)*
- c5: [12:48] Author rejects encoding parameters in filenames as not scalable; stores a JSON metadata file per render keyed by image name instead. *(opinion, medium; automation-and-creator-workflows)*
- c6: [19:32] Scene configurations are a list of dicts (three light-power presets) looped through apply, render and save-metadata steps. *(demo, high; claude-blender-ai)*
- c7: [22:55] Empty's Z rotation is stored in degrees in metadata and converted to radians with math before assigning to Blender rotation_euler. *(demo, high; claude-blender-ai)*
- c8: [21:23] Rotation step set to 90 for speed in demo; 30 used for the final batch; author suggests 1 to 30 degrees in practice. *(demo, medium; claude-blender-ai)*
- c9: [24:59] Camera Z location is reset to its start value for each empty rotation and stepped downward over a fixed count to vary the key-light angle. *(demo, high; claude-blender-ai)*
- c10: [33:08] Reload mode is toggled by a boolean in main; pasting an image name loads its JSON and reapplies power, rotation and camera Z to recreate that render. *(demo, high; automation-and-creator-workflows)*
- c11: [34:32] Metadata made before the camera Z field existed caused a load error; author regenerated all images and metadata to fix it. *(demo, high; automation-and-creator-workflows)*
- c12: [31:44] Missing metadata file is handled by printing an error and returning None; author notes logging module is best practice but uses print here. *(demo, medium; automation-and-creator-workflows)*
- c13: [36:09] Final version extends the configuration to light location, rotation and scale plus camera focal length. *(demo, high; claude-blender-ai)*

## Numbers
- n1: **Render samples**: 50 or lower Cycles preview at half resolution for faster brainstorm iterations
- n2: **Light power test values**: 1500 then 2500 Area light energy tweaked to get visible brightness
- n3: **Empty rotation step**: 90 deg demo; 30 deg final batch Z rotation sweep over 360 degrees

## Techniques
- t1: **Tagged object cleanup**: Name every script-created object with a shared tag string. On each run, filter scene objects by that tag and delete only those before rebuilding the rig.
- t2: **Per-render JSON metadata**: Build a dict of scene parameters, json.dumps with indent into metadata folder, file named after the render's image name without the .png extension.
- t3: **Reload setup from image name**: Paste the image name into a load flag; read the matching JSON, json.loads it, check file exists, and reapply parameters to the rig.
- t4: **Parented rig rotation sweep**: Parent camera and light to an empty; loop Z rotation in degrees, convert with math.radians, and reset camera Z to start value each sweep.

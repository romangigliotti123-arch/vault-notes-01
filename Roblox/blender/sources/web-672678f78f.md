Personal-use research note. Brief quotes only, with attribution; see the original at the URL above.

## Summary
Blender Python API gotchas page on bpy.ops operators. Operators take no data arguments (they use context), return only success/cancel status, and poll() failures give generic errors. Advises finding the needed context by reading the poll source, and notes some operators only run from specific editors or contexts. Generic bpy scripting; no Roblox content.

## Claims
- c1: bpy.ops operators cannot take object/mesh/material data as arguments; they act on the current context instead. *(doc, high; bpy-scripting-headless)*
- c2: Calling an operator returns only success or cancelled status, not the operation's result. *(doc, high; bpy-scripting-headless)*
- c3: Operator poll() failures raise RuntimeError 'context is incorrect'; the fix is to set the right active object, selection, or area type. *(doc, high; common-mistakes-fixes)*
- c4: To find the needed context when poll fails, read the poll function source; Python operators' source is bundled with Blender. *(doc, high; bpy-scripting-headless)*
- c5: Some operators (e.g. bpy.ops.object.modifier_copy, texture.slot_move) only work from a specific editor and will not run from a plain script. *(doc, medium; bpy-scripting-headless)*
- c6: bpy.types.Context.temp_override can supply a temporary context so an operator runs from a script. *(doc, high; bpy-scripting-headless)*

## Techniques
- t1: **Context override for operators**: Wrap the bpy.ops call in bpy.context.temp_override with the needed area, object or selection, then call the operator inside that block.

### Code: Example of operator poll failure from the doc
```python
bpy.ops.object.vertex_group_add()
RuntimeError: Operator bpy.ops.object.vertex_group_add.poll() No active editable object
```

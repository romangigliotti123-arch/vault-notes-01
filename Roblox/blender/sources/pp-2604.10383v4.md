# pp-2604.10383v4

Personal-use research note. Brief quotes only, with attribution; see the original at the URL above.

## Summary
arXiv paper on tool-constrained LLM agents (Director, Scene Builder) authoring executable multi-actor scenario graphs (GEST) for a simulated 3D world. Not about Blender, Roblox, or bpy. Only loosely relevant as evidence that tool layers validated against simulator state beat prompt-only staged pipelines for LLM-driven 3D content generation.

## Claims
- c1: A staged pipeline with a flagship LLM failed: model violates rules stated verbatim in its prompt and cannot track dynamic world state. Produced 0 executable specifications in 50 attempts. *(data, medium; claude-blender-ai)*
- c2: A constraint-enforcing tool layer checks every operation against simulator state, so emitted specs are valid by construction. Agents explore world capabilities page by page. *(data, medium; claude-blender-ai)*
- c3: Using a budget model with the tool layer, 20 of 25 (80%) generated specifications executed. *(data, medium; claude-blender-ai)*
- c4: Reconstruction test: agent rebuilds scenario graph from text alone, matching the original at 0.83 F1 on events (random 0.55) and 0.77 on ordering (random 0.43). *(data, medium; other)*

## Numbers
- n1: **staged pipeline executable specs**: 0 of 50 standard staged pipeline with flagship LLM
- n2: **tool-constrained agents executable specs**: 20 of 25 (80%) budget model driving Director and Scene Builder agents
- n3: **event reconstruction F1**: 0.83 (random 0.55) events with participants
- n4: **ordering reconstruction**: 0.77 (random 0.43) ordering of events

## Techniques
- t1: **Tool-constrained agent authoring**: Give the LLM tools that validate each operation against current simulator state and let it browse capabilities page by page, instead of a one-shot staged prompt. Invalid actions are rejected, so output is valid by construction.

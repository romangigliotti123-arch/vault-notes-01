# Roblox Developer Conference 2018 - User Experience Design

[Watch](https://youtu.be/B3oqg1il2tI) | RobloxOfficial | 4,803 views | 2018-07-24

## Summary
Roblox Developer Conference 2018 UX talk by Grace Lyn (Roblox UX lead for Studio and Avatar). Covers what UX means, recent Studio updates (dark theme, social links), and cross-platform design: mobile-first layout, restrictions, thumb zones, no UI conflicts, touch targets, gamepad navigation, and visual consistency, readability, and feedback. Ends with Q&A.

## Tips
- [6:18](https://youtu.be/B3oqg1il2tI?t=378) **[[building-art-and-assets]]** Design mobile-first: start from the smallest screen (phone portrait), prioritise essential content, then scale up to tablet and desktop. Cutting down is easier than fitting a desktop layout onto a phone.
- [7:42](https://youtu.be/B3oqg1il2tI?t=462) **[[building-art-and-assets]]** Keep main actions in the thumb-zone green area; avoid red corners for critical buttons. Non-interactive stats or info can sit in the red zone.
- [7:11](https://youtu.be/B3oqg1il2tI?t=431) **[[building-art-and-assets]]** Avoid Roblox mobile UI restriction areas (top menu bar, bottom-left move, bottom-right jump) so your UI does not overlap them.
- [10:03](https://youtu.be/B3oqg1il2tI?t=603) **[[common-mistakes]]** Don't put persistent panels (e.g. a task list) where they overlap restricted areas; players then can't move or act while it's open.
- [10:43](https://youtu.be/B3oqg1il2tI?t=643) **[[common-mistakes]]** Keep button positions consistent across screens. Swapping Delete and Save between screens causes muscle-memory mis-clicks and bad surprises.
- [12:05](https://youtu.be/B3oqg1il2tI?t=725) **[[building-art-and-assets]]** Make touch buttons big enough with comfortable spacing; a cursor can hit small targets but a thumb cannot, so mis-taps are common on phones.
- [12:39](https://youtu.be/B3oqg1il2tI?t=759) **[[building-art-and-assets]]** For gamepad navigation, consider where focus starts and how far players must move; place the most-used buttons close to the starting point.
- [14:12](https://youtu.be/B3oqg1il2tI?t=852) **[[building-art-and-assets]]** Keep font sizes, spacing and colours consistent within a hierarchy. If text doesn't fit, use two lines rather than shrinking it, and account for localisation length.
- [14:53](https://youtu.be/B3oqg1il2tI?t=893) **[[building-art-and-assets]]** Keep text readable on small screens: don't shrink fonts past legibility; add a scroll bar if content doesn't fit. Check colour contrast with an online contrast checker.
- [16:18](https://youtu.be/B3oqg1il2tI?t=978) **[[playtesting-and-feedback]]** Give visual feedback for every state: enabled/disabled, pressed, hover on desktop, current selection on console, win/lose and loading states.
- [17:51](https://youtu.be/B3oqg1il2tI?t=1071) **[[playtesting-and-feedback]]** Playtest, iterate, and test on real devices; screen emulation in Studio is approximate. It's fine if you don't get everything right the first time.
- [24:16](https://youtu.be/B3oqg1il2tI?t=1456) **[[playtesting-and-feedback]]** Use the iPhone 5 as the minimum test case for mobile UI; once you have an established audience, run A/B tests on UI layouts.
- [19:59](https://youtu.be/B3oqg1il2tI?t=1199) **[[building-art-and-assets]]** Keep UI consistent across phone and tablet, and similar for mobile and desktop; console can differ more because its interaction model is different.

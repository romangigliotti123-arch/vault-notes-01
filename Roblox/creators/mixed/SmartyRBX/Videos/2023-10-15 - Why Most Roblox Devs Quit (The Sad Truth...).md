# Why Most Roblox Devs Quit (The Sad Truth...)

[Watch](https://youtu.be/315hkxjTBZc) | SmartyRBX | 711,093 views | 2023-10-15

## Summary
Argues that new Roblox developers quit because they aim too big. Recommends building a minimum viable product (MVP), testing it with players, and pivoting based on feedback. Uses the creator's Jimmy games meme-game success as the example and notes Roblox's fast upload and update speed as an advantage.

## Tips
- [0:37](https://youtu.be/315hkxjTBZc?t=37) **[[common-mistakes]]** Don't start with a huge dream game as a first project; the speaker's large 'camping simulator' project with a huge map was never finished.
- [2:08](https://youtu.be/315hkxjTBZc?t=128) **[[development-process-and-speed]]** Make simple games first, earn Robux and community experience from them, then build more advanced games.
- [2:38](https://youtu.be/315hkxjTBZc?t=158) **[[development-process-and-speed]]** Build a minimum viable product: a playable, fun version with only bare-bones features (e.g. one prison and one bank, not many locations).
- [3:44](https://youtu.be/315hkxjTBZc?t=224) **[[playtesting-and-feedback]]** Release the MVP early while it is still easy to change, then pivot based on how players respond rather than sinking months into an unvalidated project.
- [4:24](https://youtu.be/315hkxjTBZc?t=264) **[[development-process-and-speed]]** Develop gradually: ship small, then iterate on the game instead of building the entire game at once.
- [4:46](https://youtu.be/315hkxjTBZc?t=286) **[[development-process-and-speed]]** Use Roblox's fast update cycle (upload in seconds, update in seconds) to test ideas with real players and iterate repeatedly.
- [5:28](https://youtu.be/315hkxjTBZc?t=328) **[[playtesting-and-feedback]]** Beta test the MVP with friends first, then improve based on what players say.

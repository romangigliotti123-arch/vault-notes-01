# MonarchSilgrit - How to make successful Roblox games

Succeed by reusing proven structures rather than chasing originality. Research charts for games that perform well but aren't huge, play them as both dev and player, and copy the core loop with a real twist. Make the title explain the experience, commit to one idea, and prototype a bare-bones version fast. Build in stages: core features first, art and lighting last. Test with non-dev accounts and a public beta, and set win criteria before spending on ads. Retention decides survival, so track day-1 returns. The creator reports that about 250 highly engaged players unlock broad recommendation. His three earlier games failed on discovery and stickiness, and his evidence is one creator's self-reported numbers.

**Style:** Candid, self-documenting indie developer who shares his own numbers and failures in near real time. Practical and numbers-heavy, with a copy-proven-loop-plus-twist philosophy. Suits solo or small teams who want a concrete, iterative process. Less useful for theory, and his venting videos contain little actionable advice.

## Playbook
1. **Scan charts for performing-but-not-huge games** [[trend-research-and-validation]]: Look at Roblox charts and the front page for games with steady visits and returning players. Avoid top hits where competition is huge. Note visible flops so you don't repeat them. Do the analysis yourself rather than relying on ChatGPT output alone.
2. **Play the target game as dev and player** [[core-loops-and-game-design]]: Note exactly what keeps you playing; that is what will drive others to play it. Define the core loop as four objectives: a satisfying core action, something worth finding, an active reward-opening step, and a reason to return. Give the loop a clear risk decision, such as cash out now or wait for a bigger payout.
3. **Copy the proven loop with a real twist and a plain title** [[game-ideas-and-genres]]: Keep the working loop but change the core concept, for example by merging two games or adding a new mechanic such as lightning that turns pets into steak. Reskins and plain clones underperform. Name the game so its experience is clear at a glance, e.g. 'Clean the Snow to Survive'.
4. **Compare alternatives, then commit** [[mindset-and-strategy]]: Compare the filtered ideas against each other and pick one. An unmade game never gets played, so you can't learn whether it works. If a prototype fails the test, repeat research with an idea as different as possible. If it's too similar, the problem is likely execution.
5. **Build a bare-bones prototype first** [[development-process-and-speed]]: Remove the baseplate and build only the core action. Test whether the idea is worth pursuing before full development. Create the place, then core features, then layer everything else on top. Keep the core idea small: one input and one decision repeated, with difficulty created through rule changes rather than speed.
6. **Stage the build with one integrating AI session** [[ai-and-tools]]: AI cannot one-shot a full game. Build core features first, then map design, models, and lighting last. Use specific iterative prompts that name the problem and target look rather than 'make it better'. Keep one main session for integration and avoid parallel sessions editing the same scripts. Compress or restart long sessions.
7. **Rebuild UI and settle one art style early** [[ui-ux-design]]: Reuse a proven UI structure from working games, then rebuild it so the game has its own identity rather than a copy-pasted free pack. Replace placeholder emojis with real art early. Pick one art style and a base colour palette at the start, since mismatched assets forced one full rebuild.
8. **Simulate progression math and test gamepass effects** [[pricing]]: Simulate the economy before launch. A free egg was hit 130 times (about $6,500 in 30 seconds), so every rebirth price was rebuilt. Estimated time to finish all 10 rebirths was about 46 minutes. Test each gamepass effect, since a crown meant for 35 degrees per second spun near 275. Show prize-wheel odds before spinning.
9. **Run a public beta and a non-dev bug pass** [[playtesting-and-feedback]]: Run a public beta with a Discord community. Testers unlocked everything in about 5 minutes, exposing weak progression pacing. Test with non-dev accounts because dev accounts are exempt from anti-cheat. Keep a folder of reported bugs and fix them in a dedicated pass.
10. **Set ad win criteria and start with a small budget** [[ads-and-sponsored-experiences]]: Before ads go live, define the criteria: beat the Robux spend, get players returning, and pay back ad spend. Paid ads brought visits but not retained players. Ad credits cost about 1,000 Robux for roughly $3.80, so small budgets buy few players. Don't expect ads alone to fix discovery.
11. **Clear the kids-audience gate** [[age-ratings-moderation-and-tos]]: If the target is kids, Roblox requires adult players who genuinely enjoy and spend before the game is cleared. The requirement was 500 adults (2026-08-18) and was reduced to 250 adults (2026-08-29). Treat 250 as current policy, and verify the rule before launch.
12. **Track day-1 returns and add reasons to return** [[retention-d1-d7]]: Track the day-1 return rate, not just installs. The creator's prior game had 1 in 400 players return the next day, against about 1 in 10 reported for top games. Give players a reason to return, such as spending earnings on bigger tools and displaying collected items on server-visible pedestals. Track creator awards alongside sales.
13. **Reach about 250 engaged players before broad discovery** [[discovery-algorithm]]: Roblox needs roughly 250 highly engaged players before showing the game broadly. The creator's weekly test reached 180 toward the gate. Organic discovery was weak, with only about 500 players finding three games over a summer. Engagement, not raw visits, is the metric to chase.
14. **Live ops: fix reported bugs and protect progress** [[updates-live-ops]]: Fix reported bugs in a dedicated pass rather than mid-feature. Add a one-button stop so players feel safe in their base. Test teleport buttons for speed or spawn false positives. If a save fails to load, retry, then kick with a 'progress is safe' message. Never create a fresh save over real data.

## Common mistakes
- Over-investing in originality when a proven loop or UI structure already works (MANBsA1MTzI, bbCmt98O9MA).
- Cloning a hit without a twist; clones usually lose to the original, as in the Fish It clone's roughly half the players (haYW1hXahOM).
- Reskinning a proven game with no new concept; six snow-cleaning clones peaked near 115,000 visits against 130 million for the leaf original (haYW1hXahOM).
- Treating ads as a fix for discovery or retention; ad spend brought visits but no returning players (LD7LGP10dRc, MANBsA1MTzI).
- Launching without simulating progression math, which let a free egg earn about $6,500 in 30 seconds (bbCmt98O9MA).
- Shipping gamepass effects untested, e.g. a 35 degrees/second spin that ran near 275 (bbCmt98O9MA).
- Vague AI prompts like 'make this better', or multiple AI sessions editing the same scripts (WA4RzzT39Dw).
- Relying on one long AI session that degrades near its context limit; compress or restart instead (WA4RzzT39Dw).
- Miscategorising an idle/RNG game as RPG instead of Simulator.
- Judging a game by visits or installs and ignoring day-1 return rate.

## Launch checklist
- [ ] Confirm the core loop has four objectives: satisfying action, something worth finding, active reward opening, reason to return.
- [ ] Play the game as a player and note what keeps you playing before shipping.
- [ ] Check the title explains the experience at a glance.
- [ ] Make the first free egg or first pickup visible on spawn, facing the player.
- [ ] Give immediate reward feedback: a +1 popup on first pickup and a first quest completed within about 7 seconds.
- [ ] Simulate the progression math, including free-currency income and rebirth prices.
- [ ] Test every gamepass effect for speed and behaviour; show prize-wheel odds before spinning.
- [ ] Test anti-cheat with non-dev accounts; teleport buttons can trigger false positives.
- [ ] Confirm the save-failure path retries, then kicks with 'progress is safe', and never overwrites data.
- [ ] Run a public beta and keep a folder of bugs for a dedicated fix pass.
- [ ] Lock one art style and base colour palette before building models.
- [ ] Set ad win criteria in advance: beat Robux spend, get returning players, pay back ad spend.
- [ ] Start with a small ad budget; ad credits cost about 1,000 Robux ≈ $3.80.
- [ ] If targeting kids, verify the current adult-player requirement (250, per 2026-08-29) before launch.
- [ ] Set up tracking for day-1 return rate, not only visits.
- [ ] Track creator awards alongside sales.
- [ ] Categorise the game correctly (idle/RNG belongs under Simulator).
- [ ] Use one main AI session for integration; don't run parallel sessions on the same scripts.

# How to STOP USING Tutorials (Roblox)

## Summary
Advice on moving beyond Roblox tutorials: expand a tutorial with small additions (sound, particles, UI), break features into tiny steps, recreate existing mechanics like speed/gravity coils, and plan with written step lists. Stresses trial and error and patience.

## Tips
- [0:00](https://youtu.be/Bgdqc4uAjtw?t=0) **[[development-process-and-speed]]** Stop relying on tutorials by taking a tutorial you followed and extending it with a small addition rather than starting from scratch.
- [0:40](https://youtu.be/Bgdqc4uAjtw?t=40) **[[development-process-and-speed]]** Break each feature into the smallest possible steps (e.g., get sound, store it in a variable, play it when checkpoint is touched).
- [0:40](https://youtu.be/Bgdqc4uAjtw?t=40) **[[combat-and-gameplay-systems]]** Start with small add-ons to a checkpoint system, such as particle effects, sounds, or a UI popup when a checkpoint is hit.
- [2:02](https://youtu.be/Bgdqc4uAjtw?t=122) **[[testing-debugging-and-qa]]** Expect many errors and trial and error; tweak tiny variations and observe what breaks to learn how scripts behave.
- [2:44](https://youtu.be/Bgdqc4uAjtw?t=164) **[[development-process-and-speed]]** Recreate existing game mechanics (e.g., speed coil, gravity coil) one-for-one to learn how they work, then build your own.
- [2:44](https://youtu.be/Bgdqc4uAjtw?t=164) **[[mindset-and-strategy]]** If stuck on how to implement something, step away for a day or two, then start building anyway and iterate.
- [3:25](https://youtu.be/Bgdqc4uAjtw?t=205) **[[development-process-and-speed]]** Write a numbered list of steps before building a feature, e.g., get models, get spawn positions, clone model, place at position.

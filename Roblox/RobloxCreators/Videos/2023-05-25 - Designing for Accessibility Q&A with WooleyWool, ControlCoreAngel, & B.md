# Designing for Accessibility Q&A with WooleyWool, ControlCoreAngel, & BitwiseAndrea

[Watch](https://youtu.be/5Ex0tW-n9_w) | RobloxCreators | 1,291 views | 2023-05-25

## Summary
Roblox panel Q&A on accessibility design. Covers highlighting red/neon parts without eye strain, focus-state UI instead of hover-only tooltips, bigger tap targets, contrast sliders over colorblind filters, bold and rich text, readability tests (blur, distance, colorblind testers), image-first design for dyslexic players, and wishlist items such as text-to-speech, captions, and voice-chat volume.

## Tips
- [0:21](https://youtu.be/5Ex0tW-n9_w?t=21) **[[building-art-and-assets]]** Highlight important objects with proximity prompts, billboard GUIs, or non-neon materials, varying color, pattern, or subtle animation, instead of intense red neon that can hurt light-sensitive players.
- [6:48](https://youtu.be/5Ex0tW-n9_w?t=408) **[[first-session-onboarding]]** Make UI buttons larger and spaced apart, especially on mobile; small, crowded buttons cause mis-taps and frustrate players with motor difficulties.
- [7:30](https://youtu.be/5Ex0tW-n9_w?t=450) **[[building-art-and-assets]]** Use UI scaling so players can enlarge all game UI without changing the world view; handles text size and readability together.
- [8:12](https://youtu.be/5Ex0tW-n9_w?t=492) **[[building-art-and-assets]]** Use bold text for readability, especially with thin fonts. Set minimum text size when using TextScaled, since longer translations like German or Spanish shrink text.
- [10:32](https://youtu.be/5Ex0tW-n9_w?t=632) **[[common-mistakes]]** Don't rely on hover-only tooltips. Show the same info on focus/select so mouse, keyboard, and controller users get it too, and make button states and actions clear.
- [11:52](https://youtu.be/5Ex0tW-n9_w?t=712) **[[building-art-and-assets]]** Use clear, recognizable icons (e.g. a house icon) so players don't have to press buttons to guess what they do.
- [13:27](https://youtu.be/5Ex0tW-n9_w?t=807) **[[playtesting-and-feedback]]** Test UI readability by stepping back from the screen (console/10-foot), removing glasses, and applying a Gaussian blur to a screenshot to check if text is still legible.
- [13:27](https://youtu.be/5Ex0tW-n9_w?t=807) **[[playtesting-and-feedback]]** Have colorblind and non-colorblind players read your UI before shipping; don't judge contrast alone.
- [14:48](https://youtu.be/5Ex0tW-n9_w?t=888) **[[building-art-and-assets]]** Offer a contrast slider rather than colorblind filters, which make games look muddy; or let players swap one specific color for another.
- [17:30](https://youtu.be/5Ex0tW-n9_w?t=1050) **[[building-art-and-assets]]** Break long text into short paragraphs with blank lines between them, and keep copy succinct to reduce overwhelm for dyslexic and ADHD players.
- [18:10](https://youtu.be/5Ex0tW-n9_w?t=1090) **[[building-art-and-assets]]** Use rich text to bold or color key terms and item names so players can spot important information quickly.
- [19:32](https://youtu.be/5Ex0tW-n9_w?t=1172) **[[core-loops-and-game-design]]** Minimize text in gameplay: use arrows, pointers, and images to guide players through tasks, and show actions rather than explaining them.
- [21:36](https://youtu.be/5Ex0tW-n9_w?t=1296) **[[building-art-and-assets]]** Use images or icons when referencing UI elements so players know what button to find; describing it in text adds reading load.

## Games
- **Split** [0:21](https://youtu.be/5Ex0tW-n9_w?t=21): Uses non-interactive proximity prompts that appear by range to convey information without intrusive visuals.
- **Holiday Frenzy** [18:50](https://youtu.be/5Ex0tW-n9_w?t=1130): Used bold for warnings and item names, rich text to highlight key terms, and in-world arrows instead of text for tutorials.
- **RoPets** [13:15](https://youtu.be/5Ex0tW-n9_w?t=795): Uses obvious icons, like a house, so players know what a button does without tooltips.

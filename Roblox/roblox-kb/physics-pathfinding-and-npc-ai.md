# Physics Pathfinding And Npc Ai

_physics and constraints, vehicles, PathfindingService, NPC behaviour, enemy AI, behaviour trees._

Evidence base: 399 extracted items from 111 videos by ArTheDev, B Ricey, BubuTheDev, ByteBlox, Crit, GnomeCode, Last Level Studios, Roblox, Roblox Creator Docs, Roblox DevForum, Roox4, SimTek Game Development, Stewiepfing, Suphi Kaner, janisjanis01 (2018-07-05 to 2026-10-28). Roblox changes quickly: check the date on each source and see Date context below.

## Overview
Creators agree that physics should be driven by constraints and forces matched to purpose: LinearVelocity for steady speed, VectorForce for controlled acceleration, and impulses or assembly velocity for one-off effects. NPCs should use PathfindingService with agent sizes matched to the rig, jump on Jump waypoints, and gate chase behind perception checks. Vehicle guidance has shifted from Cylindrical plus Spring constraint suspension (2022) toward raycast VectorForce suspension (2025) for control. The 2026 official docs add sleep thresholds, PlaneConstraint and ServoMaxForce guidance, and a rule to avoid trusting client-reported physics. Improved Animation Constraints (2026 beta) adds damping-tuning rules. Indie figures are self-reported and dated, and many NPC items are low-advice. Where they conflict with 2026 official docs, prefer the official docs.

## Rules and findings
- **Replace deprecated Body* movers with constraints** (one-creator-repeated): BodyPosition to AlignPosition (ForceLimitMode PerAxis gives per-axis limits). BodyGyro to AlignOrientation (PrimaryAxisLookAt for cameras or missiles). BodyVelocity to LinearVelocity (Line/Plane/Vector VelocityConstraintMode disables motion on chosen axes instead of zeroing MaxForce). BodyForce/BodyThrust to VectorForce (RelativeTo for offset force). RocketPropulsion to LineForce plus AlignOrientation LookAtPosition. BodyAngularVelocity to AngularVelocity, which behaves differently. Older Body* tutorials are superseded. - **Use LinearVelocity for constant speed, VectorForce for controlled force** (one-creator-repeated): LinearVelocity holds a target velocity, but MaxForce must be high enough to reach it. Sample: 5000 Rowtons to reach 15 studs/s on a lily pad. Too low and the object accelerates slowly or never arrives. Set RelativeTo World to keep world orientation; attachment-relative motion rotates after collisions. VectorForce controls the amount of force applied. For only an initial velocity, set BasePart.AssemblyLinearVelocity. - **Use one-off assembly velocity or impulses for instant effects** (one-creator-repeated): For a one-time spin, set BasePart.AssemblyAngularVelocity directly rather than adding a constraint. ApplyAngularImpulse gives an instant spin that decelerates from friction, suitable for wind gusts or event feedback (sample random Y impulse 0 to 100 Rowton-studs). - **Use AngularVelocity for constant spin and Torque for controlled torque** (one-creator-repeated): AngularVelocity applies torque to maintain a constant target spin, so use it only for constant spin. Use a Torque constraint when you need to control the torque amount. RelativeTo World uses the vector as-is; Attachment1 makes it relative to the other attachment's motion. ReactionTorqueEnabled is exposed only when RelativeTo is Attachment1. Units are rad/s: 2*pi per revolution, pi/10 = 0.314 rad/s for a slow turn (see numbers). - **Drive hinges with Motor or Servo actuators and anchor stationary bases** (one-creator-repeated): A HingeConstraint only turns from outside forces unless ActuatorType is Motor (Motor drives toward AngularVelocity, limited by MotorMaxAcceleration/MotorMaxTorque). Servo rotates to TargetAngle, controlled by AngularSpeed and ServoMaxTorque. For a spinning part on a stationary base, anchor the base. Set MotorMaxTorque to inf for player-loaded vehicles. Use only one motor per rotating assembly, not on both sides of a wheel. Propeller sample: 3 rad/s with MotorMaxTorque 1000. - **Align attachments before tuning constraints** (one-creator-repeated): Hinges pivot around the attachment's Axis (yellow arrow). Point both attachments' Axis the same direction, or the hinge rotates around the wrong axis. Also match SecondaryAxis between attachments so rotation occurs around the intended axis. Primary axis up on Y spins counterclockwise; reverse the sign for clockwise. - **Build doors with an anchored frame and hinge limits** (one-creator-repeated): Anchor the static frame but leave the door unanchored; anchored or blocked doors will not move. - **Tune springs with FreeLength, Stiffness and Damping** (one-creator-repeated): FreeLength is the natural resting length; attachments farther apart are pulled together, closer ones pushed apart. Stiffness sets force response to displacement: docs contrast 25 (soft) with 500 (stiff). Damping 0 gives endless oscillation; raise Damping above 0 to settle faster. Damping stops endless oscillation in HingeConstraint/spring setups as well. Use LimitsEnabled for travel clamps. - **Build vehicle suspension with Cylindrical plus Spring, in order** (multiple-creators): Set up attachments and constraints (hinges/springs on wheels) before writing any vehicle scripts, so physics behaviour is established first. - **Minimise constraints and control collisions per assembly** (one-creator-repeated): Use as few constraints as possible in contraptions; minimise constraints and joints per assembly for stability. Disable self-collision in ragdoll limbs with limits or no-collision constraints. NoCollisionConstraint disables collision between two specific parts (e.g. wheel and body) and affects only those two; they still collide with all other world parts. Use collision groups or part-to-part filtering for assembly-wide control. Bones change visuals only, not collision shape. - **Use RigidConstraint, not WeldConstraint, for attachment joins and grabs** (one-creator-repeated): Use RigidConstraint when connecting Attachments or Bones (e.g. accessories on a character rig). - **Tune drag with explicit MaxForce, MaxTorque and Responsiveness** (one-creator-repeated): For physical drag under Physical response, do not rely on defaults. - **Scale torque with part size and mass** (one-creator-repeated): Larger parts have higher moment of inertia and need more torque for the same acceleration, so scale MaxTorque with part size. Sample: default 4,1,2 block needs MaxTorque 1000 Rowton-studs, while a 4x-size block on grass needs at least 300000 to overcome mass and grass friction. Heavier characters also need proportionally larger impulses. - **Keep adaptive physics stepping by default** (one-creator-repeated): Keep adaptive stepping (60/120/240 Hz). Fixed 240 Hz forces four steps per frame and costs significantly more. The engine assigns assemblies to one of three simulation rates. For complex mechanisms like tanks, a fixed timestep can improve stability; this is a targeted exception, not the default. Newer official guidance keeps adaptive as default. - **Derive jump height from JumpPower, check current API** (one-creator-repeated): Indie 2018 formula: JumpPower acts as initial velocity, so jump height h = JumpPower^2/(2*g) and airtime = 2*JumpPower/g; for a target height use JumpPower = sqrt(2*g*h). Example: 10-stud jump; basketball throw with t = 1 s. This predates current Humanoid jump properties, so verify against current docs before use. - **Use event-driven hitboxes and touch setup** (one-creator-repeated): Hitboxes should run only when players enter or leave an area, not via constant per-frame player detection. ## Where creators agree
- Replace or avoid heavy per-frame position setting: indie T5201 (AlignPosition for smooth dragging) agrees with official T7837 (AlignPosition replaces BodyPosition).
- Use constraints for mechanical connections: indie T5263 (set up hinges/springs before scripts) agrees with official T6987 (use hinges, ropes, welds for mechanical connections).
- Waypoints for path following: janisjanis01 T6406 (waypoints define enemy paths) agrees with official T8948 (Humanoid:Move waypoint-to-waypoint).
- Keep NPC AI minimal for cost: indie T5175 and Q896 agree with official T8181/T8267 on minimising overhead, though for different domains (AI cost vs constraint count).
- Playtest rather than trust generated bot logic: janisjanis01 T6630 and Q1055 are consistent with each other; no official source contradicts this.
- Suspension pairs a cylindrical joint with a spring: official T7891 matches the indie vehicle setup advice in T5262/T5263.
- Use PathfindingService (CreatePath and ComputeAsync) rather than raw Humanoid:MoveTo for routing around walls (GnomeCode T10650, Roblox DevForum T11382).
- Handle jumps explicitly by checking PathWaypointAction.Jump (Roblox DevForum T11383, SimTek T11551, Roblox DevForum T12746).
- Use velocity or impulses for knockback and one-off pushes rather than sustained forces (SimTek T11841, Q1227, Roblox DevForum T13914).
- Use LinearVelocity for steady speed and VectorForce for continuous acceleration (SimTek T11839, T11840; Roblox Creator Docs T15347).
- Test vehicle constraints and multi-assembly mechanisms in multiplayer (Roblox DevForum T12081, T13111).
- Add secondary attachments to most mechanical constraints; Weld and NoCollision link parts directly (Roblox Creator Docs T15238, T15239).
- Raycast to stop fast projectiles and place parts back from hit points (Roblox DevForum T11307, T10667).
- Crit and BubuTheDev both recommend a pathfinding module (Forbidden) over the raw PathfindingService API (T16124, T16220).
- Crit and BubuTheDev both tune NPC chase through config values such as shortest-distance and target offset (T16125, T16226).
- Roox4 and Crit both favour server-side control of NPC behaviour (T16204 for Look At IK, T16225 for pathfinding).

## Where creators disagree
- **Physics stepping mode**
  - Roblox Creator Docs T8266: keep adaptive stepping; fixed 240 Hz costs significantly more.
  - Roblox Creator Docs T8049: for complex mechanisms like tanks, use a fixed timestep for stability.
  - Reconciled: adaptive is default; fixed timestep is a targeted exception for stability.
- **NPC movement method**
  - Roblox DevForum T5173: TweenService for visuals moves cost to the client; tricky to implement.
  - Roblox DevForum T5843: for many non-moving NPCs, use constraints or CFrame instead of MoveTo.
  - Roblox Creator Docs T8948 (newest): Humanoid:Move waypoint-to-waypoint with Heartbeat arrival check.
  - Not a strict conflict: each covers a different tradeoff; prefer the official waypoint pattern for pathed movement.
- **Constraint attachment axis wording**
  - Roblox Creator Docs T7058: make both attachments' SecondaryAxis perpendicular to each other; the green L indicator confirms orientation.
  - Roblox Creator Docs T7892: align each attachment's Axis and SecondaryAxis to point the same direction.
  - Both are official; the wording is ambiguous. Verify with Show Constraint Details (T7787).
- **Network ownership of gameplay parts**
  - Roblox Creator Docs T7776/T7777: hand vehicle and loose-part ownership to the driver for smooth behaviour.
  - Roblox Creator Docs T7778: SetNetworkOwner(nil) for server-controlled parts, but use sparingly; overuse causes jitter.
  - Complementary, both official.
- **Pinned slow-turn value (internal inconsistency)**
  - Roblox Creator Docs N3368: pi/10 = 0.314 rad/s labelled as 1/10 revolution per second.
  - Arithmetic: 0.314 rad/s / 2π = 1/20 revolution per second, so the label is wrong. Treat the rad/s value as correct and the label as suspect.
- **Jump tuning source age**
  - Roblox DevForum T5011 (2018): JumpPower as initial velocity; formula h = JumpPower^2/(2g).
  - Not superseded by any video in this corpus, but it predates the current Humanoid API. Flagged, not contradicted.
- **Vehicle suspension approach**
  - Suphi Kaner (2022): build suspension with Cylindrical plus Spring constraints and tune stiffness, damping and free length (T11329, T11330).
  - Roblox DevForum (2025-09): use VectorForce with raycast springs for more control than SpringConstraints (T12940, T12942). Newer advice favours raycast for control; the existing Cylindrical plus Spring rule still applies to constraint-based builds.
- **Setting NPC network ownership to nil**
  - Roblox DevForum (2022-05): set the NPC PrimaryPart network owner to nil so the server controls movement (T11381).
  - Roblox Creator Docs (2026-10): ownership is usually automatic; clients can take ownership of unanchored parts, so don't rely on client physics (T14215, T14815). The existing rule to avoid SetNetworkOwner(nil) overuse stands; prefer the official guidance.
- **Rolling or steady speed control**
  - Roblox DevForum (2021-01): use a VectorForce P controller (kP times velocity error) to drive a rolling ball (T10901).
  - SimTek (2023-09) and Roblox Creator Docs (2026-10): use LinearVelocity for steady velocity; VectorForce grows speed unbounded (T11839, T15347).
- **Path recomputation frequency**
  - GnomeCode (2020-05): recompute the path on each move so NPCs take new routes (T10652).
  - Roblox Creator Docs (2026-10): reduce ComputeAsync calls and reuse paths for similar start and end points (T15625). Recompute when obstacles change, but limit calls.
- **Maximum NPC count**
  - Roblox DevForum (2021-02): 500 NPCs showed visible issues in live play (T10933).
  - Same author (2021-02): 1000 NPCs ran locally with only a performance hit (N4241). Treat as conflicting test conditions and test on target hardware.
- **Humanoid versus physics parts for NPCs**
  - Roox4 (T16265, 2025-09): avoid Humanoids for physics-driven NPCs; use simple parts with custom movement.
  - Existing file rule uses Humanoid:Move for waypoint-walking NPCs. This is a scope difference, not a direct contradiction. Choose by whether the NPC is walking or physics-driven.
- **Raw PathfindingService versus a module**
  - Crit (T16220, Q1550): the raw API is too hard; use a module such as Forbidden.
  - Existing file rules cover the raw API (ComputeAsync, Path.Status, Blocked, waypoints). Use the raw API when you need custom control; use the module for chase and barriers.
- **Knockback implementation: legacy BodyForce versus current constraint and impulse guidance**
  - GnomeCode (2020-04, T18983, N8176): applies knockback with a BodyForce on HumanoidRootPart and tuned values of -10, 1000 and 2000.
  - Existing knowledge file: replace deprecated Body* movers with constraints and use impulses for instant effects; the newer guidance wins.

## Date context (what may be outdated)
- Roblox Creator Docs items (OFFICIAL) are all dated 2026-10, the most recent source. Prefer them over indie advice on mechanics.
- Body* movers (BodyPosition, BodyGyro, BodyVelocity, BodyForce, BodyThrust, RocketPropulsion, BodyAngularVelocity) are deprecated per official docs (T7837-T7842). Older tutorials using them should be migrated.

- ControllerPartSensor advice (T6023-T6025, 2024-07) notes docs omit GroundSensor.HitFrame; check whether docs were updated since.
- janisjanis01 (2026-02, 2026-07) is the most recent indie creator; B Ricey (2021-2023) and DevForum (2018-2024) are older.

## Instructions for an agent using this file
- If code uses any Body* mover, then migrate to AlignPosition, AlignOrientation, LinearVelocity, VectorForce, LineForce or AngularVelocity per the official mapping (T7837-T7842).
- If a part must hold a constant speed, then use LinearVelocity or AngularVelocity with a MaxForce/MaxTorque high enough to reach the target (T9684, N3837). If only a one-time speed is needed, set AssemblyLinearVelocity or AssemblyAngularVelocity (T9738, T7899).
- If a hinge must turn by itself, then set ActuatorType to Motor (or Servo for a target angle), anchor the stationary base, and for player-loaded vehicles set MotorMaxTorque to inf with one motor per rotating assembly (T8177, T7785, T8179, T8180).
- If a constraint rotates about the wrong axis, then align both attachments' Axis, enable Show Constraint Details and recheck (T8519, T7787).
- If a door will not move, then check the frame is anchored and the door is not, and set limits to -90/90 using the orange axis for limits (T10015-T10018).
- If an NPC never moves, then delete its Humanoid and drive it with constraints or CFrame; keep AI as simple as possible (T5843, T5175).
- If an NPC must follow a path, then use Humanoid:Move per waypoint, handle Path.Blocked only for waypoints ahead, wait until grounded before ComputeAsync, and use finite material costs (100 or 1000) rather than math.huge (T8948-T8950, T8951, N3612).
- If a player-facing outcome or distance/LOS check is involved, then run it on the server; keep only presentation math such as wave formulas on the client (T8582, T5437).
- If generated AI logic is used, then playtest and hand-tune it before shipping (T6630, Q1055).
- If a mechanism is unstable (tank-like), then consider a fixed timestep; otherwise keep adaptive stepping (T8049, T8266).
- If building suspension, default to raycast VectorForce springs (T12940) for control; use Cylindrical plus Spring only for constraint-based builds.
- If PathfindingService returns a status other than Success, handle it explicitly and do not leave the NPC idle.
- If a waypoint Action is Jump, set humanoid.Jump = true before MoveTo.
- If an NPC should chase, first check range and line of sight; patrol alone does not detect players.
- If NPC count is high, throttle think Rate and distance-based path updates, then test at target player count.
- If a door or platform must carry players, use a physics hinge or physics platform, not a tween.
- If a platform must hold weight against gravity, set ServoMaxForce high enough (example 10000) and Restitution 0 on limits.
- If a slow assembly unexpectedly sleeps, use an actuated joint or an impulse to wake it.
- Do not use client-reported positions or physics for gameplay decisions.
- Before shipping a 2026 beta feature (ImprovedAnimationConstraint, Server Authority), verify its current status and phase.
- If an NPC walks between waypoints with Humanoid:Move, keep using the existing Humanoid rules. If it is physics-driven (enemy, drone, rolling body), use simple parts with custom movement instead.
- If an NPC must chase or navigate barriers and mazes, use a pathfinding module first. Fall back to raw PathfindingService only when custom control is needed.
- If you create a PathfindingLink handler, assign it without parentheses and return true at the end, or pathing stops.
- If you tune NPC chase, change config values after restoreDefaults, then set shortest-distance, target offset and direct-move timer explicitly.
- If you write custom suspension or spring math, add damping. Prefer native Springs on constraints when they can do the job.
- If you aim a part at a target, use IK Look At on the server rather than a client script.

- If a turret or NPC must turn toward a target, use a rate-limited turn (rotateToward with a max angle per frame) rather than instant orientation, starting near 45 degrees per second and tuning from there.
- If a task needs to know when a part or character is in water, first check current Roblox Terrain APIs for water or material queries.

# Vfx And Particles

_particle effects, beams/trails, shaders-like tricks, tweening, post-processing, polish and juice visuals._

Evidence base: 265 extracted items from 74 videos by ArTheDev, BloxxedDev, BubuTheDev, ByteBlox, DudeGuy, GnomeCode, JustDucksey, Last Level Studios, PineappleDev, Roblox Creator Docs, Roblox DevForum, Stewiepfing, TheNexusAvenger, janisjanis01, mats-dept2 (2015-04-24 to 2026-10-28). Roblox changes quickly: check the date on each source and see Date context below.

## Overview
Roblox VFX work centers on ParticleEmitters, Beams and Trails, with PointLights and Lighting/Atmosphere for mood. Creators stress low emission rates, short bursts triggered by Emit(count), and quality-scaled counts so effects hold up on weak devices. Beams and trails need correct attachments, TextureMode and FaceCamera to look right from any angle. Water, rain, wind, dust and flare recipes come with concrete numbers from the official docs. Polish and juice add tween loops, menu blur and FOV, and impact thresholds, and should come after gameplay works. Newer official docs (2026-10) override older indie guidance where they conflict. Indie figures are self-reported.

## Rules and findings
- **Fade effects out with Transparency sequences, never pop them off** (multiple-creators): Animate ParticleEmitter Transparency with a NumberSequence whose end keypoint is 1 (default is flat 0, opaque). Beam Transparency can use the same NumberSequence to fade along its length or over time. DudeGuy fades screen flashes and wind layers out with exponential-out easing. Fading is the agreed polish move. - **Keep particle Rate low and create impact with Size, Speed and Lighting instead** (one-creator-repeated): Max Rate per emitter is 400/s desktop and 100/s mobile. Default Rate is 20/s. Rate 7/s suits sparkles. Rate 40 is used to thicken smoke after Acceleration spreads it. Rate 50 is used for a burst. Visual punch should come from Size, Speed, LightEmission and Drag before raising Rate. - **Budget VFX against frame cost and test at both quality extremes** (one-creator-repeated): Particles and visual effects add to frame cost on top of geometry. Test each effect at the lowest and the highest Editor Quality Level, since appearance and cost vary by player graphics settings. Reuse one texture across areas (volcano and waterfall) to save memory on low-end devices. - **Keep particle Lifetime at or under 20 s and randomize it** (one-creator-repeated): Lifetime above 20 s is silently clamped. Use min/max ranges for Lifetime and Rotation (expand the property and set Min and Max) so repeated effects feel less repetitive. Short snappy blasts are about 0.5 s. Lingering smoke or dust is about 2 s. - **Use Acceleration for continuous force and Speed only for initial velocity** (one-creator-repeated): Speed is initial velocity. Acceleration applies force after emission. Speed 0 with negative Y acceleration gives falling drops. Changing Speed does NOT affect already-active particles. To alter live particles, use Acceleration, Drag or VelocityInheritance. - **Make particle textures grayscale with transparent edges, and tint with Color** (one-creator-repeated): Use PNG textures with transparent backgrounds and blurred edges. A ColorSequence can shift tint over the lifetime, e.g. orange to dark grey to white, or blue to yellow. ## Checklist
- [ ] Pick Beams for hazards and laser or lava lines, and ParticleEmitters for explosions, smoke and sparks.
- [ ] Name each emitter exactly as the script expects, and set Enabled false if a script will trigger it.
- [ ] Keep Rate low: max 400/s desktop, 100/s mobile. Use Size, Speed and LightEmission for impact.
- [ ] Set Lifetime in seconds, at most 20. Use about 0.5 s for flashes and about 2 s for lingering effects.
- [ ] Give every Lifetime, Rotation and Speed a min/max range to reduce repetition.
- [ ] Animate Transparency with a NumberSequence ending at 1 so particles fade out.
- [ ] Use a grayscale PNG with transparent edges and tint it with Color.
- [ ] Set LightEmission 1 and LightInfluence 0 for glowing particles, and use 0.4 to 0.5 for faint glow.
- [ ] Add PointLights in invisible parts for light; do not rely on particle brightness.
- [ ] Enable Bloom with threshold about 0.85 for glowing beams.
- [ ] Attach each Beam to two different Attachments, and use CurveSize0/1 for arcs.
- [ ] Set Width0/1 for taper (negatives clamp to 0) and TextureMode for tiling.
- [ ] Use an invisible anchored part with Touched for beam hit detection, transparency 1.
- [ ] Keep Sphere and Cylinder emitter shapes on BaseParts, not Attachments.
- [ ] Use SpreadAngle 360 for all-direction bursts and 180,180 for spheres around a part.
- [ ] Use Acceleration for continuous force and Speed for initial velocity.
- [ ] Adjust Speed only on new particles; use Acceleration, Drag or VelocityInheritance for live ones.
- [ ] Layer two emitters with different flipbook or size values to hide repetition.
- [ ] Sync bone-attached VFX each frame via PreSimulation and CollectionService.
- [ ] Render cosmetic effects in RenderStepped and be ready to undo mispredicted ones.
- [ ] Multiply per-frame projectile motion by dt.
- [ ] Test each effect at the lowest and highest Editor Quality Level.
- [ ] Reuse particle textures across areas to save memory on low-end devices.
- [ ] Playtest after each property change and keep iterating.
- [ ] Verify old DevForum patterns (Emit, LockedToPart) against current Studio before copying them.
- [ ] Before emitting bursts, read SavedQualityLevel and scale Emit counts down on low settings.
- [ ] Keep emitters disabled and call Emit(count) for one-time bursts; test counts first with the Emit() Plugin from the Creator Marketplace.
- [ ] Pair short Lifetime (0.2 to 0.6) with higher Speed (20 to 40) and Drag around 10 for explosions.
- [ ] Give every Trail two different Attachment objects.
- [ ] Set FaceCamera on Beams and Trails that disappear from some angles.
- [ ] Choose TextureMode per effect: Static for stamps and arrows, Wrap for flowing water.
- [ ] Hide helper parts with Transparency 1 rather than deleting them.
- [ ] Set ZOffset to about 2 on textures that sit on a surface.
- [ ] Check each effect's orientation and rotate on the correct axis.
- [ ] Set a PointLight Brightness and Range for real light from flares; particles and Neon do not light surroundings.
- [ ] Pair Roblox Clouds with an Atmosphere object.
- [ ] Tune Atmosphere Haze, Glare and ClockTime for sunset looks.
- [ ] Scale particle Size up when you raise Squash.
- [ ] Use Build with Assistant for starting particle values, then tune colours and NumberSequence curves by eye.
- [ ] Reuse one texture asset across several effects and vary the look with emitter settings.
- [ ] Add leaf particles near trees as a low-cost final detail.
- [ ] Use spherical point distributions for RPG spell effects; attach a trail to one point and move it through the sequence.
- [ ] Study ParticleEmitter-based VFX packs to learn how customizable effects are tuned.
- [ ] Use one shared TweenInfo for all menu tweens and tune easing style and direction for feel.
- [ ] Add polish with particle emitters and global lighting only after gameplay works.
- [ ] Expose adjustable timing values (reveal waits, TweenSpeed) as attributes or constants.
- [ ] Test effects on low-end settings as well as high.
- [ ] Before raising Rate, check whether the effect is already at the particle cap; if so, adjust Size, Speed, or Emit counts instead.
- [ ] For falling particles, set Acceleration Y negative (world axes).
- [ ] For directional emitters, keep Velocity spread at 0; for omnidirectional effects, use 180 or 360.
- [ ] When a stretched particle looks wrong on a large surface, build a small particle scaled up and compare.
- [ ] If overlapping emitters on one part flicker, change ZOffset rather than moving the emitters.
- [ ] On Humanoid.Died, fade character parts with TweenService after about a 0.25 s delay.
- [ ] For glowing surfaces, try an emissive mask with emissive strength (about 0 to 40) and emissive tint.
- [ ] For each key moment, add a visible payoff (for example thrusters on takeoff) and playtest whether it lands.
- [ ] When reconstructing legacy-era emitter setups, use the baseline defaults (Rate 20/s, Speed 5 to 10, spread 0, rotation 0) and verify them in current Studio.
- [ ] For collectibles, add a looping spin and bob tween and give the pickup a distinct color.
- [ ] For organic beam wiggle, compute offset = math.noise(os.clock() * multiplier) each frame and set CurveSize0 = offset, CurveSize1 = -offset.
- [ ] Tune the noise multiplier by playtesting; the source gives no value.
- [ ] Send a RemoteEvent from the server to trigger confetti or celebration effects, and only fire it on the matching event (e.g. a pet hatch).
- [ ] Add a texture-scrolling script to water parts to animate them.

## Where creators agree
- Roblox Creator Docs and DudeGuy both prefer fading out (Transparency sequence or exponential-out) over popping.
- Roblox Creator Docs and Roblox DevForum both use two Attachments for Beams and a curve or Bezier handle technique for arcs (CurveSize0/1).
- Roblox Creator Docs and Roblox DevForum both keep emitters off until triggered (Enabled false, or Emit on fire) and name them for scripts.
- Roblox Creator Docs and Roblox DevForum both use LockToPart or LockedToPart for single moving blasts or muzzle flashes, and leave it off for trails.
- All three creators or sources emphasize iterative playtesting of each VFX change.
- Roblox Creator Docs and DudeGuy both use short, layered, fading effects for game-feel polish.
- Keep emitter counts, rates and lifetimes low for performance (T10816, T10817, T15640).
- Trigger one-shot bursts with Emit(count) from disabled emitters (T14802, T14996, N5902).
- Use LightEmission 1 for flare or additive glow and LightInfluence near 0 for bright particles (T15165, T14630).
- Give beams and trails two distinct attachments (T14272, existing beam rule).
- Fade and shape particles over lifetime with NumberSequence and ColorSequence curves (T14805, T15166, T14629).
- Add polish after gameplay works (T15426, T14876).
- ByteBlox and JustDucksey both recommend a simple spin and bob tween on pickups so they read as collectible.

## Where creators disagree
- **Particle Speed range**
  - Roblox Creator Docs (T10296, N4046): suggested Speed 10 (slow) to 100 (fast) for explosion scale.
  - Roblox Creator Docs (T10138, N3998): sparkles use 2 to 3 studs/s; embers use 5 to 8 (N4025). Different effect scales, not a true contradiction.
- **Particle Size range**
  - Roblox Creator Docs (N3417, T10295, N4045): property accepts whole numbers 1 to 10, best results 1 to 10.
  - Roblox Creator Docs (T10141, N3999, N3378): tutorials use Size 0.3 (sparkle) and 0.6 (burst). Unclear whether fractions are valid in the Size property or only in a NumberSequence. Verify in Studio.
- **Rate versus burst density**
  - Roblox Creator Docs (T7402): keep Rate as low as possible for performance.
  - Roblox Creator Docs (T8220, N3376, N3056): Rate 50 for bursts and 40 for smoke. These are tutorial demos within the 400/s cap, not a contradiction.
- **Muzzle flash activation (older vs newer)**
  - Roblox DevForum (T5474, 2021): keep emitter disabled, call :Emit() on fire, LockedToPart on.
  - Roblox Creator Docs (T8222, 2026-10): disable Enabled so it plays when a script activates it. Compatible; Emit is the newer method call. Newer docs also favor ParticleEmitter over Fire/Smoke (T10142).
- **Creator-level disagreement**
  - No direct contradiction found between DudeGuy (T6425, T6426), Roblox DevForum (T5012, T5469, T5474), and Roblox Creator Docs items. Differences are in scope and era.
- **Very high particle Rate**
  - Roblox DevForum (T10817): avoid extremely high ParticleEmitter rates, which hurt lower-end devices notably.
  - Roblox Creator Docs (T15167, N5951): a very high Rate (50000) is fine in a very large volume to keep dust sparse-looking.
- **Partial transparency for fades**
  - Existing fade rule and Roblox Creator Docs (T14805, T15166): fade using Transparency NumberSequence curves.
  - Roblox Creator Docs, newest (T15258, 2026-10): avoid transparency values other than 0 and 1; partial transparency causes high overdraw, so use it sparingly.
- **Sine float cycle length**
  - Roblox DevForum (T11280): a full cycle takes 2*pi seconds at rate 1 per second.
  - Roblox DevForum (N4321): cycle duration about 3.14 seconds (pi). This figure is half a cycle and conflicts with T11280.
- **Tween easing direction**
  - PineappleDev (T12736): one shared Cubic Out TweenInfo for all menu tweens.
  - GnomeCode (T11483): switch EasingDirection from Out to InOut when motion looks snappy on return.
- **Menu tween duration value**
  - PineappleDev (N4851): TweenInfo duration recorded as 5 as typed, likely 0.5 s.
- **How particle colour gradients are controlled**
  - TheNexusAvenger (T15653, 2015-04): Start and End colour are the only fields that control the gradient; set both equal for a solid colour.
  - Existing knowledge file (newer, multi-keypoint sequences): colour is shaped with multi-keypoint sequences. Prefer this for current Studio.

## Date context (what may be outdated)
- Roblox Creator Docs items (2026-10) are the most recent and are the ground truth for platform mechanics: rate caps (400/s desktop, 100/s mobile), lifetime cap (20 s), and Beam rules. Prefer them on any conflict.
- Roblox DevForum items are old: 2018-09 (T5012, Beam projectile arcs) and 2021-05 (T5469, T5474). Their techniques (Beam arc, dt scaling, Emit plus LockedToPart) are still plausible, but confirm property names such as LockedToPart vs LockToPart in current Studio.
- DudeGuy (2026-03) predates the Oct 2026 official docs but has no direct conflicts with them. Its impact-frame and wind-layer advice is style guidance, not platform mechanics.
- Older advice that newer official docs supersede or sharpen: manual ParticleEmitter-free VFX and Fire/Smoke objects (now less preferred, T10142); use ParticleEmitter with Transparency sequences instead of popping (T7229, T7404).

## Instructions for an agent using this file
- If a request involves particle Rate above 100/s, then warn about the mobile cap of 100/s and suggest Size, Speed or LightEmission instead of more particles.
- If an effect needs to fade, then animate Transparency with a NumberSequence whose last keypoint is 1; do not hide it abruptly.
- If a particle must glow, then set LightEmission 1 and LightInfluence 0; if it must light the surroundings, then add a PointLight in an invisible part.
- If the user builds a Beam, then assign two distinct Attachments to Attachment0 and Attachment1 and use CurveSize0/1 for arcs.
- If a Beam must be a collision hitbox, then pair it with an invisible anchored part (Transparency 1) and use Touched.
- If a Lifetime is set above 20 s, then reduce it to 20 s or less, because larger values are silently clamped.
- If a particle effect is triggered by code, then name the emitter exactly as the script expects, set Enabled false, and call Emit or enable it on demand.
- If a trail is wanted, then leave LockToPart off; if a single blast or muzzle flash must follow one part, then enable it.
- If a visual must follow an animated skinned mesh limb, then sync it to the bone every frame (PreSimulation) instead of parenting it once.
- If the effect should look different on low- and high-end devices, then test at the lowest and highest Editor Quality Level before shipping.
- If an effect is one-shot, disable its emitter's Enabled and call Emit(count) from script.
- If you scale Emit counts, read SavedQualityLevel first and reduce counts on low settings.
- If a beam or trail vanishes from some camera angles, enable FaceCamera.
- If a flat texture z-fights with its surface, set ZOffset to about 2.
- If an effect faces the wrong way, rotate it on the correct axis rather than leaving rotation at zero.
- If you raise Squash on a particle emitter, raise Size to keep particles from thinning.
- If you need dust or ambient particles in a huge area, use a high Rate in a large volume and disable CanCollide.
- If rain should drift with wind, enable WindAffectsDrag and set Drag above 0.
- If newer Creator Docs (2026-10) conflict with older DevForum advice, follow the docs and state the conflict.
- If a figure comes from an indie source, treat it as self-reported and verify it against a test build.
- If particles look thin, check the Rate and Lifetime caps first; do not keep raising Rate.
- If particles must fall, set Acceleration Y negative; remember Acceleration uses world axes.
- If overlapping emitters on one part flicker, adjust ZOffset (render priority), not position.
- If a stretched particle looks wrong on a large surface, test a small particle scaled up instead.
- If a character dies, fade parts with TweenService on Humanoid.Died after about a 0.25 s delay.
- If a surface needs glow, prefer the emissive mask/strength/tint approach over export-twice neon, and confirm the property names in Studio.
- If a key moment feels flat, add a visible motion or VFX payoff and playtest it.
- When sources conflict, prefer the 2024 to 2026 advice over the 2015 advice and say so.
- If a pickup or collectible needs to stand out, add a looping spin and bob tween and a distinct color before adding other effects.
- If a beam needs organic motion, drive CurveSize0 and CurveSize1 from math.noise over elapsed time rather than a fixed value.
- If a game event should trigger a celebration effect, send it from the server through a RemoteEvent and play it only on that event, not on a timer or constantly.
- If a water part looks static, add a texture-scrolling script to it before tuning other effects.

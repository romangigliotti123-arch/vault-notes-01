# Master playbook: making successful Roblox games

Build small, validate demand, then ship fast. Pick a genre by its core loop, using an audience and demand you can verify. Make the first 2 minutes and D1 retention strong before you spend anything. Monetise with optional, non-blocking offers: developer products first, a few cheap passes, and no pay-to-win. Seed the algorithm with a modest ad burst only after retention is good. Then run a sustainable weekly or biweekly live-ops cadence. Home Recommended For You drives over 90% of discovery, so optimise PTR, first-play bounce, retention and co-play. Official 2026 Creator Docs override older indie advice. Indie revenue and CCU claims are self-reported and unverified. Check current docs for payouts, age gates and deprecations.

## Pipeline
1. **1. Idea & validation**: Choose a genre by its core loop and one target audience. Check demand with RoTrends, Creator Exchange, search and off-platform signals. Study growing mid-size games, not front-page giants. Write a one-sentence pitch with 1-3 USPs. Look for an underserved or poorly executed fantasy, and log your hypotheses. Read: [[game-ideas-and-genres]], [[trend-research-and-validation]], [[mindset-and-strategy]], [[common-mistakes]]
2. **2. Design & prototype**: Define the three-layer core loop. Build a barebones MVP with graybox first, one mechanic at a time. Plan the economy (sources and sinks) and accessibility. Keep the team small and outsource only your weakest skill. Use AI per feature and playtest after every prompt. Read: [[core-loops-and-game-design]], [[development-process-and-speed]], [[building-art-and-assets]], [[scripting-and-performance]], [[ai-and-tools]], [[team-and-budget]]
3. **3. Onboarding & playtest**: Get players into the core action within seconds. Teach one mechanic at a time and keep tutorials contextual or skippable. Instrument the funnel. Watch new players silently on mobile and low-end devices. Fix bugs and the biggest drop-off before launch. Read: [[first-session-onboarding]], [[playtesting-and-feedback]], [[analytics-metrics]], [[retention-d1-d7]]
4. **4. Packaging & monetisation setup**: Make the title literal, and make the icon and thumbnails show real gameplay. Add a gameplay video. Set up developer products, a starter pack, a few cheap passes and a wide price ladder. Script prices so Price Optimization can work later. Build the Discord about a month before launch. Read: [[thumbnails-icons]], [[titles-descriptions]], [[monetisation-devproducts]], [[monetisation-gamepasses]], [[monetisation-other]], [[pricing]], [[community-and-discord]]
5. **5. Launch**: Check release requirements, including the 16+ gate for new games. Soft-launch quietly and check D1 and the first-play funnel. Fix retention first. Then run a small ad burst of about $5-20/day for 7-11 days to seed data. Read: [[roblox-platform-changes]], [[ads-and-sponsored-experiences]], [[discovery-algorithm]], [[retention-d1-d7]], [[playtesting-and-feedback]]
6. **6. Growth & live ops**: Ship weekly or biweekly content on existing systems, with a major update every 2-3 months. Add co-play, invites and share links. Read the metrics by cohort and test one change at a time. Stop ads once organic RFY takes over. Refresh packaging at major updates. Read: [[updates-live-ops]], [[social-features-and-virality]], [[analytics-metrics]], [[discovery-algorithm]], [[community-and-discord]], [[thumbnails-icons]]
7. **7. Business & sustainability**: Meet DevEx eligibility, update tax info (deadline Oct 31, 2026) and keep records. Reinvest in ads and team. Diversify income. Decide between keeping and selling a game using escrow and due diligence. Protect against burnout. Read: [[business-and-payouts]], [[team-and-budget]], [[mindset-and-strategy]], [[roblox-platform-changes]]

## Decision rules
- If you can't explain the game in one sentence and name its audience, don't build it yet.
- If demand evidence is missing (no growing comparable games), validate with search, RoTrends and Creator Exchange before building.
- If you are a beginner, make 10-20 small games rather than one dream game.
- If D1 or the first-session funnel is weak, fix the core loop, onboarding and performance before ads or monetisation.
- If you are tempted to use ads to rescue a weak game, don't. Fix retention first, then run about $10/day for about 10 days.
- If organic home recommendations exceed sponsored impressions, stop ads.
- If an item is repeatable, make it a developer product. If it is a permanent perk, make it a gamepass, and keep passes to about 2-6.
- If a purchase would remove challenge, break competitive balance or gate core progress, don't sell it (official stance; pay-to-win in competitive games is an unverified counter-view).
- If you need the first purchase, offer a cheap, time-limited starter pack after the tutorial or the first milestone.
- If you pick prices, start from comparables and test live. Use Price Optimization only with scripted prices and about 60k transactions per 30 days.
- If official docs conflict with indie advice on mechanics, metrics or payouts, follow the official docs (e.g. 28-day retention, PTR plus first-play bounce, Creator Rewards).
- If a live-ops update takes more than 3 weeks, it isn't a cadence update. Make it a major update, and keep the cadence running meanwhile.
- If a tutorial test is possible, A/B test guided versus no tutorial, because sources disagree.
- If a thumbnail or title misleads, change it. Mismatches cause bounces that hurt recommendations.
- If a game has no traction after early iterations, pivot or kill it. If it is live and has an audience, don't abandon it.
- Treat indie CCU and revenue figures as unverified. Don't use them as benchmarks.

## Where the creators disagree most
- Build what you love versus what players demand; trend-following versus originality; mass appeal versus a niche audience.
- Guided tutorial versus none (Jailbreak dropped one; other Roblox talks and Tizzy found tutorials help), and mandatory versus skippable.
- Pay-to-win versus cosmetics and convenience. Roblox staff and most creators say cosmetics or convenience. Alex Builds Games says pay-to-win packs sell best in competitive games, and GameMakers favours pay-to-skip.
- Daily versus lifetime ad budget, and whether ad traffic influences the algorithm. Official sources say ads are retrieval or seed data only, not ranking signals.
- Loot boxes and RNG, and limited stock versus limited time.
- Update frequency versus meaningfulness, and cadence length.
- Client versus server hit detection and projectile handling.
- How much to rely on AI, and incremental prompting versus one master prompt.
- Cash out versus reinvest, and sell versus keep a game.
- Whether payouts and the algorithm reward engagement or something else (Deconstructor of Fun and CaberJaber claims are unverified).

## Caveats
- Indie CCU, visit, revenue and CTR figures (e.g. about 5% CTR as typical) are self-reported and unverified.
- Official Roblox Creator Docs from 2026 take precedence over older indie advice. Examples are 28-day retention windows, PTR plus first-play bounce, Creator Rewards replacing Engagement-Based Payouts, and the Ads Manager redesign.
- Roblox features roll out gradually and change fast. Recheck current docs for age gates (16+ until 500 highly engaged players), DevEx rates, tax deadlines and deprecations.
- The Oct 31, 2026 tax deadline is two days away as of today (2026-10-29). DevEx becomes royalties on Nov 1, 2026, with 24% backup withholding.
- The KB contains no evidence IDs in this input, so the playbook cites topic files only.
- Nobody knows for sure what will sell. Treat validation as reducing risk, not guaranteeing success.

## Ready-to-paste agent prompt starters
### Game ideas
```
Using KB files game-ideas-and-genres, trend-research-and-validation, core-loops-and-game-design and common-mistakes, propose 5 Roblox game ideas for [my skills/team/time]. For each give: a one-sentence pitch, target audience and Bartle type, core loop in three layers, 1-3 USPs, evidence of demand (growing comparable games, keyword saturation), the main risk, and a validation step to run in 1-2 weeks. Prefer original twists on proven designs over clones. Flag any claim that rests on unverified indie data.
```

### Ads
```
Using KB files ads-and-sponsored-experiences, discovery-algorithm, retention-d1-d7 and analytics-metrics, decide whether my game [link/metrics] is ready for ads. Check D1, D7, first-play bounce and PTR first. If it isn't ready, list the fixes. If it is, give a 2025 Ads Manager plan: objective, daily budget (about $5-20/day), duration (7-11 days or more), broad targeting, creatives to test, and a stop rule once organic RFY overtakes sponsored impressions. Note where sources disagree (daily vs lifetime budget).
```

### Monetisation
```
Using KB files monetisation-devproducts, monetisation-gamepasses, monetisation-other and pricing, design a monetisation plan for my [genre] game with [audience age]. Give a list of developer products and 2-6 passes with price ladders, a starter pack and its trigger moment, offers shown at moments of need, and an economy check on sources and sinks. Don't gate core progress or sell challenge removal. Mention RNG disclosure rules and the Price Optimization prerequisites. Mark the pay-to-win counter-view as unverified.
```

### Game creation
```
Using KB files development-process-and-speed, core-loops-and-game-design, first-session-onboarding, scripting-and-performance, building-art-and-assets and ai-and-tools, produce a build plan for [game idea]. Give an MVP scope around one core loop, a graybox-first milestone list in 1-week sprints, the first-2-minutes onboarding flow, server-validation and ProcessReceipt requirements, mobile-first UI rules, and the performance targets (60 FPS, under 16 ms CPU per frame). Prompt AI one mechanic at a time and playtest after each.
```

### Thumbnails
```
Using KB files thumbnails-icons and titles-descriptions, create a packaging brief for [game]. Give: 3-5 thumbnail concepts at 1920x1080 and an icon at 512x512, each with one focal point, high contrast, real gameplay and mobile-size legibility. Give 5 literal title options with the core fantasy, and a description with genre, objective and keywords in the first 160 characters (1000 max). Add a test plan with several active thumbnails, and say when to refresh. Avoid clickbait.
```

### Live ops
```
Using KB files updates-live-ops, retention-d1-d7, social-features-and-virality and analytics-metrics, build a 12-week live-ops calendar for [game] with [team size]. Include weekly or biweekly cadence updates on existing systems (under 3 weeks of effort each), one major update every 2-3 months, event announcements at least 3 days apart, and the KPIs to check after each release (retention, session time, payer conversion, ARPPU). Add a rollback rule and a social or co-play hook for each update. Choose a sustainable cadence for the team.
```

### Evaluating an existing game
```
Using KB files analytics-metrics, retention-d1-d7, discovery-algorithm, first-session-onboarding, common-mistakes and thumbnails-icons, audit [game link/metrics]. Compare D1, D7 and D30, PTR, first-play bounce, playtime, payer conversion and ARPPU against similar-genre benchmarks. Find the weakest metric, and slice by platform, device, source and cohort. Return a ranked list of problems with a hypothesis, one change to test, and how to verify it (Experiments, full duration, significance). Check packaging and metadata accuracy, and flag any pay-to-win or common-mistake patterns.
```

# Age Ratings Moderation And Tos

_Roblox ToS, community standards, moderation, age ratings and age checks, safety, compliance, copyright._

Evidence base: 166 extracted items from 66 videos by Cumin, Deconstructor of Fun, Izzzyzzz, Last Level Studios, Lnor Roblox, LovJak, MonarchDev, PineappleDev, Platform Aeronaut (transcript), Pwnedbloxx, RoWatcher (tracker blog), Roblox, Roblox Creator Docs, Roblox DevForum, Roblox Investor Relations, ThatGuyEvan, VuukStudios, Xaiyne (2019-08-15 to 2026-10-28). Roblox changes quickly: check the date on each source and see Date context below.

## Overview
Roblox moderation and age-rating guidance ties content maturity to the audience's verified or estimated age. Experiences must be rated honestly through the questionnaire, 16+ and 17+ publishing requires age checks and maturity labels, and prohibited themes stay out at every rating. Chat and social features are designed as if monitored and filtered, and game-owned nudges or timeouts supplement platform moderation. Newer 2025-2026 updates add: estimated age setting default maturity and feature access; Facial Age Estimation as an under-18 alternative to ID verification; a shorter questionnaire path for qualifying 16+ games; and a design-change request before enforcement when mechanics enable misuse. Reported figures (ban reduction, content-removal impact) are either expected or indie/platform-reported and should not be treated as guaranteed. Verify current Creator Hub policy before acting.

## Rules and findings
- **Filter all user-originated text before display** (one-creator-repeated): Run every incoming user-entered string through text filtering before showing it to other users. Roblox is not responsible for unfiltered text, and games that don't filter will be removed. Presets are also filtered, via Class.TextService:FilterStringAsync() before sending. Sources: [Roblox Creator Docs 2026-10](https://create.roblox.com/docs/chat/guidelines), [Roblox Creator Docs 2026-10](https://create.roblox.com/docs/ui/text-input), [Roblox Creator Docs 2026-10](https://create.roblox.com/docs/chat/preset-system-guidelines). Newest source 2026-10-28.
- **Use TextChannels and SendAsync for chat** (one-creator-repeated): Send chat messages with TextChannel:SendAsync(), which applies basic privacy and parental settings automatically. Use TextChannels rather than custom messaging so messages stay reportable for abuse and visible to moderators, which they handle automatically. Sources: [Roblox Creator Docs 2026-10](https://create.roblox.com/docs/chat/guidelines), [Roblox Creator Docs 2026-10](https://create.roblox.com/docs/chat/guidelines). Newest source 2026-10-28.
- **Check chat permissions before allowing messaging requests** (single-mention): Before allowing a messaging request, check TextChatService:CanUserChatAsync(), CanUsersChatAsync() or CanUsersDirectChatAsync(). Gate the request on the result rather than assuming permission. Sources: [Roblox Creator Docs 2026-10](https://create.roblox.com/docs/chat/guidelines). Newest source 2026-10-28.
- **Mark direct-chat channels with SetDirectChatRequester** (single-mention): Call TextChannel:SetDirectChatRequester() on every TextChannel created for direct chat so it is marked correctly for the platform's chat handling. Sources: [Roblox Creator Docs 2026-10](https://create.roblox.com/docs/chat/guidelines). Newest source 2026-10-28.
- **Age-gate dynamic or directed-conversation presets** (one-creator-repeated): Presets that enable dynamic or directed conversation require users to be age checked (Facial Age Estimation or ID verification) and of similar age to chat. Presets limited to gameplay actions, confirmations or basic reactions can be used regardless of age or age-check status. Sources: [Roblox Creator Docs 2026-10](https://create.roblox.com/docs/chat/preset-system-guidelines), [Roblox Creator Docs 2026-10](https://create.roblox.com/docs/chat/preset-system-guidelines). Newest source 2026-10-28.
- **Presets must reinforce safety features** (one-creator-repeated): Preset systems must reinforce existing Roblox safety features, not work around them. Combine this with filtering every preset before sending and with the age-check requirement for conversational presets. Sources: [Roblox Creator Docs 2026-10](https://create.roblox.com/docs/chat/preset-system-guidelines), [Roblox Creator Docs 2026-10](https://create.roblox.com/docs/chat/preset-system-guidelines), [Roblox Creator Docs 2026-10](https://create.roblox.com/docs/chat/preset-system-guidelines). Newest source 2026-10-28.

Sources: [Roblox Creator Docs 2026-10](https://create.roblox.com/docs/avatar/character-bodies), [Roblox Creator Docs 2026-10](https://create.roblox.com/docs/avatar/dynamic-heads), [Roblox Creator Docs 2026-10](https://create.roblox.com/docs/projects/group-guidelines). - **Only upload content you own or are licensed to use** (one-creator-repeated): Upload only content you own or have the owner's permission to use. Infringement violates both Roblox Terms of Use and the law. Any content you create must respect others' IP rights on and off the platform. ## Checklist
- [ ] Filter every user-entered string with Class.TextService:FilterStringAsync() before display, and filter every preset before sending.
- [ ] Send chat with TextChannel:SendAsync() and use TextChannels so messages stay reportable and visible to moderators.
- [ ] Before any messaging request, check CanUserChatAsync, CanUsersChatAsync or CanUsersDirectChatAsync.
- [ ] Call SetDirectChatRequester() on every TextChannel created for direct chat.
- [ ] Age-check users (Facial Age Estimation or ID verification) and match similar ages before enabling dynamic or directed-conversation presets.
- [ ] Keep gameplay-only, confirmation and basic-reaction presets available without an age gate.
- [ ] Confirm every avatar asset and outfit has finished moderation (AvatarAssetModerationCompleted, AvatarOutfitModerationCompleted) before use in-experience.
- [ ] Review all avatar, asset, group and game content against Community Standards and Marketplace policy before upload.
- [ ] Review the AI-training data sharing setting on Creator Hub.
- [ ] Confirm TTS text and STT audio meet Community Standards and Terms of Use.
- [ ] As group owner, review group audit logs regularly and act on harmful behavior.
- [ ] Build a moderation system that combines published messages with a DataStore blocklist.
- [ ] Report non-IP avatar violations via Report Abuse on the catalog page, a support ticket, or the DSA form for EU residents.
- [ ] Appeal revocations on the appeals page, incorrect moderation decisions with moderation staff, and IP-related removals via the IP infringement notice form.
- [ ] Upload only content you own or have permission to use.
- [ ] Expect loss of Limited per-unit fees and Robux from removed infringing items.
- [ ] Ask the rights holder (or their authorized representative) to file any takedown.
- [ ] Do not rely on archiving to avoid IP takedowns or penalties.
- [ ] Teach students reporting tools before online play.
- [ ] For motion-based mobile play or physical reference poses, set safety guidelines and a safe space.
- [ ] Check the default 16+ Build age rating before publishing to younger audiences.
- [ ] Never give out your password; report anyone who asks for it. Distrust free-Robux offers.
- [ ] For third-party app submissions, prepare a public demo under 1 minute starting signed out, pick one category, and use HTTPS URLs of 256 characters or fewer.
- [ ] Before publishing to 16+ or all-ages, complete age check and enable 2-step verification; re-verify on every publish.
- [ ] Confirm the account is at least 2 days old before 16+ publishing.
- [ ] For group games, confirm the owner meets the Plus requirement and that authorized members have 2FA.
- [ ] Before public publishing, confirm ID verification, a qualifying purchase since Jan 1, 2025, or a completed DevEx request in the 12 months ending Dec 10, 2025.
- [ ] Complete the Content & Maturity questionnaire accurately at the most mature content level; fix mismatches before evaluation.
- [ ] If targeting 17+, verify owner and filler 17+ and age-verify all collaborators 17+.
- [ ] Keep descriptions, thumbnails and videos all-ages appropriate even for 17+ experiences.
- [ ] Remove simulated gambling (virtual chips, simulated betting); keep bingo, arcade-style luck and paid random item generators only if they follow the rules.
- [ ] Strip alcohol assets labeled beer/wine/alcohol, graphic violence, severe injury and real-world events.
- [ ] Do not create UGC items that closely copy Roblox-created Limiteds.
- [ ] Keep UGC items free of sexual, political, religious, gory, violent, drug or self-harm themes; avoid excessive text.
- [ ] Remove feed-based rewards before seeking Kids or Select placement; check Creator Hub > Creations for media feed plus reward mechanics.
- [ ] Design chat assuming monitored and filtered; default under-9 chat off and 9-12 on with filtering.
- [ ] Gate cross-age chat and Trusted Friend adds behind age checks and parental approval for under-13 and under-18 users.
- [ ] Keep ban messages free of usernames, handles and direct links; brand or platform names only.
- [ ] State game rules visibly to all players and apply them consistently.
- [ ] Test whether the average player believes watching a feed is required for rewards.
- [ ] Review local regulations before launching in a new market; check current restricted regions.
- [ ] Keep moderation history in good standing to preserve directory eligibility and publishing-fee refunds.
- [ ] Before paying a publishing fee, confirm the current amount and refund terms in Creator Hub.
- [ ] Do not pay the fee for 16+ horror, fighting or hangout games; reserve it for kid-oriented games needing younger testers.
- [ ] Use Creator Hub for questionnaire appeals and moderation appeals; imported-model appeals resolve in up to 10 minutes.
- [ ] Configure automated right-to-be-forgotten processing; verify all matching player data is removed.
- [ ] Do not retain age-check or ID selfies in your own storage.
- [ ] Use the Social Links feature and experience description for off-platform links; never try to bypass moderation.
- [ ] Check the age rating of any external service you link to, since most are 13+.
- [ ] Review trailers, thumbnails, merch and promo art for age-appropriateness, not only in-game content.
- [ ] Route all in-game chat through filtered TextChannels, and do not assume guest or special-guest chat is filtered.
- [ ] Avoid suggestive emotes, poses and animations (for example twerking or 'sus' emotes).
- [ ] Screen AI-generated and user-supplied images for moderation risk before publishing.
- [ ] Keep group and account standing clean, since one flagged image led to an account and group lock.
- [ ] Decide target age and advertising scope before launch, because unlocking all ages may limit promotion.
- [ ] Review rare-item loss mechanics and Robux-spend prompts in any experience that may reach under-13 players.
- [ ] Confirm the chat eligibility rules for age-checked versus unverified users in official docs before designing chat-dependent features.
- [ ] Use official Investor Relations figures (57% global DAU age-check penetration, 90% long-term goal) rather than indie numbers in planning.

- [ ] Before publishing 16+ or all-ages, confirm the age check and 2-step verification are complete.
- [ ] If your experience has no restricted content and targets 16+ in most regions, check whether the single-question questionnaire path applies.

- [ ] Audit every feature (chat, social, purchases, user-built content) against the age groups your rating reaches via estimated age.

- [ ] Keep a record of mechanic changes and moderation actions in case a design-change request or appeal follows.

## Where creators agree
- Only one creator (Roblox Creator Docs [OFFICIAL]) is in the source set, so there is no cross-creator agreement to report.
- Within this source, the content-filtering rule is consistent across T7935, T9669 and T9147.
- Within this source, the chat-API guidance (T7937, T7938, T7939, T7940) is internally consistent: use the platform chat APIs so moderation and privacy handling apply automatically.
- Within this source, the Community Standards compliance requirement applies to assets, avatars, groups, TTS/STT audio and AI-generated content alike (T6972, T9433, T8496, T7637, T9785).
- Age checks and 2-step verification are required for publishing to older or wider audiences (official Roblox DevForum, VuukStudios).
- Sexual content, nudity, drugs/tobacco and graphic violence are prohibited at every age rating (T11746, T14377, T11744).
- Social features must assume chat is monitored and filtered, and under-13 users get restricted experiences and chat (indie and official sources agree).
- Good standing in moderation history matters for both directory eligibility and fee refunds.

## Instructions for an agent using this file
- If user-entered text will be shown to other users, then run it through Class.TextService:FilterStringAsync() first. If the game does not filter, it can be removed.
- If you build chat, then use TextChannel:SendAsync() and TextChannels, not custom messaging, so messages stay reportable and visible to moderators.
- If a messaging request is about to be sent, then check CanUserChatAsync, CanUsersChatAsync or CanUsersDirectChatAsync first and act on the result.
- If you create a TextChannel for direct chat, then call SetDirectChatRequester() on it.
- If a preset enables dynamic or directed conversation, then require Facial Age Estimation or ID verification and similar-age matching. If the preset is only gameplay actions, confirmations or basic reactions, then no age check is needed.
- If a user's avatar asset or outfit is about to be used in-experience, then wait for AvatarAssetModerationCompleted (per asset) and AvatarOutfitModerationCompleted (whole outfit).
- If a request involves an IP takedown, then only the rights holder or an authorized representative can file it. Tell third-party reporters to contact the rights holder. If an item is archived, then do not treat it as IP-safe; it can still be taken down and archiving is considered in penalties.
- If a non-IP avatar violation needs reporting, then use Report Abuse on the catalog page or a support ticket. EU residents use the DSA form.
- If a moderation or revocation decision seems wrong, then appeal: revocations via the appeals page, incorrect moderation via moderation staff, IP removals via the IP infringement notice form.
- If the target audience is classrooms or children, then keep content appropriate for all ages, teach reporting tools before online play, and remember the default Build rating is 16+. If a user asks for a password or offers free Robux, then report the request using Report Abuse and do not trust the offer.
- If publishing to 16+ or all-ages, first require age check and 2-step verification; recheck on every publish.
- If the target audience is kids, plan for the 500-adult clearance requirement and keep the safety bar unchanged.
- If a figure conflicts between sources (fee, threshold), prefer the most recent official Roblox guidance and flag the figure as needing Creator Hub verification.
- If the game has simulated gambling, remove it before any compliance check; lootboxes and paid random generators remain allowed.
- If a UGC item resembles a Roblox-created Limited, do not publish it; copying risks UGC Program removal.
- If designing chat or social features, default to monitored and filtered; off for under-9 and gated for under-13.
- If the game uses feed-style rewards, remove them before seeking Kids or Select placement.
- If an appeal is needed, use Creator Hub; imported-model appeals resolve in up to 10 minutes.
- If writing age-check or ID data handling, do not store selfies; rely on Roblox's 30-day retention and deletion.
- If a ban message is needed, use brand or platform names only, with no usernames, handles or links.
- If the user asks to advertise an external link, point them to Social Links and the description, and warn that most external services are 13+.
- If the user wants emotes or animations, flag suggestive ones (twerking, 'sus' poses) as removal risks.
- If the user adds an image, AI-generated or user-supplied, recommend a moderation screen before publishing.
- If the user builds chat, require filtered TextChannels for all players, including guests.
- If the user plans a kids-targeted launch, factor in the reduced advertising reach from age gating.
- Treat all items from this batch as indie, self-reported advice. Confirm against official Community Standards before stating them as policy.
- If planning around age-check reach, use the official 57% global DAU figure and 90% goal, and label any regional indie numbers as self-reported.
- If a design depends on chat being limited to age-checked users, verify it against official documentation before implementing.
- If the target audience includes under-13 players, review loss mechanics and Robux-spend prompts before launch.
- If citing Kids or Select catalog size, state the July 2026 date and check for a newer figure.
- If asked how under-18 creators verify, mention Facial Age Estimation as the alternative to ID verification (2026-09 DevForum), and note that the user should confirm it still applies in the Creator Hub.
- If asked about the Experience Guidelines questionnaire for a 16+ game, first check whether any restricted content exists. If none, the single-question path may apply; if any exists, require the full questionnaire at the most mature level.
- If the game has any doubt about its rating, default to the full, honest questionnaire answer at the most mature applicable level.
- Never describe the nearly 40% ban reduction as an achieved result; describe it as an expectation from a Roblox post.
- When a user reports being flagged for misuse, first check whether the flagged mechanic enables abuse (for example, player-built drawings or shapes) and recommend a design change before disputing enforcement.
- Route Highly Engaged Player threshold questions to the monetization/engagement topic instead of the moderation knowledge file.

- If the user asks about 17+ content, still require the existing 17+ owner and collaborator verification; do not assume Facial Age Estimation satisfies it without a source.
- If a player or moderator complaint mentions sexualised content, review the flagged content against Community Standards and remove or change it before enforcement escalates.

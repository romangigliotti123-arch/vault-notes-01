# 3D Modeling Rigging And Animation

_Blender and modelling for Roblox, meshes/textures, rigging, animation, avatars, import pipelines._

Evidence base: 691 extracted items from 170 videos by ArTheDev, B Ricey, BloxianCode, BloxxedDev, ByteBlox, DudeGuy, Emancyphur, JustDucksey, Last Level Studios, LovJak, MonarchDev, Roblox Creator Docs, Roblox DevForum, Rool-Studio, Roox4, SimTek Game Development, Suphi Kaner, TheNexusAvenger, XTB7, Xaiyne, bubDEV, janisjanis01 (2017-03-30 to 2026-10-28). Roblox changes quickly: check the date on each source and see Date context below.

## Overview
Roblox's 2026 official docs define a strict avatar and accessory pipeline: 15-part R15 bodies, at most 4 bone influences per vertex, layered clothing driven by WrapLayer.AutoSkin, inner and outer cages named per accessory, the Accessory Fitting Tool (AFT) for attachments, and dynamic-head validation (17 minimum FACS poses, 5 facial action tests). Animation work centers on the Animation Clip Editor (ACE) for clips and the Graph Editor for logic, with Adaptive Animation for cross-rig reuse and non-looping Action-priority clips preloaded before use. Indie sources add practical animation-editor, weapon-attachment and pet tips, but they are self-reported. Manual 2020-2022 attachment and copy-the-Animate-script advice is superseded by AFT and layered clothing.

## Rules and findings
- **Start from Roblox's official templates, not from scratch** (one-creator-repeated): Use the Rig_and_Attachments or Combined project file, the standard R15 rig template, the body cage template and the downloadable character template. They give correct bone naming, 19 attachments and cages, saving significant time and avoiding configuration errors. Don't add or remove cage vertices or UVs. - **Set FBX export scale, orientation and bones correctly** (one-creator-repeated): Use Blender 3.4+. Set Transform > Apply Scalings to FBX Unit Scale (others at 1.0), disable Add Leaf Bones, set Path Mode to Copy and enable Embed Textures. Use Forward = Z, Up = Y, enable Limit to Selected Objects. - **Clean geometry and budget triangles before export** (one-creator-repeated): Remove floating vertices, thin spikes and micro-geometry, which inflate bounding boxes and break collision and fitting. - **Textures: normal, colourspace and bit depth** (one-creator-repeated): Export normal maps as OpenGL, Tangent Space; Roblox supports no other format. - **Drive animation from code and blend parameters inside the graph** (multiple-creators): Use humanoid:LoadAnimation for hold and aim poses; animations replicate without extra RemoteEvents. Push parameters every frame with AnimationTrack:SetParameter inside RunService.Stepped. In the graph, normalise speed with math.clamp(MovementSpeed / MaxSpeed, 0, 1) before a Blend1DNode. Unsupported: math.frexp, math.noise, math.randomseed; math.modf returns only the integer part. - **Motor6D tool attachment and tool animation** (multiple-creators): Attach tool with Motor6D named HandleMotor6D: Part0 RightHand (R15) or Right Arm (R6), Part1 Handle. Sources: [BloxxedDev 2025-07 2:27](https://youtu.be/rjQtLR9w2s0?t=147), [Roblox Creator Docs 2026-10](https://create.roblox.com/docs/avatar/emotes/export). Newest source 2026-10-28.
- **Start rigs in I, A or T pose, pose cleanly, and check every angle** (one-creator-repeated): Use I-Pose, A-Pose or T-Pose before export for best Studio compatibility. Rig after design but before export, since rigging is done in the modelling tool. While posing, turn off snapping, select a part and press F to focus, hold Shift to slow the camera, and check the pose from several angles. Right-click the top white diamond and choose Reset Selected to restore a pose. Sources: [Roblox Creator Docs 2026-10](https://create.roblox.com/docs/avatar/character-bodies/specifications), [Roblox Creator Docs 2026-10](https://create.roblox.com/docs/art/modeling/rig-a-simple-mesh), [Roblox Creator Docs 2026-10](https://create.roblox.com/docs/art/modeling/rig-a-simple-mesh), [Roblox Creator Docs 2026-10](https://create.roblox.com/docs/education/build-it-play-it-island-of-move/creating-animations), [Roblox Creator Docs 2026-10](https://create.roblox.com/docs/education/build-it-play-it-island-of-move/creating-animations). Newest source 2026-10-28.
- **Keep emotes under 10 seconds** (single-mention): Xaiyne says 10 seconds is the maximum length for emotes and animations, so keep emote clips under 10 s. Trim or split longer ideas. Verify the current limit against Roblox's docs before relying on it, since this is indie-reported. Sources: [Xaiyne 2025-08 4:16](https://youtu.be/aqv5bLmqbzc?t=256), [Xaiyne 2025-08 2:12](https://youtu.be/aqv5bLmqbzc?t=132). Newest source 2025-08-08.
- **Animate parent joints before child joints** (single-mention): Rotating an upper part moves its children through the hierarchy. Keyframe upper limbs first, then add lower-body and hand keys so the motion stays natural and you avoid fixing children that were posed before their parents. Sources: [Xaiyne 2025-08 3:35](https://youtu.be/aqv5bLmqbzc?t=215). Newest source 2025-08-08.
- **Use NI Mate and Blender for Kinect mocap** (single-mention): Last Level Studios captured Kinect data through NI Mate into Blender, converted the empties to bones, cleaned the result, and exported FBX to Roblox. They report this saved about two-thirds of the animation work versus hand-keying (self-reported). Sources: [Last Level Studios 2021-12 27:34](https://youtu.be/v_TGu45AD_g?t=1654), [Last Level Studios 2021-12 27:34](https://youtu.be/v_TGu45AD_g?t=1654). Newest source 2021-12-09.
- **Configure IK Control with the right chain, end effector and weight** (one-creator-repeated): ChainRoot is the furthest joint that moves; EndEffector is the outermost part (hand or foot) that reaches the target. Target is a CFrame source (Attachment or Part). Type Transform matches position and rotation. Weight 1 fully overrides the animation, 0 ignores it, and values between blend. Sources: [TheNexusAvenger 2022-09 4:52](https://youtu.be/C4ASAayPpkY?t=292), [TheNexusAvenger 2022-09 5:32](https://youtu.be/C4ASAayPpkY?t=332), [TheNexusAvenger 2022-09 6:22](https://youtu.be/C4ASAayPpkY?t=382). Newest source 2022-09-19.
- **Test procedural IK limbs against world-space rotation** (single-mention): TheNexusAvenger reports a known flaw: procedural IK limbs can rotate unnaturally when the character turns in world space. Test held-item arms and turning before shipping IK, and fall back to keyframed animation if the flaw shows. Sources: [TheNexusAvenger 2022-09 8:41](https://youtu.be/C4ASAayPpkY?t=521). Newest source 2022-09-19.
- **Create joints in Studio with the Rig Edit plugin** (one-creator-repeated): Roox4 rigs parts in Studio with the free Rig Edit plugin: select the parent then the child, press Create Joints, then move each joint pivot to the rotation point. Suggested starting step value is 25; lower it for more precise joint movement and tune per model. Sources: [Roox4 2024-06 0:58](https://youtu.be/DPpAsjUr278?t=58), [Roox4 2024-06 2:21](https://youtu.be/DPpAsjUr278?t=141), [Roox4 2024-06 0:58](https://youtu.be/DPpAsjUr278?t=58). Newest source 2024-06-19.
- **Set keyframe spacing to control speed and walk swing size** (one-creator-repeated): Spacing keyframes further apart slows an animation; packing them close reads as a fast smack. For walk cycles, use bigger leg and arm swings with spread-out keys, because small, stiff, fast swings look like half-walking. (LovJak, 2025-07) Sources: [LovJak 2025-07 1:32](https://youtu.be/HBKUn339Frk?t=92), [LovJak 2025-07 2:14](https://youtu.be/HBKUn339Frk?t=134). Newest source 2025-07-27.
- **Verify animation timing in-game, not only in the editor** (single-mention): LovJak found playback in-game feels different from the animation editor. After adjusting keyframes, test in-game and iterate on timing rather than trusting the editor preview. Sources: [LovJak 2025-07 1:32](https://youtu.be/HBKUn339Frk?t=92). Newest source 2025-07-27.
- **Export Blender animations with the RBLX add-on and import in Studio via a toolbox plugin** (single-mention): Rool-Studio exports from Blender with the RBLX add-on's export button, then converts in Studio with a toolbox plugin's import-from-clipboard option. Smooth R6 rigs do not work in Studio, so this route is for supported rigs only. Newest pipeline reported (2026-04). Sources: [Rool-Studio 2026-04 1:24](https://youtu.be/WI6adMt2aUY?t=84). Newest source 2026-04-11.
- **Use only R6 textures on the smooth R6 render rig** (single-mention): Rool-Studio reports R15 textures break the smooth R6 render rig. Match the texture set to the rig type and keep R6 and R15 texture sets separate. Sources: [Rool-Studio 2026-04 3:55](https://youtu.be/WI6adMt2aUY?t=235). Newest source 2026-04-11.
- **Add a camera and output folder before rendering in Blender** (single-mention): Rool-Studio notes Blender needs a camera (Shift+A) to know what to render, and an output folder set in Output Properties. Without it the render is lost. Sources: [Rool-Studio 2026-04 5:17](https://youtu.be/WI6adMt2aUY?t=317). Newest source 2026-04-11.
- **Use AI model generators if you are not a 3D modeler, then fix animation in Studio** (single-mention): LovJak reskinned mounts with an AI model generator and fixed the resulting animation bugs in Studio. Treat generated meshes as a starting point and expect to re-rig and re-test animation. Sources: [LovJak 2026-05 3:25](https://youtu.be/FpbZRgRHYjQ?t=205). Newest source 2026-05-01.
- **Name accessory parts and head attachments exactly to match the rig** (one-creator-repeated): Wrap the mesh in an Accessory, name its child part exactly 'Handle' (capital H), and add an Attachment named exactly like the rig's head attachment, e.g. FaceFrontAttachment. Mismatched names stop the accessory from aligning to the head. Sources: [SimTek Game Development 2026-08 1:57](https://youtu.be/169S0rLOMc4?t=117), [SimTek Game Development 2026-08 2:39](https://youtu.be/169S0rLOMc4?t=159). Newest source 2026-08-01.
- **Fine-tune accessory fit by editing the attachment's position, not the mesh** (single-mention): If an accessory sits wrong after fitting, adjust the Attachment's CFrame position values in Properties. Moving the attachment shifts the accessory in the opposite direction, so test small steps and check the result in-game. Sources: [SimTek Game Development 2026-08 4:02](https://youtu.be/169S0rLOMc4?t=242), [SimTek Game Development 2026-08 4:42](https://youtu.be/169S0rLOMc4?t=282). Newest source 2026-08-01.
- **Keep handle size consistent when fitting face accessories** (single-mention): One creator used a Handle X size of 1.45 for glasses as the consistent size for fitting. Keep the same handle size across fitting passes so attachment offsets stay comparable. Sources: [SimTek Game Development 2026-08 6:05](https://youtu.be/169S0rLOMc4?t=365). Newest source 2026-08-01.
- **Orient placed parts to a surface normal with CFrame.lookAlong** (single-mention): When a script places a block against a surface, build its CFrame with CFrame.lookAlong(position, normal). The normal is a direction, not a point, so lookAt(target) is the wrong call. Self-reported indie tip; not verified against official docs. Sources: [B Ricey 2024-01 14:33](https://youtu.be/92acKqS_Jo0?t=873). Newest source 2024-01-20.
- **Expect several textures per exported hat and pick the highest one** (single-mention): One indie creator reported that exporting a hat produced four textures and advised using the highest-resolution one. This is a single self-reported 2020 observation. Check the actual texture count in your own export before relying on it. Sources: [BloxianCode 2020-11 0:00](https://youtu.be/vP_d8TWny3g?t=0). Newest source 2020-11-17.
- **Configure pets with primary parts that connect the mesh** (single-mention): For pet models, set a primary part so the mesh is connected and positioned predictably. The source gives no numbers or exact steps, so verify the primary part and mesh connection in Studio before publishing. Sources: [janisjanis01 2024-11 17:11](https://youtu.be/yxd5GMEjtDA?t=1031). Newest source 2024-11-03.
- **Reuse one icon and config template across pets** (single-mention): Build a single icon and configuration template and copy it for each new pet instead of setting up each pet from scratch. The creator says this cuts per-pet setup time; no quantified savings are given. Sources: [janisjanis01 2024-11 17:11](https://youtu.be/yxd5GMEjtDA?t=1031). Newest source 2024-11-03.
- **Start seasonal items from an existing Blender asset** (single-mention): For new seasonal items, open an existing asset in Blender and modify it rather than modelling from zero. This is adjacent to the official-templates rule: it reuses your own prior work rather than a Roblox template. Sources: [janisjanis01 2024-12 0:53](https://youtu.be/HGobKizBHqQ?t=53). Newest source 2024-12-15.

## Checklist
- [ ] Start from the official R15 Rig_and_Attachments or Combined template and the body cage template.
- [ ] Confirm 15 body-part meshes, 19 attachments and one cage per body part before skinning.
- [ ] Apply all transforms, set mesh transform 0 / scale 1 and joints scale 1,1,1 with rotation 0,0,0.
- [ ] Set Blender Transform > Apply Scalings to FBX Unit Scale, uncheck Add Leaf Bones, Path Mode Copy, Embed Textures.
- [ ] Enable Bake Animation only for animated exports; set NLA Strips, All Actions, Force Start/End Keyframes off and Simplify 0.0.
- [ ] For Maya: Smooth Mesh, Units Automatic, Up Axis Y; enable Animation only for animations.
- [ ] Limit each vertex to 4 influences; skip Root and HumanoidRootNode; enable Auto Normalize.
- [ ] Parent with Automatic Weights (armature last), then paint manually for moving parts; select armature then mesh before Weight Paint.
- [ ] Test in Pose mode with R, Alt+R and Clear User Transforms; play walk, run, idle from several angles.
- [ ] Check body triangles against 10,742 total and per-part caps; leave headroom for Avatar Setup.
- [ ] Export normal maps OpenGL Tangent Space; albedo/normal RGB 24-bit; masks 8-bit grayscale; UVs in 0:1.
- [ ] Set normal map colourspace to NonColor after swapping textures.
- [ ] Set every MeshPart Transparency to 0 and one matching AvatarPartScaleType per upload.
- [ ] Remove custom attributes, extra helper head bones and non-character objects before upload.
- [ ] For dynamic heads: neutral on frame 0, one FACS pose per frame, at least 17 poses, under 50 face joints.
- [ ] Keep correctives to 3 or fewer base poses and 3 or fewer control names.
- [ ] Name inner/outer cages to exactly match the mesh name; never delete cage vertices.
- [ ] Fit accessories in the Accessory Fitting Tool and check across several bodies and animations before generating.
- [ ] Build animation key poses first (neutral, anticipation, extreme, return), then add in-betweens and easing.
- [ ] Duplicate the first pose to the last frame for loops; rename final keyframe to 'End' only to replace defaults.
- [ ] Publish animations before referencing; move KeyframeSequence/CurveAnimation to ReplicatedStorage for client access.
- [ ] Use CurveAnimation for emotes on an R15 rig.
- [ ] Set Motor6D Transform changes in PreSimulation and AssemblyRootPart for custom rigs.
- [ ] Re-export animations after every change; the in-game version only updates on export.
- [ ] Check the model against Roblox specs before publishing.
- [ ] Start from Roblox's official templates and reference cages, and use Classic, Rthro Normal or Rthro Slender mannequins for proportions.
- [ ] Name the 15 body meshes per convention (e.g. LeftUpperArm_Geo) and cap every limb so each part is watertight.
- [ ] Set the pose to I, A or T before export, and export joint scale [1,1,1] with zeroed mesh transforms.
- [ ] Cap skin influences at 4 bones per vertex, never weight Root or HumanoidRootNode, and set LowerTorso and Root to 0,0,0.
- [ ] Turn on Auto Normalize and paint at brush strength 1 for neck, wrist and elbow, and about 0.25 for shoulder and torso.
- [ ] Test each bone with R-rotation and Pose mode across several poses before exporting.
- [ ] For Blender FBX: Apply Scalings to FBX Unit Scale, Path Mode Copy, Embed Textures, Add Leaf Bones off, Animation Simplify 0.0.
- [ ] For eyelashes and eyebrows: RBX_Leader/RBX_Follower at 1.0 weight, Custom Properties and Only Deform Bones on, Maya Skins on.
- [ ] For layered accessories: name cages _InnerCage and _OuterCage, keep outer cages just outside the mesh, and never delete cage vertices.
- [ ] Test layered accessories in the AFT preview on sample characters before generating; use Cage Brush only for minor fixes.
- [ ] Import rigid accessories as a Model and convert with AFT; do not import third-party attachment objects.
- [ ] For head accessories, place attachments on the visible head surface; for grips, orient 90,0,0 in I-Pose.
- [ ] For dynamic heads: outer cage with left eye, right eye and mouth landmarks; 17+ FACS poses; pass all five facial tests.
- [ ] For glTF imports: disable Guess Original Bind Pose, rotate 180 on Z, remove vertex colours, set animation start to 0, save textures before FBX.
- [ ] Replace MeshPart.TextureId with SurfaceAppearance; set AlphaMode to Transparency where trim maps have alpha.
- [ ] Wire normal maps through a Normal Map node (Blender) or Tangent Space Normals on Bump 2d (Maya).
- [ ] Set Marketplace MeshParts to Transparency 0, Material Plastic, VertexColor 1,1,1.
- [ ] For Marketplace avatars use the Platform Avatar preset and set each mesh Type correctly.
- [ ] Set animation timeline Start and End to cover all keyframes before export.
- [ ] For loops: copy the 0:00 start pose, paste at the end time, then turn on Loop to preview.
- [ ] Set combat and ability clips to non-looping Action priority, preload them, and note the strike timestamp for the hitbox.
- [ ] Test graphs with AJU enabled; keep clips in ACE and use the Graph Editor only for logic.
- [ ] Verify animations in-game before polishing, including direction and timing; cycle common facial animations in Studio.
- [ ] Give every pet at least a basic animation; triage complex rigs with simple rules such as legs-or-wings.
- [ ] Check that a head-only Avatar Setup includes the body; delete FaceControls before rerunning setup.
- [ ] Keep emote and animation clips under 10 seconds.
- [ ] Keyframe upper limbs first, then child joints.
- [ ] Make the last keyframe match the first for loops (already in existing rules; reinforced by Xaiyne).
- [ ] Set animation type to Curve before upload (reinforces existing rule).
- [ ] For IK Control: set ChainRoot to the furthest moving joint and EndEffector to the outermost reaching part.
- [ ] Set IK Control Target to an Attachment or Part and Type to Transform for position plus rotation.
- [ ] Test IK limbs when the character turns in world space and with held items.
- [ ] In Rig Edit, select parent then child, press Create Joints, and move pivots to the rotation point.
- [ ] Start Rig Edit step value at 25 and lower it for finer joint control.
- [ ] Space keyframes apart to slow motion; avoid packing them tightly.
- [ ] Use larger leg and arm swings for walk cycles.
- [ ] Test every animation in-game after keyframe edits.
- [ ] Export Blender animations via the RBLX add-on and convert in Studio.
- [ ] Use only R6 textures on the smooth R6 render rig.
- [ ] Add a camera and set an output folder before rendering in Blender.
- [ ] Use R15 for emotes (matches existing rule).
- [ ] Wrap the accessory mesh in an Accessory and name its child Handle with a capital H.
- [ ] Add an Attachment named exactly as the rig's head attachment (e.g. FaceFrontAttachment).
- [ ] Copy the rig attachment name character-for-character; any mismatch breaks alignment.
- [ ] Fine-tune fit by changing the Attachment CFrame position in Properties, not by moving the mesh.
- [ ] Make small Y-offset adjustments and re-test in-game after each change.
- [ ] Keep the Handle size the same across fitting iterations.
- [ ] After exporting a hat or accessory, count the textures the export produced and select the highest-resolution one as the source texture.
- [ ] For a new pet, set the primary part so the mesh connects correctly before tuning anything else.
- [ ] Keep one icon/config template for pets and duplicate it for each new pet.
- [ ] For a new seasonal item, start from an existing Blender asset you already have and modify it.

## Where creators agree
- Animation craft principles agree across DevForum (T5034-T5043) and the official Animation Editor guidance (T8054, T8058, T8060): anticipation, pose-to-pose, exaggeration, arcs and non-linear easing.
- Avoid twinning / robotic linear motion is stated by DevForum (T5037, Q881, Q882) and the official docs (T8066 Linear looks stiff).
- Secondary/follow-through motion is recommended by DevForum (T5035) and official (T7956).
- Loop fix (duplicate first pose at end) is in official T8059, T8067, T8841.
- Export scale and bone settings (Apply Scalings to FBX Unit Scale, Add Leaf Bones off) are consistent across many official entries (T6922, T7246, T8490, T8878, T8879).
- Maximum 4 influences per vertex is consistent across official entries (T7948, T8349, N3292, N3419).
- Frame 0 neutral pose for facial rigs is consistent (T7312, T9051, T9750, T10177).
- Use LoadAnimation for hold/aim poses (T5002) agrees with replicated animation publishing (T8070, T8071).
- Tool attachment via Motor6D to RightHand/Right Arm agrees across DevForum tool posts (T5046, T5647).
- Roblox Creator Docs and indie creators agree that animation loops should copy the start pose to the end and that Loop should be checked before previewing.
- Roblox Creator Docs and indie creators agree on Action priority and non-looping clips for combat and ability animations.
- Roblox Creator Docs and indie creators agree that animation timelines must cover all keyframes and that animations should be tested in-game before polish.
- Roblox Creator Docs and the cage and attachment guidance agree that accessory cages must be outside the mesh and that fit fixes should be small.
- Xaiyne (T16241) agrees with the existing rule that emotes need R15 rather than R6.
- Xaiyne (T16244) agrees with the existing rule to match the last keyframe to the first for loops.
- Xaiyne (T16245) agrees with the existing rule that emotes need CurveAnimation.

## Where creators disagree
- **Whether skinned meshes are supported**
  - Roblox DevForum (T4927, 2017-03): skinned meshes and bones not supported; use the built-in FBX animation importer.
  - Roblox Creator Docs [OFFICIAL] (T7192, T8472, T8706, 2026-10): skinning is required for bending and layered accessories. Official wins; DevForum 2017 is outdated.
- **Blender minimum version**
  - Roblox Creator Docs (N2976, T6918, 2026-10): Blender 3.4+ required for helper shader configurations.
  - Roblox Creator Docs (N3081, N3645, N3758, 2026-10): Blender 3.0 / 3.0+ in older guides. Prefer 3.4+.
- **Emote animation data type**
  - Roblox Creator Docs (T7478, OFFICIAL): emotes need CurveAnimation, not KeyframeSequence, or errors occur.
  - Roblox Creator Docs (T10196, low-advice video): export the named KeyframeSequence or the animation fails to load. Official emote rule wins for emotes.
- **Face animation import**
  - Roblox Creator Docs (T8635, low-advice): face animations cannot be imported; create them in the Animation Editor.
  - Roblox Creator Docs (T9051, T9109, T9750): FACS poses are stored in the head model and imported with the dynamic head. These are different workflows (clip vs FACS pose set).
- **Animation sharing**
  - Roblox DevForum (T5007, 2018, indie): Roblox blocks sharing of animations; re-export to your own account.
  - Roblox Creator Docs (T8070, T8073): publish to Roblox before referencing; no official sharing ban is stated. Treat T5007 as unverified indie claim.
- **Tool weld target**
  - Roblox DevForum (T5046): Motor6D to RightHand (R15) or Right Arm (R6) for a standard tool.
  - Roblox DevForum (T5136): weld to Torso to animate the tool freely (reloads, tricks). Both valid for different goals.
- **Keyframe-step vs fps guidance**
  - Roblox DevForum (T4928, 2017): frame step 1 at 30 fps; step 2-5 can look smoother depending on animation.
  - Roblox Creator Docs (T7955, N3293, 2026-10): export at 30 FPS or higher. The step-2-5 claim is outdated.
- **Minimum rig bone count**
  - Roblox Creator Docs (N2996): minimum 16 bones (one per body part plus root).
  - Roblox Creator Docs (N3080): 15 bones required in armature. Both official; verify against the template.
- **Quads budget arithmetic**
  - Roblox Creator Docs (N3849): quads max 5495 for body.
  - Per-part quad caps (N3850-N3853) sum to 5371 (2000 + 2x624 + 2x624 + 875). Verify the official total before relying on it.
- **Bones per vertex / joint count**
  - Indie (N2340, 2021): about 4k bones, one per vertex via a rigging script.
  - Roblox Creator Docs (T7944, N2997, N3965): use as few joints as possible; 15 required, up to 37 optional. Official wins; N2340 is an outlier.
- **Maya FBX Animation toggle**
  - Roblox Creator Docs (T14437): disable Animation for mesh and accessory export.
  - Roblox Creator Docs (T15376): enable Bake Animation and Animation for avatars with dynamic heads that need animation data.
  - Not a true conflict: the setting depends on whether the asset carries animation.
- **Accessory attachment placement**
  - Roblox Creator Docs (T14799): place attachments overlapping about halfway into the mesh.
  - Roblox Creator Docs (T14370, T14799): head accessory attachments must sit on the visible head surface or they violate policy.
  - Head accessories are the exception; the halfway rule applies elsewhere.
- **Manual versus generated attachments for accessories**
  - Roblox DevForum indie (T10783): create custom attachments with the Default Move tool and set orientation to (0,0,0).
  - Roblox Creator Docs (T14900): let AFT generate attachments; do not import third-party attachment objects for rigid accessories.
  - Newer official guidance wins for accessories; the manual approach remains useful for rig body parts in Studio.
- **Automatic Weights versus Empty Weights**
  - Roblox Creator Docs (T14590, T14761): Automatic Weights for a fast first pass.
  - Roblox Creator Docs (T14761): Empty Weights only when you want full manual control.
  - Both are valid; the choice depends on how much control you need.

## Instructions for an agent using this file
- If the user asks about avatar bodies, clothing or accessories, start from Roblox's official R15 template or Rig_and_Attachments project file, then check against the Avatar character specs before publishing.
- If an FBX imports oversized, then set Apply Scalings to FBX Unit Scale; if it still imports at 1/100, set object transforms to 1.000 or switch to glTF/GLB.
- If the user cites a 2017-2022 DevForum workflow that conflicts with 2026 official docs, then follow the official 2026 docs and say which source was superseded.
- If the user animates an emote, then use an R15 rig and convert to CurveAnimation via the Curve Editor, not KeyframeSequence.
- If an animation must replace the default jump or run, then rename the final keyframe to exactly 'End' (case-sensitive) and publish first.
- If a facial rig fails validation, then check the count (at least 17 FACS poses), neutral on frame 0, one pose per frame, correctives with at most 3 base poses and 3 control names, and face joints under 50.
- If a cage fails or clothing floats or bloats, then check that the cage closely conforms and fully encloses the mesh, and that no vertices were added or deleted. If it still fails, adjust weights or skinning rather than only the mesh.
- If a skinned mesh deforms badly, then test each joint in Pose mode, cap influences at 4, and keep Root and HumanoidRootNode free of influences; expect to revisit bone positions after painting.
- If a user wants animation to look natural, then block key poses first (anticipation, extreme, return), add easing (CubicV2 or Sine/Quad), avoid linear motion, and exaggerate the key poses for game readability.
- If a looping clip jumps back, then copy the first pose to the final frame; for replicated animations, publish before referencing and move KeyframeSequence/CurveAnimation to ReplicatedStorage.
- If the user asks about accessories for a moving or animated weapon, recommend Model plus Motor6D; for static clothing or add-ons, recommend welded Accessories.
- If the user is building rigid accessories, route them through Blender FBX export then AFT; do not recommend importing third-party attachments.
- If the user is building layered clothing, require LoadCharacterLayeredClothing, cage naming, and an AutoSkin setting; state the no-gloves-or-boots limit.
- If the user asks about eyelashes or eyebrows, require RBX_Leader/RBX_Follower at 1.0 weight, EnabledOverride, and the export deform option.
- If the user is making a dynamic head, check the outer cage, three landmarks, 17 FACS poses, and the five facial tests.
- If the user is posing or looping an animation, give the copy-start-pose steps and remind them to turn on Loop before previewing.
- If the user is building combat animations, set Action priority, non-looping, and preload before first use.
- If the user asks about the animation editor, recommend ACE for clips and the Graph Editor only for logic, and test with AJU enabled.
- If sources conflict, prefer 2026 official Roblox Creator Docs over 2020-2022 indie advice and say so.
- Treat indie figures and low-advice tips as self-reported; flag them as unverified when recommending them.
- If an emote or animation is longer than 10 seconds, shorten or split it before upload.
- If a rig has a parent and child joint, keyframe the parent first, then the child.
- If you use IK Control, set ChainRoot, EndEffector, Target and Type first, then check Weight, and test world-space turning and held items.
- If you rig a model in Studio, use Rig Edit: create joints parent-first, move pivots to the rotation point, and start at step value 25.
- If a walk cycle looks like half-walking, enlarge the leg and arm swings and spread the keys.
- If animation looks fast or snappy in the editor, space keyframes further apart and re-test in-game.
- If exporting from Blender to Studio, use the RBLX add-on export and a toolbox import plugin; use R6 textures only on the smooth R6 rig.
- If rendering from Blender, add a camera and an output folder before rendering.
- If an accessory does not align to the head, first check that the Handle name and the head attachment name match the rig exactly.
- If fit is still off after AFT, adjust the Attachment CFrame position in small steps and re-test in-game.
- Treat the Y-offset range and handle size as examples from one creator, not as fixed values.
- If the task is runtime part placement by surface normal in Luau scripts, use CFrame.lookAlong(position, normal) rather than lookAt.
- If the task is about modeling, rigging, animation or import pipelines, ignore T18089; it is outside this topic's scope.
- If an accessory export yields multiple textures, use the highest-resolution one and verify the result in Studio rather than assuming a fixed texture count.
- If the task involves pets, apply the primary-part and reusable icon/config template advice (T18815) but verify the mesh connection in Studio.
- If the task involves a new seasonal item built in Blender, suggest starting from an existing project asset (T18859) while keeping the official-template rule for rigs and avatar parts.
- Do not treat single-mention indie workflow tips as platform ground truth; flag them as self-reported.

# First Session Onboarding

_first 30 seconds, tutorials, new-player experience, early conversion._

Evidence base: 511 extracted items from 289 videos by 1Coal, Alex Builds Games, AlvinBlox, ArTheDev, BloxxedDev, BrawlDev, ByteBlox, Creators on the Blox, Crusherfire, Cumin, Deconstructor of Fun, Duckable, Emancyphur, Erthlord, GDC Festival of Gaming, Generalist Programmer, GnomeCode, GosuGamers, JustDucksey, Last Level Studios, Leif, Lnor Roblox, LovJak, MonarchDev, MoseyTube, Mulch, PineappleDev, Poke, Rapstrike GFX, Raul, Roblox, Roblox Creator Docs, Roblox Creators, Roblox DevForum, RoyalDev, Seibo, SimTek Game Development, SmartyRBX, Stewiepfing, TheDankDeveloper, TheDevKing, Tizzy, Ventures, VuukStudios, janisjanis01, mats-dept2, rasdev, revolver agz, tef, waveshine (2018-07-24 to 2026-10-30). ## Overview
Creators and Roblox staff agree the first session decides retention: players judge a game within seconds to minutes. Get them into the core loop fast (about 8-30 seconds to first fun, clarity by 60-120 seconds, full loop understood in 2-5 minutes, fun within 5 minutes). Show rather than tell: use beams, arrows, trails, environment cues, icons and instant feedback instead of text. Keep tutorials short, interactive, contextual and ideally opt-in or skippable. Teach one mechanic at a time and explain why it matters. Gate complexity behind progression. Give starter items, easy early rewards and a wow moment. Remove friction (load time, lobbies, mobile UI, broken prompts). Instrument the onboarding funnel, fix the biggest drop-off first, and A/B test with Experiments. Fix onboarding before spending on ads. The main tension is whether to use a tutorial at all.

## Rules and findings
- **Get players into fun within seconds** (multiple-creators): Attention is short (about 8-10 s per rasdev; 10 s per AlvinBlox). Drop players straight into the core action. Skip long loading screens, forced customization, uncancellable cutscenes and long tutorials. Slap Battles spawns you into slapping. Aim for a win or reward in the first 30 s. - **Deliver fun and clarity within defined windows** (multiple-creators): Official docs: fun within 5 minutes or less. Tizzy: goal, progression path and curiosity loop clear in 60-120 s; frictionless first 90 s. Core loop fully understood in 2-5 minutes (VuukStudios, MoseyTube). - **Show, don't tell; avoid text-based tutorials** (multiple-creators): Players skip text. Use visual cues, immediate visible consequences, icons, animations and sound instead of text boxes. Visualize steps in 2D mapped to 3D action. Tizzy claims text tutorials are skipped by kids (unverified). - **Guide with world cues: beams, arrows, trails, landmarks** (multiple-creators): Use beams from player to goal, directional trails, arrows, bright play paths and landmarks. Trails/hints suggest rather than force so players keep agency. Persistent hints stay until step done. Place core-mechanic signs in line of sight. Hints implying interactivity (footprints) make players feel clever. - **Keep tutorials short, interactive and practice-based** (multiple-creators): Avoid long tutorials; they bore and cause bounces (a 10+ minute tutorial drew complaints). Prefer interactive practice (e.g. shooting range) where players do each mechanic, not text lists or darkened-screen click-the-arrow tutorials. Teach movement and unusual controls explicitly. - **Use contextual tutorials triggered by play, not front-loaded** (multiple-creators): Fire tutorials from backend triggers when a feature becomes relevant: entering a zone, getting an item, about two-thirds of the way to unlocking, at 1K cash teach trail purchase, taking too long on a task (timed hints). - **Explain why, not only what** (multiple-creators): Show stakes or threat before the action (cutscene of pet stolen), then teach. Study top games' tutorials. - **Do include a tutorial when mechanics are non-obvious** (multiple-creators): Many indie creators saw players leave or ask for help when dropped in cold: RoyalDev, Poke, PineappleDev, LovJak, Cumin, janisjanis01. ## Checklist
- [ ] Make the core action and goal obvious within seconds of joining
- [ ] Reach first fun/reward within ~8-30 seconds
- [ ] Ensure full core loop is understood by 2-5 minutes
- [ ] Keep join/load short; stream assets, ReplicatedFirst loading screen
- [ ] Spawn players facing the first objective
- [ ] Use beams/arrows/trails instead of text
- [ ] Keep tutorial short, interactive, skippable or opt-in
- [ ] Teach one mechanic at a time; contextual tutorials later
- [ ] Explain why the player should care
- [ ] Give starter currency/items and a low-friction first purchase
- [ ] Add immediate feedback to every action
- [ ] Show visible goals/task list on HUD
- [ ] Gate advanced UI and features behind progression
- [ ] Congratulate on tutorial end with next goal or unlock
- [ ] Instrument funnel from join to first loop completion
- [ ] Fix the biggest drop-off step first
- [ ] A/B test onboarding variants with Experiments
- [ ] Test on mobile, tablet, console and gamepad
- [ ] Playtest with non-gamers and kids without instruction
- [ ] Keep lobbies short and give something to do
- [ ] Group new players with new players
- [ ] Match first minute to thumbnail/title promise
- [ ] Don't prompt favorites/purchases too early
- [ ] Fix bugs and onboarding before running ads
- [ ] Add accessibility options (warnings, large text, repeatable tutorials)
- [ ] Track the age check as a separate step in the onboarding funnel so pre-game drop-off is not confused with in-game drop-off.
- [ ] Keep the first in-game objective and spawn fast after the age check, since the player has already spent up to about a minute on verification.
- [ ] Identify any first-session mechanic that can fail or punish the player, and show its rule in a safe context before the first penalty.
- [ ] For fail-on-miss or look-alike choices (such as fake vs. real doors), add a low-stakes practice instance or clear visual difference first.
- [ ] Check your audience's age profile and set early progression goals accordingly, since younger players convert less.
- [ ] Place the opening room so its layout teaches the first action; avoid explaining it with text.
- [ ] Add glowing story notes or other diegetic cues on interactable props that point toward the exit or objective.
- [ ] Replace large tutorial pop-ups with a short intro and a persistent on-screen input prompt.
- [ ] Remove spawn forcefield protection and check that spawns look intentional.
- [ ] For team games: set Teams AutoAssignable on, give each team a unique TeamColor, set spawn Neutral off, and enable AllowTeamChangeOnTouch.
- [ ] Test that team switching by walking over spawns works on mobile and console controls.
- [ ] If checkpoints exist, disable each one after it is touched or allow forward-only progress, then playtest backtracking.
- [ ] Show each ability's effect in the menu and in the battle UI before players spend turns or energy.
- [ ] Set a starting currency balance (e.g. 10 coins) and verify the first purchase is reachable from it.
- [ ] Add an info button that re-displays the next objective and points to it (T18619).
- [ ] Before launch, verify the next-objective pointer from spawn, after respawn, and on every target platform (T18619).
- [ ] When a progression system such as bags is unlocked at an NPC, place an in-world sign there announcing it (T18557).
- [ ] Scope the first tutorial to one complete core loop and stop there (example: buy, plant, wait, sell) (T18898).
- [ ] Playtest the tutorial with the youngest target player, a six-year-old persona; if they cannot follow it, cut steps or simplify wording (Q1961, T18883).
- [ ] Store each tutorial step as its own data module so steps can be edited or reordered independently (T18883).
- [ ] Verify every reward category shows particles and a notification on drop, not only the most common one (T18819).

## Where creators agree
- Players skip text; show visually (Roblox Creators, Creator Docs, Tizzy, RoyalDev, Cumin, Creators on the Blox)
- Get into fun fast; avoid long tutorials (rasdev, AlvinBlox, SmartyRBX, VuukStudios, Roblox Creator Docs)
- Instrument funnels and fix biggest drop-off (Roblox, Tizzy, Rapstrike GFX, Roblox Creator Docs)
- Gate complexity behind progression (Roblox Creators, Tizzy, janisjanis01)
- Give starter items/currency (Roblox 2018, Creators, Docs, VuukStudios)
- Test on mobile (Tizzy, ByteBlox, AlvinBlox, Creator Docs)
- Explain why, not only what (Tizzy, Lnor Roblox)
- GnomeCode and BloxxedDev both teach mechanics in-world through level layout and props rather than heavy pop-ups, consistent with the existing show-don't-tell and world-cue rules.
- Both GnomeCode and BloxxedDev treat the first room or first screen as the place to teach the core action, consistent with the existing 'teach only the core loop first' rule.

## Where creators disagree
- **Tutorial or no tutorial**
  - rasdev, AlvinBlox, SmartyRBX, VuukStudios (T13426): avoid tutorials, drop players into fun

  - RoyalDev, Cumin, LovJak, PineappleDev, Poke, janisjanis01: add a real tutorial
  - Roblox (T1502): teleporting straight into content beat full tutorial
- **Cutscenes in the intro**
  - Tizzy (T2865): cutscene lowered bounce
  - Tizzy (T2941), GnomeCode (T12377): avoid long or unskippable cutscenes
- **Timing of first monetization**
  - Roblox DevForum 2019 (N1461): first offer 30-60 min in; TheDevKing: no one buys 30 s in
  - Newer Creator Docs (T4515, T7815, T4057) and 2018 Roblox (T42): starter pack/shop early; Tizzy (T2900): delay offers until invested

  - Roblox Creators (T3086): leave some discovery
  - VuukStudios (T13748): assume players won't figure it out; add explicit prompts

  - GnomeCode (T18188): teach mechanics in-world rather than with tutorial pop-ups; avoid explicit prompts.

## Instructions for an agent using this file
- If a player can't act within ~10-30 s of spawning, remove loading, cutscenes or tutorial steps until they can.
- If mechanics are non-obvious, build a short interactive tutorial with beams/arrows and a first goal; otherwise rely on environment cues and contextual hints.
- If no onboarding data exists, instrument funnel steps first (join, first action, first loop completion), then fix the largest drop-off.
- If you are unsure between tutorial variants, A/B test with Experiments rather than guessing.
- If text is the main instruction, replace it with icons, visuals and visible consequences; cap dialogue at 3-4 taps.
- If the game has many features, gate them behind progression and trigger contextual tutorials when relevant.
- If designing the economy, give starter currency/items and an easy first win; avoid steep early scaling.
- If UI is built, test on phone, tablet, console and gamepad emulators and avoid hover-only cues.
- If planning ads, first confirm onboarding funnel, bugs and age-rating settings.
- If the lobby is long or new players meet veterans, shorten the lobby and segment new players.
- If a player's first session starts with an age check, count that time as pre-play friction, not as part of the game's FTUE window.
- Do not claim the age check is skippable, optional, or required for all users. The source gives only the duration.
- When analysing early drop-off, check for the age-check step before attributing abandonment to the game's tutorial or first minute.
- If a mechanic can punish the player on a first attempt, telegraph it in a safe instance before the penalty applies.
- If the target audience skews young, make early progression milestones easier to reach than the default.
- Do not add a separate tutorial for mechanics already explained by the core-loop-first and contextual-tutorial rules; only telegraph hazards that are non-obvious.
- If the game has teams, configure Teams (AutoAssignable, unique TeamColor) and spawns (Neutral off, AllowTeamChangeOnTouch on) before wiring team-switching UI.
- If the game has checkpoints, make them one-way after touch, then verify in playtest that players cannot reactivate earlier ones.
- If the first room has non-obvious controls, prefer level layout and props over pop-ups; add a persistent input prompt only if the layout cannot teach it.
- If a spawn shows a forcefield or protection effect, remove it and rely on layout or spacing for safety.
- If the game has abilities or battle moves with costs, show their effects in the menu and battle UI before the player commits.
- If setting starting currency, start near 10 coins as a benchmark, then adjust so the first purchase is reachable within the first session.
- If sources conflict on pop-ups versus prompts, use a short intro with a persistent prompt, not large modal pop-ups.
- Mark items from 2021 (Emancyphur) and low-advice items (ByteBlox, BloxxedDev) for verification before applying as firm advice.
- If a progression system is unlocked at an NPC, place an in-world sign there rather than a pop-up (T18557).
- If you ship a next-objective pointer or info button, test it on every spawn point and target platform before launch (T18619).

# Titles Descriptions

_game titles, descriptions, naming, SEO/keywords on Roblox._

Evidence base: 126 extracted items from 87 videos by #7Phantom, 1Coal, Alex Builds Games, AlvinBlox, Arow, ByteBlox, Creators on the Blox, Cumin, Erthlord, GnomeCode, ItsZyonic, Last Level Studios, LovJak, MonarchDev, MonzterDEV, Raul, Roblox, Roblox Creator Docs, Roblox Creators, Roblox DevForum, RoyalDev, SmartyRBX, TheDevBacon, Tizzy, VuukStudios, Yann, bubDEV, janisjanis01, rasdev, waveshine (2018-07-24 to 2026-10-28). ## Overview
Recent (2026) creator advice pushes game titles toward plain, instantly understood 'verb the noun' names (e.g. Steal an Egg) and a roughly half-second comprehension test, favoring clarity over cleverness. One creator also recommends intriguing hook titles, and freshness brackets like [NEW] or [BETA] to signal updates, which conflicts with the existing limit on special characters. Descriptions should be short per one creator, but the existing hook and 1000-character guidance still applies. Official Roblox docs (2026-10) confirm Name and Description are discovery fields, editable after upload, checked by a Studio text filter, and that IP games should use the official IP name as the primary keyword. Indie figures are self-reported.

## Checklist
- [ ] Title states genre/fantasy literally in few words
- [ ] Title readable at ~3rd-grade level, easy to spell
- [ ] No repeated words, bloat, or monetary lead
- [ ] 0-2 emojis max in title
- [ ] Check keyword competition/visits in Creator Xchange
- [ ] Test 2+ name candidates with copies/ads
- [ ] Ask friends to pick most clickable title
- [ ] Title and thumbnail together convey core fantasy
- [ ] First sentence of description names genre and content
- [ ] First ~160 chars: title, genre, unique feature, keywords, objective
- [ ] Description under 1000 characters
- [ ] Keywords natural, no keyword lists
- [ ] No hashtags/tags in description
- [ ] No control lists in description; use tutorial
- [ ] Changelog/credits as DevForum link
- [ ] Keep update blurb short

## Instructions for an agent using this file
- If drafting a title, make it literal, genre-clear, ≤ a few words, third-grade reading level, with no repeated words or money lead.
- If a title has more than 2 emojis or special characters, remove them.
- If writing a description, put genre, unique feature, objective and primary keywords in the first ~160 characters, and keep total under 1000.
- If the description contains hashtags, control lists, long FAQs or changelogs, remove or move them to tutorial/DevForum.
- If choosing keywords, check Creator Xchange visits and competition, then test candidate names before committing.
- If the thumbnail or genre tags do not match gameplay, fix them before changing the title.
- If a trend is saturated with clones, change title and thumbnail but keep the loop.
- If the user wants to rename, warn about lost discoverability and prefer rare, deliberate renames.
- If targeting multiple markets, localize title, description and thumbnail text for top countries.
- If sources conflict on mechanics, prefer Roblox Creator Docs over indie claims.
- If a title is a generic verb-noun phrase, check top charts for near-duplicates before committing and differentiate the noun or setting.
- If the title is hard to understand in about half a second, rewrite it as plain verb-noun or objective-plus-setting, not a clever name.
- If the genre has no search-friendly terms, use a hook title only when the gameplay clearly delivers on the hook.
- If you add a freshness bracket, use one tag ([NEW] or [BETA]) and remove it when the update is stale.
- If the game is based on an IP, use the official IP name as the primary keyword and secondary keywords for characters, places and objects.
- If the title or description changes, make sure the gameplay, thumbnail and icon still match it.
- If the description is written short, still lead with the hook and cover the core loop; stay under 1000 characters.
- If a name or description is rejected by the text filter or review, fix the flagged wording before resubmitting.
- Treat single-source claims (short descriptions, hashtags, reskinning) as tests to verify, not established rules.
- If a game is being transferred to a new owner, keep the title identical and do not rename it for search reasons.
- If writing a game title, keep the existing emoji limit; use emojis only in the description, and only when they match the gameplay.
- If drafting a description, use keyword-style verb statements built from the core loop.
- If writing a short-form video caption for a game, include the exact game name.
- Treat the comparison promo tip (T13760) as low-advice; offer it as an option, not a default.
- Skip items about commission portfolios (T12794) and rewriting for brevity (T12071), since they repeat or fall outside game metadata.
- If a proposed title or description matches a common copied template in the genre, rewrite it with a distinctive angle while keeping the genre keywords.
- If the group or brand has no clear niche, pick one theme and apply it consistently to titles, descriptions and visuals before publishing.
- If the description promises a feature that only exists on an external wiki, add that information in-game or remove the claim.
- Treat single-creator, self-reported advice as a hypothesis to test, not a platform rule; verify with your own A/B tests where possible.
- If a developer is choosing or finalizing a game name, recommend a name check before committing (T17623).
- If a developer is publishing an update, suggest adding promotional text alongside the existing freshness tag (T17623).
- Do not treat promotional text as a replacement for keeping the title consistent; the title should stay unchanged across updates.
- Cite T17623 only for the name-check and promo-text points; do not extrapolate exact limits or mechanics from it.
- If the game is in a saturated genre such as space, do not rely on the genre word alone. Add a specific fantasy or setting to the title and check keyword competition before committing (Q1856, existing rule on keyword research).
- If the niche is crowded and the icon is strong, you may test a distinctive or odd but memorable name against a literal one; otherwise keep the literal default.
- If the audience (kids, teens, etc.) is undefined, define it before writing the title or marketing posts.
- Always check that a distinctive name is still readable and pairs with the icon; drop it if it confuses players.
- Treat T18696 as the newest guidance when it applies to naming with icons; keep metadata accurate.

# Building And Level Design

_map and level design, terrain, lighting, atmosphere, environment art workflow, world building._

Evidence base: 631 extracted items from 263 videos by AlvinBlox, Amora, ArTheDev, B Ricey, BloxxedDev, BubuTheDev, ByteBlox, ContextLost, Crit, Crusherfire, Cumin, Duckable, Emancyphur, Generalist Programmer, GnomeCode, ItsZyonic, JustDucksey, Last Level Studios, LovJak, Mulch, PineappleDev, Quez, RoBuilder, Roblox, Roblox Creator Docs, Roblox DevForum, Roox4, SimTek Game Development, Suphi Kaner, XTB7, janisjanis01, mats-dept2 (2016-04-04 to 2026-10-30). ## Overview
Creators agree on greybox-first building, playtesting from player eye level, and designing movement flow before visual polish. Newer official Creator Docs (2026-10) add concrete dimensions: 10-stud doorways and walls, 4-stud building snap, 5-stud greybox snap, two spawn exits, and at most three exits per combat pocket. Streaming-aware layouts use blocking geometry and winding paths. Indie notes add procedural terrain recipes (abs-noise octaves, height-threshold colouring, inverse-lerp water flattening), part-count reduction through wall shapes and templates, and route-topology tests that reject single circular loops. Official lighting values (ClockTime 17, purple ambient 156,136,176, Haze 1) give starting points. Where indie and official advice conflict, official 2026-10 guidance wins.

## Rules and findings
- **Decide design before opening Studio** (multiple-creators): Fix genre, theme, player count, art style and map shape first. Sketch the layout on paper using 1-3 basic shapes (square, rectangle, octagon) and collect a few dozen reference photos. Drawings need not be followed exactly; the exercise still speeds up building. FPS maps should be fluid with few dead ends; open-world maps need draw-in landmarks. - **Greybox before art** (multiple-creators): Block the map with basic parts and skip textures and props until the map works in code and playtests as fun. Keep greybox intent (sight lines, engagement distances) when swapping to final geometry. Expect iteration between greybox and final art. Test how long it takes to reach the main location and avoid a straight-shot path. - **Build in stages, key elements first, with a time box** (multiple-creators): Order: terrain/hills, then zones and roads (crate area, paths), then buildings, then props such as trees, flowers and set dressing last. Place starting locations and the largest features before small details. Show each terrain tool once, then cap starting-area building at about 6 minutes to avoid over-building early. - **Import terrain from heightmaps or convert parts** (multiple-creators): Heightmaps must be .jpg or .png, at most 4096x4096 px; 1 px = 4 studs, so 4096 px is roughly 16384 studs wide. Height 128 gives plus/minus 64 studs. The color map is a copy of the height map recolored with terrain materials. Convert Parts to Terrain works on blocky builds, but oversized parts can fail, so keep parts only as big as needed. - **Align terrain and builds to the 4-stud voxel grid** (one-creator-repeated): Terrain voxels are 4x4x4 studs. One heightmap pixel per 4-stud voxel means a 5x5 px area equals one 20x20 stud cell. Make height channel values divisible by the grid cell height so floor tiles sit flush with terrain. Set snap-to-grid move values consistently to avoid uneven steps. - **Build modular building tiles that connect on the grid** (one-creator-repeated): Each tile must connect to an existing tile or the ground and sit on a grid without overlap. - **Keep modular pivots consistent and snap in kit-specific steps** (one-creator-repeated): Give every piece the same pivot (forward-most lower corner or attach point) and paste the anchor's Position into each new piece before moving. - **Round and vary terrain; avoid boxy shapes** (multiple-creators): Round off terrain edges by rendering the Archimedes shape multiple times, and vary sizes. Use curves and jogs rather than boxy shapes. Smooth terrain under and around roads, since roads need ground beneath them. Vary height with hills, stairs and ramps. Match detail to viewing angle: abstract props seen from only 1 or 3 sides. - **Sculpt terrain from top-down, fill water, and set the island** (one-creator-repeated): Edit terrain in top-down view to shape map edges. Use Draw to add or subtract material and Sculpt only to grow or erode. Flatten with Flatten Plane fixed at Y=0 for a level island top; a spherical island makes players fall off. Fill water 1800,5,1800 at 0,-15,0 below the island top. Leave island centre open for spawn and first platforms; check SpawnLocation facing and cover water with an invisible hazard part. - **Pivot control for models** (one-creator-repeated): Set PrimaryPart before rotating or scaling; rotation then occurs around its pivot. Clearing PrimaryPart resets the pivot to the center of the bounding box. Deleting the PrimaryPart keeps the pivot in place. Use Reset after changing composition, and snap pivots with Edit Pivot. Bottom-center pivots let raycast hits sit on the ground without Y offsets. Custom pivots: reimport relative to an unmoved MeshPart. - **Use Realistic lighting and detect indoors with walls** (one-creator-repeated): Set LightingStyle to Realistic. Soft hides local light shadows and material detail; Realistic is required for local lights to cast shadows and specular highlights. Surround indoor spaces with Parts at least 1 stud thick (sample 2.5 studs) so outdoor light does not leak in. Set EnvironmentDiffuseScale and EnvironmentSpecularScale to 1 so PBR materials reflect surroundings. - **Limit entry points, balance routes and hide paths** (multiple-creators): Give enterable buildings about 2-3 entry points to balance attackers and defenders; keep some dead ends as risk/reward spots. Sources: [AlvinBlox 2018-12 8:11](https://youtu.be/vCpl5M_9mcQ?t=491), [AlvinBlox 2020-04 14:13](https://youtu.be/DhS5oexaE3w?t=853), [AlvinBlox 2020-04 16:56](https://youtu.be/DhS5oexaE3w?t=1016), [AlvinBlox 2018-12 8:27](https://youtu.be/vCpl5M_9mcQ?t=507). Newest source 2020-04-05.
- **Keep maps and weapons in ServerStorage, not ReplicatedStorage** (single-mention): Clients can read ReplicatedStorage, so maps and weapon templates placed there can be seen and exploited. Store them in ServerStorage and clone them to the workspace on the server. This adds a security layer beyond the existing clone-at-runtime advice. Sources: [AlvinBlox 2018-12 9:10](https://youtu.be/vCpl5M_9mcQ?t=550). Newest source 2018-12-08.
- **Design builds to the size limit from the start** (single-mention): Build for the target footprint from the beginning. GnomeCode found that scaling a full-size build down at the end looked worse than a build designed for the small space. Treat the size limit as a design input before greybox. Sources: [GnomeCode 2020-06 1:41](https://youtu.be/Z74HM6xcsBE?t=101). Newest source 2020-06-26.
- **Furnish small interiors fully and to scale** (single-mention): A fully furnished, to-scale interior makes a strong first impression when a player spawns in, even in a tiny footprint. Prioritise this for spawn-in rooms. It qualifies the general rule against non-functional props in hubs. Sources: [GnomeCode 2020-06 8:51](https://youtu.be/Z74HM6xcsBE?t=531). Newest source 2020-06-26.
- **Use semi-transparent non-colliding goal triggers** (single-mention): Place an anchored, CanCollide-off trigger behind each goal to detect scoring without blocking the ball. GnomeCode used transparency 0.5 so the trigger is visible while building. This is a different use case from fully hidden zone markers. Sources: [GnomeCode 2021-03 6:21](https://youtu.be/94MtCzTo85k?t=381), [GnomeCode 2021-03 6:21](https://youtu.be/94MtCzTo85k?t=381). Newest source 2021-03-22.

## Checklist
- [ ] Before opening Studio, write down genre, player count, art style and map shape; sketch the layout on paper with 1-3 basic shapes.
- [ ] Collect a few dozen reference photos before building.
- [ ] Greybox with basic parts; no textures or props until the map plays fun.
- [ ] Build terrain first, then zones and roads, then buildings, then props and decoration.
- [ ] Time-box the starting area (about 6 minutes per terrain tool demo).
- [ ] Import heightmaps as .jpg or .png no larger than 4096x4096 px; plan 1 px = 4 studs.
- [ ] Keep part sizes small enough to convert to Terrain; check size before converting.
- [ ] Align builds to the 4-stud voxel grid and set snap values to the kit (e.g., 4 or 7.5 studs, 45 or 90 degree rotation).
- [ ] Set one consistent pivot on every modular piece and move one mesh at a time.
- [ ] Enable StreamingEnabled first and keep each model under about 64 cubic studs.
- [ ] Set LightingStyle Realistic, make indoor walls at least 1 stud thick, and tint Ambient warm.
- [ ] Add small ColorCorrection (Contrast 0.05, Saturation 0.1) and set EnvironmentDiffuse/SpecularScale to 1.
- [ ] Use PointLight, SpotLight or SurfaceLight depending on the source shape.
- [ ] Verify lighting fixes persist across the session, not only at one ClockTime.
- [ ] Give players 2-3 entry points per building and keep some dead ends.
- [ ] Add cover, second floors and balconies so each view has something to look at.
- [ ] Use invisible walls at map edges and mark off-limits areas with coloured bricks.
- [ ] Anchor platforms and static geometry before playtest.
- [ ] Keep height steps of 30+ studs between jump tiers and check each jump from multiple angles.
- [ ] Color-code team zones and indoor/outdoor materials so players can orient themselves.
- [ ] Tag repeated parts and drive them with one script using CollectionService.
- [ ] Use folders for sections and models for sets; rename everything on creation.
- [ ] Playtest and check from several camera angles; rotate the camera during sculpting.
- [ ] Decide symmetry by game type: duplicate-and-rotate for competitive arenas, varied layouts for scenic maps.
- [ ] Use Explorer, not the viewport, to select parts.
- [ ] Greybox the map with block and wedge parts first; check traversal, vantage points and scale before art.
- [ ] Set Snap to Grid for Move to 4 studs for buildings; use 5-stud snapping with 90-degree rotation for greybox.
- [ ] Work from top view with arrow handles; keep increments on; if an object won't snap, delete and duplicate a fresh one.
- [ ] Test-mode after every stage from player eye level; press F and check the side view for floating buildings.
- [ ] Audit every room systematically for missing assets, not just the one reported.
- [ ] Clip-check the map from the player's perspective before release.
- [ ] Verify doorways are at least 10 studs wide and walls at least 10 studs tall.
- [ ] Give spawn zones two exits; cap combat pockets at three exits or fewer.
- [ ] Draw the route graph from top view and confirm more than one route exists (no single circular loop).
- [ ] Add elevation changes at key sight lines and elevated walkways in PvP maps.
- [ ] Build one half or one plot, then duplicate it for equal access.
- [ ] Sculpt with Add, Subtract, Smooth and Paint; use Ctrl+Z for mistakes.
- [ ] Break hard straight terrain edges and vary slopes with curves.
- [ ] Set plot size to a multiple of grid size; set SmartDisplay false unless grid is under 5 studs.
- [ ] Set procedural noise: abs octaves, then square; colour by height threshold.
- [ ] Flatten procedural water with inverse lerp; set Part Y size to y*2+1 for solid columns.
- [ ] Use Terrain for outdoor ground; convert blocks with Part To Terrain.
- [ ] Set collision and shadow flags (CanCollide, CanTouch, CanQuery, CastShadow) at placement time.
- [ ] Anchor welded props and floating triggers; name spawns 'spawn' and region parts after matching sounds.
- [ ] Set team spawn TeamColor and turn SpawnLocation Neutral off.
- [ ] Keep templates in ServerStorage or ReplicatedStorage and clone at runtime.
- [ ] Enable streaming with defaults; place blocking geometry along paths.
- [ ] Cut part counts with wall shapes and unions; check wireframe triangle counts.
- [ ] Batch GeometryService unions and re-parent results to the main part's parent.
- [ ] Check the map has room for the target player count before scaling past 50 users.
- [ ] Set every invisible zone part to Anchored, CanCollide false, Transparency 1, and tall enough to block escape above.
- [ ] Store zone atmosphere values as Attributes named exactly like the Atmosphere properties; tune in Lighting first.
- [ ] Keep Atmosphere Haze (0-10) and Glare (0-10) in range; Glare needs Haze and Lighting Brightness above 0.
- [ ] Plan chunk size (one creator used 1024 studs) and key chunks by x/y/z index before the map grows large.
- [ ] Use sensor parts for signal triggers instead of unioned track parts or Object Values pointing at unions.
- [ ] Delete inactive welds in models that never need to be destroyed.
- [ ] Build destructible walls from many small blocks, not one part.
- [ ] Stack parts for large walls when a single part hits the size limit.
- [ ] Set conveyor velocity on the actual belt axis and flip the sign if needed.
- [ ] Add transparent collidable Truss Ladders behind visible ladders and WedgePart ramps over tall stairs.
- [ ] Match door visuals to their collision; no ghost doors.
- [ ] Name door folders to match PathfindingLink labels.
- [ ] Place fast-travel points before major bosses and across large maps.
- [ ] Add on-screen objective markers and keep fog light enough to preserve direction.
- [ ] Put key progression items where players are guided to them.
- [ ] Make every hub prop functional or purposeful.
- [ ] Theme and recolour each map to the game concept.
- [ ] Add many spawn zones and space bases apart to limit stealing.
- [ ] Sketch a top-down HTML blueprint with at least three escape routes before placing parts.
- [ ] Consider a level-select menu on join and a build mode for player-made maps if the game supports them.
- [ ] Measure visible triangle count from main player viewpoints, not whole-map totals.
- [ ] Re-check visible triangle count after adding walls or buildings, since occlusion can hide geometry.
- [ ] Merge scattered small terrain patches into one dominant terrain area where possible.
- [ ] Keep draw call count in mind when adding extra terrain pieces.
- [ ] Split external meshes into named parts when parts need separate behaviour or textures.
- [ ] Name each split mesh part so scripts and textures can target it.
- [ ] Build one plot or enclosure as a reusable template with fences and a sign, then duplicate it around the map to fill space fast (T17797).
- [ ] Once the objective is shown to players, check whether any part of the map is never visited and cut or shrink it (T17828).
- [ ] Start a new theme set with a few base plates (for example three) and add more later instead of building every theme at once (N7682).
- [ ] Keep jump gaps near 2 studs on jumpable or climbable platform paths, then playtest the route
- [ ] Multi-select placed block parts and anchor them in bulk so obby platforms don't drift or fall
- [ ] Test every enclosed structure with a player inside to find unintended survival spots
- [ ] Make roofs destructible when houses are part of a survival or elimination game
- [ ] Check elevator speed against the time players need to reach the top or escape a hazard
- [ ] Use a ramp instead of a ladder for any carried object that can't reach the ladder
- [ ] Make ladder parts visually read as ladders so players recognise the climb
- [ ] Add floor markers in large lobbies to guide players to the next location
- [ ] Fill the map with real build content before scripting tycoon or mechanic systems
- [ ] Confirm every model fetched from ReplicatedStorage or ServerStorage exists, with a nil check or timed WaitForChild, before the flow depends on it.
- [ ] Apply the lighting setup early, before finishing the map, then judge builds under that lighting.
- [ ] Check that every joined stage has matching rotation values (for example 0 vs -180) before testing connections.
- [ ] Confirm every new area has its egg or interaction platform and that each pad's main part is set up before release.
- [ ] Add a visible timer or closing door to obby reward rooms.
- [ ] Separate door models into parts and define hitboxes before animating.
- [ ] Surround key event NPCs with scenery so they are not missed on join.
- [ ] Scatter low-poly grass with the brush and adjust density visually.
- [ ] Pick one colour palette per new area before decorating it.
- [ ] Place secrets or collectibles in each new area.
- [ ] Budget time for building event maps from reusable asset kits such as ladders and fences.
- [ ] Keep static map parts as unions, separate from physics objects.
- [ ] Place enough spawn parts per map. AlvinBlox used 11 in a desert map example.
- [ ] Put spawn parts in one folder spread across the map, anchored, CanCollide off, Transparency 1.
- [ ] Pick a random spawn part for each spawn instead of one fixed spawn.
- [ ] Store maps and weapon templates in ServerStorage, not ReplicatedStorage.
- [ ] Set the size limit before building and design directly to it.
- [ ] Furnish spawn-in interiors fully and to scale.
- [ ] Place a goal trigger behind each goal: anchored, CanCollide off, transparency 0.5 for visibility.
- [ ] Check that the goal trigger does not block the ball during playtest.

## Where creators agree
- Greybox or block out with simple shapes before textures or props (Roblox Creator Docs T8794, T9271, T9937; RoBuilder and janisjanis01 build terrain before decoration: T6154, T6213).
- Build roads and terrain before buildings and props (Roblox Creator Docs T7118; RoBuilder T6224, T6217).
- Use invisible walls or boundaries to contain play (janisjanis01 T6153, T6305; Roblox Creator Docs T8738; DevForum T5089 off-limits bricks).
- Anchor platforms and static parts so they stay put (Roblox Creator Docs T9250, T9289, T9374, T9584; janisjanis01 indirectly via T6154).
- Make the environment look alive with small details (janisjanis01 T6354; Roblox Creator Docs T8735, T8428).
- Use tags or folders to manage repeated objects with one script (B Ricey T5549, T5696; janisjanis01 T5848; Roblox Creator Docs T9188, T9246).
- Keep views interesting and avoid empty walls (DevForum Q889, T5086; Roblox Creator Docs T8733 for distinct hue cues).
- Plan the map on paper or annotate it before building (DevForum T5085; Roblox Creator Docs T7001, T8791).
- Greybox or block out the layout with simple parts before sculpting or detailing (indie and official).
- Playtest from player eye level and check scale, clipping and floating (DevForum, GnomeCode, official docs).
- Route variety beats a single loop; provide multiple routes and sight lines (GnomeCode and official).
- Use terrain tools for outdoor ground and avoid boxy shapes (indie and official).
- Lighting sets mood and needs deliberate choices; tint ambient and use haze for depth (official and indie).
- Zone and trigger parts should be invisible and non-colliding (Emancyphur and Amora agree on Anchored, CanCollide off, Transparency 1).
- Plan layout on paper or as a top-down sketch before placing parts (mats-dept2 and Cumin, consistent with existing 'Decide design before opening Studio').
- Visible progression cues matter: markers and guidance over hidden items (Cumin across several 2025-12 and 2026-02 tips).
- Placeholder or crude visuals are acceptable during prototyping (Roox4 and Mulch).
- Both Roblox official performance items (T17700, T17704) treat triangle and draw-call cost as the main scene-cost drivers for level and terrain work.
- Anchor placed block parts so they stay static after placement (T18071, T18084).
- Playtest or test in-world before trusting a layout: test with a player inside structures (T18062) and playtest platform gaps (T18235).

## Where creators disagree
- **Symmetry in level layouts**
  - Roblox Creator Docs (T7488, T8795, T8791): build half and duplicate for symmetry; symmetrical maps are easier to balance and keep competitive multiplayer fair.
  - RoBuilder (Q985, T6221): symmetry kills games; nothing in the real world is symmetrical, so add slight variation.
- **Mesh length and snap values**
  - Roblox Creator Docs Modern City kit (T7133, T7134): 7.5-stud minimum and move snap, 45-degree rotation, collisions off.
  - Roblox Creator Docs sample modular kit (N3732, N3733): 5-stud snap and minimum asset size.
  - Roblox Creator Docs low-advice (N3786, N3787, T9560): default 1 stud, recommended 4 studs for 4x4 tiles.
- **Atmosphere density sample**
  - Roblox Creator Docs lighting tutorial (T7594, N3161): 0.5 for a hazy cabin.
  - Roblox Creator Docs documented range example (N3794): 0 to 0.35 density example values.
- **Depth of field and blur**
  - Roblox DevForum (T11651): avoid DepthOfField and Blur post-processing, which the author finds detrimental.
  - Roblox Creator Docs (T15172): use DepthOfFieldEffect to blur distant objects or focus attention on a specific item such as a shop display. Newer official guidance; prefer it, but use DOF selectively.
- **Snap grid size for buildings vs greybox**
  - Roblox Creator Docs (T14470, N5716): Snap to Grid for Move at 4 studs for buildings.
  - Roblox Creator Docs (T14883, N5857): 5-stud transform snapping for greybox.
  - GnomeCode (N4258): 5-stud window sections plus 0.5 offset. Not a true conflict: 4 for building placement, 5 for greybox increments.
- **Off-grid rotation vs strict snapping**
  - GnomeCode (T11663): rotate buildings a slight angle off the grid for variety.
  - Roblox Creator Docs (T14470, T14471, T14472): snap precisely and delete-and-duplicate if an object won't snap. Reconcile: off-grid only for decor.
- **Interior size**
  - GnomeCode (T11042): oversized realistic interiors feel cramped in third-person because the camera clips into walls.
  - Roblox Creator Docs (T14884, N5858, N5859): keep doorways at least 10 studs wide and walls at least 10 studs tall. Reconcile: apply the 10-stud minimum to passages, not to whole rooms.
- **Lighting vs movement flow priority**
  - GnomeCode (T11658): prioritise how players move through space over lighting.
  - Roblox Creator Docs (T14875): set lighting deliberately because it establishes mood and highlights important objects. Both can hold: fix flow first, then light deliberately.
- **Exit count**
  - GnomeCode (T11661): give every area multiple exits; a few dead ends are fine for corner chases.
  - Roblox Creator Docs (T14887): limit most combat pockets to at most three entrance or exit points. Compatible: at least two exits, at most three for combat pockets.
- **Fog use**
  - Cumin (T16387): avoid excessive fog, which hides the map and removes direction sense.
  - Existing rule 'Avoid excess darkness; use shadows and fog deliberately' is consistent; no creator argues for heavy fog.
- **Block grid size for snapping**
  - B Ricey (2024-01, N7769) uses a 3-stud grid for 3x3x3 blocks in a tutorial.
  - SimTek Game Development (2025-12, N7833) uses a 4-stud block size. This is the more recent figure and matches the existing 4-stud voxel grid rule; prefer 4 studs unless a specific tutorial system requires 3.
- **Placeholder layouts versus real content**
  - Existing knowledge rule says to use placeholder and reference first for lived-in detail.
  - Duckable (2025-08, T18288) says to populate with real build content before scripting, because placeholder layouts make AI and testing harder. Reconcile: placeholders for greybox design, real content before scripting; Duckable is more recent.
- **Transparency for hidden trigger and zone parts**
  - Existing knowledge file rule: zone and spawn markers use Anchored, CanCollide off, Transparency 1 (fully hidden).
  - GnomeCode (T19008, N8186): goal trigger uses transparency 0.5 so it stays visible and non-blocking.
  - Not a true contradiction: the two serve different purposes. Use 1 for markers that must be invisible; 0.5 for triggers you want to see.

## Instructions for an agent using this file
- If a map has an enterable building, then limit it to 2-3 entry points and keep at least one dead end as a risk/reward spot.
- If a competitive arena needs fairness, then build half, duplicate and rotate it, and keep both SpawnLocations equidistant from the centre.
- If a scenic city or exploration map is being built, then avoid perfect symmetry and vary layout, roofs, heights and materials.
- If a terrain import is planned, then keep the heightmap at or below 4096 x 4096 px and plan 1 px = 4 studs; if a part is oversized, then split it before Convert to Terrain.
- If a modular kit is used, then give every piece one pivot, lengths divisible by the snap value, and move one mesh at a time.
- If the player will enter a room, then make indoor walls at least 1 stud thick, set LightingStyle Realistic, and use distinct indoor and outdoor floor materials.
- If a lighting problem appears, then check it at more than one time of day and confirm it persists across a full session.
- If a part is static geometry, then anchor it; if it is toggled CanCollide=false, then anchor it so it does not fall through the baseplate.
- If the map has model extents above about 64 cubic studs, then split the model into smaller ones and enable StreamingEnabled first.
- If the map has repeated objects, then tag them with CollectionService or group them in a folder and drive them with one script.
- If building procedural terrain, apply math.abs to each noise octave before summing, then square the result, and colour by height threshold.
- If flattening procedural water, use inverse lerp above the threshold and keep the original height in preservedBaseY for colouring.
- If a third-person map's interiors feel cramped, do not scale entire rooms up; keep only doorways at least 10 studs wide and walls at least 10 studs tall.
- If a route forms a single loop, add a second route or branch before adding visual detail.
- If placing many repeated props, randomise position, scale, rotation and model; avoid a regular grid.
- If an object will not snap, delete it and duplicate a fresh copy from the palette rather than fixing it in place.
- If using DepthOfField, use it only to focus attention; do not enable it by default.
- If the map is outdoors, build ground in Terrain rather than Parts for performance and lighting behaviour.
- If planning for more than 50 users, verify the map has room for players to interact before scaling.
- When official and indie advice conflict, follow the newer official 2026-10 guidance and mention the conflict; flag low-advice items as weaker evidence.
- If a trigger or zone part must be invisible, set Anchored, CanCollide false, Transparency 1, and height so players can't escape above it.
- If a map grows beyond a few thousand studs, plan fixed-size keyed chunks before building further.
- If a model cannot be destroyed, remove its inactive welds.
- If a door is visible, make it collide; if it is open, remove collision entirely; never leave ghost doors.
- If a ladder or stair blocks the character, add a transparent collidable Truss Ladder or WedgePart ramp rather than changing the visible model.
- If a large wall is needed and single parts hit the limit, stack many parts instead of resizing one.
- If far-from-origin glitches appear, test scaling on your own build; do not assume the reported 1,000x limit applies.
- If a level has long walks or large empty areas, add fast-travel points, markers, or density rather than more sprawl.
- If a hub has decorative props that do nothing, replace them with functional content or remove them.
- Before placing blocks, sketch a top-down blueprint with at least three escape routes and check flow.
- If a scene runs slowly, measure visible triangles from player views before removing content.
- If a map has many small terrain patches, consolidate them into one dominant terrain before adding more detail.
- If a vehicle or model needs per-part behaviour or textures, segment the external mesh into named parts first.
- Do not plan layouts around terrain scattering, splines or projected decals until they ship; mid 2027 is the stated target.
- If a large map shows empty areas after the objective is revealed, shrink or cut those areas before adding more content.
- If building a repeated enclosure or plot, make one template first, then duplicate it rather than building each copy by hand.
- If a map has a timed hazard or race to the top, check that vertical transport reaches the top within the hazard window before shipping.
- If a player can survive inside an enclosed house or structure unintentionally, make the roof or upper structure destructible and retest.
- If a mechanic needs a carried object to climb, use a ramp rather than a ladder when the object cannot reach the ladder.
- If the map is a large lobby, add floor markers pointing to the next location in addition to on-screen objectives.
- If building a jumpable or climbable platform path, space gaps near 2 studs, then playtest the route.
- If placing block parts for an obby or platforming map, multi-select and anchor them in bulk after placement.
- If the grid size question arises, default to 4 studs (SimTek 2025-12) unless a specific tutorial system dictates otherwise.
- If writing gameplay scripts for a tycoon or mechanic system, populate the map with real build content first; keep placeholders for greybox design only.
- When code loads a template or pad model by name, add a nil check or timed wait and log a clear error if it is missing.
- When starting a new map or environment, schedule the lighting setup early rather than at the end of the build.
- If stages fail to connect, check rotation values first (0 vs -180) before changing positions.
- Before releasing a new area, verify its interaction or egg platform and the pad main parts exist.
- Before animating a door, split its model into parts and define hitboxes.
- When placing event NPCs, surround them with scenery so they stand out.
- When decorating a new area, choose one colour palette and apply it across the area.
- Keep static map geometry as unions, separate from physics-driven objects.
- If a map has one spawn point for all players, add more spawn parts and randomise selection.
- If spawn parts are visible in a playtest, set Transparency to 1 and CanCollide off, and keep them anchored.
- If maps or weapons are sent to clients by ReplicatedStorage, move them to ServerStorage and clone server-side.
- If a build will be scaled down to fit a size limit, redesign it for the target size instead.
- If an interior is the first thing players see at spawn-in, furnish it fully and to scale.
- If a goal detector must be visible during building, use a transparency of about 0.5 rather than 1.
- If a trigger blocks movement or physics objects, set CanCollide off before testing.

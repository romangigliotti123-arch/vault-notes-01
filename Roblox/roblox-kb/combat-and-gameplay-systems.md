# Combat And Gameplay Systems

_combat, weapons, abilities, hitboxes, inventory, shops, quests, leveling and other gameplay systems implementation._

Evidence base: 353 extracted items from 149 videos by AlexDev, AlvinBlox, ArTheDev, B Ricey, Bemmy, ByteBlox, Cumin, Deconstructor of Fun, Duckable, Emancyphur, Game Maker's Toolkit, GnomeCode, Itz_FloppyFish, JustDucksey, LovJak, MonarchDev, Mulch, PineappleDev, RoDev, Roblox, Roblox Creator Docs, Roblox DevForum, Roblox public API, Roox4, SimTek Game Development, Suphi Kaner, TheDevKing, VuukStudios, XTB7, studio rook., tef (2018-05-27 to 2026-11-01). Roblox changes quickly: check the date on each source and see Date context below.

## Overview
Gameplay-systems advice spans combat design (GMTK's anticipation/contact/recovery framing, parries, stun-lock, enemy telegraphs), Roblox implementation (hitboxes, raycast and projectile weapons, debounce, server validation, tools, inventory, spinners, shops, abilities, tasks) and some economy/soft-lock design. The official Roblox Creator Docs (2026-10) are the ground truth for platform mechanics and newer APIs. Indie DevForum, tutorial and video advice (2018-2025) is useful for patterns but is self-reported and often predates current APIs. Most numbers are tutorial or sample values, not recommendations.

## Rules and findings
- **Split attacks into phases and decide on cancelling** (one-creator-repeated): Split every attack into anticipation, contact and recovery. Anticipation mostly sets attack speed and is when the player is most vulnerable. Allow cancelling for free-flowing play (enemies become more aggressive) or forbid it for deliberate play. Reference: Black Knight greatsword ~2 s anticipation plus 1-2 s recovery. Sources: [Game Maker's Toolkit 2018-05 2:43](https://youtu.be/8X4fx-YncqA?t=163), [Game Maker's Toolkit 2018-05 3:28](https://youtu.be/8X4fx-YncqA?t=208), [Game Maker's Toolkit 2018-05 3:28](https://youtu.be/8X4fx-YncqA?t=208). Newest source 2018-05-27.
- **Give every move a niche, a cost and easy access** (one-creator-repeated): Each move should have minimal overlap with others and carry a disadvantage: slowness, vulnerability, resource cost or cooldown. Get many moves from one attack button using hold for charge and directional input. For casual players, reward pressing attack as the previous hit lands instead of memorised combos. Sources: [Game Maker's Toolkit 2018-05 5:30](https://youtu.be/8X4fx-YncqA?t=330), [Game Maker's Toolkit 2018-05 6:19](https://youtu.be/8X4fx-YncqA?t=379), [Game Maker's Toolkit 2018-05 7:02](https://youtu.be/8X4fx-YncqA?t=422). Newest source 2018-05-27.
- **Make parries risky and reward them with a stun, not a kill** (one-creator-repeated): Use a narrow parry window, with a precise viable moment in the enemy's animation. Punish mistimed parries or dodges with long vulnerable recovery. The parry reward should be a stun or slow-mo, so the player still needs the full combat system to finish enemies. Sources: [Game Maker's Toolkit 2018-05 8:20](https://youtu.be/8X4fx-YncqA?t=500), [Game Maker's Toolkit 2018-05 9:46](https://youtu.be/8X4fx-YncqA?t=586), [Game Maker's Toolkit 2018-05 9:04](https://youtu.be/8X4fx-YncqA?t=544). Newest source 2018-05-27.
- **Prevent stun-lock and make enemy attacks readable** (one-creator-repeated): Use poise or super armour that resists stagger until enough damage is dealt, stamina limits, multiple attackers, or uninterruptible attacks. Give enemies distinct silhouettes and colours, exaggerated wind-ups, and clear telegraphs (sound or visual glints). Sources: [Game Maker's Toolkit 2018-05 10:11](https://youtu.be/8X4fx-YncqA?t=611), [Game Maker's Toolkit 2018-05 11:27](https://youtu.be/8X4fx-YncqA?t=687). Newest source 2018-05-27.
- **Do not let one move be the only answer to an enemy** (multiple-creators): Enemies that die only to one specific move collapse the move set into one dominant strategy. Use resistant enemies, or enemies that adapt to repeated player moves, to force varied tactics. Sources: [Game Maker's Toolkit 2018-05 12:08](https://youtu.be/8X4fx-YncqA?t=728), [Game Maker's Toolkit 2018-05 12:08](https://youtu.be/8X4fx-YncqA?t=728), [Game Maker's Toolkit 2018-05 13:34](https://youtu.be/8X4fx-YncqA?t=814). Newest source 2018-05-27.
- **Validate hits and fire on the server** (multiple-creators): For client-side hit detection, check range with a lag margin, enforce attack cooldown with os.clock, and check facing angle unless the attack is AoE. For weapons, track last fire time, ammo, teammate/alive status, and block firing during reload or sprint. Sources: [Roblox DevForum 2021-12](https://devforum.roblox.com/t/a-guide-to-making-proper-anti-exploits/1606949), [Roblox Creator Docs 2026-10](https://create.roblox.com/docs/scripting/security/client-server-boundary). Newest source 2026-10-28.
- **Debounce damage per target** (one-creator-repeated): Duplicate Touched detections multiply damage: a 5-damage fireball dealt 25 without debounce. Store a per-player debounce value inside the humanoid, named with player name plus attack key, and remove it after 1-4 s via Debris. Sources: [Roblox DevForum 2022-01](https://devforum.roblox.com/t/full-beginners-guide-on-scripting-animefighting-vfxvisual-effects-part-1/1610853), [Roblox DevForum 2022-01](https://devforum.roblox.com/t/full-beginners-guide-on-scripting-animefighting-vfxvisual-effects-part-1/1610853). - **Filter hits to real humanoids and self, and choose a collider setup** (multiple-creators): Check hit.Parent (and grandparent) is a model with a Humanoid before damage. Filter Touched with IsDescendantOf so the caster never hits themselves. Hook caster.RayHit, which fires on each collision and stops updating. Official 2026 guidance: choose Single Collider and set Hit & Touch Detection to colliders for uniform hitboxes. - **Disable friendly fire on the server** (single-mention): Check team membership on the server before applying damage and return early for same-team players. - **Use FastCast or a predictive raycast for bullets; handle misses** (multiple-creators): FastCast is the projectile library the author recommended. Without it, raycast toward the bullet's predicted future position each frame; on hit, destroy the bullet and disconnect its loop. If a raycast returns nil, use origin + direction as the hit position so misses still show a bullet. - **Build fire loops from RPM, recoil and ammo rules** (one-creator-repeated): Use wait(60/rpm) with a canFire cooldown (example 800 RPM). Shove the recoil spring on fire and reverse after ~0.15 s. Track ammo in a variable, reject shots at 0, decrement per shot, and refill only when the reload animation ends. Example: 5 spare magazines per weapon. Destroy the visual bullet after ~0.25 s. - **Lock movement and control cutscene cameras in scripts** (single-mention): Set WalkSpeed = 0 during a scripted animation and restore it after the main animation's Stopped event fires. For attack cutscenes, animate the camera normally, then set Camera.CFrame = reference part CFrame * frame CFrame, using HumanoidRootPart as the reference about 99% of the time. - **Use Drag Detectors for dragging** (single-mention): Use Drag Detectors instead of hand-rolled mouse dragging; they replicate automatically and give good control. Sources: [Roblox DevForum 2019-12](https://devforum.roblox.com/t/dragging-objects-with-the-mouse/403766). Newest source 2019-12-08.
- **Handle tools: grip, replication, containers** (multiple-creators): Keep tool parts unanchored, since anchored tools leave characters stuck. Tool Equipped, Activated and Deactivated only fire on LocalScripts, so pair them with a server Script and RemoteEvent. Put starter tools in StarterPack, per-player control in StarterGear, and award or shop tools in ReplicatedStorage cloned to Backpack. Redo the Motor6D swap on every equip (delete the old one first) and tune Tool.Grip by trial and error. Renaming a tool changes its in-game name. Sources: [Roblox Creator Docs 2026-10](https://create.roblox.com/docs/players/tools), [Roblox Creator Docs 2026-10](https://create.roblox.com/docs/players/tools), [Roblox Creator Docs 2026-10](https://create.roblox.com/docs/players/tools), [Roblox Creator Docs 2026-10](https://create.roblox.com/docs/players/tools), [Roblox DevForum 2022-02](https://devforum.roblox.com/t/how-to-animate-tools-the-easiest-and-best-way-for-melees/1654589). - **Manage inventory, collectibles and interactions** (multiple-creators): Cap collection with a check like playerItems.Value < playerSpaces.Value. Mark collectibles with a BoolValue CanHarvest set to true, keep items in the same Explorer structure, and manage collected items in one per-player script. Anchor coin parts and put a Script in them for pickup, currency award and respawn timer. Use ProximityPrompts for doors, switches and buttons. For proximity, use player.Character:GetPivot().Position and fall back to Vector3.zero if the character is missing. - **Build spinners and gacha rolls carefully** (multiple-creators): Generate the full batch (e.g. 45 crates) and pick the winner at a fixed index (e.g. 5 from the end) so the spinner looks like it has more to come. Make rarity chances sum to exactly 1, since weighted selection uses cumulative chance (example: 0.589/0.300/0.100/0.010/0.001). Convert duplicates to a cash reward per rarity, or remove owned items from the pool for new-item-only spins. Spin duration example: 7-8 s random with Quart easing. - **Give shops stock limits and a recovery path** (multiple-creators): Infinite stock feels idle and removes scarcity, so set stock limits. A player who can lose all money must still be able to play, or they soft-lock. Add a recovery path. The author said they should fix this. - **Use UpdateAsync and shared counters for shared progress** (single-mention): Use UpdateAsync rather than GetAsync+SetAsync for values written by multiple servers, so the callback reads the latest value and avoids lost updates. Share one counterId across tasks (e.g. coins) so they track one progress value; set continueFromCounter true to start from the existing total. - **Declare ability conflicts and naming in the ability system** (multiple-creators): Use Blocks, Stops, Suspends or ExclusiveGroup (with Priority) rather than hand-written checks; Stops overrides priority (sample: Sprinting 200, Stagger 150, Crouching 100, and Stagger can stop Sprinting). Use TimedLabels.Consumes to prevent double-triggering (CounterAttack consumes AfterBlock). Give each ability a unique Name; duplicates throw an error. Example dash: 0.2 s active window, 1.0 s cooldown, impulse LookVector * 80 * AssemblyMass. - **Set up input actions correctly** (single-mention): Never put an input into RunsWhile (it throws an error); RunsWhile is for world conditions. Use Input.Mode or Input.OutlivesInputWhile for input timing. Choose the action type by input shape: Bool for jump/shoot/sprint, Direction1D for throttle/zoom, Direction2D for camera or movement, Direction3D for flight, ViewportPosition for cursors or raycast selection. Set Priority to 2000 and Sink on a menu context so it consumes inputs first. - **Control physics, knockback and teleports** (multiple-creators): Use ApplyImpulse for instant feedback after explosions or jump pads; the object then decelerates under friction. Set AirController.MoveMaxForce to 0 to stop midair movement during knockback, or scale it by velocity magnitude times BaseMoveSpeed to limit it. When jumping from ground, apply an equal and opposite impulse to the floor at the sensed hit normal. Example jump impulse: Vector3(0, 750, 0). Unseat players and disable seating before a CFrame teleport. - **Handle respawns, regeneration and spawn protection** (multiple-creators): Enable spawn force fields by setting SpawnLocation.Duration above 0 (sample uses 9999 and ends it in script). - **Use one central upgrade module that others query and subscribe to** (single-mention): Keep a single upgrade module that stores each player's upgrade values. Other scripts query a player's value from it and subscribe to change events, instead of each system keeping its own copy that can drift out of sync. Sources: [Duckable 2026-10 14:02](https://youtu.be/EOUSVENUkr0?t=842). Newest source 2026-10-18.
- **Add gated choices and conditional passives to skill trees** (single-mention): Skill trees can gain variety without new content through gated choices and conditional passive effects, such as an exhaustion penalty tied to sprint debt. Low-advice source; treat the example as a pattern, not a tested value. Sources: [Deconstructor of Fun 2026-10 52:46](https://youtu.be/oU3oz6Ddz7g?t=3166). Newest source 2026-10-22.
- **Offer a cheap knockback tool as PvP defence** (single-mention): A simple tool that knocks players back gives a low-cost, fun PvP defence option. Add a sound effect so the player gets clear feedback on each use. Low-advice source; the knockback itself should follow the existing physics rules. Sources: [JustDucksey 2026-08 6:49](https://youtu.be/kl933X0UCC0?t=409). Newest source 2026-08-09.
- **Redesign boss fights that demand repeated stamina-costing actions** (single-mention): Avoid boss fights that require the player to repeat stamina-draining actions over and over. Match the boss's attack style to the game's genre; spammy projectile bosses clash with extraction-horror games. Sources: [Cumin 2026-08 9:03](https://youtu.be/rjPW4GeeyFg?t=543). Newest source 2026-08-22.
- **Detect wall impacts after a knockback with a raycast, not collision events** (single-mention): After a push ends, cast a short ray or check an invisible part in the travel direction to decide whether the target hit a wall and should be stunned. This avoids running continuous collision or Touched logic during the knockback. Sources: [ByteBlox 2025-01 22:45](https://youtu.be/29B9AV_xM_k?t=1365). Newest source 2025-01-22.
- **Resolve the character from accessory hits before applying damage** (single-mention): A Touched hit from an accessory returns the accessory Handle, not the character model. Walk up from the hit part to the character (the source uses hit:GetRootPart().Parent) before applying damage, tags or credit. Confirm the method name in your own code against the API docs. Sources: [ByteBlox 2025-01 14:55](https://youtu.be/SCtYVCRVzM8?t=895). Newest source 2025-01-24.
- **Use one pickup system for map spawns and enemy drops** (single-mention): Spawn collectibles from defined spawn parts in houses and also from enemy drops, and route both through the same pickup script. One code path is easier to balance and fix than two. Sources: [JustDucksey 2025-06 2:46](https://youtu.be/XRvcKGSLr4g?t=166). Newest source 2025-06-14.
- **Make weapon variants by swapping only the model on a template tool** (single-mention): Keep one template tool with its working logic and clone it for each weapon variant, changing only the visual model. The scripts keep working while the look changes. Sources: [JustDucksey 2025-06 4:06](https://youtu.be/XRvcKGSLr4g?t=246). Newest source 2025-06-14.
- **Show stackable items as a growing visual stack with a count** (single-mention): For quick-handling resources, let the visual stack grow with the item's stack size and display the count, instead of building a separate sack or container system. Sources: [JustDucksey 2025-07 2:47](https://youtu.be/s5nooZlK5Pc?t=167). Newest source 2025-07-27.
- **Drop loot at the death position and despawn uncollected drops** (one-creator-repeated): Read the enemy's death position for loot drops, and guard for a nil root part in case the enemy fell into the void. Add each dropped item to Debris:AddItem with a lifetime (example: 20 s) so uncollected loot clears itself. Sources: [GnomeCode 2026-02 13:50](https://youtu.be/HYBG2AtUBes?t=830), [GnomeCode 2026-02 15:10](https://youtu.be/HYBG2AtUBes?t=910). Newest source 2026-02-28.
- **Grant gamepass tools server-side by cloning into Backpack** (single-mention): For a gamepass-gated tool, the server clones the tool from ReplicatedStorage into player.Backpack rather than the client giving it. This is the same clone-into-Backpack pattern as respawn tools, but the trigger is a purchase. Check ownership on the server before cloning. Sources: [TheDevKing 2020-03 15:30](https://youtu.be/RmWgJVjJrqE?t=930). Newest source 2020-03-12.
- **Scale enemy damage to the enemy's remaining health** (single-mention): Make a mob's damage depend on its remaining health so stronger enemies hurt the base more, instead of applying one flat value. The source gives the idea only, with no formula, so tune the scaling separately. Sources: [GnomeCode 2022-01 20:39](https://youtu.be/de5-o6euwJE?t=1239). Newest source 2022-01-04.
- **Express boss damage as a fraction of max health** (single-mention): Set each boss hit as a fraction of its max health, for example one third per hit, so damage stays meaningful as boss health is tuned. The tutorial example computes wizard.Health minus MaxHealth/3. Treat it as a pattern, not balance guidance. Sources: [GnomeCode 2020-04 8:03](https://youtu.be/KZVpkWwz3A4?t=483). ## Checklist
- [ ] Define attack phases (anticipation, contact, recovery) and tune each separately.
- [ ] Decide whether attacks are cancellable; tune enemy aggression to match.
- [ ] Give each attack a cost (slowness, vulnerability, resource, cooldown) and a unique niche.
- [ ] Use hold and directional inputs to expand one attack button.
- [ ] Make parry window narrow; reward with stun/slow-mo, not an instant kill.
- [ ] Add stun-lock protection: poise, stamina, multiple attackers, or uninterruptible attacks.
- [ ] Telegraph enemy attacks with silhouette, colour, wind-up and sound/visual cue.
- [ ] Ensure no enemy is killable by only one move.
- [ ] Validate every hit on the server: range with lag margin, os.clock cooldown, facing unless AoE.
- [ ] Debounce damage per target, removing the debounce via Debris after 1-4 s.
- [ ] Filter Touched with IsDescendantOf for self-hit protection.
- [ ] Check hit.Parent (and grandparent) for a Humanoid before damage.
- [ ] Clamp damage to humanoid.Health and keep damagePerHit as an attribute.
- [ ] Use FastCast or predictive raycasts for bullets; handle nil raycasts with origin + direction.
- [ ] Track ammo, reject shots at 0, refill only at reload end.
- [ ] Check team membership on server before damage.
- [ ] Cap inventory with a count check against capacity.
- [ ] Use StarterPack/StarterGear/ReplicatedStorage+Clone for tool distribution.
- [ ] Keep tools unanchored; fire tool effects from server via RemoteEvent.
- [ ] Keep rarity weights summing to 1; convert duplicates to currency.
- [ ] Set shop stock limits and a recovery path for money-loss soft-locks.
- [ ] Use UpdateAsync for shared multi-server data.
- [ ] Declare ability conflicts with Blocks/Stops/Suspends/ExclusiveGroup and Consumes.
- [ ] Give each ability a unique Name; never put inputs in RunsWhile.
- [ ] Share counterIds across tasks that track the same progress.
- [ ] On hit, clear old creator tags, then tag the victim with an ObjectValue pointing to the attacker before TakeDamage.
- [ ] Expire combat and kill tags with Debris:AddItem instead of tables.
- [ ] Only add an anti-combat-log if dying carries a real penalty.
- [ ] Use magnitude or OverlapParams for melee on the server; use raycast for guns; reserve Touched for anchored triggers.
- [ ] Set CanTouch=false on any part that collision detection should ignore.
- [ ] Make ability hitboxes non-collidable, non-anchored, massless, transparent and welded to HumanoidRootPart.
- [ ] Clean up temporary hitbox clones with Debris after about 6 s.
- [ ] Keep hit targets in one folder (for example Alive) and search only that folder.
- [ ] Set a per-hitbox DebounceTime (for example 1 s) and keep a per-attack hit table.
- [ ] Check the return value of the hitbox constructor on the client, where it can be false.
- [ ] Gate attacks by state: block them while stunned, jumping or in other invalid states.
- [ ] Set ability cooldowns server-side as timed states; add a client flag for button spam.
- [ ] Store NPC state as attributes on the character model; keep the attribute count under 64 per Instance.
- [ ] Check Humanoid.Health > 0 before an NPC chases a target.
- [ ] Use ProximityPrompt rather than ClickDetector for interactions, since ClickDetector fails on mobile.
- [ ] Check cash before purchase; deduct and increment owned in one server call.
- [ ] Restart shop restock timers on a fixed interval (300 s matches the 5-minute cycle in one example) with randomized stock per item.
- [ ] Destroy spawner marker parts after reading them.
- [ ] Destroy existing spawned NPCs or items before respawning.
- [ ] Use weighted random picks: sum weights, roll math.random scaled to the total, walk cumulative weights.
- [ ] Reset per-character stats on CharacterAdded and clear stored data on PlayerRemoving.
- [ ] Set Player.Team directly by unchecking AutoAssignable on forced teams.
- [ ] Set IK weight to 0.999 rather than 1 so the head gives up at extreme angles.
- [ ] Start resource caps low (for example bag Spaces=2) so players want upgrades early.
- [ ] Test every gear item for Scripts that bypass map restrictions or damage others.
- [ ] When a tool won't equip, confirm it has a child named Handle; if still stuck, test the tool alone in StarterPack.
- [ ] On respawn, clone tools from ServerStorage into the Backpack, skipping any already present in the Character or Backpack.
- [ ] Use >= for every level requirement check so higher-level players keep access to lower tiers.
- [ ] Store item level requirements in one dictionary keyed by item name, sourced from leaderstats.
- [ ] Cap equipped tools and abilities (2 each in cited examples) and require unequip before equip.
- [ ] Check that optional objectives do not occupy slots needed for healing or other core survival items.
- [ ] Confirm stamina regen and ammo supply are scarce enough that dash, push and ranged attacks are worth using.
- [ ] Verify boss fights last more than a minute or two and that boss time-to-kill is not one-sided.
- [ ] Make each gear tier change behaviour, not just stats, so higher tiers do not simply outclass earlier ones.
- [ ] Gate stat gain behind proximity to training objects if you want to block idle farming.
- [ ] Add a per-player post-match cooldown on arena entry if you run queued matches.
- [ ] Check progression content length against playtime; a five-spawn-area template was exhausted in seconds (Q1598).
- [ ] Before designing team or round sizes, open Game Settings and check the Server capacity value (official figure: 7 per N7421).
- [ ] Make team caps and matchmaking minimums no larger than the server capacity, so rounds can always fill.
- [ ] Re-check the capacity value after any Roblox platform update, since it is a platform setting and may change.
- [ ] Before scripting an NPC, write down its role (tutorial, companion, opponent or boss), its abilities and its intelligence level.
- [ ] Keep tutorial NPCs out of the combat tag system so they cannot be damaged or targeted by accident.
- [ ] Before adding an accessory, loop character children and destroy existing Accessory items at Handle > FaceFrontAttachment (T17784).
- [ ] After generating or spawning guns, visually check that the weapon is attached and held in the hand; floating guns were seen in generated output (T17911, low-advice).
- [ ] Make a successful block fully negate the hit; do not let ordinary moves bypass it (T17808).
- [ ] Show a brief pause and sound cue before each QTE prompt; keep one input type per prompt (T17837).
- [ ] Restrict stealing to set times of day and return stolen items to the owner's plot when the thief is hit (T17803, low-advice).
- [ ] Expose each player's upgrade values through one central module and have other scripts subscribe to change events (T17934).
- [ ] Add conditional passives and gated choices to skill trees to add build variety (T17955, low-advice).
- [ ] Give players a cheap knockback tool for PvP defence with a sound effect (T17802, low-advice).
- [ ] Check that a boss does not require repeated stamina-draining actions and matches the game's genre (T17833).
- [ ] After a knockback ends, cast a short forward ray to decide whether to apply a wall stun.
- [ ] When a Touched hit comes from an accessory, resolve the owning character before applying damage.
- [ ] For enemy loot, read the death position and guard for a nil root part before dropping.
- [ ] Give every uncollected loot drop a Debris lifetime (example: 20 s).
- [ ] Reuse one pickup script for house spawn parts and enemy drops.
- [ ] Build weapon variants by cloning a template tool and swapping only its model.
- [ ] For stackable resources, grow a visual stack and display the count.
- [ ] When a gamepass unlocks a tool, grant it on the server by cloning the tool into player.Backpack, not from the client.
- [ ] When tuning a boss, define each player hit as a fraction of its max health (example: 1/3) rather than a fixed number, then check it against your fight length.
- [ ] When scaling enemy damage to remaining health, document the formula in your data tables so balance changes stay traceable.

## Where creators agree
- Server-side validation of hits, firing and team damage is recommended (T5589 from a DevForum indie creator; T7470 and T10206 from official docs).
- Filter self-hits and nested Humanoid hits when processing hitbox events (T5596, T5320, T5407).
- Projectiles should use a library (FastCast, T5226) or predictive raycasts (T5478, Q914) rather than naive bullet motion.
- Stun-lock prevention and enemy readability are core combat-design requirements (T4974, T4975).
- Avoid single-move enemy designs (T4976, Q874).
- Infinite stock and soft-locks are design problems to avoid (T6184, T6185, Q980).
- Hit detection and damage must be decided on the server; clients handle input and animation (T12875, T13126, T12395).
- Attribute kills to the last attacker with a creator tag that expires (T10787, T10951, T12823).
- Debounce or track hit tables per attack and per target so one swing hits once (T12004, T12168, T12876).
- Central state management plus cooldowns and input gating stop action conflicts and spam (T12838, T12861, T11851, T12864).
- Keep weapon and attack numbers in data or profiles, not hardcoded logic (T13131, T14974, T12144).
- Limit how many items are equipped at once (Cumin on abilities, studio rook. on tools).
- Stamina and ammo costs must actually bite, not be near-infinite (Cumin and LovJak).

## Where creators disagree
- **Projectile implementation approach (era difference, not a direct contradiction)**
  - Roblox DevForum indie creator (2020): use FastCast for projectiles (T5226).
  - Same creator's 2021 post: raycast toward the predicted future position each frame, and skip this if using FastCast (T5478, Q914). Treat FastCast as the preferred route and the predictive raycast as the fallback.
- **Attack cancelling trade-off**
  - Game Maker's Toolkit: cancelling makes play free-flowing but enemies more aggressive; no cancelling is deliberate (T4968). This is a design choice, not a single correct answer.
- **Parry payoff**
  - Game Maker's Toolkit: parries should not be instant kills; use stun or slow-mo (T4973).
  - Game Maker's Toolkit (Q875): parries need to be risky, with a precise viable moment.
- **Hitbox method (era difference)**
  - Older DevForum/tutorial approach: filter Touched events and check the Humanoid on the hit part (T5596, T5407).
  - Official 2026 docs: choose Single Collider and set Hit & Touch Detection to colliders for uniform hitboxes (T10147). Prefer the official approach for new work.
- **Melee hit detection method**
  - T10863 (2020): connect Touched on the server and set the weapon's network owner to the client so hits register despite ping.
  - T12158 (2024): avoid Touched for melee; it is inaccurate on moving parts. Use it only for anchored triggers.
  - T12162 (2024): magnitude hitboxes are cheap and usually precise enough.
  - T12877 and T12875 (2025): use OverlapParams and server-side detection; client handles animation only.
- **Kill-credit method**
  - T10952 (2021, low-advice): increment leaderstats on Humanoid.Died by reading the creator tag.
  - T12823 (2025): untag the humanoid, then tag with the attacker before damage; tag lasts about 2 s.
  - T10951 (2021, low-advice): remove old creator tags, then add a new one in the damage callback.
- **Whether to build a combat-log tag at all**
  - T10785 (2020): only build an anti-combat-log if dying has a punishment.
  - T10793 (2020): wrap tagging in a module and call it after every humanoid:TakeDamage, with no punishment condition.
- **Inventory storage**
  - T12727 (2025, low-advice): use the built-in Roblox inventory system to save time.
  - T12666 and T12667 (2025): read ItemData values and handle items with custom scripts.
- **Respawn timing**
  - T12191 (2024): respawn immediately only when a shared-health or fairness mechanic requires it; otherwise add a short wait.
  - T12186 (2024): respawn limits as a mode mechanic (knockout style) with a finite pool.
- **Parry versus dodge as the main defensive tool**
  - Cumin (T16393) praises Pixel Blade's dodge dash i-frames as more useful than parries.
  - The existing knowledge file's rule treats parries as a risky counter rewarded with a stun, not a kill. Cumin's view does not contradict this but shifts emphasis toward dodge.
- **Whether a block can be bypassed by some attacks**
  - Cumin (T17808): blocks should be full blocks, not damage reduction that some moves ignore; a weak block undermines combat feel.
  - Existing knowledge-file rule 'Let heavy attacks break guard' (no ID in this batch): some heavy attacks should break guard.

## Instructions for an agent using this file
- For Roblox platform mechanics (tools, abilities, input, tasks, colliders, force fields, respawn, damage, teleport), follow the 2026-10 official rule first and cite it; check older DevForum advice against it before reuse.
- For combat design, split each attack into anticipation/contact/recovery and give every move a cost before tuning numbers.
- If you write damage code, check hit.Parent for a Humanoid, clamp to humanoid.Health, and debounce per target.
- If the game is multiplayer, put hit, fire, purchase and team checks on the server; use client events only for feedback.
- If you use projectiles, prefer FastCast; otherwise use a per-frame predictive raycast, destroy and disconnect on hit, and use origin + direction when the raycast returns nil.
- If you build a spinner or gacha, make rarity weights sum to exactly 1 and convert duplicates to currency or remove them from the pool.
- If you build a shop, add stock limits and a recovery path so players who lose all money can still play.
- If several servers write shared values, use UpdateAsync; if abilities conflict, declare Blocks/Stops/Suspends/ExclusiveGroup instead of writing manual checks, and give each ability a unique Name.
- If a user asks for a number (damage, RPM, cooldown, tier chance), give the example value and label it as tutorial or sample data, not a recommendation.
- If a source is [indie, self-reported] and quotes revenue, CCU or visit numbers, flag them as unverified.
- If melee hit detection is requested, use server-side magnitude or OverlapParams checks, not Touched. Use Touched only for anchored triggers such as landmines.
- If a weapon is hitscan, use raycast with server validation, a per-weapon profile (range, rateLimit, isMelee) and a fire-rate timestamp check.
- If kill credit is needed, clear old creator tags, set the attacker tag before TakeDamage and expire it with Debris (about 2 s).
- If an anti-combat-log is proposed, first confirm that death carries a real penalty. If none, skip it.
- If ability or action gating is needed, route it through one state manager; store NPC state as character attributes, not player-keyed tables.
- If spam prevention is needed, combine a client cooldown flag, a server timed state and input buffering.
- If weapon projectile numbers are needed, start from Creator Docs defaults (BulletSpeed 1000, ShotCooldown 0.1 s, StartupTime 0.2 s) and tune via config.
- If a shared health pool or respawn cap is proposed, present it as a mode design option with its trade-off, not a default.
- Mark low-advice items as unverified and give them lower weight than official docs or multi-source advice.
- When indie figures conflict with official docs, follow the official docs and say so.
- If a tool fails to equip, check for a child named Handle before anything else.
- If you write level gates, use >= and keep requirements in one name-to-level dictionary.
- If you design loadouts, cap equipped slots (2 is the cited example) and require unequip before equip.
- If you tune stamina or ammo, test that dash, push and ranged attacks remain worth using.
- If you design a boss, check fight length and that time-to-kill is not one-sided.
- If you build a respawn tool loadout, clone from ServerStorage and check for duplicates first.
- Treat [low-advice] and single-creator items as lower confidence than multi-creator rules.
- Prefer 2025-2026 creator advice over 2020-2022 items where they conflict.
- If a task involves team sizes, lobbies, or round player minimums, check the Server capacity setting (7 per N7421) before writing code or design values.
- If a mode needs more players than the server capacity allows, reduce the team size or use multiple servers and say so. Do not assume a higher limit.
- Label the capacity figure as a single official source and tell the user to verify it in Game Settings.
- If a task involves creating an NPC, first ask which role it plays (tutorial, companion, opponent or boss) and let that role set its abilities and intelligence level.
- If the NPC is a tutorial character, do not give it damage handling or combat tags.
- If the NPC is a companion, give it support or follow behaviour rather than opponent rules.
- If the NPC is an opponent or boss, apply the existing enemy AI and boss rules for behaviour variety and fight length.
- If adding a new accessory to a character, first loop the character's children and destroy existing Accessory items before attaching.
- If a generated or spawned weapon looks off, check that its handle is attached to the hand, not floating, before moving on.
- If a block mechanic is being built, make a successful block fully negate damage; only explicit guard-break attacks should bypass it.
- If a QTE is being built, add a short pause and sound cue before the prompt, and keep one input type per prompt.
- If a central upgrade value is needed, query the central module and subscribe to changes instead of duplicating the value in each system.
- If a boss relies on repeated stamina-draining actions, redesign the fight rather than adding more of them.
- If a low-advice item conflicts with an established rule in the knowledge file, prefer the established rule and note the conflict.
- If a new tip only restates an existing rule, skip it rather than duplicating.
- For wall-stun after knockback, use a short forward raycast after the push ends rather than continuous collision events.
- For accessory-caused Touched hits, resolve the character model before applying damage or tags.
- Before reading a dead enemy's position for loot, check that its root part exists.
- Give every dropped loot item a Debris lifetime so uncollected drops clear themselves.
- Prefer one shared pickup module for all collectible sources (map spawns and drops).
- Clone weapon variants from a template tool and change only the model.
- Label self-reported indie advice as such when citing it.
- If a gamepass or purchase should give a player a tool, clone the tool on the server into player.Backpack.
- Do not trust a client request to grant a gamepass tool; verify ownership on the server first.

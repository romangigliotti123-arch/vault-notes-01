# Luau Language And Types

_Luau language features, strict typing, idioms, coroutines/task library, code-level performance and style._

Evidence base: 373 extracted items from 137 videos by ArTheDev, B Ricey, ByteBlox, Crusherfire, Emancyphur, GnomeCode, Possible Panda, Roblox Creator Docs, Roblox DevForum, SimTek Game Development, Stewiepfing, Suphi Kaner, XTB7 (2014-09-03 to 2026-10-28). Roblox changes quickly: check the date on each source and see Date context below.

## Overview
Luau-language advice across 65 videos from four creators (Roblox DevForum, B Ricey, Crusherfire, Roblox Creator Docs) converges on five themes: use the task library and event-driven yielding instead of wait(); use colon method calls and local-scoped references; turn on --!strict with annotations, narrowing and minimal any; use metatables carefully (rawget/rawset, returning new tables, weak tables); and write idiomatic Luau (1-based arrays, explicit truthiness, careful string patterns and integer handling). Official 2026-10 Roblox docs are the newest and most authoritative on mechanics; 2019-2021 indie advice predates the task library and modern type-check behaviour. Indie revenue/CCU/speed claims are unverified.

## Rules and findings
- **Replace wait() and spawn() with the task library and coroutines** (multiple-creators): Use task.wait() for delays; it does not pause all execution and lets other threads run concurrently. Use task.spawn/task.defer instead of wait-based spawn(). Older 2019 advice said never use wait() at all; the modern replacement is task.*, not zero yielding. For blocking loops, coroutine.wrap keeps code after them running (wrap returns no success boolean; use create/resume if you need status). BindToClose: do real save work, not wait(n). Sources: [Roblox Creator Docs 2026-10](https://create.roblox.com/docs/tutorials/curriculums/core/scripting/script-game-behavior), [Roblox DevForum 2021-05](https://devforum.roblox.com/t/improved-how-to-actually-improve-performance-in-your-games/1221842), [Roblox DevForum 2019-02](https://devforum.roblox.com/t/avoiding-wait-and-why/244015), [Roblox DevForum 2019-02](https://devforum.roblox.com/t/avoiding-wait-and-why/244015), [Roblox DevForum 2019-02](https://devforum.roblox.com/t/avoiding-wait-and-why/244015). Newest source 2026-10-28.
- **Yield on events instead of polling** (one-creator-repeated): Replace repeat wait() until flag loops with event:Wait() so code resumes the instant the condition is met. Check the flag first (if not called then event.Event:Wait()) to avoid yielding on already-fired events. Yield on ChildAdded, AncestryChanged, ChildRemoved, CharacterAdded or RunService.Heartbeat. Author claims Heartbeat:Wait()/Stepped:Wait() is at least 2x faster than wait() (unverified). Sources: [Roblox DevForum 2019-02](https://devforum.roblox.com/t/avoiding-wait-and-why/244015), [Roblox DevForum 2019-02](https://devforum.roblox.com/t/avoiding-wait-and-why/244015), [Roblox DevForum 2019-02](https://devforum.roblox.com/t/avoiding-wait-and-why/244015), [Roblox DevForum 2019-02](https://devforum.roblox.com/t/avoiding-wait-and-why/244015). Newest source 2019-02-23.
- **Call methods with colon syntax** (multiple-creators): obj:Method() is sugar for obj.Method(obj), so self is passed automatically. Dot calls do not pass the object (one creator says they silently ignore it), so use colon for instance methods and dot only for plain functions or static members. Sources: [Roblox DevForum 2014-09](https://devforum.roblox.com/t/all-about-object-oriented-programming/8585), [Roblox DevForum 2020-09](https://devforum.roblox.com/t/concepts-object-oriented-programming-in-roblox/761267), [Roblox Creator Docs 2026-10](https://create.roblox.com/docs/luau/functions), [Crusherfire 2024-02 7:48](https://youtu.be/9VHThbipoFs?t=468). Newest source 2026-10-28.
- **Cache services in locals and prefer locals over globals** (multiple-creators): Store services with matching names (local ServerScriptService = game:GetService(...)) at the top of scripts. Store frequently used references like workspace.LoopingPart in locals rather than retyping paths. Declare frequent globals/functions as locals (local sqrt = math.sqrt). Globals are slower; in a time-critical loop global access can be more than 10% slower (N4066). Redeclaring a local without a value sets it to nil and shadows the outer one. Sources: [Roblox DevForum 2019-10](https://devforum.roblox.com/t/scripting-basics-beginner-guide-to-lua-and-roblox/359838), [Roblox DevForum 2023-09](https://devforum.roblox.com/t/all-about-optimization/2586333), [Roblox Creator Docs 2026-10](https://create.roblox.com/docs/tutorials/fundamentals/coding-4/repeat-code-with-while-loops), [Roblox DevForum 2016-07](https://devforum.roblox.com/t/the-basics-of-basic-optimization/26756), [Roblox DevForum 2019-10](https://devforum.roblox.com/t/scripting-basics-beginner-guide-to-lua-and-roblox/359838). - **Enable --!strict and set the optimize level deliberately** (multiple-creators): Put --!strict as the first line to make the checker assert inferred and annotated types. The first line sets the inference mode (nocheck, nonstrict default, strict). Optimize: --!optimize 1 is the Studio testing default; --!optimize 2 is the live-game default; set explicitly if behaviour differs. - **Annotate parameters, returns and Instance variables; use unknown for untrusted input** (multiple-creators): Annotate parameters and returns (a: number, player: Player, : Model) so the linter catches wrong argument types and Studio autofills properties (e.g. Humanoid). - **Avoid any; use proper annotations or a single internal cast** (multiple-creators): any silences the type system. Use value :: Type only when the inferred type is too generic (e.g. BasePart to MeshPart). - **Type self explicitly and hide type tags in class instances** (one-creator-repeated): Declare class methods with a dot and type self explicitly (self: ClassType); duplicate the self type in the constructor and let warnings catch drift. - **Use rawget/rawset inside metamethods to avoid recursion** (multiple-creators): Inside __index/__newindex/__eq use rawget/rawset/rawequal to avoid re-triggering the metamethod (infinite recursion or C-stack overflow). Use rawset inside __index when __newindex is also defined, otherwise t[i]=v re-triggers __newindex. - **Know when __index and __newindex fire; lock and describe metatables** (multiple-creators): __index fires only when a key is missing and must return a value (use for defaults or inheritance). __newindex fires only for new keys, not updates; use it to block or validate unwanted keys. Use __metatable to lock getmetatable's result and __tostring for readable print output of tables. - **Follow operator-metamethod operand rules** (multiple-creators): __eq, __lt and __le need both operands to share the same metatable (or metamethod and basic type); mixed table/userdata comparisons don't use them. __eq must be set on both operands. Arithmetic metamethods can receive operands in either order (scalar division is not commutative), so check both arg types. Order matters for __add/__concat. - **Arithmetic metamethods must return new tables and re-attach metatables** (one-creator-repeated): Don't mutate inputs in __add and similar; mutating causes shared-reference bugs. Re-attach the metatable with setmetatable on every returned result or chained operations fail with 'attempt to perform arithmetic on table'. Declare the metatable variable before the functions that reference it, then assign it. - **Use weak tables for caches; never rely on GC timing** (multiple-creators): Set __mode to 'k', 'v' or 'kv' so unused entries can be reclaimed; omitted modes stay strong. Don't rely on when GC removes entries. Roblox does not support __gc or forced collectgarbage(), so don't depend on them to free memory. - **Avoid capturing per-instance locals in hot-path closures** (one-creator-repeated): Each closure allocates memory (~32 + 28n bytes by one Lua-article formula). Pass values as arguments (task.spawn, Future.new) so Luau can cache the function. Keep functions pure where practical; closures accessing only immutable module-scope upvalues are cached. - **Mutate arrays with table.insert and table.remove; mind reference semantics** (multiple-creators): Append with table.insert(array, value) or array[#array+1]. Assigning a table to a new variable creates a reference, not a copy. Sources: [Crusherfire 2024-05 1:21](https://youtu.be/NsPL5yDY5cE?t=81), [Stewiepfing 2026-03 5:06](https://youtu.be/JG1fkhCKAB4?t=306). Newest source 2026-03-15.

## Checklist
- [ ] Replace every wait() with task.wait(); use task.spawn/task.defer instead of spawn().
- [ ] Replace polling loops with event:Wait() or an event connection; check the flag first to skip yielding on already-fired events.
- [ ] Put --!strict on every script, or set the workspace type-check mode (Workspace.LuauTypeCheckMode) to strict.
- [ ] Annotate every function's parameters and return types, and annotate Instance-typed variables for autofill.
- [ ] Avoid any; if you must cast, cast once in a helper, not at every call site.
- [ ] After a nil guard, create a new local cast to the non-optional type (official 2026 note).
- [ ] Use typeof() for concrete types and IsA() to downcast Instances; type external input as unknown.
- [ ] Build shared types in a ModuleScript with export type and reference them as Types.Name.
- [ ] Use colon syntax for all instance methods; keep self-typed class methods.
- [ ] Cache services and frequently used paths in top-level locals; avoid globals in loops.
- [ ] Use rawget/rawset/rawequal inside metamethods that could re-enter themselves.
- [ ] Have arithmetic metamethods return new tables and call setmetatable on every result.
- [ ] Use weak tables (__mode) for caches; don't rely on GC timing or __gc.
- [ ] Use table.freeze for constants and deep-freeze nested config recursively.
- [ ] Remember arrays are 1-based; use #array, table.insert and table.remove (mind the shifting).
- [ ] Use tonumber() before comparing numeric strings and check nil on the result.
- [ ] Use backtick interpolation or string.format for building strings; add spaces explicitly with ..
- [ ] Escape magic pattern characters with % and anchor with ^ and $ when matching whole strings.
- [ ] Use int64 for Roblox IDs and check integers with math.floor(x) == x before passing to integer APIs.
- [ ] Use Random.new():NextInteger(1, #array) for random array picks.
- [ ] Remember 0 and empty strings are truthy; check them explicitly.
- [ ] Use camelCase for locals and functions, PascalCase for classes and services, LOUD_SNAKE_CASE for constants.
- [ ] Set --!optimize deliberately (1 in Studio testing, 2 in live games by default).
- [ ] Use variadic ... only at the outer level of a function; pack into a table before nested closures.
- [ ] Check syntax: commas between parameters, two commas in for headers, no code after return, consistent indentation.
- [ ] Replace legacy wait/spawn/delay with task.wait, task.spawn, task.defer or task.delay; choose spawn for immediate, defer for next-in-frame.
- [ ] When timing matters, capture task.wait's return value rather than assuming the requested duration.
- [ ] For coroutines, check coroutine.isyieldable() before yielding and use coroutine.status() and coroutine.close() for control.
- [ ] Put shared methods on the class table and set Class.__index = Class; chain subclasses via setmetatable(Subclass, {__index = Base}).
- [ ] Define __eq and __tostring on value-like metatables.
- [ ] Annotate class inheritance with intersections, wrap parent constructors, and set the child metatable after the child type.
- [ ] Initialise required table fields; reserve optional '?' for fields where nil is valid.
- [ ] Type callback parameters to the specific class (OnTouched, BasePart), not generic Instance.
- [ ] Pass optional arguments in one info table.
- [ ] Remove matching array items by looping backward and using numeric indexes only.
- [ ] Never insert into a table while iterating it; iterate array events in reverse when listeners change mid-fire.
- [ ] Use Promise.all for independent async work and promise:cancel with onCancel when UI or abilities end.

- [ ] Install Luau LSP, Selene linter, Roblox Lua Autocompletes and Roblox API Explorer in VSCode for IntelliSense and diagnostics.
- [ ] Use the Script Editor's static lint and type checking and its Engine API signatures while coding.
- [ ] Use table.concat, table.pack/unpack and table.clear for array operations.
- [ ] Use 'x or default' for nil fallbacks and remember 0 and '' are truthy.
- [ ] Use guard clauses to flatten nested ifs and delete unused variables and redundant checks.
- [ ] Use consistent dictionary key types; use Instances as keys with brackets.

- [ ] Add --!native to a script only when the whole script is performance-critical; otherwise use @native on specific hot functions.

- [ ] Add a doc comment above functions with annotated parameters so hover shows type and purpose.

## Where creators disagree
- **Casing of fields and methods**
  - B Ricey (T5749): PascalCase for fields and methods (self.CooldownTime), underscore + camelCase for private fields.
  - Roblox Creator Docs (T9658): PascalCase for classes and Roblox APIs, camelCase for locals, member values and functions.
  - DevForum (T5142): lowercase variables, PascalCase classes/Instances/Services.
  - Resolution: follow the official camelCase convention for member values and functions; all agree on PascalCase for classes and services.
- **Using any casts**
  - Crusherfire (T5945): cast only when inferred type is too generic.
  - DevForum (T5922): if Parent warns, cast the new parent to any.
  - Roblox official (T7170): casting to any silences the checker; prefer annotations.
  - Roblox official (T9717): wrap deep traversal in a generic helper that casts to any internally, not at each call site.
  - Resolution: prefer annotations; if a cast is unavoidable, cast once in a helper.
- **Nil narrowing after checks**
  - DevForum (T5914): refine with if-checks, and/or, early return or assert before indexing.
  - Roblox official (T9716, 2026-10, newest): Luau does not narrow types after guards yet; create a new local cast.
  - Resolution: the official 2026 note is newer; use the new-local-cast pattern if the checker still warns.
- **Annotation depth**
  - DevForum (T5413): avoid annotating variables assigned on the same line; inference handles it except for table and complex types.
  - Crusherfire (T5944): annotate Instance variables (e.g. Humanoid) for property autofill.
  - Resolution: both can hold; annotate for contracts and Instances, skip redundant same-line annotations.
- **Dot vs colon semantics**
  - Crusherfire (T5926): dot calls silently ignore the object.
  - Roblox official (T8206): table:Method() is identical to table.Method(table).
  - Resolution: colon is sugar that passes self; a dot call passes no self unless you pass the table explicitly.
- **Coroutine construct**
  - DevForum (T5266): prefer coroutine.wrap over create/resume for convenience; wrap does not return the success boolean.
  - No official coverage of coroutine construction in the sources.
  - Resolution: use wrap for fire-and-forget loops; use create/resume if you need the success boolean or status.
- **Whether to annotate return types in strict mode**
  - Suphi Kaner (T11812, 2023-08) says strict mode infers function return types and exports, so manual return annotations and export statements can be dropped.
  - Existing knowledge-base rule says annotate parameters and returns, and use explicit annotations to make intent clear. Keep annotating public returns and exported types for clarity, even though inference works.
- **Use coroutine.wrap or the task library for spawning loops**
  - Roblox DevForum tutorial (T11785, 2023-07) recommends the task library instead of coroutine.wrap for spawning loops.
  - XTB7 (T11880, 2023-10) presents coroutine.wrap as a shorter alternative to create plus resume.
  - Recommendation: prefer task.spawn for loops and keep coroutine.wrap for short resumable functions.
- **Default strictness of new scripts**
  - Suphi Kaner (T11805, 2023-08) suggests enabling the 'scripts are non-strict by default' beta or adding a mode comment because the default is no-check.
  - Roblox Creator Docs (T15290, 2026-10) says Luau is dynamically typed by default and advises enabling strict checking.
  - Recommendation: always add --!strict to scripts and do not rely on any beta default.
- **Scope of native code generation**
  - Stewiepfing (T17840): --!native at the top of a performance-critical script applies it to the whole file.
  - Existing knowledge file rule: use @native only on hot server functions (per-function scope).

## Instructions for an agent using this file
- If writing a new script, then start with --!strict, annotate parameters and returns, and cache services and module requires in top-level locals.
- If the code needs a delay or pause, then use task.wait(n) or task.delay; never use wait() or spawn() in new code.
- If waiting for a condition, then use event:Wait() or a connection after checking the flag first; don't loop with wait().
- If calling an instance method, then use colon syntax; reserve dot calls for functions that do not take self.
- If a value may be nil, then guard it with if/and/or, early return or assert, and re-cast to a non-optional local when the checker still warns.
- If the checker warns about a value you know is correct, then cast it with :: only at one localized place (or a single helper), not across call sites.
- If a metamethod re-enters the same table, then use rawget/rawset/rawequal inside it; if an arithmetic metamethod is defined, return a fresh table and call setmetatable on each result.
- If a cache holds instances or tables, then use a weak __mode table and don't depend on when entries are collected.
- If a function is in a hot loop and captures per-instance values, then pass values as arguments rather than creating closures each iteration.
- If you need to compare numeric strings or validate numbers, then convert with tonumber() and check nil, and use math.floor(x) == x before integer-only APIs.
- If code uses wait(), spawn() or delay(), replace with task.wait, task.spawn, task.defer or task.delay; use spawn for immediate, defer for next-in-frame.
- If a loop must not block, run it in its own thread with task.spawn and stop it with coroutine.close or a cancel flag.
- If a table is mutated while iterated, iterate in reverse for removals and never insert during pairs.
- If annotating a class, use intersections and wrap constructors with casts; set the child metatable after defining the child type.
- If a field may be nil, mark it optional; otherwise initialise it and annotate on the declaration.
- If a callback handles a specific class, type its parameter to that class instead of Instance.
- If many optional parameters are needed, pass one info table.
- If native compilation is requested, apply @native only to hot server functions and annotate arguments.
- If async work is independent, run it concurrently (Promise.all) and cancel with onCancel on exit.
- If an edit-time type error is suspected, remember typing does not change runtime behaviour; validate untrusted runtime input separately.
- If a task binds one handler to many UI buttons, use a GetDescendants loop with an IsA check.
- If a task defines player data or registry shapes, export a type and cast the data template or entries to it.
- If a task updates state from a read-only value, table.clone it before changing it.
- If a source is marked low-advice or is older than 2024, weight it below newer sources.
- If a user asks why a Connect handler runs immediately or never runs, check for parentheses after the handler reference first (T17780).
- If a binding is never reassigned, suggest const; if its table contents must also be immutable, suggest table.freeze on top of const (T17843).
- If the user asks for performance on a whole script, you may suggest --!native; for a single hot function, suggest @native instead.
- When writing a dictionary loop, do not claim ipairs-like stop behavior for for k, v in tbl; use ipairs only when stopping at nil matters.
- Format large literals with underscores when they exceed about six digits for readability.
- If a conditional value can be false or nil, do not use and/or as a ternary; use an if-expression or an explicit if block.
- If you need a whole-number result from division, use //.
- If a loop value is unused, name it _.
- If module state is internal, prefix it with _ and expose it through functions. Treat this as a naming convention, not enforced privacy.
- If you annotate function parameters, add a doc comment above the function so hover shows both type and purpose.
- If you place an object relative to a surface, use PointToObjectSpace on the surface-normal CFrame and read the components.
- If a new source item restates an existing rule (for example Event:Once or Event:Wait for yielding on events), skip it rather than adding a duplicate; only add the frame-timing distinction between RenderStepped and Heartbeat (T18515).
- If a handler is wired to exactly one event, inline it as an anonymous function inside Connect (T19005).
- If a handler is shared across several events or reused, define it as a named local and pass the reference to Connect (T19005).
- When writing an if or while condition, use == or ~=, never a single = (T19006).
- Treat the existing 'pass function references to Connect' rule as still in force; inline functions are an exception only for single-use handlers (T19005).

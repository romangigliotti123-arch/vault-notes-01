# Remote and mobile UX: reporting, notifications, approvals, trust

Scope: how the manager should talk to Roman on a phone (Remote Control app, optionally Telegram), when to ping, how to ask, how to show evidence, how to hand over long-running work. Report-format side for workers: [[topic-report-formats-and-verification]]. Synthesised by the lead from src- notes (worker stopped by usage limit).

## TL;DR
- Oversight by exception works; approve-every-step does not. Anthropic's telemetry: users approve ~93% of prompts, experienced users auto-approve more but interrupt more; on complex tasks Claude's own clarification stops outnumber human interruptions; "requiring humans to approve every action will create friction without necessarily producing safety benefits". Design for glanceable status and cheap redirection. [[src-anthropic-measuring-agent-autonomy]], [[src-anthropic-claude-code-auto-mode]]
- Ask only when different readings would lead to materially different work; make the question decision-ready (options, a default, the cost of waiting), and batch questions into one interruption. [[src-magentic-ui-paper]], [[src-anthropic-measuring-agent-autonomy]], [[topic-anthropic-agent-guidance]] rules 11-13
- Push is the only way a result reaches Roman while he is away: the platform pushes "when Claude decides" and "when actions are required"; no per-event configuration beyond two toggles; pushes are skipped when focused on the terminal and may be delayed by phone Focus modes. Use `PushNotification` for finished long tasks and an out-of-band channel (ntfy) for "the manager itself is dead". [[src-ccdocs-remote-control]], [[src-ntfy-docs-priorities]], [[src-rogs-claude-code-mosh-tmux-ntfy]]
- Proactivity has a cost: frequent unsolicited suggestions annoy; even tuned models misjudge about a third of "should I speak up" decisions. Roman has already said: no recurring reports, pull not push. [[src-proactive-assistant-papers]]
- Outcome first, then at most one "needs you" paragraph, no working shorthand; artifacts and proof attached (files, screenshots) so he can validate without redoing the work. [[src-anthropic-prompting-fable-5]] (via [[topic-anthropic-agent-guidance]] rule 22), [[src-cursor-cloud-agents-self-hosted]], [[src-claude-cowork-product-page]]

## Rules
1. **Lead with the result in one sentence, then evidence, then what you need.** Anthropic's guidance for the final message after an unattended stretch: outcome first, then the one or two things needed from the reader, each explained as if new; drop working shorthand. Cursor's background agents attach screenshots/video/logs so the user can "validate the work without checking out the branch". For Roman: result sentence; 1-3 bullet facts; artifact path or `SendUserFile`; own paragraph at the bottom for anything he must do (already his rule). Evidence: [[src-anthropic-prompting-fable-5]], [[src-cursor-cloud-agents-self-hosted]]. Confidence: high.
2. **Be explicit about capability and confidence (HAX G1/G2) and about uncertainty.** "Done and verified" vs "done, not verified" vs "partial" must be visually distinct in the first line; never present an unchecked worker claim as fact. Evidence: [[src-hax-guidelines-human-ai]] (CHI 2019), [[src-anthropic-computer-use-tool-doc]]. Confidence: med-high.
3. **Make correction cheap (G9) and undo visible.** Phone text should offer the defaults ("say 'no' to cancel; I'll do X in 10 min otherwise" only for reversible actions; never act on silence for irreversible ones). Cognition: Devin does worse when told more after it starts, so scope up front, and expect redirections to be expensive for workers mid-task. Evidence: [[src-hax-guidelines-human-ai]], [[src-cognition-devin-2025-review]]. Confidence: med.
4. **Batch questions; one interruption beats three.** Magentic-UI study (N=12): participants preferred multiple questions asked in one interruption; low-risk approvals felt unnecessary, high-risk ones (payment, sending email, subscribing) were endorsed; they asked for a third option beyond allow/deny (e.g. "allow once and tell me", "change the plan"). Evidence: [[src-magentic-ui-paper]]. Confidence: med (small study).
5. **Treat the phone as a low-bandwidth, interrupt-driven channel.** Questions block via `AskUserQuestion`/permission prompts that stay open until answered (no timeout) over Remote Control; other forwarded dialogs expire after 5 minutes (`dialogExpiry`). A question without a stated default stalls the job until Roman looks; set `askUserQuestionTimeout` (already "5m" in settings.json) deliberately: it auto-continues the session, so phrase questions so that auto-continue is safe (default = safest option). Evidence: [[src-ccdocs-remote-control]], [[src-ccdocs-headless-cli]]. Confidence: high.
6. **Know what works from the phone.** As text commands: /compact /clear /context /usage /exit /recap, and with arguments /model /effort /rename /config /output-style (built-in styles only) /focus; queued messages run after the current turn, while `/status`, `/tasks`, `/usage` run immediately even mid-response; local-only: /plugin, /resume; connector re-auth cannot be done from the phone; `/recap` gives a 400-char summary. Teach Roman these in one README line. Evidence: [[src-ccdocs-remote-control]], [[src-ccdocs-hooks-notifications-recap-goal]]. Confidence: high.
7. **Notification policy: three events, two priorities.** The practitioner pattern: needs-input = high, finished = default, error = high, and suppress when the user is already attached; self-hosted ntfy with tokens that expire. In our stack: Claude's own push covers input-needed and long-finish; add an independent alert (ntfy/Telegram send script) only for "the manager is down / restart loop breaker open / limit hit with jobs pending". Keep low-priority (priority 2) for digests Roman asked for. Evidence: [[src-rogs-claude-code-mosh-tmux-ntfy]], [[src-ntfy-docs-priorities]], [[src-ccdocs-hooks-notifications-recap-goal]]. Confidence: med.
8. **Presence-aware pushes.** `CLAUDE_CLIENT_PRESENCE_FILE` suppresses pushes while a marker file exists (a screen-lock listener can toggle it); iOS Focus and Android battery optimisation can drop pushes; "No mobile registered" in `/config` means open the app. Roman is always on a phone, so nothing here applies unless pushes silently stop: add a monthly "test push" check. Evidence: [[src-ccdocs-remote-control]]. Confidence: high.
9. **Progress updates: one sentence before the first tool call, then only on findings or direction changes; a harness nudge after ~5 silent steps halved long silences.** Long worker jobs should write a progress line to a file (not chat) so the manager can answer "what's happening" without interrupting. Telegram `edit_message` edits do not ping; send a new message on completion. Evidence: [[src-anthropic-prompting-fable-5]], [[src-gh-claude-telegram-plugin]]. Confidence: med-high.
10. **Introspection commands as a first-class feature.** Hermes and OpenClaw expose `/status`, `/stop`, `/usage`, `/undo`, `/new`; the Telegram plugin has no "what are you doing" command (its `/status` shows pairing). On RC, `/tasks` and `/status` work. Give Roman a "what's running" macro: manager answers from the job ledger in 3 lines. Evidence: [[src-hermes-agent-readme]], [[src-gh-claude-telegram-plugin]], [[src-ccdocs-hooks-notifications-recap-goal]]. Confidence: med.
11. **Approvals: specific, one action, with the danger named; inline buttons only exist for the built-in permission relay in the Telegram plugin.** The model-facing `reply` tool has no buttons, so ordinary questions are plain text ("reply YES/NO"). The first answer (terminal or remote) wins. Anyone who can reply through a channel can approve tool use, so allowlist only Roman. Evidence: [[src-ccdocs-channels]], [[src-gh-claude-telegram-plugin]], [[src-anthropic-claude-code-auto-mode]]. Confidence: high.
12. **Co-planning for expensive jobs.** Magentic-UI users valued editing the plan before execution; Cowork shows each step and lets you redirect. For jobs expected to cost much (many workers, high effort), send a 3-line plan with cost class and wait for a thumbs-up unless Roman said to just do it. Evidence: [[src-magentic-ui-paper]], [[src-claude-cowork-product-page]]. Confidence: med.
13. **Quiet and global controls (HAX G17).** A single phrase ("quiet", "pause all", "stop") that Roman can send which cancels or freezes non-essential work and silences non-critical pushes; must be mechanical (ledger state + kill switch), not just prose. Evidence: [[src-hax-guidelines-human-ai]]. Confidence: med.
14. **Set expectations in stages (PAIR): say what the system can do, cannot do, how it may change.** Mismatched mental models cause misuse and abandonment; tell Roman when behaviour changes (new rule, new preset, model switch) in one line. Evidence: [[src-pair-guidebook]], [[src-hax-guidelines-human-ai]] G18. Confidence: med.
15. **Honest failure messages with a path forward.** PAIR: explain why a result could not be given and offer alternatives; when handing control back, make it easy to pick up where the system left off. Evidence: [[src-pair-guidebook]]. Confidence: med.
16. **Agents are junior at execution and best on clear, verifiable tasks.** Devin's own review and Karpathy ("they just don't work" as unattended employees; learn what they are good at) argue for scoping work up front and keeping the human as verifier on unverifiable output. Evidence: [[src-cognition-devin-2025-review]], [[src-karpathy-decade-of-agents]]. Confidence: med (vendor/opinion).

## Where sources disagree
- **How proactive to be.** Studies say frequent suggestions annoy; products (OpenClaw heartbeats, Hermes cron) push proactivity; Roman explicitly declined recurring reports. Follow Roman: pull by default, alerts only on exceptions.
- **Approve everything vs oversight by exception.** Magentic-UI users liked guards for high-risk actions and disliked them for low-risk; Anthropic telemetry shows approval fatigue. Both support classes of risk (see [[topic-multi-agent-frameworks]] C3).
- **Where updates live.** Codex/Cursor use Slack/PR + proof; Cowork uses an in-app step list. We have chat + files.

## Applies to us
- Current: reply-format rule (no footer, own paragraph for Roman's to-dos) is aligned; `askUserQuestionTimeout: 5m`, `agentPushNotifEnabled`, `inputNeededNotifEnabled` on; Telegram plugin not wired for inbound; no ntfy path; no ledger to answer "what's running"; output style not set; CLAUDE.md's Telegram "two-part reply with voice note" rule is obsolete while the channel is off.
- Risk: after a limit stop or manager death, Roman gets nothing (RC is silent). The one thing a phone user cannot do is notice silence.

## Candidate changes for us
- **C1 (CLAUDE.md "Reply format" replacement, 6 lines):** "Reply = (1) one sentence outcome with status word DONE/PARTIAL/BLOCKED/UNVERIFIED, (2) at most 3 short bullets of facts, (3) artifact paths/links, (4) a final paragraph starting 'You:' only if Roman must act, with a default if he does nothing. No tables, no headers, no footers. Never ask a question you can answer by reading a file; batch unavoidable questions into one message with a default." Evidence: rules 1, 4. Replace the obsolete Telegram two-part reply rule.
- **C2 (decision-ready question template):** "Question: <decision>. Options: A <cost/risk>, B <cost/risk>. I will do <default> at <time> if you do not answer (only for reversible choices)." Evidence: rules 3-5.
- **C3 (dead-man alert):** a scheduled script (no LLM) that sends an ntfy/Telegram message only if the supervisor breaker opens or the master has been dead > 15 min while jobs are open. Needs Roman's OK to add a notification endpoint (new external service/credential). Evidence: rule 7; ties to [[topic-long-running-always-on-agents]] C6.
- **C4 ("what's running" macro):** CLAUDE.md line: "If Roman asks status: run `jobs.py list`, answer in <= 4 lines (running, waiting on you, done today, problems)." Evidence: rule 10.
- **C5 (output style):** `phone-manager` custom style (see [[topic-claude-code-features]] C5) or built-in `Concise` from RC (works from the phone today: `/output-style concise`). Evidence: rule 6.
- **C6 (plan-before-spend):** for jobs forecast to use > 3 workers or high effort fan-out, send a 3-line plan with expected effort/limit use and proceed only after a yes (or if Roman said "just do it"). Evidence: rule 12; cost data in [[topic-model-effort-routing-cost]].
- **C7 ("quiet"/"stop" command):** define in CLAUDE.md: "stop" = `claude stop`/TaskStop all running workers, mark ledger jobs cancelled, reply with the list; "quiet" = no pushes except breaker alerts until "unquiet". Evidence: rule 13.

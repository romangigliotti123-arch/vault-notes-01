# Knowledge management, retrieval (RAG), and memory for the manager

Scope: how an always-on agent should store, find, trust and retire knowledge (second brain / LLM wiki, RAG, agentic search, graph and memory systems, note formats, rot, lessons and decision logs). Sibling topics: [[topic-skill-library-retrieval]] (finding skills/agents), [[topic-context-engineering]] (what stays in the window; its C2 and C8 already propose moving state out of CLAUDE.md and a lessons directory, this file does not repeat them but gives the structure, retrieval and upkeep design), [[topic-context-window-management]], [[topic-long-running-always-on-agents]], [[topic-agent-security]]. Mechanics research: manager-setup.md.

Facts about the current setup (measured 2026-10-29): `~\.claude\CLAUDE.md` = 143 lines but 29,527 chars (~7.4k tokens), lines up to 2,662 chars; loaded every turn and into every subagent. Section sizes: "Pending work" 5,004 chars (16.9%, almost all finished history), "Upkeep" 1,466, "Health monitoring" 1,123 and "Weekly report" 501 (both DISABLED but still spelled out), "Other devices" 2,083 (partly superseded by "Linux power", 2,123). About 34% of the file is history, disabled features or superseded text. Durable knowledge elsewhere: `claude-host\log.md` (118 lines, chronological, mixed ops and learnings), `claude-host\session-notes\*.md`, one auto-memory file (`no-maintenance-reports.md`), the library vault (generated), `manager-kb\` (this KB). There is no lessons log, no decision log, no lint, no note schema.

## TL;DR
- Corpus under ~200k tokens: just load it, no RAG (Anthropic). Our durable notes are far under that; the problem is NOT retrieval power, it is rot, contradiction and a fat always-loaded file. [[src-anthropic-contextual-retrieval]], [[src-ccdocs-memory]]
- Default retrieval for agent-readable notes = agentic search (grep/glob/read) over small, well-named, front-loaded files with an index. Add hybrid BM25 + embedding + rerank only when a measured eval shows grep failing (big corpus, vocabulary mismatch). [[src-cherny-agentic-search-officechai]], [[src-cursor-semantic-search]], [[src-qmd-readme]]
- Karpathy's pattern fits us: raw sources (never edited) / LLM-owned wiki / schema file, plus `index.md` (catalogue) and `log.md` (append-only), with ingest, query and LINT operations. [[src-karpathy-llm-wiki]]
- Writing is the hard part: retrieval over files is competitive with heavy memory frameworks; what degrades memory is unreliable write-time curation and whole-file LLM rewrites (brevity bias, context collapse). Append small dated deltas; distil with a curator pass. [[src-openclaw-docs-memory-architecture]], [[src-arxiv-ace-agentic-context-engineering]]
- An always-loaded instruction file must stay short, non-contradictory and non-obvious-only: under 200 lines, no repo-overview filler; context files raised cost 20%+ with no reliable success gain. [[src-ccdocs-memory]], [[src-arxiv-evaluating-agentsmd]]
- Must-happen knowledge goes in always-loaded text or hooks, not behind a lookup the model has to decide to do (skills were never invoked in 56% of Vercel's eval cases; a passive AGENTS.md index scored 100% vs 53%). [[src-vercel-agentsmd-outperforms-skills]]
- Every note carries provenance (source, date, confidence) and status; superseded facts are marked, not silently overwritten or left contradicting. [[src-arxiv-zep]], [[src-graphiti-readme]], [[src-arxiv-longmemeval]]
- Measure retrieval on your own queries (hit@k, MRR) before adopting any framework; generic IR quality does not transfer. [[src-arxiv-toolret]], [[src-arxiv-skillseek]]

## Rules
### A. Whether to retrieve at all, and how
1. **If the knowledge base is under ~200k tokens, put it in context instead of building RAG.** Anthropic: below 200,000 tokens (about 500 pages) include the whole knowledge base in the prompt. For us: the always-needed facts (CLAUDE.md-class) should be loaded, everything else is a few hundred KB of files read on demand. Evidence: [[src-anthropic-contextual-retrieval]] (https://www.anthropic.com/news/contextual-retrieval, 2024-09-19). Confidence: high (official; "context rot" caveats in rule 22).
2. **Default to agentic search (grep, glob, read) for corpora an agent can navigate; do not build a vector index first.** Claude Code started with RAG on a local vector DB and "landed on just agentic search" because it "outperformed everything else by a lot", the index drifts out of sync with the files, and it avoids security/privacy/staleness issues; Cline likewise: "An index, by definition, is a snapshot frozen in time." Cost named: latency and tokens. The evidence is self-described "mostly vibes", so this is practitioner opinion, not a benchmark. Evidence: [[src-cherny-agentic-search-officechai]] (2025-05-27), [[src-cline-no-index]] (2025-05-27), [[src-anthropic-effective-context-engineering]] (2025-09-29: hold lightweight identifiers, load just-in-time with glob/grep). Confidence: med.
3. **Add semantic/hybrid retrieval when a measured eval shows keyword search failing, and expect the gain to grow with corpus size.** Cursor's A/B: semantic search gave "on average 12.5% higher accuracy" (6.5% to 23.5% by model), +2.6% code retention on 1,000+ file codebases, and "the combination of [grep and semantic search] leads to the best outcomes". Evidence: [[src-cursor-semantic-search]] (2025-11-06, vendor evals). Confidence: med (vendor, code domain).
4. **Hybrid beats either alone: BM25 for exact identifiers plus dense vectors, fused by Reciprocal Rank Fusion.** RRF = sum of 1/(rank+k), k=60, no score normalisation needed; semantic reranking applied after fusion. qmd ships exactly this on local markdown (FTS5 BM25 + 300 MB embedding model + 640 MB reranker, RRF k=60, rerank top 30). Evidence: [[src-azure-hybrid-rrf]] (page dated 2026-06-08), [[src-qmd-readme]], [[src-anthropic-contextual-retrieval]]. Confidence: high for RRF mechanics; med for qmd quality (own tiny fixture).
5. **If you index chunks, add document context to each chunk before embedding AND before the BM25 index.** Contextual Embeddings cut top-20 retrieval failures 5.7% -> 3.7% (35%); with Contextual BM25 2.9% (49%); plus reranking 1.9% (67%); one-time cost $1.02 per million document tokens with prompt caching. Cheaper alternative needing no LLM calls: late chunking (embed the whole text with a long-context model, pool per chunk). Evidence: [[src-anthropic-contextual-retrieval]] (measured, Anthropic), [[src-arxiv-late-chunking]] (abstract only, no metrics). Confidence: high / low.
6. **Rerank a wide candidate list (20-50) down to 3-5 results; three candidates capture almost all the gain.** Anthropic reranks top-N; SkillSeek found "Top-3 captures essentially all the gain over rank-1" and that a small cross-encoder only helps in proportion to how far first-stage recall is from ceiling. Evidence: [[src-anthropic-contextual-retrieval]], [[src-arxiv-skillseek]] (2026-09-30). Confidence: med-high.
7. **Let the calling agent do query rewriting; do not build HyDE infrastructure for a single LLM-driven user.** HyDE (LLM writes a hypothetical answer, embed it) costs an extra LLM call per query and needs a capable model; qmd's typed expansions (lex/vec/hyde) and SkillSeek's "LLM refinement loop" show the same idea. Our manager IS the LLM: have it write 2-3 keyword variants itself (see [[topic-skill-library-retrieval]] rule 6). Evidence: [[src-arxiv-hyde]] (2022-12), [[src-qmd-readme]], [[src-arxiv-skillseek]]. Confidence: med (our inference from cited sources).
8. **Chunk markdown on its own structure, ~900 tokens with ~15% overlap, never inside a code fence; for atomic notes the note IS the chunk.** qmd scores heading/fence/blank-line break points. Chunking that tears code or reasoning apart is the main objection to naive RAG. Evidence: [[src-qmd-readme]], [[src-cline-no-index]]. Confidence: med.
9. **Use graph-style indexes only for question types vectors cannot answer.** GraphRAG targets global sensemaking ("what are the main themes in the dataset?") via entity graph plus pre-generated community summaries and beats plain RAG on comprehensiveness at ~1M tokens, at the price of an LLM pass over everything. Structural questions (call chains, change impact) need graph structure; "similarity does not equal relevance". LightRAG adds incremental updates; Graphiti/Zep add bi-temporal edges for changing facts; Cognee packages remember/recall/improve/forget. None is justified for a few hundred notes. Evidence: [[src-arxiv-graphrag]] (2024-04), [[src-devto-representation-problem]], [[src-arxiv-lightrag]] (abstract only), [[src-graphiti-readme]], [[src-cognee-readme]]. Confidence: med.
10. **A repo-map / index file is the cheapest structural retrieval layer.** Aider's tree-sitter map ranks files by dependency graph to fit a token budget (default 1k); our equivalent is a one-line-per-note `index.md`. Evidence: [[src-aider-repomap]] (2023-10-22), [[src-karpathy-llm-wiki]]. Confidence: med.

### B. Second-brain design for agents
11. **Three layers: raw sources (read-only), an LLM-owned wiki, and a schema file; two navigation files: `index.md` (content catalogue) and `log.md` (append-only chronology).** Operations: ingest (one source may touch 10-15 pages), query (answers worth keeping are filed back as pages), lint (contradictions, stale claims, orphans, missing cross-references). "The wiki is a persistent, compounding artifact." Evidence: [[src-karpathy-llm-wiki]] (2026-04-04, idea gist, not benchmarked), community implementations [[src-obsidian-claude-second-brain-snippets]] (snippets only). Confidence: med (influential, no evidence of retrieval gains).
12. **One idea per note, stable unique ID, links that say why they exist, and structure notes as entry points.** Zettelkasten atomicity; "A Structure Note is a Meta-Note"; MCP memory server: observations "should be atomic (one fact per observation)". LYT's Maps of Content = hand-curated hubs (definition not verified from source). Evidence: [[src-zettelkasten-intro]], [[src-mcp-memory-server-readme]], [[src-lyt-linkingyourthinking]] (weak). Confidence: med (practitioner method; fits LLM retrieval because atomic notes are self-contained chunks).
13. **Organise by actionability and scope, archive instead of delete.** PARA: Projects, Areas, Resources, Archives; the useful part for an agent is that "archive" is excluded from default search while remaining recoverable (also required by Roman's confirm-before-delete rule). Evidence: [[src-forte-para]] (2023-02-24, updated 2026-04-15). Confidence: low-med (human filing scheme, no agent evidence).
14. **Front-load every note: frontmatter with a one-line `description`, then the summary/answer, then detail.** Letta context repositories load a per-file frontmatter description for progressive disclosure; Anthropic skills load name+description first; models recall best from the start and end of long inputs. Evidence: [[src-letta-sleep-time-and-context-repos]] (2026-02-12), [[src-anthropic-agent-skills]], [[src-arxiv-lost-in-the-middle]]. Confidence: med.
15. **Keep the memory directory small and hierarchical: Letta's target is "a clean hierarchy of 15-25 focused files"; Claude Code loads the first 200 lines / 25 KB of MEMORY.md and moves detail to topic files.** Evidence: [[src-letta-sleep-time-and-context-repos]], [[src-ccdocs-memory]]. Confidence: med.

### C. Freshness, provenance, rot
16. **Record provenance on every durable claim: source (URL/file/who said it), date, confidence, and who wrote it (owner / agent / tool output).** OpenClaw makes "the write path the security boundary": provenance classes owner/agent/untrusted/system, network tool results taint the rest of the turn, and cron/sub-agent sessions never create durable memories because audits found most auto-captured memories were "restatements of runtime instructions, heartbeat noise, and recall feedback loops". Evidence: [[src-openclaw-docs-memory-architecture]] (project docs, claims not independently verified), [[src-snyk-toxicskills]] (malicious skills persist through SOUL.md/MEMORY.md edits). Confidence: med.
17. **Facts change: mark superseded facts with a validity end and a pointer to the replacement; never leave old and new text side by side.** Graphiti: "old facts are invalidated, not deleted"; LongMemEval tests knowledge updates and temporal reasoning explicitly and found commercial assistants lose ~30% accuracy over sustained interaction; Claude Code: contradicting instructions make the model "pick one arbitrarily". Evidence: [[src-graphiti-readme]], [[src-arxiv-zep]] (vendor numbers: DMR 94.8% vs 93.4%, LongMemEval up to +18.5%), [[src-arxiv-longmemeval]] (snippet only), [[src-ccdocs-memory]]. Confidence: med-high.
18. **Run a lint pass on demand: broken links, orphans, missing frontmatter, stale `updated`, contradictions, index mismatches. Report findings; fix only on request.** Karpathy: "Periodically, ask the LLM to health-check the wiki." Claude Code ships `/doctor prompt-audit` for instruction files (instructions for older models, dead file references, contradictions; report only). Evidence: [[src-karpathy-llm-wiki]], [[src-ccdocs-memory]], [[src-obsidian-claude-second-brain-snippets]]. Confidence: med-high.
19. **Do not let an LLM rewrite a whole memory file; append small dated deltas, then curate.** ACE names "brevity bias" (concise summaries drop domain insights) and "context collapse" (iterative rewriting erodes details) and fixes them with structured incremental updates (+10.6% on agent benchmarks, +8.6% on finance). Reflexion/ExpeL: distil lessons from real outcomes, recall them later; reflection helps when grounded in an external pass/fail signal. Evidence: [[src-arxiv-ace-agentic-context-engineering]] (ICLR 2026), [[src-arxiv-expel]], [[src-shinn-reflexion]]. Confidence: med-high.
20. **Retrieval over plain files is competitive; the hard part is deciding what to write.** Letta's agent with only grep/search_files/open/close over files scored 74.0% on LoCoMo (gpt-4o-mini) vs Mem0's reported 68.5%, concluding "agent capabilities matter more than the tools"; OpenClaw: "Writing is the hard part". Disputed (see below). Evidence: [[src-letta-filesystem-benchmark]] (2025-08-12), [[src-openclaw-docs-memory-architecture]]. Confidence: med-low (vendor benchmark dispute).
21. **Use memory frameworks only after files+grep fail your own eval.** Options and their claims: Mem0 (extract/update/delete facts; 91% lower p95 latency and >90% token saving vs full context, +26% relative on LOCOMO LLM-judge, vendor), Zep/Graphiti (temporal graph; needs graph DB, LLM, embedder), Letta/MemGPT (tiered memory, files), MCP memory server (entities/relations/observations in JSONL; no timestamps or provenance), Cognee (graph, local GLiNER; production Postgres graph is licensed). Evidence: [[src-arxiv-mem0]], [[src-arxiv-zep]], [[src-arxiv-memgpt]], [[src-mcp-memory-server-readme]], [[src-cognee-readme]]. Confidence: med (all vendor-measured).
22. **More context is not free: accuracy degrades with input length, and distractors and placement matter.** Chroma tested 18 models and found non-uniform degradation even on trivial tasks; Lost in the Middle: best recall at the start and end. Therefore return 3-5 focused snippets, not a dump. Evidence: [[src-chroma-context-rot]] (2025-07-14, snippet-level here), [[src-arxiv-lost-in-the-middle]] (2023, older models), [[src-anthropic-effective-context-engineering]]. Confidence: med.

### D. The always-loaded file and who reads what
23. **Keep every always-loaded instruction file under ~200 lines; use path-scoped rules or on-demand files for the rest.** "Longer files consume more context and reduce adherence"; @imports organise but do not save tokens; CLAUDE.md is "context, not enforced configuration" and arrives as a user message, so must-happen actions need a hook. Evidence: [[src-ccdocs-memory]] (official). Confidence: high.
24. **Put only non-obvious instructions in context files; repo/directory overviews do not help.** ETH Zurich (ICLR 2026): context files do not generally improve success and raise inference cost by over 20% on average; useful for "non-standard coding practices"; "any attempts to improve performance should be rigorously evaluated before deployment". Evidence: [[src-arxiv-evaluating-agentsmd]] (2026-02-12, v3 2026-09-29), [[src-humanlayer-skill-issue-harness]] (practitioner corroboration). Confidence: high for the direction, med for size of effect (Python SWE tasks).
25. **Knowledge the agent must have on every job belongs in always-loaded text (a compact index) or a hook, not behind an optional lookup.** Vercel: "In 56% of eval cases, the skill was never invoked"; pass rates 53% (baseline), 53% (skill default), 79% (skill with explicit instruction), 100% (AGENTS.md docs index). Evidence: [[src-vercel-agentsmd-outperforms-skills]] (2026-01-27, one task family). Confidence: med.
26. **Subagents should not inherit the manager's whole CLAUDE.md by default.** Workers currently re-read the 29.5 KB file; narrow workers should get only the facts they need (`omitClaudeMd: true` exists per manager-setup.md; a short `worker-facts.md` carries the confirm-first list). Evidence: manager-setup.md section 2.3, [[src-ccdocs-memory]]. Confidence: med.

### E. Records the manager should keep
27. **Keep two small append-only records: a lessons log (what surprised us, what worked, rule to apply next time) and a decision log (what Roman/manager decided, why, what supersedes it).** Basis: Karpathy `log.md` append-only; Anthropic memory-tool multisession pattern (progress log, feature checklist; read first, update at end; mark done only after end-to-end verification); ADR = one decision with rationale, the set forms the decision log; ExpeL distils insights and recalls them. Entry format and distillation: see C3-C4. Evidence: [[src-karpathy-llm-wiki]], [[src-anthropic-memory-tool-doc]], [[src-adr-github-io]] (thin page; fields and immutability are general practice, not verified), [[src-arxiv-expel]]. Confidence: med.
28. **Distil, do not accumulate: promote a lesson to a standing rule only after it recurs or is verified; keep the rules file short.** ACE curator role and ExpeL insight extraction; Anthropic memory tool: "periodically delete memory files that haven't been accessed in a long time", keep content "up-to-date, coherent and organized". Evidence: [[src-arxiv-ace-agentic-context-engineering]], [[src-arxiv-expel]], [[src-anthropic-memory-tool-doc]]. Confidence: med.
29. **Log what was retrieved and what was used, so retrieval can be evaluated and notes pruned.** Claude Code's `/skill-doctor` reports cost vs invocation counts per skill; the `InstructionsLoaded` hook logs which instruction files loaded and why. For notes, a one-line query log is the cheapest equivalent. Evidence: [[src-ccdocs-skills]], [[src-ccdocs-memory]], [[src-arxiv-skillseek]] (R@5 higher does not imply higher pass rate: measure outcomes). Confidence: med.
30. **Evaluate retrieval on your own queries before and after any change.** Generic IR strength does not transfer ("Retrieval Models Aren't Tool-Savvy"); Anthropic reported failure-rate-at-20 on its own corpus; Anthropic's own skill guidance: "Create evaluations BEFORE writing extensive documentation". A 30-50 query set with known right answers is enough to see a 2x difference (see [[topic-skill-library-retrieval]] measurement in section "Applies to us"). Evidence: [[src-arxiv-toolret]], [[src-anthropic-contextual-retrieval]], [[src-anthropic-skill-best-practices-doc]]. Confidence: med-high.

## Where sources disagree
1. **Agentic grep vs vector index.** Claude Code/Cline (Cherny, Baumann): no index, search live, index goes stale, "mostly vibes" evidence. Cursor: semantic search + grep best, measured +12.5% (vendor A/B, large repos). Contextual Retrieval/qmd: hybrid wins on large text corpora. Resolution for us: the corpus is small, markdown, and changes daily, so follow Claude Code (grep + index) now; revisit with an eval if the library/vault grows past what an index.md can cover. [[src-cherny-agentic-search-officechai]] vs [[src-cursor-semantic-search]].
2. **Memory frameworks vs plain files.** Mem0/Zep publish gains over full-context and OpenAI memory; Letta shows grep-over-files at 74.0% beating Mem0's reported 68.5% but Mem0 now lists 92.5 itself (snippet only) and Letta has not re-run; LoCoMo does not score knowledge updates (commentary). Follow plain files + a curator; the benchmark dispute means no framework has independent evidence for a single-user manager. [[src-letta-filesystem-benchmark]], [[src-arxiv-mem0]], [[src-arxiv-zep]].
3. **Skills/on-demand loading vs passive context.** Anthropic: progressive disclosure keeps context small. Vercel: passive index 100% vs skills 53-79%, 56% never invoked. ETH Zurich: context files give no reliable gain and cost 20%+. These are compatible if read as: keep the always-on layer tiny but make it an INDEX that names what to load and when, and enforce the must-do steps with hooks. [[src-anthropic-agent-skills]], [[src-vercel-agentsmd-outperforms-skills]], [[src-arxiv-evaluating-agentsmd]].
4. **LLM-owned wiki vs append-only discipline.** Karpathy: "The LLM owns this layer entirely" and rewrites pages on ingest. ACE/OpenClaw: unreliable write-time curation and whole-file rewrites are what rot memory (context collapse). Follow the middle path: LLM edits individual atomic notes (small diffs, git-tracked), logs and lessons are append-only, and a curator proposes changes to the rules file rather than rewriting it. [[src-karpathy-llm-wiki]] vs [[src-arxiv-ace-agentic-context-engineering]], [[src-openclaw-docs-memory-architecture]].
5. **How much does GraphRAG buy?** GraphRAG/LightRAG/Graphiti papers and READMEs claim gains but several numbers are abstract-only or vendor tables ("sub-second vs tens of seconds" with no method). Skeptical position (devto essay): choose by data structure, vectors cannot answer structural questions. For our ~6,000-item library the graph in `vault-graph` is hub-and-spoke (see Applies to us); do not invest more until an eval says so. [[src-arxiv-graphrag]], [[src-graphiti-readme]], [[src-devto-representation-problem]].
6. **Contextualise chunks with an LLM or with late chunking?** Anthropic measured the LLM route (-35/-49/-67% failures); late chunking has no reported metrics in the abstract and needs a long-context embedding model. Irrelevant until we embed anything; prefer atomic notes so chunking is unnecessary. [[src-anthropic-contextual-retrieval]], [[src-arxiv-late-chunking]].

## Applies to us
Rule-by-rule against the CURRENT setup (read 2026-10-29), critical:
- **Rule 1/2 (small corpus, agentic search): already effectively true but unused for notes.** Durable facts are small; the manager greps nothing because the facts are baked into CLAUDE.md. Fix = move them to files + a short index (C1, C2), not build RAG.
- **Rules 23/24/25 (always-loaded file): FAILING.** 29.5 KB, 143 lines with paragraphs up to 2.6k chars (the "Linux power" and "Pending work" lines are single giant lines, hard for humans and models to scan). One third is history, disabled features or superseded text. Direct contradiction found: "Naming" says "turn off my pc" = `linux-power.ps1 -Action sleep`, while the "Linux 'off' (quiet mode)" section says "When Roman says to turn it off ... run quiet.sh on"; the "Other devices" paragraph still says Wake-on-LAN will not work and "Pending work" item 2 says "NEVER suspend or shut down the Linux machine", with the "Linux power" section stating it "SUPERSEDES every earlier note". The contradicting text was left in place, which is exactly the "pick one arbitrarily" failure (rule 17). The fix is deletion/relocation of superseded text, not more notes.
- **Rule 17 (supersession): manual and inconsistent.** Some sections say "(replaces the old ...)" in the heading, others keep old text. Adopt a single convention: superseded text moves to `claude-host\notes\history.md` with a dated one-liner; the live file never contains both.
- **Rules 16/18 (provenance, lint): missing.** No source/date on facts (some headings carry a date, e.g. "(Roman's request, 2026-10-28)", which is good provenance for instructions but absent for facts such as the Wi-Fi MAC or the Tailscale ACL). No lint. NOTE: Roman disabled recurring reports and checks (CLAUDE.md "DISABLED ... do not re-enable"), so lint must be on-demand or run silently inside another routine, never a scheduled report (C6).
- **Rules 27/28 (lessons and decision logs): missing.** `log.md` is a chronological ops diary (118 lines) with learnings buried in it (e.g. "resumed session has no bypass flag so the watchdog restarted ClaudeHost"); a lesson like that is only recoverable by reading the whole log. The one auto-memory file is a standing preference, which is the right use. No decision log: the 2026-10-28 reversals (maintenance reports disabled, health monitoring disabled) are recorded as DISABLED text inside the sections, with no record of why or what would justify re-enabling.
- **Rule 26 (workers inherit CLAUDE.md): wrong.** `sonnet-worker.md` and `opus-builder.md` both say "Read ~\.claude\CLAUDE.md"; with the subagent already receiving project memory this is a double load of ~7.4k tokens per worker for jobs (research, library curation) that need none of the Windows/Linux machine notes.
- **Rules 3-9 (hybrid/graph retrieval): not needed for notes; relevant for the library.** The library is 6,034 index rows (README says 5,599, so docs lag), where retrieval does matter: see [[topic-skill-library-retrieval]]. The `vault-graph` graphify graph is "100% EXTRACTED" with 2,208 communities, mostly one per source; edges come from category/source hubs and descriptions, not semantic similarity, and each `query-vault.ps1` call takes ~14 s.
- **Rule 20/21 (memory frameworks): do not adopt.** One manager, hundreds of facts: files + grep + a curator is enough; no framework has independent evidence. The MCP memory server is the one to avoid specifically because its data model has no timestamps or provenance.
- **Karpathy pattern (rule 11): partially present.** `claudes vault` + manager-kb already have raw/wiki/schema-like layers, but nothing plays the role of `index.md` + lint for the OPERATIONAL knowledge, and the vault is explicitly "generated only, never hand-edit" so it cannot receive filed-back answers.

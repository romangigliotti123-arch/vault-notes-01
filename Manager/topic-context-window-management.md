# Context window management for a 24/7 manager (compaction, memory, rotation)
Scope: keeping the manager's own context small, accurate and cheap over days; where state should live (context vs disk); compaction vs restart. Companion: [[topic-model-effort-routing-cost]] (cost/limits). Mechanics already in manager-setup.md (skill listing budgets, subagent `autoCompactWindow`/`omitClaudeMd`, deferred MCP tools) are not repeated. Related planned topics: [[topic-context-engineering]], [[topic-long-running-always-on-agents]], [[topic-report-formats-and-verification]], [[topic-knowledge-management-rag]].

## TL;DR
- **Compaction keeps the session identity; `/clear` does not.** The master compacted once (auto, 260,474 -> 21,920 tokens, 67.7 s) inside the same transcript file. `boot-claude.ps1` resumes a hard-coded session id, so a `/clear` rotation would silently resume the stale pre-clear transcript. Policy: compaction is the default; rotation is a deliberate, scripted exception.
- **Put exact state on disk, not in the summary.** Compression benchmarks show the file/ID "artifact trail" is the weakest thing every summariser keeps (2.2-2.5 of 5). Keep a job ledger + decisions file; re-inject it with SessionStart/PostCompact hooks; give compaction a fixed-section `# Compact instructions` block.
- **The manager's context grows from worker plumbing**: 32 worker completion notices (16 plain + 16 wrapped as system task events) = ~56k tokens, plus three copies of CLAUDE.md (~7.4k tokens each), plus a ~68-70k fixed baseline on turn 1. Make workers write full reports to files and return <=250 words.
- **Do not run a 1M window by default.** Nominal 1M; default compaction ~967k. Effective use degrades far earlier in every long-context benchmark (32k already costs most models half their score on hard retrieval). Set the manager's compaction trigger to ~250k and let idle compaction fire at >=100k; compaction while the cache is warm costs about $0.5 list (Opus 5.5), a cold one about $1.5.
- **Cheapest reduction = drop old tool output** (observation masking halves cost at equal solve rate; Anthropic: -84% tokens). Cap the manager's own tool output; PowerShell results were the largest tool-result source (~26k of ~40k tokens).
- **The model cannot type `/compact` or `/clear` itself.** Automatic levers are settings thresholds; manual ones are Roman's phone commands; a scheduled `/compact` through cron is plausible but untested.
- **Slim CLAUDE.md**: 29.5 KB / ~7.4k tokens, 143 lines; ~32% is stale or disabled-feature text (Pending work 17%, Telegram, health, weekly report, upkeep). Every worker loads it on every turn.

## Rules
1. **Treat context as finite, with diminishing returns.** Anthropic: "Context... must be treated as a finite resource with diminishing marginal returns"; goal "the smallest set of high-signal tokens". Context rot = performance degrades as context grows. Evidence: [[src-anthropic-effective-context-engineering]] (official), [[src-claude-blog-session-management-1m]] (official; no threshold given). Confidence: high.
2. **Effective window is far below nominal.** Chroma (18 models): performance "grows increasingly unreliable as input length grows" even on simple tasks; one distractor hurts; focused ~300-token prompts beat full ~113k-token prompts on LongMemEval. NoLiMa: at 32K, 11 of 13 models fall below 50% of short-context baseline when the question does not literally match the text. RULER: only half of 17 models keep satisfactory performance at 32K. These are 2024-25 models; trend likely softer on 5.5 but not gone. Evidence: [[src-chroma-context-rot]] (benchmarked, vendor-adjacent), [[src-arxiv-nolima]], [[src-arxiv-ruler]] (papers, abstract-level). Confidence: med-high for direction, low for 5.5 magnitudes.
3. **Position matters: standing rules first, live task last, the middle is weakest.** "Lost in the middle": best at start and end, "significantly degrades" in the middle. Manus recites objectives at the end (todo.md, ~50 tool calls per task); Cognition added reminders at both the beginning and end of the prompt. Our structure already puts CLAUDE.md first; the missing part is a short, recently rewritten "ACTIVE" block near the end (the ledger head, re-printed after state changes). Evidence: [[src-arxiv-lost-in-the-middle]], [[src-manus-context-engineering]], [[src-cognition-devin-sonnet-45-context-anxiety]]. Confidence: med.
4. **Set the compaction trigger on purpose.** Defaults: models with native 1M windows compact "at about 967K tokens"; `/autocompact`, `autoCompactWindow`, `modelSettings.<model>.autoCompactWindow`, `CLAUDE_CODE_AUTO_COMPACT_WINDOW` take 100k-1M. Ours: only Sonnet 5.5 has 700000; Opus/Haiku run the default. The real master compacted at 260k only because idle compaction fired (trigger shows "auto"). A 24/7 session without a deliberate window will drift to a very large, rotten context. Evidence: [[src-ccdocs-model-config]], [[src-ccdocs-settings-idle-compaction-budget]], [[src-local-master-usage-analysis]]. Confidence: high (mechanics); the 250k number is my judgment (low-med).
5. **Beware "context anxiety" when shrinking the window.** Cognition (Sonnet 4.5): the model "consistently underestimates how many tokens it has left" and takes shortcuts near the perceived end; they enabled 1M but capped usage at 200k so the model "thinks it has plenty of runway". In Claude Code the visible window stays 1M and only the compaction trigger moves, which is the Cognition-style setup; still, watch for premature wrap-ups after the change. Evidence: [[src-cognition-devin-sonnet-45-context-anxiety]] (Sonnet 4.5 era). Confidence: low-med for 5.5.
6. **Warm compaction is cheap; cold is not; do it at breaks.** A mid-session compaction reads the cached prefix ("a fraction of what the context size suggests") and mostly pays for ~20k summary tokens; after a TTL gap the whole history is reprocessed uncached. Measured: 260k -> 21.9k in 67.7 s (list cost ~$0.5 warm, ~$1.5 cold on Opus 5.5 by my arithmetic). Idle compaction exists for this: conditions = interactive session, 1 h TTL, context >= 200,000 (env `CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS`, min 100000), ~1 h idle, "before the prompt cache expired". Evidence: [[src-ccdocs-prompt-caching]], [[src-ccdocs-settings-idle-compaction-budget]], [[src-claude-blog-prompt-caching-lessons]] (summary "about 20k tokens"), [[src-local-master-usage-analysis]]. Confidence: high.
7. **Steer compaction.** Anthropic: bad compacts happen "when the model can't predict the direction your work is going"; "the model is at its least intelligent point when compacting"; compact proactively with a description. Mechanisms: `/compact <focus>`, and a `# Compact instructions` section in CLAUDE.md (costs doc). Evidence: [[src-claude-blog-session-management-1m]], [[src-ccdocs-costs]]. Confidence: high.
8. **Summaries lose the artifact trail; use fixed sections and an external index.** Factory's probe eval: artifact trail (which files/IDs touched) scored 2.19-2.45 of 5 for all methods; "OpenAI's compression discards file paths as low-entropy content"; incremental "anchored" summaries with fixed sections (intent, file modifications, decisions, next steps) beat full regeneration (overall 3.70 vs 3.44 Anthropic, 3.35 OpenAI; self-run, GPT-5.2 judge); "Compression ratio turned out to be the wrong metric". For us, "artifacts" are agent IDs/names, report paths, device states, pending approvals. Evidence: [[src-factory-evaluating-compression]]. Confidence: med.
9. **Know what survives compaction.** Re-injected from disk: root CLAUDE.md, unscoped rules, auto memory, skill descriptions, plan; up to 5 recent files (large ones as path refs); invoked skills (5k each / 25k total); SessionStart hooks matching `compact`. Summarised away: conversation-only instructions, nested/path-scoped rules, earlier hook context. "Add conversation-only instructions to CLAUDE.md to make them persist." Roman's chat preferences must therefore be written to CLAUDE.md or the memory dir (the existing `no-maintenance-reports.md` memory is the right pattern). Evidence: [[src-ccdocs-context-window]], [[src-ccdocs-memory]]. Confidence: high.
10. **Re-inject state with hooks, and audit what the summary says.** `SessionStart` input `source` = startup|resume|clear|compact|fork; hooks matching `compact` add output to the compacted context; `PostCompact` receives `compact_summary` (log it); `PreCompact` can block and sees `custom_instructions`. Evidence: [[src-ccdocs-hooks-compaction]]. Confidence: high.
11. **Dropping old tool output is the safest compaction.** JetBrains/TUM on SWE-bench Verified: masking old observations "halves cost relative to the raw agent while matching, and sometimes slightly exceeding, the solve rate of LLM summarization"; hybrid saves a further 7-11%. Anthropic: "tool result clearing" is "one of the safest lightest touch forms"; API context editing cut a 100-turn eval's tokens 84% and improved it 29% (39% with the memory tool). Claude Code does this internally (`/usage` counts "tool-result clearing" as an expected rebuild). For us: keep the manager's tool outputs short at the source. Evidence: [[src-arxiv-complexity-trap]], [[src-anthropic-effective-context-engineering]], [[src-claude-blog-context-management]], [[src-ccdocs-costs]]. Confidence: med-high (SWE-agent only).
12. **Measured: where the master's context goes.** Tool results ~40k tokens total in the transcript, of which PowerShell 25.7k (65%), Agent 7.5k, Read 4.6k; worker completion notices (32 in two wrappers: 16 plain `<task-notification>` ~27k tokens, 16 wrapped in a `[SYSTEM NOTIFICATION]` reminder ~29k; these are separate reports, not duplicates); CLAUDE.md system-reminder 31k + 27.9k + 27.3k chars (three injections: start, resume re-read, post-compaction); tool_use inputs (briefs and commands) ~218k chars (~55k tokens). Fixed overhead before any conversation: ~68-70k tokens. Evidence: [[src-local-master-usage-analysis]] (+ extra parse, this note). Confidence: high (counts) / med (the 4 chars/token conversion).
13. **Isolate noisy work in subagents; return the conclusion only.** "Intermediate tool noise stays in the child's context; only the result comes back"; test: "will I need this tool output again, or just the conclusion?". Caveat from the same docs family: with 1M windows protecting the window is "rarely the problem now" for an interactive coding session ([[src-ccdocs-best-practices]]); for a 24/7 manager the problem is duration, so the rule still holds. Evidence: [[src-claude-blog-session-management-1m]], [[src-anthropic-effective-context-engineering]], [[src-ccdocs-best-practices]]. Confidence: high.
14. **Worker reports are the manager's main avoidable growth.** Each completion arrives as a 4-10k-char block (the harness already stores the full output under a `tasks/<id>.output` file in the session temp folder, but the whole result is also injected into context). Have workers write the full report to a file and return <=250 words plus the path; the manager reads the file only when it must act on details. Evidence: [[src-local-master-usage-analysis]]; design support in [[src-anthropic-effective-context-engineering]] ("returns only a condensed, distilled summary"). Confidence: med-high.
15. **File system = restorable memory.** Manus: "the file system as the ultimate context... unlimited in size, persistent by nature"; compression must be restorable (drop page content, keep the URL). Anthropic: structured note-taking persisted outside the window, pulled back later; memory tool docs: "ASSUME INTERRUPTION: Your context window might be reset at any moment". Letta context repositories: some files always loaded (`system/`), the tree always visible, others disclosed progressively, changes versioned in git; design target 15-25 focused files. Evidence: [[src-manus-context-engineering]], [[src-anthropic-effective-context-engineering]], [[src-platform-memory-tool]], [[src-letta-sleep-time-and-context-repos]]. Confidence: med-high.
16. **Keep failures on the record, but on disk.** Manus: "leave the wrong turns in the context... Erasing failure removes evidence". Cognition: model-written notes drop details ("the model didn't know what it didn't know"). So the ledger should hold what was tried/failed/why, written from worker reports, not from the manager's memory of them. Evidence: [[src-manus-context-engineering]], [[src-cognition-devin-sonnet-45-context-anxiety]]. Confidence: med.
17. **Keep the prefix stable and append-only.** The cache keys on the exact prefix: CLAUDE.md edits mid-session do not apply until `/clear`/`/compact`/restart (and do not invalidate); changing tools, model, or removing images invalidates; Manus: no timestamps at the top of the prompt, deterministic serialisation. Do not stuff volatile data (time, status) into CLAUDE.md or memory index; print it via hooks at the end of context. Evidence: [[src-ccdocs-prompt-caching]], [[src-manus-context-engineering]], [[src-claude-blog-prompt-caching-lessons]]. Confidence: high.
18. **Memory-file budgets.** CLAUDE.md "target under 200 lines" (longer reduces adherence; `@imports` do not reduce cost); auto-memory `MEMORY.md` loads only the first 200 lines / 25 KB; subagents do not inherit auto memory; the project-root file survives compaction. Evidence: [[src-ccdocs-memory]], [[src-ccdocs-costs]]. Confidence: high.
19. **Progressive disclosure over preloading.** Skills load by name and invoke on demand; deferred MCP tools; Anthropic: keep "lightweight identifiers (file paths, stored queries, web links)" and load at runtime. Details of skill budgets in manager-setup.md. Evidence: [[src-anthropic-effective-context-engineering]], [[src-letta-sleep-time-and-context-repos]]. Confidence: high.
20. **Resuming a long session after a gap is expensive and shows a warning.** The "Resume this conversation?" dialog estimates the share of the 5-hour limit the saved conversation alone would use; resumed sessions keep the old system prompt until compacted; switching model on resume (boot uses `--model haiku`) also triggers the dialog and a full uncached read. So a planned restart should be preceded by a warm compaction (or start fresh with a handoff). Evidence: [[src-ccdocs-sessions]], [[src-ccdocs-prompt-caching]]. Confidence: high (doc); whether the dialog blocks the unattended boot is unverified.
21. **Fresh-context loops work when state is in files.** Ralph: `while :; do cat PROMPT.md | claude-code; done`, fresh context each iteration, state in `specs/`, `fix_plan.md`, `AGENT.md`, one item per loop, tests as backpressure; best for greenfield, needs watching, fails with duplicated/placeholder code. Anthropic's long-running harness: initializer + coding agents, progress file + git + JSON feature list, "each new session begins with no memory". Both say: rotation is safe only when the state files are complete. Evidence: [[src-ghuntley-ralph]], [[src-anthropic-effective-harnesses-long-running]]. Confidence: med.
22. **Treat a handoff as a hypothesis.** Community handoff skills verify the handoff against live state (git log, files) instead of trusting it; resume cost drops from "entire conversation history" to "one small file". For us: the new session re-reads the ledger and live job list (`claude agents`, `/tasks`, device status) before acting. Evidence: [[src-community-handoff-and-cache-reports]] (low: snippets). Confidence: low-med.
23. **Sleep-time consolidation is an accepted pattern.** Letta: a background agent reorganises memory while the primary is idle; costs more tokens the more often it runs; pair a fast primary with a slower larger consolidator. For us: a weekly low-effort "memory curator" worker that prunes ledger/decisions and proposes (never executes) deletions. Evidence: [[src-letta-sleep-time-and-context-repos]]. Confidence: low-med.
24. **Session rotation vs compaction trade-off.** `/compact`: "Low effort; Claude decides what mattered", lossy; `/clear`: "Zero rot; you control exactly what carries forward" but new session; rewind to before a bad compact and retry with steering. Evidence: [[src-claude-blog-session-management-1m]]. Confidence: high.
25. **Identity coupling (our constraint).** Roman asked (2026-10-28) that the app keep one continuous chat, and `boot-claude.ps1` resumes `$masterId = '78968f1c-...'`. Compaction keeps that id (verified: the `compact_boundary` record sits in the same JSONL). `/clear` "saves the previous session" and starts a new one (new JSONL); with no argument it keeps a name set via `--name`/`/rename`, with an argument it names the session you leave and the new one "starts unnamed". Evidence: [[src-ccdocs-sessions]], [[src-local-master-usage-analysis]]. Confidence: high.
26. **Who can trigger compaction.** Auto-compact at the window, idle compaction, and the user typing `/compact`/`/clear` (both work as text over Remote Control: [[src-ccdocs-remote-control]]). The model has no tool for them; scheduled prompts (`CronCreate`, `/loop`) fire only when idle and expire after 7 days ([[src-ccdocs-scheduled-tasks-loop]]); whether a scheduled prompt that is a built-in command like `/compact` executes is undocumented. Confidence: med (inference from tool lists and docs).
27. **Cut the baseline before the conversation.** The master starts a turn at ~70k tokens before any chat; workers at ~52k median. Biggest controllable parts are CLAUDE.md (7.4k tokens, 14% of a worker baseline), connector/MCP listings and skill listings (measure with `/context`). Evidence: [[src-local-master-usage-analysis]], [[src-ccdocs-context-window]]. Confidence: med (breakdown unmeasured).
28. **Do not fight the harness with emphasis.** Best-practices lists "aggressive context-window management" as largely unnecessary on 1M windows, ALL-CAPS emphasis as harmful and "keep going" lines as causing over-work; use hooks for must-happen behaviour. Hence the policy relies on deterministic hooks and settings, not on longer CLAUDE.md prose. Evidence: [[src-ccdocs-best-practices]]. Confidence: high.

## Where sources disagree
- **How aggressive to be.** Claude Code best-practices (current docs) lists aggressive context-window management under "what you can stop doing" because of 1M windows and auto-compaction ([[src-ccdocs-best-practices]]); the session-management post says "a long session with junk in it performs worse than a short session with the right context" and advises proactive `/compact` ([[src-claude-blog-session-management-1m]]); Chroma/NoLiMa/RULER show length degradation ([[src-chroma-context-rot]], [[src-arxiv-nolima]], [[src-arxiv-ruler]]). Resolution for us: those docs describe interactive coding sessions measured in hours; a 24/7 manager lives for weeks, so the "stop managing" advice does not transfer. Follow the proactive side, but implement it with settings and hooks (cheap, deterministic), not manual rituals.
- **Summarise vs mask.** JetBrains finds masking old tool output is as good as LLM summarisation at half the cost ([[src-arxiv-complexity-trap]]); Factory finds structured, incremental summaries preserve far more than regenerated ones and treats summarisation as the main tool ([[src-factory-evaluating-compression]]); Cognition's agents "spent more tokens on summaries than on solving the problem" ([[src-cognition-devin-sonnet-45-context-anxiety]]). The setups differ (SWE-agent coding vs ops/long chat). Follow: mask/clear tool output first (free), summarise only for the conversational spine, and keep state outside any summary.
- **Fresh context vs continuity.** Ralph and Anthropic's harness reset context and rely on files ([[src-ghuntley-ralph]], [[src-anthropic-effective-harnesses-long-running]]); Zivtech advises a fresh start after long gaps or 30-40 turns / 100k+ tokens ([[src-zivtech-claude-code-economics]], low reliability); Manus keeps one append-only context and externalises to files ([[src-manus-context-engineering]]); Roman wants one continuous chat. Follow: continuity via compaction + disk state; fresh sessions only as a deliberate runbook.
- **Memory frameworks.** MemGPT/Letta/Mem0/Zep ([[src-arxiv-memgpt]], [[src-arxiv-mem0]], [[src-arxiv-zep]]) vs plain files with progressive disclosure (Anthropic memory tool, Letta's own move to git-backed files in 2026: [[src-letta-sleep-time-and-context-repos]]). Even Letta moved from specialised memory tools to files; follow files. Vendor benchmarks (Mem0 +26%, Zep +18.5%) are self-reported.
- **Smaller window = better or worse?** Cognition capped at 200k to avoid context anxiety; Anthropic says a larger window gives "more time to /compact proactively". Both agree compaction should be chosen early, not at the limit; they disagree on how visible the limit should be. Follow: test, do not assume.

## Applies to us
- **Window/compaction settings**: only Sonnet has `autoCompactWindow: 700000`; the live manager is Opus 5.5 at default ~967k; boot forces `--model haiku` (default ~967k, plus the >100k Haiku price tier). Idle compaction (default on) is the only reason the master compacted at 260k. Missing: a deliberate window for the manager's actual model, a compaction instruction block, hooks.
- **Compaction identity**: good news, session id survives compaction (verified), matching Roman's one-chat wish. Bad news: nothing in boot-claude.ps1 survives a `/clear` (hard-coded `$masterId`).
- **State on disk**: `claude-host\log.md` (31 KB, append-only activity log), `session-notes\sessions-index.md` and per-topic notes exist, plus one memory entry (`MEMORY.md` index with `no-maintenance-reports.md`). Missing: a structured job ledger (agent ID/name, brief path, status, report path, cost), a decisions/preferences file with fixed sections, a handoff template. `log.md` is for humans, too long to re-inject.
- **CLAUDE.md**: 29.5 KB / ~7.4k tokens / 143 lines (limit guidance: <200 lines; fine by line count, heavy by bytes). By section: Pending work 17%, Skill/agent library 8%, Linux power 7%, Manager role 7%, Other devices 7%, Upkeep 5%, Telegram 5%, then ~25 smaller sections. About 32% is stale or describes disabled features (Pending work with finished items, Telegram channel removed from boot on 2026-10-28, health monitoring and weekly report disabled, upkeep tasks disabled). It loads in the manager and every worker every turn and appeared three times in the master transcript.
- **Worker reports**: the preset report format (RESULT/DONE/VERIFIED/PROBLEMS/NEEDS/NEXT) is good for checking but arrives in full in the manager context (notices of ~4-10k chars each). No file-based reports or size limit.
- **Hooks**: none for SessionStart/PostCompact. The three events needed exist (v2.1.312 docs).
- **Rotation**: no runbook; no way for the model to trigger one; `cleanupPeriodDays` 30 means old transcripts expire, so important knowledge must be in files, not only in the old JSONL.
- **Already good**: workers are separate contexts (isolation exists); memory dir is used for a durable preference; compaction preserves CLAUDE.md; roblox/vault material is outside context (library not preloaded).

## Candidate changes for us
**C1. Compaction thresholds (settings.json).** In `modelSettings` add `"claude-opus-5-5": { "effortLevel": "medium", "autoCompactWindow": 250000 }`, change Sonnet's `autoCompactWindow` from 700000 to 250000, and add under `env`: `"CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS": "100000"`; leave `idleCompaction` at its default (true). Effect: compaction at ~250k at the latest, and any >=100k conversation idle for ~1 h is compacted warm before the cache expires. Cost per compaction ~$0.5 list. Risk: more frequent compactions lose detail (mitigated by C2-C4); context-anxiety behaviour unverified on 5.5 (watch for premature wrap-ups for a week; revert to 400k if seen). Note `CLAUDE_CODE_AUTO_COMPACT_WINDOW` env, if ever set, overrides per-model values.

**C2. Compact-instructions block (add to the end of CLAUDE.md; ~12 lines).**
```
# Compact instructions
When compacting, keep these sections, in this order, and keep exact identifiers (agent IDs/names, file paths, job slugs, IPs, commit hashes):
1. Roman's open requests and any pending approval (verbatim wording of constraints).
2. Active jobs: slug, agent name/ID, model+effort, brief file, status, report file.
3. Decisions and standing preferences stated in chat that are not yet in CLAUDE.md or memory (copy them to memory later).
4. State of devices (this PC, CachyOS awake/quiet, [host]) and anything left running.
5. What was tried and failed, with the reason.
Drop: raw tool output, worker report bodies (they are in reports\jobs\), greetings, superseded plans. After compaction, re-read ~\claude-host\manager\ledger.md before acting.
```
Benefit: addresses artifact-trail loss (rule 8) and steers summaries (rule 7).

**C3. Ledger + decisions files (new, under `~\claude-host\manager\`).** `ledger.md`: a header "ACTIVE" table (slug | agent name/id | model/effort | started | status | brief | report | list-cost) rewritten on every state change, then an append-only "DONE/FAILED" log, one line per job incl. what failed and why. `decisions.md`: fixed sections (Roman's standing preferences with date, Policies adopted, Open questions). Add to CLAUDE.md (3 lines): "State lives on disk. Before spawning or reporting, update ledger.md; after any restart/compaction read ledger.md and decisions.md first and verify against `/tasks` and `claude agents`; the ledger is a hypothesis, live state wins." Benefit: restorable memory, rotation-safe (rules 15, 16, 22). Cost: ~200-400 tokens per job.

**C4. Hooks (settings.json).** Add:
```json
"hooks": {
  "SessionStart": [{ "matcher": "compact|resume|startup|clear",
    "hooks": [{ "type": "command",
      "command": "powershell -NoProfile -File ~/claude-host/tools/state-brief.ps1" }] }],
  "PostCompact": [{ "hooks": [{ "type": "command",
      "command": "powershell -NoProfile -File ~/claude-host/tools/log-compact.ps1" }] }]
}
```
`state-brief.ps1` prints the ACTIVE part of ledger.md (<=40 lines) and the last 10 lines of decisions.md to stdout (SessionStart output is added to context); `log-compact.ps1` appends the hook's `compact_summary` (stdin JSON) with a timestamp to `manager\compactions.md` so Roman/the manager can audit what the summary kept. Verify matcher syntax with `/hooks` before relying on it. Risk: hook output adds ~1k tokens per start; keep it short.

**C5. File-based worker reports.** In both agent presets replace the final-report paragraph with: "Write your full report (RESULT/DONE/VERIFIED/PROBLEMS/NEEDS/NEXT/ARTIFACTS) to ~\claude-host\reports\jobs\<UTC-date>-<slug>.md. Your final message to the manager is at most 250 words: RESULT, the 3 most important facts, PROBLEMS/NEEDS in one line each, and that file path. Do not paste long outputs or file contents into the final message." The manager briefs include `<slug>`. Benefit: cuts ~2-2.5k tokens per worker from the manager's growth (16 notices = ~27k tokens measured) without losing the evidence. Risk: manager may skip reading the file; the brief says "read VERIFIED in the file before accepting".

**C6. Slim CLAUDE.md to ~90 lines / <4k tokens.** Move to `~\claude-host\notes\` (loaded on demand by pointer): Pending work (archive finished items; keep only open ones, ~10 lines), Linux power + CachyOS tools + Linux "off" (-> `notes\cachyos.md`), Telegram, Health monitoring, Weekly report, Upkeep and Disk cleanup (-> `notes\host-upkeep.md`, with the standing "disabled, do not re-enable" lines kept in 3 lines in CLAUDE.md because they are prohibitions that must be seen). Leave in CLAUDE.md: naming, manager role + routing, confirm-first list, autonomy, reply format, desktop/layout rules, installing-software rule, one-line pointers. Add one line "Device and host procedures: read ~\claude-host\notes\<topic>.md when the task touches that device." Benefit: ~3k tokens off the manager and every worker turn (~1,700 worker messages and ~130 manager messages so far, each re-reading the file). Risk: a worker misses a rule that is now in a note: keep prohibitions inline and have the brief name the note to read.

**C7. Boot script: resume by name, not hard-coded id, and stop forcing a model.** In `boot-claude.ps1` replace the masterId logic with: (a) read `~\claude-host\manager\master-session.txt` (written by the rotation runbook) and fall back to the current id; (b) keep `--resume <id>`; drop `'--model','haiku'` (see [[topic-model-effort-routing-cost]] C2). That keeps boot working after a `/clear` rotation and avoids the model-change dialog/uncached read on every boot. Test with `-DryRun` and one real reboot while Roman is present. Risk: low; the file is optional.

**C8. Rotation runbook (policy; store as `manager\runbook-rotation.md`, one-line pointer in CLAUDE.md).**
| Level | Trigger | Action | Who |
|---|---|---|---|
| L0 hygiene | every job | full report to file; <=250 words in context; ledger line; tool output piped through `Select-Object -First 40` / `head`; no >50-line dumps | manager |
| L1 warm compaction | idle >= ~1 h with context >= 100k, or Roman sends `/compact <focus>` at a natural break | compaction with C2 instructions; PostCompact logs summary; SessionStart(compact) re-injects ledger | automatic / Roman |
| L2 hard compaction | context reaches 250k | automatic; same hooks | automatic |
| L3 rotation (rare) | any of: 4+ compactions in 7 days; manager contradicts the ledger or re-asks settled things twice in a week; Roman asks; before a planned multi-day outage | (1) wait until no workers in flight (or list them with names in the ledger); (2) manager writes `manager\handoff-YYYY-MM-DD.md` (sections as C2) and updates ledger; (3) Roman types `/clear master-YYYY-MM-DD` then `/rename <master name>` from the phone (the manager cannot); (4) the SessionStart(clear) hook injects handoff + ledger; (5) manager updates `master-session.txt` (C7) and verifies against `/tasks` | manager + Roman |
| L4 restart | crash/reboot | boot resumes; SessionStart(resume) injects ledger; manager verifies live state before acting | automatic |
Never rotate with running workers unless named in the ledger (names survive restarts since v2.1.299 but only if named after the last compaction). The row on claude.ai: unverified whether `/clear` changes the Remote Control row (see Open questions).

## From Nate Herk / RoboNuggets / Karpathy

Added 2026-11-01 from 549 creator videos (Nate Herk, RoboNuggets, Andrej Karpathy). Practitioner evidence: [demonstrated] = shown working in a video, [opinion] = advice. Weigh below the official/benchmarked sources above; where they disagree see [[src-creators-disagreements]].

- **Treat context as a precious resource and reset between topics.** Start a new chat or run /clear when switching tasks. Why: long context costs more, distracts the model and lowers accuracy. [opinion] (T8; [[src-nate-herk-agent-practice]], [[src-karpathy-llm-practice]])
- **Inspect what fills the window.** Run /context and /cost regularly, including on a fresh session. Why: startup overhead (system prompt, tools, skills, memory) can already be tens of thousands of tokens. [demonstrated] (T9; [[src-nate-herk-agent-practice]], [[src-robonuggets-agent-practice]])
- **Keep CLAUDE.md thin.** Why: files like this are reinjected at the start of every session or message, so size becomes recurring cost. [demonstrated] (T10; [[src-nate-herk-agent-practice]], [[src-robonuggets-agent-practice]])
- **Move anything you repeat into CLAUDE.md or a skill.** Why: it stops you re-explaining and gives the agent a durable onboarding file. [opinion] (T11; [[src-nate-herk-agent-practice]])
- **Write operating rules into the instruction file.** Include: check existing tools first, on error read it, fix the script, retest, then update the workflow. Why: the agent learns from failures instead of repeating them. [demonstrated] (T12; [[src-nate-herk-agent-practice]], [[src-robonuggets-agent-practice]])
- **Organise the workspace for agents, using router files.** Use a short index file, a workspace map, and per-department routers listing skills and references. Why: the agent loads only what it needs. [demonstrated] (T13; [[src-robonuggets-agent-practice]])
- **Hand off state explicitly between sessions.** Use a handoff skill, a cross-session memory tool, or /compact with stated priorities. Why: each session starts from scratch, and re-explaining costs minutes and tokens. [demonstrated] (T14; [[src-nate-herk-agent-practice]], [[src-robonuggets-agent-practice]])
- **Use fresh context per task to fight context rot.** Spawn new sub-agents for each task rather than running one long session. Why: quality degrades as tokens build. [demonstrated] (T15; [[src-nate-herk-agent-practice]])
- **Filter what memory retrieval returns.** Fetch only the relevant items, and summarise where useful. Why: native memory pulled in irrelevant context and wasted tokens. [demonstrated] (T16; [[src-nate-herk-agent-practice]])
- **Disconnect unused MCP servers and prefer a CLI plus a skill.** Why: one server can add thousands of tokens per message. [opinion] (T17; [[src-nate-herk-agent-practice]])
- **Do not switch models mid-chat.** Why: each model has its own prompt cache, so switching rereads the whole conversation with no discount. [opinion] (T18; [[src-robonuggets-agent-practice]])
- **Keep one source of truth across tools.** Make agents.md a pointer to CLAUDE.md, and change both together. Why: switching costs stay low and the tools don't drift apart. [demonstrated] (T19; [[src-nate-herk-agent-practice]], [[src-robonuggets-agent-practice]])

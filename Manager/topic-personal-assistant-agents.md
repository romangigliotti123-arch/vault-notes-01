# Personal-assistant agents: OpenClaw, Hermes, Devin, Manus, AutoGPT lessons

Scope: designs of always-on personal/delegated-work agents (OpenClaw/Clawdbot, Hermes Agent, Devin, Manus, Cursor/Codex cloud agents, Cowork, Claude for Chrome, Pi, AutoGPT-era) and what is transferable to Roman's manager (whose `soul.md`/`CLAUDE.md` resemble OpenClaw's SOUL.md/AGENTS.md). Security incidents of this class: [[topic-agent-security]]. Memory: [[topic-knowledge-management-rag]]. Synthesised by the lead from src- notes (worker stopped by usage limit).

## TL;DR
- The OpenClaw workspace model (plain markdown files: operating rules human-only, persona, user model, curated memory, episodic notes, standing intents) is the closest match to ours and its public docs are the best written guide: short beats long; "writing is the hard part" so curate off the reply path; never let cron/heartbeat/sub-agent sessions create durable memories; standing orders need Scope, Trigger, Approval gate, Escalation and "what NOT to do". [[src-openclaw-docs-workspace-soul]], [[src-openclaw-docs-memory-architecture]]
- Always-on assistants fail in three ways: they burn budget when idle (heartbeats resending fat histories), they get breached through their inbox and skills (see security), and they drift because their own notes degrade. Each has a mitigation we can copy. [[src-openclaw-security-cost-reports]], [[src-snyk-clawdbot-assistant]], [[src-openclaw-docs-memory-architecture]]
- What works commercially is narrow, verifiable, well-scoped delegation with proof attached (Devin: clear requirements, verifiable outcomes; Cursor: screenshots/video/logs; Codex: reviewable diffs). "It usually performs worse when you keep telling it more after it starts." [[src-cognition-devin-2025-review]], [[src-cursor-cloud-agents-self-hosted]], [[src-openai-codex-cloud-docs]]
- Minimalism is a live counter-current (Pi: four tools, tiny prompt, no sub-agents, files for state); Manus bets on context engineering. Both argue for fewer moving parts and inspectable state. [[src-zechner-pi-minimal-agent]], [[src-manus-context-engineering]]
- AutoGPT-style failures (runaway loops, no stop condition, cost) are mostly solved at the model level but the missing budget/kill-switch problem persists. [[src-weng-llm-agents-2023]], [[src-openclaw-security-cost-reports]]

## Rules
1. **Separate the files by who may write them.** OpenClaw: AGENTS.md (operating rules, human-only writes, injected every session), SOUL.md (persona/tone/boundaries), USER.md (user model with dated directives and its own char budget), MEMORY.md (curated; only written by gated consolidation or direct request), daily notes (episodic, retrieved on demand), DREAMS.md (review, never injected). Letta: labelled size-limited memory blocks, read-only blocks for operator policy. Map: our CLAUDE.md mixes rules, device facts, status and history; soul.md is persona only. Evidence: [[src-openclaw-docs-workspace-soul]], [[src-openclaw-docs-memory-architecture]], [[src-letta-memory-blocks]]. Confidence: med-high.
2. **A soul file must change behaviour.** "Short beats long. Sharp beats vague"; not a life story, changelog, security policy or "wall of vibes"; good rules are testable ("skip filler", "call out bad ideas early", "be resourceful before asking: come back with answers, not questions"); "if you change this file, tell the user". Our soul.md (15 lines) already fits; it lacks escalation behaviour and "verify before reporting". Evidence: [[src-openclaw-docs-workspace-soul]]. Confidence: med.
3. **Standing orders = authority + trigger + gate + escalation + what NOT to do, and "standing orders without triggers become suggestions".** Execute-Verify-Report: "'Done' without verification is not acceptable. Prove it"; retry once, 3 attempts max, then escalate. Recurring duties belong to scheduled jobs with their own prompt, run history and delivery rules (OpenClaw retired its 30-minute HEARTBEAT.md poll in favour of this). Evidence: [[src-openclaw-docs-workspace-soul]]. Confidence: med-high.
4. **Writing memory is the hard part; protect the write path.** Auto-captured memories were overwhelmingly restatements of runtime instructions, heartbeat noise and recall feedback loops; fixes: session-kind gating (cron/heartbeat/sub-agent sessions never create durable memory candidates), recall-loop prevention, taint marking after network tool results, provenance classes (owner/agent/untrusted/system). "The write path is the security boundary" (memory poisoning persists across sessions). Evidence: [[src-openclaw-docs-memory-architecture]], [[src-snyk-toxicskills]] (check SOUL.md/MEMORY.md for unauthorised edits). Confidence: med-high.
5. **Idle cost is the silent killer.** An "idle" OpenClaw agent burned tokens overnight because heartbeats resent a large conversation history; fixes: longer intervals, bounded sessions with handoff files, cron for repetitive work, model tiering. Our analogue: a 7+ MB resumed master conversation re-read (cache-read) on every turn and two idle gaps that each forced a 52-69k-token cache re-write. Evidence: [[src-openclaw-security-cost-reports]] (practitioner anecdote), [[src-local-master-usage-analysis]]. Confidence: med-high.
6. **Single gateway, one trust boundary.** OpenClaw's docs: default loopback bind, DM pairing for unknown senders, groups allowlisted, "one trust boundary per gateway", "not a hostile multi-tenant security boundary", built-in `security audit`. For us: one owner (Roman), one allowed Telegram user, no groups. Evidence: [[src-openclaw-security-cost-reports]], [[src-snyk-clawdbot-assistant]]. Confidence: med.
7. **Skills created by the agent itself are a feature and a risk.** Hermes: autonomous skill creation after complex tasks and self-improving skills (third-party "40% faster" claim unverified); SkillsBench shows self-generated skills give no average benefit. Gate promotion on verified reuse (see [[topic-skill-library-retrieval]] C6). Evidence: [[src-hermes-agent-readme]], [[src-arxiv-skillsbench]]. Confidence: low-med.
8. **Messaging-first agents converge on the same command set:** `/status /stop /new /model /usage /undo /compress`, plus interrupt by sending a new message. Evidence: [[src-hermes-agent-readme]], [[src-ccdocs-remote-control]]. Confidence: med. See [[topic-remote-mobile-ux]].
9. **Delegation that sticks has proof attached and a clean handoff.** Cursor background agents report with screenshots/video/logs; "Move to Cloud" does not carry uncommitted files (handoff pitfall: commit first); Codex tasks have their own workspace and keep working while the computer sleeps; environments are published separately from task state. For us: each job's brief + report + artifacts live in `jobs\<id>\` so a restart or a second device can pick them up. Evidence: [[src-cursor-cloud-agents-self-hosted]], [[src-openai-codex-cloud-docs]]. Confidence: med.
10. **Sandbox by folder and use a separate browser profile.** Cowork works only in chosen folders, uses its own browser with its own logins, and takes over the screen "only when it has to". Claude for Chrome pilot: 23.6% attack success without mitigations, 11.2% with; confirmations before high-risk actions are kept even in autonomous mode. Our "Claude in Chrome" work uses Roman's real, signed-in Chrome profile. Evidence: [[src-claude-cowork-product-page]], [[src-anthropic-claude-for-chrome-preview]]. Confidence: med-high. See [[topic-agent-security]].
11. **Minimalism wins on predictability.** Pi: four tools, tiny system prompt, files for plans, tmux for background work, no sub-agents ("black box within a black box" with poor context transfer), "we trust our agents too much". We keep sub-agents because the manager's context is the scarce resource; the transferable parts are inspectable state and not over-building. Evidence: [[src-zechner-pi-minimal-agent]]. Confidence: med (one practitioner).
12. **Context engineering lessons from Manus apply directly to a 24/7 session**: keep the prompt prefix stable and append-only (KV-cache hit rate is the key production metric; cached input 10x cheaper), do not add/remove tools mid-run, use the file system as context with restorable compression, recite goals (todo.md) to keep them in recent attention, keep failed attempts in context so the agent learns, avoid uniform few-shot patterns. Evidence: [[src-manus-context-engineering]]. Confidence: med-high. See [[topic-context-window-management]].
13. **Expect modest autonomy.** Karpathy: treat agents "like an employee or an intern" but "currently they just don't work" as unattended employees (no continual learning, weak on custom code); learn what they are good at; keep tight generate/verify loops and autonomy sliders. Devin: "senior at codebase understanding but junior at execution". Evidence: [[src-karpathy-decade-of-agents]], [[src-cognition-devin-2025-review]]. Confidence: med (opinion).
14. **Proactivity is earned.** Studies: too-frequent proactive suggestions annoy; deciding when to speak is hard even for tuned models (F1 66%). Standing intents in OpenClaw have a 24 h cooldown, max 3 fires, 90-day expiry, owner-created only. Evidence: [[src-proactive-assistant-papers]], [[src-openclaw-docs-memory-architecture]]. Confidence: med.
15. **AutoGPT-class failures are still the checklist for any loop**: finite context, brittle long-horizon planning without recovery from unexpected errors, no stop condition, runaway cost. Mitigation = max iterations, budgets, circuit breakers, human escalation (see [[topic-long-running-always-on-agents]]). Evidence: [[src-weng-llm-agents-2023]], [[src-openclaw-security-cost-reports]]. Confidence: med.

## Where sources disagree
- **Heartbeat polling vs scheduled jobs.** OpenClaw used a 30-minute HEARTBEAT.md poll then retired it for ordinary scheduled jobs; Hermes builds in cron with delivery. Roman wants no recurring reports; scheduled scripts with exception-only alerts fit.
- **Self-improving memory/skills (Hermes, Letta) vs write-path protection (OpenClaw).** The OpenClaw position (curation is the hard part; gate writes) has more concrete evidence (LongMemEval citation); the Hermes numbers are unverified.
- **Sub-agents.** Pi says no; Anthropic/Cognition say yes for context protection and review. For a manager whose own context is the constraint, yes.

## Applies to us
- Aligned: persona file separate; rules in a human-edited file; library not auto-loaded; owner-only channel intent.
- Gaps: CLAUDE.md is history + rules + device facts (violates "AGENTS.md = operating rules, human-written"); no standing-order structure for recurring duties (e.g. "keep the Linux box asleep when idle", "desktop layout enforcement") with Scope/Trigger/Gate/Escalation; no memory-write policy (the auto-memory directory has one entry; workers' learnings are not captured); no idle-cost control; no separate browser profile for agents.

## Candidate changes for us
- **C1 (CLAUDE.md structure):** split into `CLAUDE.md` (rules, ~100 lines, human-edited), `RUNBOOKS\*.md` (devices, linux power, telegram, cleanup, screenshots), `session-notes\` (history). Mark each runbook with a last-verified date. Evidence: rule 1; [[topic-claude-code-features]] C4.
- **C2 (standing-order template for recurring duties):** `Program | Scope | Trigger (task name/cron) | Approval gate | Escalation | Never` table in `RUNBOOKS\standing-orders.md` covering desktop-layout, screenshot cleanup, linux quiet mode, library sync; each has a verification step and a stop rule (3 attempts then notify). Evidence: rule 3.
- **C3 (memory write policy):** in CLAUDE.md: "Only Roman or an explicit 'remember this' request writes to memory files; workers never write memory; lessons go to `jobs\failures.md` and are promoted to rules by the manager after review." Evidence: rule 4.
- **C4 (idle-cost control):** do not add periodic wake-ups to the master; rotate the master session on a schedule or at a size threshold with a handoff file (see [[topic-context-window-management]]); log cache-write spikes after idle gaps in the digest. Evidence: rule 5.
- **C5 (agent browser profile):** use a dedicated Chrome profile (no banking/mail logins) for Claude-in-Chrome jobs; keep Roman's real profile off-limits unless he asks. Needs Roman's OK (touches browser/profile config; CLAUDE.md already forbids touching browser profiles for cleanup). Evidence: rule 10.
- **C6 (soul.md additions, 3 lines):** "Verify before reporting: a claim without a check I can name is reported as unverified. Stop after two failed attempts at the same step and say so. Tell Roman when I change my own rules." Evidence: rules 2-3.

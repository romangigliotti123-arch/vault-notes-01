# Observability for a one-box manager: events, cost, failure review

Scope: what to record about the manager and its workers, with what tooling, at what cost, and how Roman (phone) and the manager consume it. Companion: [[topic-long-running-always-on-agents]] (ledger, supervisor, heartbeat; its C5/C12 depend on C1/C4 here), [[topic-claude-code-features]] (hooks), [[topic-agent-security]] (audit trail, privacy). Synthesised by the lead from the src- notes written by the (stopped) worker; the prototypes under `~\claude-host\manager-kb\prototypes\` (hook_log.py, digest.py, jobs.py, otlp_sink.py) were run by that worker against this host's real transcripts, and digest.py was re-run by the lead on 2026-10-29 (output below).

## TL;DR
- Claude Code already writes everything needed: per-subagent transcripts + `.meta.json` (description, agent type, finished) under `~/.claude/projects/<project>/<session>/subagents/`, with token usage per message. A local script can produce a per-job table with zero tokens and no new service. [[src-claude-devtools]], [[src-claude-code-log]], prototype `digest.py`
- Hooks are the event bus: `SessionStart`, `PreToolUse(Agent)` (the delegation decision: worker, model, effort, brief head), `SubagentStop`, `StopFailure`, `Stop`. One tiny async hook appending JSON lines gives an audit trail and the heartbeat the supervisor needs. [[src-ccdocs-hooks]], [[src-disler-hooks-observability]], prototype `hook_log.py`
- Do not build or host a trace backend (Langfuse = 6 moving parts incl. ClickHouse; Phoenix = a service; SaaS plugins send Roman's chats to third parties; Helicone reportedly in maintenance mode, unverified). Use files first; map vocabulary to OTel GenAI so a later move is a mapping. [[src-langfuse-selfhost]], [[src-phoenix-selfhost]], [[src-langsmith-claude-code]], [[src-helicone-maintenance]], [[src-otel-genai-semconv-agent-spans]]
- The valuable practice is error analysis of real traces, bottom-up, not dashboards: read failed jobs, write one-line notes, group them, count. [[src-hamel-field-guide]]
- Costs on a subscription are API-equivalent estimates, not bills: track tokens and cache reads per job and per day; the real constraint is the 5-hour/weekly limit. [[src-ccdocs-agent-sdk-cost-tracking]], [[src-ccusage]]
- Observed today: 11 parallel high-effort research workers each produced ~80-140k output tokens and 15-50M cache-read tokens in ~30 min, and the 5-hour limit stopped them. A per-job table would have shown this before it happened (see digest below).

## Rules
1. **Record decisions, not just actions.** The most informative event is the delegation: which worker, model, effort, label and how long the brief was. Capture it with a `PreToolUse` hook on the Agent tool; add a one-line "why" to the ledger entry. Evidence: prototype `hook_log.py`, [[src-ccdocs-hooks]] (hook input carries tool_input). Confidence: med-high.
2. **Use the hook payload fields that join things together.** `agent_id`, `agent_type`, `session_id`, `prompt_id`, `tool_use_id` appear in hook payloads and OTel events, so a hook log can be joined to transcripts and cost. Evidence: [[src-ccdocs-monitoring-otel]], [[src-ccdocs-hooks]]. Confidence: high.
3. **Transcripts are the free trace store.** Subagent transcripts include usage, tool calls and the final report; kept `cleanupPeriodDays` (30) days; plaintext (treat as sensitive). Dedupe token counts by `message.id` because one message is written once per content block; result `usage` excludes subagents while `total_cost_usd` includes them. Evidence: [[src-ccdocs-agent-sdk-cost-tracking]], digest prototype. Confidence: high.
4. **Cost numbers are estimates and API-equivalent on a subscription.** `total_cost_usd` is a client-side estimate; ccusage prices tokens from LiteLLM tables. Prefer token counts, cache-read vs cache-creation, and a count of workers; watch the limit window (`ccusage blocks` or `/usage`). A resumed session's total already includes earlier spend. Evidence: [[src-ccdocs-agent-sdk-cost-tracking]], [[src-ccusage]]. Confidence: high.
5. **Claude Code has built-in OpenTelemetry; it is off by default and fails silently.** Metrics (`token.usage`, `cost.usage` with model/effort attributes), log events (`tool_decision`, `tool_result`, `api_error`, `safety_event` since 2.1.307), traces (beta: subagent spans nest under the parent tool span). Content logging flags are all off by default; do not enable raw bodies. Set exporter intervals short or data is lost on kill; `CLAUDE_CODE_OTEL_DIAG_STDERR=1` shows export errors; project-level settings OTEL vars are ignored (use user env). Evidence: [[src-ccdocs-monitoring-otel]], [[src-ccdocs-agent-sdk-observability]]. Confidence: high.
6. **Minimal OTel capture without a backend: an OTLP/HTTP-JSON sink that appends lines to a file, or an OpenTelemetry Collector `file` exporter with rotation.** The 30-line Python sink rotates at 20 MB; the collector's fileexporter has `max_megabytes/max_days/max_backups`. Cost: one always-on process. Worth it only if per-request cost/latency by effort is needed; hook logs plus transcripts cover job-level needs. Evidence: [[src-otel-collector-fileexporter]], [[src-mlflow-claude-otel-tracing]] (any OTLP-HTTP backend works), prototype `otlp_sink.py`. Confidence: med.
7. **Stop-hook trace shippers (Langfuse, LangSmith, Braintrust) are SaaS-first and send full transcripts out.** LangSmith: subagents only traced on completion; redaction is "a safety net, not a guarantee". On this box that means Roman's chats, tool output and possibly secrets leave the machine; publishing/exporting data externally is a confirm-first action. Evidence: [[src-langfuse-claude-code]], [[src-langsmith-claude-code]], [[src-braintrust-claude-code]]. Confidence: high.
8. **Background-session supervision is not available to the master.** The master is an interactive session started by Task Scheduler; the daemon supervisor restarts only background sessions, and after a reboot those show `failed` for 48 h then `stopped`. `claude agents --json` is the supported listing (do not parse `~/.claude/jobs`). Evidence: [[src-ccdocs-agent-view]]. Confidence: high.
9. **Read-only viewers on demand, not services.** claude-code-log renders a transcript to Markdown/HTML (`--depth agent` includes subagents); claude-devtools shows per-subagent execution trees and per-turn token attribution but needs a GUI. For a phone user: the manager generates a Markdown summary of a worker's transcript when Roman asks "what did X do". Evidence: [[src-claude-code-log]], [[src-claude-devtools]]. Confidence: med.
10. **Dashboards that nobody watches are waste.** disler's pipeline (hooks -> Bun -> SQLite -> WebSocket -> Vue) proves the event-bus idea; keep the sender and SQLite/JSONL, skip the UI. Pull model: a digest file answered on demand (Roman asked for no recurring reports). Evidence: [[src-disler-hooks-observability]], local policy in CLAUDE.md. Confidence: high (for us).
11. **Failure review beats generic metrics.** Hamel Husain: error analysis of real traces is the highest-ROI activity: open-ended notes on bad behaviour, group into a taxonomy, count frequencies (three issues covered >60% in his example); use binary pass/fail with a written critique, avoid generic scores. For us: a `jobs\failures.md` where each failed/partial job gets one line (what happened, root cause class: brief gap / env / capability / verification miss), reviewed weekly by the manager. Evidence: [[src-hamel-field-guide]]. Confidence: med-high.
12. **Make the context cost visible too.** Manus: KV-cache hit rate is the key production metric (input:output ~100:1; cached vs uncached 10x price difference); context-tax / `/context` / devtools token attribution show what is sent every turn. A SessionStart hook on resume gets `prompt_cache_likely_expired` and `estimated_cache_write_usd`. Evidence: [[src-manus-context-engineering]], [[src-ccdocs-hooks]]. Confidence: med-high.
13. **Use OTel GenAI vocabulary for local column names.** `gen_ai.agent.name/id`, `gen_ai.conversation.id`, `gen_ai.tool.call.id`, `gen_ai.usage.input_tokens/output_tokens/cache_read.input_tokens` (status: Development, not stable). Evidence: [[src-otel-genai-semconv-agent-spans]]. Confidence: med.
14. **Audit trail for confirm-first.** Log every blocked/asked action (hook decision) and Roman's approval with time and channel; Claude Code's `tool_decision` / `safety_event` OTel events and `PermissionRequest`/`PermissionDenied` hooks are the sources. Evidence: [[src-ccdocs-monitoring-otel]], [[src-ncsc-prompt-injection-not-sqli]] (log inputs, outputs, tool calls and failed actions). Confidence: high.
15. **Avoid vendor lock to shaky vendors.** Helicone reportedly moved to maintenance mode after joining Mintlify (snippet only: its URL returned 404 on re-check, treat as unverified); Langfuse joined ClickHouse; Vibe Kanban sunset. Files and open formats survive. Evidence: [[src-helicone-maintenance]], [[src-langfuse-selfhost]]. Confidence: med (snippet-level for Helicone).

## Reference stack (files only, ~0 tokens)
| Layer | What | Where | Cost |
|---|---|---|---|
| Event log | `hook_log.py` as async hook for SessionStart, SubagentStop, StopFailure, Stop, PreToolUse(Agent) | `claude-host\events\events.jsonl` (+ `run\<session>.hb` heartbeat) | none |
| Job ledger | `jobs.py` (new/set/list/effect) | `claude-host\jobs\ledger.jsonl` | none |
| Daily digest | `digest.py [date]` reads transcripts | printed on demand; optional file `jobs\digest-YYYY-MM-DD.md` | none |
| Cost/limit view | `/usage`, `npx ccusage blocks` | on demand | none |
| Failure notes | one line per failed/partial job | `jobs\failures.md` | few tokens |
| Optional | OTLP file sink for exact per-request cost | `claude-host\otel\*.jsonl` | one process |
Digest output on 2026-10-29 (lead re-run): 25 worker rows; 11 research workers launched 07:49-07:51 show 74-143 messages, 80-137k output tokens, 14.7-51.3M cache-read tokens each, finished within ~30 min; the `<synthetic>` model label marks transcripts whose last message was a harness-generated limit notice.
Do NOT build: Langfuse/Phoenix/Grafana stack, a live dashboard, per-token cost accounting in dollars, any export to SaaS without Roman's OK.

## Where sources disagree
- **Plugin tracing (Langfuse/LangSmith/Braintrust) vs native OTel.** Vendors push hook-based plugins; Anthropic documents OTel and MLflow shows any OTLP backend works. For us neither needs a backend; hooks + transcripts suffice.
- **Log content or not.** Observability vendors want full prompt/tool content; Anthropic defaults to off and warns to enable only where the pipeline is approved. For a host with secrets in tool output: keep content logging off and redact (hook_log.py redacts token-shaped strings).
- **Dollars vs tokens on subscription.** ccusage and SDK show USD; on a flat plan they are only relative. Use tokens and window percentage.

## Applies to us
Currently: `claude-host\log.md` (manual one-liners), `watchdog.log` (disabled), `desktop-layout.log`, no hooks, no ledger, no digest, no failure notes, `agent_push` notifications on. The manager cannot answer "what did my workers do last night and what did it cost" without reading transcripts by hand. The 5-hour limit was hit on 2026-10-29 with no early warning.

## Candidate changes for us
- **C1 (hook event log; prerequisite for the supervisor in [[topic-long-running-always-on-agents]] C5/C6):** copy `prototypes\hook_log.py` to `~\claude-host\tools\hook_log.py`; register in `~/.claude/settings.json` as async command hooks for `SessionStart`, `SubagentStop`, `StopFailure`, `Stop` and `PreToolUse` with matcher `Agent`: `python ~/claude-host/tools/hook_log.py` (use `python -I`-compatible, no network). Benefit: audit trail + heartbeat + delegation record. Risk: hook errors (script never raises, exits 0); confirm hook JSON field names on 2.1.312 with one test run.
- **C2 (digest on demand):** copy `digest.py` to `claude-host\tools\`; CLAUDE.md line: "When Roman asks what happened/what it cost: `python -I tools\digest.py [date]`, read the table, summarise in 3 lines. No scheduled reports." Benefit: answers "overnight" questions without tokens; respects the no-recurring-reports rule. Evidence: rules 3-4, 10.
- **C3 (limit awareness):** add to the manager's rules "before launching more than 3 workers or any effort high+ fan-out, run `npx ccusage blocks --json` or `/usage` and stage the work if more than 50% of the 5-hour window is used". Evidence: today's limit stop; rule 4. (Verify ccusage reports subscription windows on this host first.)
- **C4 (decision/approval records):** the ledger event `needs_roman` stores question, proposed default, expiry; Roman's approval is logged with the RC timestamp (see [[topic-long-running-always-on-agents]] C12). Evidence: rule 14.
- **C5 (failure notes):** `jobs\failures.md` one-liners with a root-cause class; weekly (on Roman's request) the manager groups them and proposes preset/brief changes. Evidence: rule 11.
- **C6 (optional OTel file sink):** only if C1/C2 prove insufficient; run `otlp_sink.py` as a scheduled task; set `CLAUDE_CODE_ENABLE_TELEMETRY=1`, `OTEL_METRICS_EXPORTER=otlp`, `OTEL_LOGS_EXPORTER=otlp`, `OTEL_EXPORTER_OTLP_PROTOCOL=http/json`, `OTEL_EXPORTER_OTLP_ENDPOINT=http://127.0.0.1:4318`, short export intervals, `CLAUDE_CODE_OTEL_DIAG_STDERR=1`. Leave all `OTEL_LOG_*` content flags unset. Evidence: rules 5-6.
- **C7 (quality gate for the manager itself):** keep 20 real past jobs (brief + worker + outcome) in `jobs\eval\` and re-run the manager's new brief template against 3-5 of them when the brief template or presets change; measure pass/fail by the verifier. Evidence: [[src-anthropic-demystifying-evals]] via [[topic-anthropic-agent-guidance]] rule 31.

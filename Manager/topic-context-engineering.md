# Context engineering for a long-lived manager (Anthropic guidance applied)

Scope: what Anthropic says about curating the tokens an agent sees (static vs just-in-time context, compaction, tool-result clearing, note-taking, sub-agent isolation, cache behaviour), and how an always-on, phone-driven manager should apply it. Sibling topics: [[topic-context-window-management]] (mechanics and third-party research), [[topic-long-running-always-on-agents]], [[topic-anthropic-agent-guidance]] (orchestration rules). Mechanics of what loads and what survives compaction: [[src-ccdocs-context-window]], [[src-ccdocs-prompt-caching]] (not repeated here).
Facts about the current setup (read 2026-10-29): master = one interactive Remote Control session (transcript 78968f1c) booted with `--model haiku --effort high --dangerously-skip-permissions`; CLAUDE.md 29.5 KB (~7.4k tokens) loaded every turn and into every subagent; Pending-work state and dated STATUS notes live inside CLAUDE.md; `log.md`, `session-notes\*.md` and an auto-memory MEMORY.md (one entry) exist; the skill/agent library is on disk behind `find.ps1` / PICKS.md (just-in-time by design); `syncClaudeAiPlugins:false` is set; `modelSettings` give only Sonnet 5.5 an `autoCompactWindow` (700000).

## TL;DR
- Treat context as a finite budget: "the smallest set of high-signal tokens that maximize the likelihood of your desired outcome". More is not better; recall degrades gradually with length. [[src-anthropic-effective-context-engineering]], [[src-platform-context-windows]]
- Keep the always-loaded layer tiny and non-discoverable (CLAUDE.md < 200 lines); load everything else just-in-time by pointer (paths, scripts, skills, search tools). [[src-ccdocs-best-practices]], [[src-ccdocs-memory]], [[src-anthropic-agent-skills]]
- For work that outlives one window use notes on disk (progress file, JSON state, git), not memory of the conversation, and restart routines that read them first. [[src-anthropic-effective-harnesses-long-running]], [[src-platform-memory-tool]], [[src-platform-prompting-best-practices]]
- Sub-agents are the context-isolation tool: only the brief goes in, only a condensed summary comes out; long artifacts go to files with a path handed back. [[src-ccdocs-agent-sdk-subagents]], [[src-anthropic-multi-agent-research-system]]
- Process bulky data outside the model (scripts/code/hooks) so only the answer enters context. [[src-anthropic-code-execution-with-mcp]], [[src-anthropic-advanced-tool-use]]
- Every request resends the whole history: for an always-on session the cost of a fat context is paid on every Telegram message. Compact at natural breaks with explicit instructions, `/clear` between unrelated jobs, never edit the prefix mid-session. [[src-ccdocs-best-practices]], [[src-claude-blog-prompt-caching-lessons]], [[src-ccdocs-costs]]
- State does not belong in instructions: put dated status in a notes file and re-read it at session start; conversation-only instructions are lost at compaction. [[src-ccdocs-memory]], [[src-ccdocs-context-window]]
- Long-context agents drift (Vend: invented people, claimed to be human); re-ground a long-lived agent from files and keep its role text in CLAUDE.md/soul.md, which are re-injected after compaction. [[src-anthropic-project-vend-1]]

## Rules
### A. What it is and why it matters
1. **Define the job as curation of tokens, every turn.** Context engineering = "the set of strategies for curating and maintaining the optimal set of tokens (information) during LLM inference", the successor to prompt engineering; it is iterative, done each time you decide what to pass to the model. Evidence: [[src-anthropic-effective-context-engineering]] (https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents, 2025-09-29). Confidence: high (official).
2. **Context is a finite budget with diminishing returns (context rot).** Recall and accuracy degrade as token count grows - "a phenomenon known as context rot" - gradually, not as a cliff, across models; curating what is in context "is just as important as how much space is available". Third-party benchmark of 18 models agrees (even one distractor hurts; focused ~300-token prompts beat ~113k-token ones on LongMemEval). Evidence: [[src-platform-context-windows]], [[src-anthropic-effective-context-engineering]], [[src-chroma-context-rot]] (2025-07, third-party). Confidence: high (official doc) / med (Chroma, vendor with retrieval interest).
3. **Bigger windows do not remove the problem.** Anthropic argues that waiting for larger windows will not remove the pollution and relevance problems; 1M windows are now default on current models and compaction is automatic, yet "a focused context gets you better answers and costs less" and `/clear` between tasks is still worth doing. Opus 5 docs claim instruction following and reasoning "stay consistent throughout the window" (vendor claim). Evidence: [[src-anthropic-effective-context-engineering]], [[src-ccdocs-best-practices]], [[src-platform-prompting-opus-5]]. Confidence: med-high.

### B. The always-loaded layer
4. **Write instructions at the right altitude and start minimal.** Avoid brittle if-else logic and vague guidance; begin with a minimal prompt, add instructions/examples from observed failures; "Minimal does not have to mean short"; use sections. Prefer a few diverse canonical examples to a laundry list of edge-case rules. Evidence: [[src-anthropic-effective-context-engineering]]. Confidence: high.
5. **CLAUDE.md: only what the agent cannot find, under 200 lines.** Test: "Could it find this by reading the code? Would it actually go and look? If both are yes, leave it out." Longer files "consume more context and may reduce adherence"; contradictions are resolved arbitrarily; imports organise but do not reduce cost. `/doctor` proposes cuts, `/doctor prompt-audit` finds stale and contradictory lines; `/usage` can flag "Trim CLAUDE.md" with a per-request token count. Evidence: [[src-ccdocs-best-practices]], [[src-ccdocs-memory]], [[src-ccdocs-costs]]. Confidence: high.
6. **Procedures and bulky reference go in skills / path-scoped rules, not CLAUDE.md.** A skill costs only name+description each turn and loads its body when needed (three-level progressive disclosure: metadata -> SKILL.md -> bundled files; scripts run without loading code or data into context). Path-scoped rules load only when a matching file is touched but are summarised away at compaction unless unscoped. Evidence: [[src-anthropic-agent-skills]] (2025-10-16), [[src-ccdocs-best-practices]], [[src-ccdocs-context-window]]. Confidence: high.
7. **State is not instruction.** Progress, dated status and TODOs belong in notes files; CLAUDE.md is re-read from disk after compaction, but "conversation-only instructions" and nested/path-scoped files are not guaranteed to be. Add standing instructions given in chat to CLAUDE.md to make them persist. Evidence: [[src-ccdocs-memory]], [[src-ccdocs-context-window]], [[src-anthropic-effective-harnesses-long-running]]. Confidence: high.
8. **Delete emphasis and old-model scaffolding.** IMPORTANT/ALL CAPS "mostly makes Claude over-apply the rule"; "think hard", "be thorough", "keep going, don't be lazy" are plain text that can cause over-work; "Tune anti-laziness prompting" when moving to newer models; skills written for older models can be too prescriptive. Evidence: [[src-ccdocs-best-practices]], [[src-platform-prompting-best-practices]], [[src-anthropic-prompting-fable-5]]. Confidence: high.

### C. Just-in-time retrieval and tool context
9. **Keep lightweight identifiers, load on demand.** Agents hold file paths, stored queries, links and fetch with tools at runtime; folder structure, names and timestamps are signals; progressive disclosure lets the agent build understanding layer by layer. Trade-off: slower and needs good tools/heuristics. Evidence: [[src-anthropic-effective-context-engineering]]. Confidence: high.
10. **Hybrid beats pure either way.** Claude Code loads CLAUDE.md up front and uses glob/grep just-in-time; the SDK blog advises starting with agentic search (grep/tail, file layout as context engineering) before semantic search, which is faster but less accurate, harder to maintain and less transparent (the blog's wording, paraphrased). Evidence: [[src-anthropic-effective-context-engineering]], [[src-anthropic-agent-sdk-blog]]. Confidence: high.
11. **Bloated, overlapping tool sets are a top failure.** "If a human can't clearly choose a tool, the agent likely can't either." Few targeted tools, namespaced; defer tool definitions: Tool Search cut tokens ~85% and lifted MCP accuracy (Opus 4 49->74%, Opus 4.5 79.5->88.1%); worthwhile when definitions exceed ~10K tokens or 10+ tools, little value under 10. Connected MCP servers add names/instructions even when idle; disable unused ones; prefer CLI (`gh`) over MCP for context efficiency. Evidence: [[src-anthropic-effective-context-engineering]], [[src-anthropic-writing-tools-for-agents]], [[src-anthropic-advanced-tool-use]], [[src-ccdocs-best-practices]]. Confidence: high.
12. **Keep tool results small; do bulk processing outside the model.** Claude Code caps tool responses at 25,000 tokens; concise vs detailed response modes (72 vs 206 tokens in the example); filter/aggregate in code so the agent "sees 5 rows of a 10,000-row sheet" (150,000 -> 2,000 tokens in the article's example); programmatic tool calling -37% tokens; hooks can pre-filter verbose output. For test/verification harnesses: print a few lines, write detail to a log file, tag errors for grep, precompute summaries ("The test harness should not print thousands of useless bytes"). Evidence: [[src-anthropic-writing-tools-for-agents]], [[src-anthropic-code-execution-with-mcp]], [[src-anthropic-advanced-tool-use]], [[src-anthropic-building-c-compiler]], [[src-ccdocs-costs]]. Confidence: high.
13. **Clear stale tool results first - "safest lightest touch" compaction.** API context editing: oldest tool results replaced with placeholders past a threshold (default trigger 100,000 input tokens, keep last 3 tool uses, `exclude_tools`, `clear_at_least` so a cache break is worth it); memory-tool pairing warns the model before clearing. Internal numbers: context editing +29%, with memory tool +39% on an agentic search eval; -84% tokens on a 100-turn web search. Evidence: [[src-anthropic-effective-context-engineering]], [[src-platform-compaction-context-editing]], [[src-claudecom-context-management]] (2025-09-29). Confidence: med-high (internal evals). Disagreement with Manus ("keep the wrong stuff in") below.

### D. Long-horizon techniques
14. **Pick the technique to the work shape.** Compaction for long back-and-forth; structured note-taking for iterative, milestone-driven work; multi-agent / sub-agent architectures for parallel exploration. Evidence: [[src-anthropic-effective-context-engineering]]. Confidence: high.
15. **Compaction: preserve decisions, tune for recall first, tell the model.** Claude Code keeps key decisions, unresolved bugs and recently touched files. Custom summariser should preserve: problems and how resolved; options tried or set aside and why; everything asked/decided/ruled out "stated exactly"; exactly where things stand; what is open/promised/next; hard-to-reconstruct specifics kept exactly; user's words close to verbatim, assistant reasoning condensed (full prompt in [[src-platform-prompting-fable-5-1]]). If the harness compacts, say so in the prompt ("your context will be automatically compacted... do not stop tasks early due to token budget concerns... save your progress and state") or the model may wind down near the limit. Evidence: [[src-anthropic-effective-context-engineering]], [[src-platform-prompting-fable-5-1]], [[src-platform-prompting-best-practices]]. Confidence: high.
16. **Compaction has a price and a timing.** `/compact` is itself a large request (it reads the whole conversation) and costs most after the cache expired; run it at natural breaks, with a focus (`/compact keep the API changes and the test commands`) or a "# Compact instructions" section in CLAUDE.md; idle sessions on the 1-hour TTL are compacted before expiry (`idleCompaction`, threshold 200,000 tokens). Fable 5.1 guidance: with cheaper cache reads, later compaction points may now be the better trade. Evidence: [[src-ccdocs-best-practices]], [[src-ccdocs-prompt-caching]], [[src-ccdocs-settings-idle-compaction-budget]], [[src-platform-prompting-fable-5-1]]. Confidence: high.
17. **A fresh window plus disk state often beats compaction.** "consider starting with a brand new context window rather than using compaction. Claude's latest models are extremely effective at discovering state from the local filesystem" - and be prescriptive about the restart ("Call pwd... Review progress.txt, tests.json, and the git logs... run a fundamental integration test"). The harness post found compaction alone insufficient for multi-session work. Resets are model-dependent: needed for Sonnet 4.5 context anxiety, largely unnecessary on Opus 4.5+. Evidence: [[src-platform-prompting-best-practices]], [[src-anthropic-effective-harnesses-long-running]], [[src-anthropic-harness-design-long-running-apps]]. Confidence: high.
18. **Structured note-taking recipe.** First window differs from later ones (set up tests, init script, feature list); structured state in JSON (models alter it less than Markdown), freeform text for progress notes, git for checkpoints and revert; one item at a time, "Mark a feature complete only after end-to-end verification"; never remove or edit tests; every session starts: read progress file + git log + state file, run a basic check, then work. Evidence: [[src-anthropic-effective-harnesses-long-running]] (2025-11-26), [[src-platform-memory-tool]], [[src-platform-prompting-best-practices]]. Confidence: high.
19. **Memory protocol: look first, write as you go, assume interruption.** Memory-tool system text: "ALWAYS VIEW YOUR MEMORY DIRECTORY BEFORE DOING ANYTHING ELSE... ASSUME INTERRUPTION: Your context window might be reset at any moment"; keep it "up-to-date, coherent and organized... rename or delete files that are no longer relevant. Do not create new files unless necessary". Fable guidance: one lesson per file with a one-line summary on top, record corrections and confirmed approaches with the why, do not save what the repo already records, delete notes that turn out wrong. Claude Code auto memory loads only the first 200 lines / 25 KB of MEMORY.md (an index) and topic files on demand. Evidence: [[src-platform-memory-tool]], [[src-anthropic-prompting-fable-5]], [[src-ccdocs-memory]]. Confidence: high.
20. **Sub-agents isolate context in both directions - design the boundary.** In: "The only content you pass from parent to subagent is the Agent tool's prompt string". Out: only the final message returns; "The parent receives a concise summary, not every file the subagent read". Large artifacts: subagents write to the filesystem and return a lightweight reference, avoiding a "game of telephone" and token overhead; the lead saves its plan to memory because context beyond ~200k tokens was truncated; for long horizons summarise completed phases, store essentials externally and spawn fresh subagents with clean context and careful handoffs. Evidence: [[src-ccdocs-agent-sdk-subagents]], [[src-anthropic-multi-agent-research-system]], [[src-anthropic-effective-context-engineering]]. Confidence: high.
21. **But isolation is lossy and not always needed.** Results return as lossy summaries and each handoff degrades fidelity; a single loop keeps all step results so the agent "can connect them"; use subagents when a single loop shows measurable degradation from context bloat, when parallel tasks need disposable fresh windows, or when tool choice is overloaded. Claude Code docs now list "use subagents to protect your context window" among advice to stop following because running out is rare. Evidence: [[src-claudecom-fold-subagents]] (2026-10-22), [[src-ccdocs-best-practices]]. Confidence: med-high.
22. **Do not feed the model a token countdown or invite it to wind down.** Fable 5: harness-shown remaining-token counts can make the model suggest a new session or trim its work; avoid surfacing counts or add "You have ample context remaining. Do not stop, summarize, or suggest a new session on account of context limits." Context awareness (injected budget tags) exists on Sonnet 5, Sonnet 4.6, Haiku 4.5; not on Opus 4.7+, Sonnet 5.5, Haiku 5.5, Fable/Mythos. Harness text appended after every tool result can be misread by Sonnet/Haiku 5.5 as prompt injection. Evidence: [[src-anthropic-prompting-fable-5]], [[src-platform-context-windows]], [[src-platform-prompting-sonnet-5-5]]. Confidence: high.
23. **Give long runs a clock.** "Claude can't tell time and, left alone, will happily spend hours running tests"; Opus 5.5 responds to `elapsed 340s / 1200s` lines and finishes teams sooner at comparable quality. Evidence: [[src-anthropic-building-c-compiler]], [[src-anthropic-prompting-opus-5-5]]. Confidence: med-high.

### E. Cost and cache discipline
24. **Every request resends the history; long sessions pay for everything in them.** "a one-line question in a session that has been open all day still draws usage for the whole conversation". `/clear` between unrelated tasks costs nothing; `/compact` is a big request; cache lasts about an hour on a subscription (main conversation), five minutes for subagents unless changed; scheduled tasks and cross-session messages that fire while idle reprocess full context. Evidence: [[src-ccdocs-best-practices]], [[src-ccdocs-costs]]. Confidence: high.
25. **Append-only, static first, dynamic last.** Put system prompt and tools first (cached), then CLAUDE.md, then session context, then messages; pass changed information in the next user message/tool result with `<system-reminder>` tags instead of editing the system prompt; do not add/remove tools or switch models mid-session (use subagents for a different model); plan mode is implemented as tools so tool definitions never change; compaction reuses the parent's exact prefix and appends the summary request (about a tenth of the price). For API users on newer models, editing earlier turns or the system prompt invalidates thinking blocks too. Evidence: [[src-claude-blog-prompt-caching-lessons]], [[src-platform-prompting-fable-5-1]], [[src-ccdocs-prompt-caching]]. Confidence: high.
26. **Watch cache hit rate like uptime.** The Claude Code team alerts on cache breaks and declares incidents; `/usage` now shows a prompt-cache line (hit %, misses, expected rebuilds) for the main conversation. A harness bug that cleared reasoning every turn (Mar 26-Apr 10 2026) made Claude "forgetful and repetitive" and drained limits; code review and dogfooding missed it. Evidence: [[src-claude-blog-prompt-caching-lessons]], [[src-ccdocs-costs]], [[src-anthropic-april-23-postmortem]]. Confidence: high.

### F. Behaviour of long-lived agents
27. **Long contexts make agents unpredictable; re-ground them.** Project Vend phase 1: after a long context the agent invented a contractor, claimed to be a person who would deliver in a blazer, and hallucinated a payment account; authors cite "the unpredictability of these models in long-context settings". Phase 2: forced procedures/checklists ("institutional memory") were among the most impactful fixes. Evidence: [[src-anthropic-project-vend-1]], [[src-anthropic-project-vend-2]]. Confidence: med-high (one deployment).
28. **Verifiers and reviewers should start with clean context.** The grader uses "a separate context window to avoid being influenced by the main agent's implementation choices"; `/code-review` runs in a fresh subagent "that never saw your conversation". Evidence: [[src-platform-managed-agents-outcomes]], [[src-ccdocs-best-practices]]. Confidence: high.
29. **Mid-run user input needs the right slot.** Haiku/Sonnet 5.5 discount "user" text inside or directly after tool results as possible injection; deliver it as a user-turn text block after the last tool_result. Evidence: [[src-platform-prompting-haiku-5-5]], [[src-platform-prompting-sonnet-5-5]]. Confidence: high (doc), test needed locally.
30. **Re-test context machinery on every model change.** Context resets were added for one model and became dead weight on the next; "harnesses encode assumptions about what Claude can't do on its own". Evidence: [[src-anthropic-managed-agents]], [[src-anthropic-harness-design-long-running-apps]]. Confidence: high.

## What changed in 2026 (added 2026-11-01)
- **Offload before summarising** (Deep Agents): tool results >20,000 tokens go to a file with path + 10-line preview; at 85% of the window old write/edit arguments become file pointers; only then an LLM summary with originals saved on disk. Reserve explicit slots for goal and next actions in the summary; test that the objective survives summarisation. [[src-langchain-context-management-deep-agents]] (vendor; thresholds are config). Same direction as Claude Code's own change that oversized tool output now persists to a file (see [[src-zivtech-claude-code-economics]]).
- **Hooks and skills as context filters** and CLAUDE.md under ~200 lines with workflow detail in skills; delegate verbose output (tests, logs) to subagents. [[src-ccdocs-costs-2026-update]].
- **Context for a fresh agent = a repo-resident map**, not the lead's chat: teammates and subagents do not inherit conversation history, only CLAUDE.md, skills, MCP and the spawn prompt. [[src-ccdocs-agent-teams]], [[src-openai-harness-engineering-infoq]] (docs directory as source of truth).
- **Workflows keep intermediate results in script variables**, so fan-out never enters the manager's window. [[src-ccdocs-workflows-usage-and-limits]].

## Where sources disagree
1. **Compaction vs fresh start vs notes.** Context-engineering post offers all three by task shape [[src-anthropic-effective-context-engineering]]; prompting guide: consider a fresh window plus filesystem state over compaction [[src-platform-prompting-best-practices]]; harness post: compaction alone is not enough for multi-session projects [[src-anthropic-effective-harnesses-long-running]]; Claude Code docs: compaction is automatic so "you'll rarely run out of context" [[src-ccdocs-best-practices]]; Fable 5.1: compact later [[src-platform-prompting-fable-5-1]]. For a single always-on session the three combine: auto-compaction as the safety net, `/clear`-with-handoff at job boundaries, notes files as the real memory.
2. **Clear or keep failed attempts?** Anthropic's context editing clears stale tool results (lightest-touch compaction) [[src-platform-compaction-context-editing]]; Manus keeps failed actions and stack traces in context so the model updates its beliefs, and treats irreversible compression as risky [[src-manus-context-engineering]]. Both agree on restorable compression (keep the path/URL, drop the body). For us: clear bulky success output, keep one-line records of failed attempts and why in the job note.
3. **Do subagents protect context?** Research-system and context-engineering posts: yes, core benefit [[src-anthropic-multi-agent-research-system]]; Claude Code docs (Oct 2026-era): rarely the real problem now, and each subagent costs extra tokens and a lossy summary [[src-ccdocs-best-practices]], [[src-claudecom-fold-subagents]]. For a manager whose own context lives for weeks and is billed on every Telegram message, isolation of bulky, tool-heavy worker output is still the point; but keep the report channel narrow.
4. **How bad is rot at 1M tokens?** Chroma: all 18 models degrade even on simple tasks [[src-chroma-context-rot]]; Anthropic's Opus 5 page claims consistency across the window [[src-platform-prompting-opus-5]]; an arXiv study finds agent success decays with step count rather than context length [[src-arxiv-how-fast-do-agents-rot]]. Net: assume rot and drift are real for multi-week histories, keep jobs short (few dependent steps), verify at boundaries, and measure rather than trust either side.
5. **Retrieval flavour.** SDK blog: start with agentic (lexical, file-layout) search, semantic search later [[src-anthropic-agent-sdk-blog]]; Anthropic's older contextual-retrieval work (embeddings + BM25) targets static corpora [[src-anthropic-contextual-retrieval]]. Our library search (`find.ps1` over an index, `PICKS.md`) is the agentic/lexical kind and fits the advice.
6. **Counting tokens for the model.** Older Sonnet/Haiku 4.x had injected countdowns; current guidance says avoid surfacing counts to Fable and notes the 5.5 models do not receive them [[src-anthropic-prompting-fable-5]], [[src-platform-context-windows]]. Follow current: no countdowns, one reassurance line if the model starts wrapping up.

## Applies to us
The manager is the textbook case for these rules: one session, weeks long, phone-driven, delegating heavy tool work. What it gets right: the 1000s-item library is NOT in `~/.claude/skills` and is reached by a search script plus a PICKS shortlist (just-in-time, progressive disclosure); workers run as nested subagents whose transcripts stay out of the manager context; `syncClaudeAiPlugins:false` removed ~70 ambient skills; `log.md`, `session-notes\`, and auto-memory exist as external notes; Telegram replies are phone-short. What is missing or wrong:
- **CLAUDE.md is 7.4k tokens of mixed content**: much of it device/tool inventory that is discoverable from the machines or only needed for some jobs (Linux power, quiet mode, desktop layout, screenshots, disk cleanup, Telegram internals), three DISABLED feature sections still loaded every turn and into every worker, and a "Pending work" state log with dated STATUS notes whose older paragraphs are contradicted by newer ones ("SUPERSEDES every earlier note"). Rules 5-8 apply directly.
- **No compaction policy**: nothing tells the compactor what to keep (open worker jobs, Roman's standing instructions, pending approvals), `autoCompactWindow` is set only for Sonnet 5.5, and the master is Haiku 5.5 (Haiku prompts over 100,000 tokens are billed at a higher rate on the API per [[src-platform-context-windows]]; on a subscription the same fact shows up as faster usage burn - unmeasured). Rules 15-16.
- **No job journal / session-start routine**: after a restart or compaction the manager re-learns what is running from the transcript. `boot-claude.ps1` has a boot message but there is no "read pending.md and the last log lines" step documented in CLAUDE.md. Rules 17-19.
- **Worker output is unconstrained**: briefs do not cap report length or require artifacts to go to files, so one chatty worker report (screenshots paths, logs) lands in the manager's context permanently. Rules 12, 20.
- **Standing instructions given in chat** (e.g. "no maintenance reports") rely on auto-memory entries or CLAUDE.md edits happening; nothing says to persist them the same turn. Rule 7.
- **Manager helper scripts** (`linux-power.ps1`, `cachyos-run.ps1`, `find.ps1`) print whatever they print; no convention of "one status line + log path". Rule 12.
- Workers do not inherit the manager's auto memory (subagents get their own `memory:` directory only if configured), so lessons learned in one job are not seen by the next worker unless the manager restates them. Rule 19.
Not applicable now: API context editing / memory-tool code (Claude Code has its own), tool search (MCP servers are few and deferred), code-execution-with-MCP (only if MCP tool count grows), task budgets and context-awareness tags (not supported on Claude Code / on these models).

### Operating model for the long-lived manager (derived)
1. **Thin by design**: manager context holds Roman's messages, briefs, one-screen reports and decisions; anything else is a path.
2. **State on disk**: `session-notes\pending.md` (state, one line per open job: id, worker, started, done-when, report path), `jobs\<id>\brief.md|report.md|evidence.txt`, `log.md` (append-only, one line per closed job), lessons directory (one lesson per file).
3. **Session start** (boot, after `/clear`, after compaction): read `pending.md` and the last 20 lines of `log.md`; check which jobs are still running (`/tasks`); then answer Roman.
4. **Job close**: append to log.md and update pending.md in the same turn the result is relayed; write lessons from PROBLEMS.
5. **Boundary hygiene**: when no workers are running and Roman's topic changes, the manager writes a handoff to pending.md and the session is compacted or cleared; a long idle (cache expired) is the cheap moment.
6. **Never** edit the prefix mid-session expecting immediate effect (CLAUDE.md edits apply after `/clear`, `/compact` or restart per [[src-ccdocs-prompt-caching]]); never switch the master's model mid-session; model switches happen by choosing the worker.

## Candidate changes for us
C1. **Thin the manager's inputs (workers return little, write the rest to files).** Add to the brief template in CLAUDE.md: "Report format: RESULT, DONE, VERIFIED, PROBLEMS, NEEDS, NEXT, ARTIFACTS, max 25 lines in total. Anything longer (logs, command output, transcripts, lists over 10 items) goes to `~\claude-host\jobs\<job-id>\` and you give me the path. Never paste screenshots or raw logs into the report." Add to the manager rules: "Do not read a worker's file in full to relay it; read the report and, if I need proof, `Select-String` or `Get-Content -Tail 20` one named evidence file." Expected benefit: the manager's per-job context cost stays near constant; matches rules 12, 20. Risk: a worker truncates something Roman wanted verbatim; mitigate by listing ARTIFACTS with paths and sending files via SendUserFile.
C2. **Move state out of CLAUDE.md and add a session-start routine.** Create `~\claude-host\session-notes\pending.md` (copy the current "Pending work" and STATUS paragraphs there, resolve the contradictions into a clean current list) and `~\claude-host\jobs\`. CLAUDE.md gets: "State: open jobs and pending decisions live in session-notes\pending.md; the finished-job log is log.md. At session start, after /clear and after any compaction: read pending.md and the last 20 lines of log.md, then check /tasks for running workers, before replying. At job close, update both in the same turn as telling Roman." Also add the boot-time prompt line in boot-claude.ps1's boot message (config edit: ask Roman). Benefit: restarts and compactions stop depending on the transcript; the manager can be `/clear`ed safely. Risk: stale notes if the manager forgets to update; add a one-line check ("pending.md matches /tasks") to the session-start routine.
C3. **Compaction instructions in CLAUDE.md.** Add a section the docs say compaction honours ([[src-ccdocs-costs]]): "# Compact instructions: When compacting, keep exactly: Roman's standing instructions and anything he asked for, decided, ruled out or approved (his words, verbatim); every open job (id, worker, what it must deliver, done-when, report path); pending approvals; the current state of each machine/device I touched; errors we hit and how they were fixed; paths, ids, hostnames and numbers. Everything else may be condensed to its conclusion." (Derived from the six-item summary prompt in [[src-platform-prompting-fable-5-1]].) Benefit: the compactor knows what a manager must not lose. Risk: low; a long instruction slightly lengthens CLAUDE.md.
C4. **Compaction window and idle behaviour for the Haiku master.** In `~/.claude/settings.json` `modelSettings`: add `"claude-haiku-5-5": {"effortLevel":"high","autoCompactWindow":150000}` (value to be tuned; the setting's valid range is documented as 100000-1000000 for subagents, assume the same here and check `/status` after restart). Leave `idleCompaction` at default (it compacts a long idle conversation shortly before the 1-hour cache expires; the docs list "interactive terminal / VS Code / desktop session" as eligible, so whether a Remote Control master qualifies is unverified). Consider `crossSessionInbound: "hold"` only if cross-device messaging gets used, because idle-delivered cross-session messages replay full context each time ([[src-ccdocs-costs]]). Benefit: bounded per-message cost for an always-on session. Risk: more frequent compactions (each a large request) and slight loss of detail; mitigated by C2/C3. Config change: needs Roman's OK.
C5. **Persist standing instructions the same turn.** Add to soul.md: "When Roman gives a standing instruction (do/don't from now on, a preference, a rule about money, messages or devices), I write it to CLAUDE.md or the matching ref file before replying; a chat-only instruction is lost at compaction." Source: [[src-ccdocs-memory]]. Benefit: stops the 'he told me, I forgot' failure after any compaction or restart. Risk: CLAUDE.md creep; mitigate with the 200-line audit in C6.
C6. **Make `/doctor prompt-audit` + a length check a routine, not a one-off.** Add to `manager-evals\harness-audit.md` (see C9 in [[topic-anthropic-agent-guidance]]): "Monthly and after any model change: run /doctor prompt-audit and /usage; CLAUDE.md must be under 120 lines and 4k tokens; delete lines Claude can derive; list every 'never/must/required/important' and move true never-rules into permissions.deny or a hook." Benefit: stops regrowth (CLAUDE.md went from 26.7 KB in `CLAUDE.md.bak-2026-10-28` to 29.5 KB on 2026-10-29, +10% in a day, mostly dated blocks). Risk: none.
C7. **Script output convention for manager tools.** Convention for `~\claude-host\tools\*.ps1` and `cachyos-run.ps1` wrappers: print at most 10 lines to stdout (one status line first: OK/FAIL + key facts), write full output to `~\claude-host\jobs\<job-id>\<tool>.log` and print the path; add `-Verbose` to stream everything. Benefit: rule 12; the manager context no longer swallows SSH noise. Risk: workers must read the log for details (they can).
C8. **Lessons directory instead of re-explaining.** Create `~\claude-host\lessons\` (one file per lesson, first line = one-line summary; why it mattered; corrected approach) and an index `lessons\INDEX.md` (<100 lines). After each job the manager adds a lesson only for recurring or costly surprises (e.g. "CachyOS login shell is fish: pipe scripts to bash -s"); briefs include "read lessons\INDEX.md and any file relevant to this job". Source: [[src-anthropic-prompting-fable-5]] memory snippet ("one lesson per file with a one-line summary at the top... delete notes that turn out to be wrong"). Benefit: workers inherit fixes without CLAUDE.md growth (they do not inherit auto memory). Risk: stale lessons; add a 'last verified' date and prune monthly (a manual version of the between-session consolidation Anthropic announced as the research-preview "dreaming" for Managed Agents on 2026-05-06: dedupe, drop stale entries, flag recurring mistakes; secondary coverage only, no primary doc read).
C9. **Do not edit the prefix and do not switch the master model while working.** Add to CLAUDE.md under Upkeep: "CLAUDE.md/soul.md edits take effect after /clear, /compact or restart; make them at job boundaries and tell Roman if a restart is needed. The master stays on its configured model; use a worker with another model instead." Source: [[src-ccdocs-prompt-caching]], [[src-claude-blog-prompt-caching-lessons]]. Benefit: avoids unplanned full-cost cache rebuilds. Risk: none.
C10. **Test `/clear` in the Remote Control session before relying on it.** Procedure for a worker or Roman: on a throwaway state, run `/clear` in the RC master and check claude.ai/code and the phone app: same row? new row? old row archived? (manager-setup.md says compaction rewrite or `/resume` to another conversation archives the old server session on reconnect.) If `/clear` breaks the row, use compaction + C2 notes only. Benefit: prevents losing the phone connection. Risk: a brief disconnect during the test; do it when Roman is not mid-task.

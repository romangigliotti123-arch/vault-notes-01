# Retrieval and curation for a 5,600-item skill/agent library

Scope: finding the right skill/agent among thousands, quality over breadth, evaluating retrieval, curation, how skills should be loaded. Current tooling: `~\claude-library\tools\find.ps1` (weighted keyword match over `index.tsv`), `PICKS.md` (hand-written best items for ~90 jobs), `query-vault.ps1` (graphify graph), `NAMES.txt`. Security of imported skills: [[topic-agent-security]]. Knowledge notes side: [[topic-knowledge-management-rag]]. Synthesised by the lead from src- notes (worker stopped by the usage limit).

## TL;DR
- Breadth does not help; relevance and quality of the 1-3 retrieved items do. With 34k real skills in the pool, skill benefits are "fragile" and approach no-skill baselines in hard scenarios; curated skills give +16.6 points on SkillsBench but self-generated skills give none. Our PICKS.md layer is the right design. [[src-arxiv-agentic-skills-in-the-wild]], [[src-arxiv-skillsbench]]
- BM25 over name + description (+ a short profile) is a strong baseline at scale; an LLM query-rewrite loop did not beat it in 3 of 4 settings; appending raw body text adds noise (-3.2%); hand 3-5 candidates to the agent. find.ps1's design (field-weighted keyword scoring on name/category/description) is already close to the evidence. [[src-arxiv-skillseek]], [[src-arxiv-field-aware-skill-retrieval]]
- The failure that matters is not retrieval quality but the decision to retrieve: Vercel found the skill was never invoked in 56% of eval cases, while a compressed index placed in always-loaded context reached 100%. Put "run PICKS/find before briefing" where it cannot be skipped. [[src-vercel-agentsmd-outperforms-skills]]
- Measure with your own queries: generic retrievers do poorly on tool/skill retrieval (ToolRet), so build a 40-50 query eval set from real Roman jobs and track hit-rate. [[src-arxiv-toolret]], [[src-arxiv-skillret]]
- Keep the library out of the always-on listing (skill names are always in context; descriptions share a 1% budget); native loading only for a handful. [[src-ccdocs-skills]], [[src-anthropic-tool-search-tool-doc]]

## Rules
1. **Quality and relevance dominate; prune and gate.** Retrieval + refinement lifted Opus 4.6 on Terminal-Bench 2.0 from 57.7% to 65.5% but only when initial skills were relevant; curated skills +16.6 pp, self-generated -1.3 pp, and 18 of 84 tasks regressed with curated skills. A skill used for the wrong job costs tokens and can hurt. Evidence: [[src-arxiv-agentic-skills-in-the-wild]] (2026-04-06), [[src-arxiv-skillsbench]] (2026-02-13, partly snippet-level). Confidence: med-high.
2. **Index what describes the skill, not its body.** SkillSeek: name + description + a short structured profile; raw body added noise (-3.2% pass rate); plain BM25 matched an LLM rewrite loop; reranker gains grow when stage-1 recall is far from ceiling; top-3 captures nearly all the gain; differences under ~2% are noise. Evidence: [[src-arxiv-skillseek]] (2026-09-30, single-trial caveat). Confidence: med.
3. **Score fields separately (name > description > body/category).** Field-aware retrieval (separate sparse and dense per field, combined) beats flattening, with larger gains as the bank grows (Recall@10 77.95 on SkillRet). find.ps1 already does leaf-name 12 / name 6 / category 3 / description 2 / +4 per matched word / +5 own. Evidence: [[src-arxiv-field-aware-skill-retrieval]], [[src-arxiv-skillret]]. Confidence: med.
4. **Hybrid lexical + semantic with reciprocal rank fusion is the standard upgrade.** RRF sums 1/(rank+k), k=60, no score normalisation; BM25 catches exact identifiers that embeddings miss; reranking on top; Anthropic's contextual retrieval cut top-20 failures 5.7% -> 1.9% with contextual embeddings + BM25 + rerank. A local hybrid tool for markdown exists (qmd: SQLite FTS5 + embeddinggemma 300M + qwen3 reranker 0.6B, RRF k=60, MCP server) but needs ~2 GB of local models and a Node runtime: optional, and it must be registered with track-software.ps1 if installed. Evidence: [[src-azure-hybrid-rrf]], [[src-anthropic-contextual-retrieval]], [[src-qmd-readme]]. Confidence: med-high; qmd's own quality numbers are a tiny non-independent fixture.
5. **Index both granularities and link them.** Embedding tools and their parent agents together (+19.4% Recall@5 on LiveMCPBench) and hierarchical routing (server first, then tool; MCP-Zero 98% fewer tokens) fit a library of coarse agents and fine skills. Evidence: [[src-arxiv-tool-to-agent-retrieval]], [[src-arxiv-mcp-zero]], [[src-arxiv-rag-mcp]] (tool-selection accuracy 43% vs 14% baseline when retrieving then exposing few tools). Confidence: med.
6. **Evaluate retrieval on your own queries.** Models and retrievers that do well on web QA do badly on tool retrieval; poor retrieval degrades end-to-end pass rate. Build ~40-50 queries from real jobs (phrased the way Roman phrases them), each with 1-3 acceptable ids, and compute hit@3 for find.ps1, PICKS lookup and any new method. Higher recall does not guarantee a higher pass rate, so also spot-check end-to-end on 5-10. Evidence: [[src-arxiv-toolret]], [[src-arxiv-skillseek]], [[src-anthropic-agent-skills]] ("build evals first"). Confidence: high (method), med (numbers).
7. **The decision to retrieve is the weak link.** "In 56% of eval cases, the skill was never invoked"; a passive, always-loaded index (AGENTS.md compressed docs index) scored 100% vs 53% baseline, explicit invoke instructions 79%. Practical: keep PICKS pointers in always-loaded context (cheap, a few lines) and have a hook/brief template force the lookup step for jobs of known categories, rather than relying on the manager deciding to search. Evidence: [[src-vercel-agentsmd-outperforms-skills]] (2026-01-27, vendor eval, wording-sensitive). Confidence: med.
8. **Descriptions are the interface: what AND when, third person, pushy, with "when not".** 1,024-char limit, key use case first; avoid vague names (helper, utils); consistent naming; descriptions drive triggering for native skills and are all find.ps1 indexes. Evidence: [[src-anthropic-skill-best-practices-doc]], [[src-gh-anthropics-skills-skill-creator]], [[src-ccdocs-skills]]. Confidence: high.
9. **Unique names are mandatory at scale.** Claude Code keys agents by frontmatter `name`; duplicates overwrite silently. wshobson's fix: plugin-scoped names; our build-index already errors on duplicates and prefixes imported ids. Add a lint for missing trigger phrases ("Use when ...") and oversized SKILL.md. Evidence: [[src-gh-wshobson-agents]]. Confidence: high.
10. **Progressive disclosure everywhere.** Name+description in listing, body on demand, bundled files only when needed; a compact always-visible index plus on-demand content is the same idea as aider's repo map and our NAMES/PICKS. Evidence: [[src-anthropic-agent-skills]], [[src-aider-repomap]], [[src-anthropic-effective-context-engineering]]. Confidence: high.
11. **Tool/skill search at the platform level exists but is for API tools.** Tool Search (`defer_loading`, BM25/regex) degrades past 30-50 tools; Claude Code defers MCP tools by default. Not a substitute for a library lookup of skills that are not installed. Evidence: [[src-anthropic-tool-search-tool-doc]], [[src-anthropic-advanced-tool-use]]. Confidence: high.
12. **Skills that grow from experience must be verified before storing.** Voyager stores only skills verified by environment feedback; ExpeL distils reusable insights; SkillWeaver's practised APIs transfer across models (+54% for weaker agents); Reflexion works because the feedback is an external pass/fail signal. For us: promote a worker-created skill to the library only after a second job used it successfully; log each use. Evidence: [[src-arxiv-voyager]], [[src-arxiv-expel]], [[src-arxiv-skillweaver]], [[src-shinn-reflexion]]. Confidence: med.
13. **Curate before release; measure usage; delete the unused.** Anthropic's own advice: sandbox folder first, promote after organic traction, "curation before release is important to avoid redundant skills"; `/skill-doctor` flags never-invoked skills (host terminal only). For an offline library: a usage log gives the same signal. Evidence: [[src-thariq-skills-lessons]], [[src-ccdocs-skills]]. Confidence: med.
14. **Imported skill trust is a retrieval-time concern too.** A retrieved skill is executable instructions: prefer first-party and high-trust sources in ranking; show the source and licence in results; never auto-run bundled scripts. Evidence: [[src-arxiv-malicious-agent-skills]], [[src-snyk-toxicskills]], [[src-anthropic-skills-security-doc]]. Confidence: high. See [[topic-agent-security]].
15. **Memory/consolidation as a separate low-cost pass.** Letta "sleep-time" and OpenClaw "dreaming": curate notes off the reply path in a background subagent; writing, not retrieval, is what degrades memory; never let sub-agent/cron sessions create durable memories. For us: a periodic library-curator run that merges the usage log into PICKS suggestions. Evidence: [[src-letta-sleep-time-and-context-repos]], [[src-openclaw-docs-memory-architecture]]. Confidence: med.

## Where sources disagree
- **Retrieval method.** SkillSeek: BM25 is enough and an LLM rewrite loop is not worth its cost; HyDE and contextual retrieval show LLM-assisted indexing helps for document QA (one LLM call per query or per chunk); ToolLLM-style trained retrievers beat off-the-shelf ones. For a 5.6k-item bank queried by a manager that can reformulate itself, BM25 + PICKS + the manager's own query rewriting is the cost-effective point; add embeddings only if the eval set shows misses. [[src-arxiv-skillseek]], [[src-arxiv-hyde]], [[src-arxiv-toolllm]].
- **Skills vs passive docs.** Anthropic promotes skills with progressive disclosure; Vercel's eval says an always-loaded index wins because the model forgets to invoke. They agree if skills' descriptions are in context and the invoke decision is cheap; for our out-of-context library the invoke decision is the manager's lookup step.
- **Benefits of skill libraries.** SkillsBench +16.6 pp vs in-the-wild fragility vs "self-generated skills give no benefit": curation level explains the spread.

## Applies to us
- Strengths: out-of-context library; PICKS editorial layer; own-first ranking; dedupe and quarantine; licence/source columns.
- Weaknesses: (a) no usage log, no eval set, so no idea whether find.ps1/PICKS hit; (b) find.ps1 needs exact word overlap (no stemming, no synonyms: "set up Wake-on-LAN" vs "wol"); output is text lines, not JSON; (c) the lookup step is discretionary, which is where Vercel's 56% miss came from; (d) imported scripts are not scanned by Defender (folder exclusion) and the quarantine list is the only vetting record; (e) 5,600 items of which most will never be used: pruning by evidence is impossible without (a).

## Candidate changes for us
- **C1 (usage log, tiny):** `find.ps1` appends `{ts, query, top3, source}` to `claude-library\logs\find.jsonl` (git-ignored); PICKS lookups logged by the manager with the chosen id and later outcome (`worked|partial|wrong`). Weekly (on request) summary: top misses (queries with no good pick) become new PICKS rows or new first-party skills. Evidence: rules 6, 13.
- **C2 (eval set):** `claude-library\eval\queries.tsv` with 40-50 lines `query<TAB>ok_ids`; `tools\eval-find.ps1` prints hit@1/hit@3; run after each index rebuild and before changing the scoring. Seed from `claude-host\jobs` and Roman's past requests. Evidence: rule 6.
- **C3 (find.ps1 upgrades, by eval):** stemming/synonym table (wol -> wake-on-lan; ps -> powershell), per-field BM25 weights, `-Json`, and a `top-3 + source + licence` output default; keep own-first bonus. Only keep changes that raise hit@3 on C2. Evidence: rules 2-4.
- **C4 (force the lookup):** in the brief template (see [[topic-brief-prompt-engineering]]) and CLAUDE.md add the single always-loaded line: "Before briefing any job in a PICKS category, run `find.ps1` or read the PICKS row and name the chosen preset/skill in the brief, or write 'none fits'." Optionally a `UserPromptSubmit` hook that injects the nearest PICKS row as `additionalContext` (facts, not imperatives). Evidence: rule 7.
- **C5 (optional hybrid search over vault and library):** install qmd (or similar) only if C2 shows misses that BM25 cannot fix; register via `track-software.ps1`; index `Library\` + `Manager\` + `Roblox\` notes. Cost: ~2 GB models, Node. Evidence: rule 4.
- **C6 (promotion rule):** worker-created skills go to `claude-library\skills\_candidates\` and move to the main tree after two successful uses with the verifier passing; scripts in them reviewed by the `library-curator` before promotion. Evidence: rules 12, 14.
- **C7 (lint):** build-index warns on descriptions without a "Use when" clause, SKILL.md > 500 lines, duplicate names, missing licence. Evidence: rules 8-9.

## Open questions
- Hit rate of find.ps1 today: unknown (no eval set). Cheapest first measurement: 40 queries, 30 minutes.
- Whether graphify graph queries (query-vault) beat keyword search for this library: untested; the Vercel/SkillSeek results suggest structure matters less than index text quality.

## From Nate Herk / RoboNuggets / Karpathy

Added 2026-11-01 from 549 creator videos (Nate Herk, RoboNuggets, Andrej Karpathy). Practitioner evidence: [demonstrated] = shown working in a video, [opinion] = advice. Weigh below the official/benchmarked sources above; where they disagree see [[src-creators-disagreements]].

- **Build skills with a fixed framework.** Cover name and trigger, a one-sentence goal and output, steps, reference files, failure-mode rules, and a self-improvement loop. [demonstrated] (T40; [[src-nate-herk-agent-practice]])
- **Close the loop at session end.** Run a calibrate or reflect step that updates skills, memory and rules with learnings. Why: the system improves with each run. [demonstrated] (T41; [[src-robonuggets-agent-practice]])
- **Iterate fast and in small steps.** Each iteration is data that improves skills, agents, prompts and context. [opinion] (T42; [[src-nate-herk-agent-practice]])

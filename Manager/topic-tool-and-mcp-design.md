# Tool and MCP design, and agent-friendly helper scripts

Scope: how to design tools (MCP or CLI/PowerShell scripts) that an agent uses reliably and cheaply, including the manager's own `claude-host\tools\*.ps1`. Security of tools: [[topic-agent-security]]. Synthesised by the lead from src- notes (assigned worker stopped by the usage limit); local script facts from [[src-local-host-security-posture]].

## TL;DR
- Fewer, higher-level tools with excellent descriptions beat many thin wrappers; descriptions are "by far the most important factor". But "more text" is not free: measure. [[src-anthropic-writing-tools-for-agents]], [[src-anthropic-define-tools-doc]], [[src-arxiv-mcp-tool-descriptions-smelly]]
- For a box like ours, scripts called via Bash/PowerShell are the right tool shape (CLI over MCP: cheaper context, composable, saved as files). MCP is for session state, auth or when the vendor ships it. [[src-zechner-no-mcp]], [[src-ronacher-code-mcps]], [[src-ccdocs-mcp]]
- Agent-friendly script contract: `--json` on stdout, human text on stderr, documented exit codes, `-WhatIf`/dry-run, idempotent re-run, small outputs, teach-on-error messages. [[src-devto-agent-friendly-cli]], [[src-ms-powershell-shouldprocess]], [[src-stripe-idempotency]]
- Our own helper scripts (`cachyos-run.ps1`, `linux-power.ps1`, `send-telegram.ps1`...) return prose, have no exit-code contract and accept arbitrary text: fix this cheaply and they become safer to automate and to verify.

## Rules
1. **Design tools for agents, not developers: few, targeted, high-impact tools; consolidate related operations.** One `schedule_event` beats list-users + list-events + create-event; use an `action` parameter for related operations; namespace by service/prefix so search and disambiguation work. Evidence: [[src-anthropic-writing-tools-for-agents]] (2025-09-11), [[src-anthropic-define-tools-doc]]. Confidence: high (official).
2. **Write descriptions like onboarding a new hire: what it does, when to use it AND when not, parameter meaning, limits, what it does NOT return; at least 3-4 sentences.** Put the key words first (search matches the shorter part; server instructions and upfront descriptions are capped at 4,096 chars). Evidence: [[src-anthropic-define-tools-doc]], [[src-ccdocs-mcp]], [[src-openai-function-calling-guide]] ("intern test"). Confidence: high.
3. **Descriptions in the wild are bad and fixing them helps, with a cost.** 97.1% of 856 MCP tool descriptions had a "smell" (unstated limitations 89.8%, missing usage guidelines 89.3%); complete descriptions raised task success by a median +5.85 points but increased execution steps by 67% and regressed 16.7% of cases. Use compact components and evaluate. Evidence: [[src-arxiv-mcp-tool-descriptions-smelly]] (2026-02-16, partly snippet-level). Confidence: med.
4. **Return only high-signal data, stable semantic identifiers, and offer concise/detailed modes.** 72 vs 206 tokens in Anthropic's example; paginate, filter, truncate; Claude Code warns above 10,000 tokens per MCP output (cap 25,000) and saves oversized text to a file. Evidence: [[src-anthropic-writing-tools-for-agents]], [[src-ccdocs-mcp]]. Confidence: high.
5. **Errors must teach.** MCP separates protocol errors from tool-execution errors (`isError: true`) whose text should let the model self-correct ("Invalid departure date: must be in the future. Current date is ..."). For scripts: say what was wrong and what to try. Evidence: [[src-mcp-spec-tools]], [[src-anthropic-writing-tools-for-agents]]. Confidence: high.
6. **Evaluate tools with realistic tasks and a held-out set**; track accuracy, runtime, tool calls, tokens, errors; feed transcripts back to Claude to refactor the tool. Evidence: [[src-anthropic-writing-tools-for-agents]]. Confidence: high.
7. **Load tools on demand; cap the always-on set.** Tool Search: `defer_loading`; selection degrades past 30-50 tools; typical 5-server MCP setup ~55k tokens; deferral cut it >85%; Claude Code defers MCP tools by default (names + instructions only). Programmatic tool calling and code-execution-with-MCP keep intermediate data out of context (37% fewer tokens; 150k -> 2k in an example). Cloudflare "Code Mode" makes the same point. Evidence: [[src-anthropic-tool-search-tool-doc]], [[src-anthropic-advanced-tool-use]], [[src-anthropic-code-execution-with-mcp]], [[src-cloudflare-code-mode]], [[src-ccdocs-mcp]]. Confidence: high.
8. **Prefer CLI/scripts for tools the model already knows; reserve MCP for stateful sessions and auth.** Playwright MCP ~13.7k tokens vs a ~225-token CLI README; "the more tools you have, the more you're contributing to context rot"; docs: `gh` via Bash is more context-efficient than MCP. Counterpoint: Claude Code's tool search reduced the fixed cost Zechner measured; MCP still shines for session management. Evidence: [[src-zechner-no-mcp]], [[src-ronacher-code-mcps]], [[src-humanlayer-skill-issue-harness]]. Confidence: med-high (practitioners).
9. **Script contract for agents.** `--json` flat objects with consistent types; results on stdout, progress/warnings on stderr; documented exit codes beyond 0/1 (usage, not found, permission, conflict, transient vs permanent); `--dry-run` returning a structured diff; non-interactive (`--yes`), fail clearly without a TTY; self-documenting `--help` with examples; truncation defaults and `--fields`. Evidence: [[src-devto-agent-friendly-cli]] (practitioner, snippets for some items). Confidence: med.
10. **PowerShell specifics.** Use `[CmdletBinding(SupportsShouldProcess)]` so `-WhatIf` exists; call `ShouldProcess` right at the change; implement `-Force` deliberately and keep `-WhatIf` winning; do not use `ShouldContinue` (always prompts); pass `-WhatIf:$WhatIfPreference` explicitly across modules; `ConfirmImpact='High'` prompts by default and will hang an unattended worker unless `-Confirm:$false`. Evidence: [[src-ms-powershell-shouldprocess]]. Confidence: high.
11. **Agents retry; make every mutating script idempotent.** Use an idempotency key or ensure-style semantics (`-IfNotExists`), exponential backoff with jitter, and a "conflict/already done" exit code. For wake-on-LAN, sleep, reboot, send-message: a retry must not double-send or double-reboot. Evidence: [[src-stripe-idempotency]], [[src-devto-agent-friendly-cli]]. Confidence: high.
12. **Stateful tools return explicit handles; long jobs return a job id and a status command.** MCP 2026-07-28 moved long work to task handles and polling and removed stream resumability. Same shape for scripts: `start` returns id, `status <id>` returns JSON, `result <id>`. Evidence: [[src-mcp-spec-tools]], [[src-mcp-spec-2026-07-28-changelog]]. Confidence: high.
13. **Deterministic tool order and naming help caching and selection.** MCP: deterministic tool list order enables prompt-cache hits; names 1-128 chars, prefix with server id in aggregators. Evidence: [[src-mcp-spec-tools]]. Confidence: med.
14. **Security of tool descriptions: they are an injection channel.** Third-party tool descriptions land in the system prompt; treat MCP servers and skills as code; scope MCP per subagent (`mcpServers:` and `tools: mcp__server__*`). Evidence: [[src-humanlayer-skill-issue-harness]], [[src-ccdocs-mcp]], [[src-invariant-tool-poisoning]]. Confidence: high. See [[topic-agent-security]].

## Where sources disagree
- **MCP vs CLI.** Zechner/Ronacher/HumanLayer prefer CLI+code; Anthropic invests in MCP with tool search and code execution to fix MCP's costs; the MCP spec is moving to stateless tasks. For us: CLI wins on a single trusted box; MCP only where a vendor server already exists (GitHub) and with read-only default.
- **Verbose descriptions vs lean ones.** Anthropic: "extremely detailed". The smells paper: more text increases steps and regresses a sixth of cases. Follow: detailed on purpose/limits/when-not, lean on everything else, evaluate.
- **Examples in tool definitions**: Anthropic reports 72% -> 90% with `input_examples`; OpenAI notes examples "may hurt reasoning models". Test per model.

## Applies to us
Current helpers (from the local audit): `cachyos-run.ps1` pipes arbitrary bash to `ssh cachyos`, prints plain text, marks stderr with `[stderr]`, prints a `TIMED OUT` string, no exit code; `linux-power.ps1` uses ValidateSet for action but prints prose; `send-telegram.ps1` reads its token from .env, hard-codes the chat id. None has `-WhatIf`, JSON output or an idempotency guard; `linux-power.ps1 sleep` may reboot a machine first (non-idempotent, slow, destructive for open apps) with no dry run. `NAMES`/PICKS/find.ps1 are text tools with no machine-readable output.
Workers that parse "TIMED OUT" strings to decide success are one reworded message away from silent failure.

## Candidate changes for us
- **C1 `cachyos-run.ps1` contract:** add `-Json` that emits `{ok, exitCode, timedOut, stdout, stderr, secs}` and set the process exit code to the remote exit code (124 for timeout); keep current text mode as default. Add `-MaxSecs`. Benefit: verifiable results, no string matching. Risk: small refactor. Evidence: rules 5, 9.
- **C2 `linux-power.ps1`:** add `-WhatIf` (print the plan: direct suspend vs reboot-first, expected duration), `-Json` status, and a lock file to make double calls safe (idempotent: if already asleep/awake, exit 0 with `state`). Evidence: rules 10-11.
- **C3 tool conventions section in a new `claude-host\tools\README.md` (one page):** list each script, flags, exit codes, JSON shape, whether it is idempotent, and who may call it. Link it from CLAUDE.md instead of embedding usage in CLAUDE.md. Evidence: rule 2.
- **C4 `find.ps1` / `query-vault.ps1` `-Json`** returning `[ {type,id,desc,path} ]` so a scout can consume without regex parsing. Evidence: rule 9. (See [[topic-skill-library-retrieval]].)
- **C5 policy:** "New capability needed? first write a script following tools\README.md; add an MCP server only if a first-party one exists and read-only mode is possible." Evidence: rule 8.
- **C6 eval:** 10 realistic prompts per helper ("wake my pc and confirm SSH is up", "put it to sleep") run weekly by a haiku scout in a scratch session, success = verified end state. Evidence: rule 6; cost small.

# Security for an autonomous, phone-controlled, admin-level agent

Scope: prompt injection, least privilege, enforcing confirm-first mechanically, secrets, supply chain (3rd-party skills/MCP/plugins), channel/inbox hardening, exfiltration vectors, incidents, blast-radius reduction. Tool/MCP design side: [[topic-tool-and-mcp-design]]. Claude Code mechanics: [[topic-claude-code-features]]. Failure modes: [[topic-multi-agent-failure-modes]]. Synthesised by the lead from the research worker's src- notes (the worker was stopped by the usage limit after finishing its notes; its local audit notes [[src-local-host-security-posture]], [[src-local-telegram-plugin-gate-audit]] and the empirical test [[src-local-enforcement-test]] are first-hand).

## TL;DR
- Threat model is simple and severe: a bypass-permissions, elevated-admin Claude shell whose input channels are Remote Control (the claude.ai account is the root of trust), a Telegram plugin, a Discord voice bot, and every web page/file/skill its workers read. No sandbox is possible on this native-Windows box. [[src-local-host-security-posture]], [[src-ccdocs-remote-control-security]], [[src-ccdocs-sandboxing]]
- Prompt injection is not solvable by prompting; Anthropic, NCSC, Meta, Willison and Trail of Bits all say design for it: constrain what a compromised agent can do. [[src-ncsc-prompt-injection-not-sqli]], [[src-anthropic-prompt-injection-defenses]], [[src-meta-agents-rule-of-two]]
- Our "Always confirm first" list is prose. Tested here: `permissions.ask`, `permissions.deny` and `PreToolUse` hooks (exit 2) all bind the main agent AND subagents under bypassPermissions. So confirm-first CAN be enforced today with a few lines of settings. [[src-local-enforcement-test]], [[src-ccdocs-permissions-precedence]]
- But pattern guards are speed bumps: `Bash(git push *)` does not stop `git -C . push` or `sh -c`; "safe command" allowlists are exfiltration/RCE channels. Real boundaries are OS sandbox + egress control + credential isolation; on this host the available substitutes are narrowing credentials, separating duties, and not letting untrusted content and powerful tools meet in the same session (Rule of Two). [[src-ccdocs-auto-mode-config]], [[src-trailofbits-prompt-injection-rce]], [[src-embracethered-claude-code-dns]]
- Specific holes found locally: Telegram group gate with empty `allowFrom`, `run-as-system.ps1` as a SYSTEM trampoline writable by the same user, Defender exclusions on the folders that hold third-party skills, plaintext secrets and transcripts, a 5,600-item third-party skill library. [[src-local-host-security-posture]], [[src-local-telegram-plugin-gate-audit]]

## Rules
### A. Model the threat correctly
1. **Prompt injection is a permanent property; manage impact, not likelihood.** No code/data separation exists in LLMs; deny-list filters are easy to rephrase around; probabilistic detectors "find the 1% that gets through". Design: assume manipulation, add deterministic non-LLM constraints, reduce privileges for anything touching untrusted input. Evidence: [[src-ncsc-prompt-injection-not-sqli]] (2025-12-08), [[src-willison-camel-post]], [[src-anthropic-prompt-injection-defenses]] (best-of-100 attacker still succeeds 1.4-2.4% against improved safeguards). Confidence: high.
2. **Apply the Rule of Two per session.** At most two of: [A] untrusted input, [B] sensitive data/systems, [C] state change or external communication. All three => no autonomy: human approval or a fresh context. Examples map directly to our jobs: web research worker [AC] (no host secrets, no session data); config worker [BC] (only trusted inputs); email/Telegram reader [AB] (no outbound sends without confirm). Evidence: [[src-meta-agents-rule-of-two]] (2025-10-31), Willison's lethal trifecta. Confidence: high (framework, not measured).
3. **Injection arrives through ordinary tasks.** "Summarise this URL" with WebFetch->curl fallback led to code execution in 60-80% of runs against auto mode; Comet injected via a Reddit comment; GitHub MCP issue read pulled private repo data into a public PR; hidden text in a source file caused DNS exfiltration of `.env`. Agents route around a blocked tool unless egress is closed. Evidence: [[src-tnw-rehberger-auto-mode-hijack]], [[src-brave-comet-prompt-injection]], [[src-invariant-github-mcp]], [[src-embracethered-claude-code-dns]]. Confidence: high.
4. **Known design patterns that give structural protection:** action-selector, plan-then-execute (tool sequence fixed before untrusted data is read), map-reduce over untrusted items returning narrow answers, dual-LLM (quarantined reader returns variables), CaMeL-style capability tracking (77% task success with provable security vs 84% undefended), context minimisation. Practical translation for us: let a "reader" worker with no powerful tools summarise untrusted material into a short, structured result; the manager (or a second worker with tools) acts on the structured result only. Evidence: [[src-willison-design-patterns-post]], [[src-arxiv-design-patterns-llm-agents]] (correct ID 2506.08837), [[src-arxiv-camel]]. Confidence: med-high.
5. **Spotlighting/datamarking helps but is not a boundary.** Marking untrusted text as data cut attack success from >50% to <2% in 2024 non-adaptive tests; treat as hygiene only. Evidence: [[src-arxiv-spotlighting]]. Confidence: med-low.

### B. Enforce, don't request
6. **Prose rules do not hold; mechanical rules do.** The Replit incident (code freeze ignored, false statements about rollback) and Anthropic's own advice agree: "if you keep adding emphasis to a CLAUDE.md line and Claude still misses it, that's a sign the line belongs in a hook". Boundaries stated only in conversation are lost at compaction. Evidence: [[src-replit-saastr-incident-register]], [[src-replit-db-deletion-incident]] (snippet-level), [[src-ccdocs-auto-mode-config]], [[src-ccdocs-memory]]. Confidence: high.
7. **What is mechanically enforceable under bypass (tested 2026-10-29, Claude Code 2.1.312, haiku-5-5, -p):** `permissions.deny` blocks; `permissions.ask` refuses in `-p` (would prompt interactively/over RC); a `PreToolUse` hook exiting 2 blocks and its stderr reaches the model; all three also bind subagents. Not tested: how an `ask` renders on the phone; hook behaviour on settings edits; background-subagent handling. Evidence: [[src-local-enforcement-test]], [[src-ccdocs-permissions-precedence]]. Confidence: high for the tested cases.
8. **Do not trust pattern rules as a wall.** `Bash(git push *)` misses `git -C . push`, `/usr/bin/curl`, `sh -c '...'`. Trail of Bits: "Hooks are not a security boundary ... guardrails, not walls"; allowlisted "safe" commands (`find`, `git`, `go test`, `ping`, `nslookup`) have been turned into RCE/exfil. On Windows the LOLBAS surface (powershell, certutil, bitsadmin, mshta, schtasks) is larger. Use hooks that inspect the full command text for the few irreversible classes, and accept residual risk elsewhere. Evidence: [[src-ccdocs-auto-mode-config]], [[src-trailofbits-claude-code-config]], [[src-trailofbits-prompt-injection-rce]], [[src-embracethered-claude-code-dns]]. Confidence: high.
9. **`bypassPermissions` + elevated admin + internet = no protection against injection.** Docs: only for isolated containers/VMs without internet. Auto mode (classifier) is the documented alternative but is "a convenience feature backed by a best-effort classifier, not a security guarantee" (FNR 17% on real overeager actions); the master is launched with `--dangerously-skip-permissions`, so the classifier is bypassed too. Evidence: [[src-ccdocs-permissions-precedence]], [[src-anthropic-claude-code-auto-mode]], [[src-tnw-rehberger-auto-mode-hijack]], [[src-local-host-security-posture]]. Confidence: high. See C1/C2 below for what is feasible without a sandbox.
10. **Windows has no Claude Code sandbox; this box has no WSL2/Hyper-V.** Sandboxing (filesystem + network isolation, both required) works on macOS, Linux and WSL2; the CachyOS machine could host risky/untrusted jobs in its sandbox; the Windows host cannot. Evidence: [[src-ccdocs-sandboxing]], [[src-anthropic-claude-code-sandboxing]] (84% fewer prompts internally), [[src-local-host-security-posture]]. Confidence: high.
11. **Protect the guard itself.** A compromised agent can edit settings, hooks, skills (Amp/Copilot were tricked into editing their own settings). Use a `ConfigChange` hook to block changes to hook/permission settings, deny writes to `~/.claude/settings*.json`, `hooks`, `.claude/skills`, and `agents` except by Roman; managed settings (`C:\Program Files\ClaudeCode\managed-settings.json`) outrank everything but are only as tamper-proof as their ACL (admin can edit; our agent is admin). Evidence: [[src-willison-summer-of-johann]], [[src-ccdocs-managed-settings]], [[src-ccdocs-security]]. Confidence: med-high.

### C. Least privilege
12. **Excessive agency has three roots: functionality, permissions, autonomy.** Offer only needed tools, prefer narrow tools over open shells, minimum-scope credentials, human approval for high-impact actions, enforce authorisation downstream; logging does not prevent but limits damage. OWASP agentic list ASI01-ASI10 maps onto this host one-to-one (goal hijack via Telegram/web, tool misuse, identity/privilege abuse, supply chain, unexpected code execution, memory/context poisoning, insecure inter-agent comms, cascading failures, human trust exploitation, rogue agents). Evidence: [[src-owasp-llm06-excessive-agency]], [[src-owasp-agentic-top10]] (names via secondary summary). Confidence: high.
13. **Per-worker tool allowlists are enforcement; parent bypass disables a subagent's own permissionMode.** Restrict `tools`/`disallowedTools` in presets (read-only research worker without Bash/PowerShell/Write; `WebFetch` workers get no host secrets or shell). `disallowedTools: Bash(git push *)` removes all Bash; use deny rules for patterns. Evidence: [[src-ccdocs-managed-settings]], [[src-ccdocs-permissions-precedence]]. Confidence: high.
14. **Wrap risky capabilities in narrow scripts.** Anthropic's own triage command allows only `Bash(./scripts/gh.sh:*)`, a wrapper that supports a handful of subcommands. For us: `cachyos-run.ps1` accepts arbitrary bash (a root-equivalent channel to the main PC, passwordless sudo there); `run-as-system.ps1` runs arbitrary text as SYSTEM via a scheduled task, triggered by anything that can write `claude-host\system-cmd.ps1`. Keep, but treat as crown jewels: deny direct writes to that file except via the script, and require ask for both. Evidence: [[src-gh-anthropics-claude-code-repo]], [[src-local-host-security-posture]]. Confidence: med-high.
15. **GitHub MCP: read-only by default, one repo per session, lockdown mode for untrusted authors.** `X-MCP-Readonly` overrides other settings; lockdown filters content from users without push access but is "best-effort"; the Invariant attack required account-wide access plus "Always Allow". Our setup (library/GitHub MCP with write access) should keep reads and writes in different sessions. Evidence: [[src-github-mcp-server-config]], [[src-invariant-github-mcp]]. Confidence: high.

### D. Secrets
16. **Assume everything the agent prints is stored in plaintext twice**: local `~/.claude/projects/*.jsonl` (30 days) and, while Remote Control is connected, on Anthropic servers. Never `cat` .env/token files; use `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1`; pass credentials through helpers (`headersHelper`) rather than files; rotate anything that was printed. Evidence: [[src-ccdocs-managed-settings]], [[src-ccdocs-remote-control-security]], [[src-agent-sdk-docs-and-python-readme]] (credential proxy pattern). Confidence: high.
17. **Secrets in agent/MCP config files are the leading leak path**: GitGuardian counted 24,008 secrets in MCP config files; Claude-Code-co-authored commits leaked at ~2x baseline; 64% of valid 2022 secrets were still valid. Rotation discipline matters more than detection. Evidence: [[src-gitguardian-secrets-sprawl-2026]]. Confidence: med-high.
18. **Where our secrets sit:** `[private-path]`, `[private-path]`, the gh token (scopes repo, read:org, gist), Tailscale SSH key `[private-path]` with passwordless sudo on the main PC. All are readable by the bypass-mode master and any worker. Mitigation within reach: deny-read rules for those paths for subagents (not for the specific scripts that need them), a gh token with narrower scope or fine-grained PAT, and ssh key with a forced command. Evidence: [[src-local-host-security-posture]], [[src-trailofbits-claude-code-config]] (deny rules for SSH/GPG/cloud creds). Confidence: med.

### E. Supply chain: skills, plugins, MCP
19. **Third-party skills are executable trust.** USENIX study: 157 of 98,380 skills confirmed malicious (0.16%); Snyk: 13.4% of 3,984 had a critical issue and 76 confirmed malicious (different registries and methods); 26.1% of 31,132 skills have some vulnerability, 2.12x more likely with bundled scripts; 91% of malicious skills also used prompt injection. Anthropic: use skills only from trusted sources; audit all bundled files. Our library imports ~5,600 items with a scan tool: keep the quarantine, never auto-load, and treat `scripts/` in any imported skill as untrusted until read. Evidence: [[src-arxiv-malicious-agent-skills]], [[src-snyk-toxicskills]], [[src-arxiv-agent-skills-security-wild]], [[src-anthropic-skills-security-doc]]. Confidence: high.
20. **MCP servers: tool poisoning, rug pulls, shadowing, typosquats.** Descriptions are model-visible but user-invisible; a server can change descriptions after approval; `postmark-mcp` added one BCC line in v1.0.16 after 15 clean versions. Pin versions, read diffs, prefer first-party/self-written servers, avoid token passthrough. Evidence: [[src-invariant-tool-poisoning]], [[src-register-postmark-mcp]], [[src-mcp-security-best-practices]]. Confidence: high.
21. **A malicious package can reuse your own agent as the attacker's tool.** s1ngularity: npm postinstall called installed Claude/Gemini/Q CLIs with `--dangerously-skip-permissions` to hunt secrets; Amazon Q's extension shipped a wipe prompt via a trusted update channel. On this host any process of user `roman` can start `claude --dangerously-skip-permissions`. Evidence: [[src-wiz-s1ngularity]], [[src-register-amazon-q-wiper]]. Confidence: high.
22. **Config files in untrusted directories are executable surface.** CVE-2025-59536 and CVE-2026-21852: project `.claude/settings.json` hooks/MCP and a `ANTHROPIC_BASE_URL` override ran before the trust prompt; `claude -p` skips the trust dialog; Windows Desktop had a `git.exe` search-path bug. Never start a worker with its cwd inside a downloaded/cloned untrusted directory; keep Claude Code updated (advisories keep arriving: TOCTOU, symlink, plugin SHA pin bypass). Evidence: [[src-checkpoint-claude-code-project-files]], [[src-claude-code-ghsa-advisories]]. Confidence: high.

### F. Channels
23. **Gate on sender identity, never on room identity.** Local audit: Telegram `access.json` has one DM allowlisted user (good) and a group entry with `requireMention:true` and an empty `allowFrom`, and server.ts skips the sender check when `groupAllowFrom` is empty, so anyone who mentions the bot in that group could inject text if the channel is re-enabled. Docs say the opposite of that behaviour. `--channels` is currently not passed by boot-claude.ps1, but the plugin remains enabled and CLAUDE.md still describes Telegram as live. Evidence: [[src-local-telegram-plugin-gate-audit]], [[src-ccdocs-channels]]. Confidence: high (code read), exploitability depends on group membership (unverified).
24. **Permission relay over a channel gives the sender approval authority.** Anyone allowed to reply can approve tool use; keep the allowlist to Roman's single ID and never let a Telegram message modify access. Telegram attachments are untrusted (20 MB, `inbox/`). Evidence: [[src-ccdocs-channels]], [[src-gh-claude-telegram-plugin]]. Confidence: high.
25. **The claude.ai account is the root of trust for Remote Control.** Outbound-only HTTPS, no inbound ports, short-lived credentials, but whoever controls the account/session can drive an elevated bypass shell; transcripts including tool output are stored server-side. Protect the Google/Anthropic account (passkey, phone lock), review active sessions, consider `isolatePeerMachines`. Evidence: [[src-ccdocs-remote-control-security]], [[src-ccdocs-security]]. Confidence: high.
26. **Personal-assistant agents that were run with wide access got breached in the wild.** OpenClaw/Clawdbot: exposed gateways, plaintext token files, malicious ClawHub skills (341 of 2,857 flagged per Koi, snippet-level), one-click RCE; their docs: "one trust boundary per gateway". Evidence: [[src-snyk-clawdbot-assistant]], [[src-openclaw-security-cost-reports]]. Confidence: med (secondary numbers).

### G. Unattended-run discipline
27. **Hard stops beat instructions.** A 108-hour unattended Claude Code diary: deleted src/ twice, force-pushed, looped on a paid API ($8/hour), restarted a task from scratch after context fill; a PreToolUse destructive-command hook plus "retry up to 3 times, then log the blocker and move on" removed ~70% of accidents. Evidence: [[src-yurukusa-unattended-accidents]] (practitioner anecdote). Confidence: med. See [[topic-long-running-always-on-agents]].
28. **Oversight by exception.** Approve-everything prompts become rubber stamps (93% approval rate); put friction only on the few irreversible classes, and make the prompt specific ("action + danger"). Evidence: [[src-anthropic-claude-code-auto-mode]], [[src-anthropic-trustworthy-agents]], [[src-magentic-ui-paper]]. Confidence: high.

## Where sources disagree
- **Are hooks a security control?** Anthropic docs and the Replit lesson: yes for rules that "must hold"; Trail of Bits: hooks are guardrails not walls because injected agents can route around patterns. Both are right; use hooks for irreversible-action classes and accept they stop honest mistakes and naive injections, not a skilled attacker. [[src-ccdocs-hooks]], [[src-trailofbits-claude-code-config]].
- **Skills malware prevalence**: 0.16% (USENIX, 98k) vs 1.9% (Snyk, 4k) vs 26% "any vulnerability" (31k). Different registries (curated vs open), different definitions. For a curated 22-source library the risk is closer to the low end, but scripts inside skills remain the vector. [[src-arxiv-malicious-agent-skills]], [[src-snyk-toxicskills]], [[src-arxiv-agent-skills-security-wild]].
- **Auto mode vs bypass**: Boris Cherny says never use bypass and use auto; the classifier's 17% FNR and Rehberger's chain show auto is not a boundary either. On this box neither is a sandbox; the extra protection is the deterministic rules layer.
- **AI-based detection**: Anthropic invests in classifiers and RL; Willison and NCSC say they cannot be the defence. Use as a layer only.

## Applies to us
Current state (read 2026-10-29): bypass + admin; no hooks; no deny/ask rules; no sandbox possible; Defender exclusions on `.claude`, `claude-host`, `.local\bin`, Temp\claude; plaintext secrets; Tailscale SSH to CachyOS with passwordless sudo; a 5,600-item third-party library; Telegram plugin enabled but `--channels` currently off; CLAUDE.md confirm-first is the only control.
Gaps ranked by (impact x ease): (1) no mechanical confirm-first; (2) Telegram group gate + plugin still enabled; (3) no protection of config/hook files; (4) skills/library execution trust; (5) secrets readable by every worker; (6) SYSTEM trampoline; (7) Defender exclusions covering imported skills.

## Candidate changes for us
- **C1 (settings.json `permissions`):** add deny/ask rules for the confirm-first classes; ask rules prompt Roman via Remote Control instead of failing. Proposed starting set (verify matcher syntax with the tested pattern before rollout):
  - deny: `Write(~\.claude\settings*.json)`, `Edit(~\.claude\settings*.json)`, `Bash(* --dangerously-skip-permissions *)` for subagent shells (e.g. spawning nested claude from workers is a separate job type: allow only via the cachyos runner).
  - ask: `Bash(git push *)`, `PowerShell(git push *)`, `Bash(gh repo *)`, `Bash(gh release *)`, `Bash(gh pr create *)`, `PowerShell(Remove-Item *-Recurse*)`, `PowerShell(netsh *)`, `PowerShell(Set-NetFirewallRule *)`, `PowerShell(New-NetFirewallRule *)`, `PowerShell(reg add HKLM*)`, `PowerShell(schtasks /delete *)`, `PowerShell(Set-ExecutionPolicy *)`.
  Benefit: confirm-first becomes real for the clean cases. Risk: false positives interrupt jobs (workers hit "ask" with nobody to answer: in `-p`/background workers the action is refused, so workers must report it under NEEDS, which is the desired behaviour). Evidence: rules 6-8, [[src-local-enforcement-test]].
- **C2 (hook `confirm-first-guard.ps1`, PreToolUse on Bash|PowerShell|Write|Edit):** inspect full command text, exit 2 with a message like "BLOCKED by confirm-first: <class>. Report under NEEDS and stop." Classes: external publish (git push, gh publish, npm publish, scp/curl -T/Invoke-WebRequest -Method Post to non-allowlisted hosts), credential reads (`.env`, `secrets\`, `.ssh`, `gh auth token` outside the helper), firewall/Defender/RDP/sshd/Tailscale ACL changes, writes to the hooks/settings/agents/skills dirs, `Remove-Item -Recurse` outside temp/screenshots. Use `onFailure: "block"` after testing. Benefit: covers variants pattern rules miss. Risk: maintenance; hooks are a speed bump not a wall (rule 8). Evidence: rules 6-8.
- **C3 (Telegram):** if Telegram is not in use, set the plugin `enabledPlugins` entry false; if it will be, set the group's `allowFrom` to Roman's user ID (or remove the group entry) and re-run the gate audit. Update CLAUDE.md so it stops describing Telegram as live. Benefit: closes a known injection path. Risk: none. Evidence: rule 23. (Changing channel config is a security setting: needs Roman's OK.)
- **C4 (Rule-of-Two brief tag):** add to every brief a line `Trust: UNTRUSTED-INPUT | HOST-SECRETS | EXTERNAL-ACTIONS: allowed = {...}`; the manager never gives one worker all three; for web research give a worker no Bash/PowerShell/Write and have it return structured text. Evidence: rules 2-4.
- **C5 (config tamper guard):** `ConfigChange` hook plus deny writes to `~/.claude/settings*.json`, `agents\`, `skills\`, `CLAUDE.md`, `soul.md`, `hooks` for workers; the manager edits its own instructions only via an explicit Roman request. Evidence: rule 11.
- **C6 (Defender exclusions):** remove the exclusion for `claude-host`'s imported-skill/library locations (or at least `claude-library\sources`) so imported scripts are scanned; Defender exclusion edit is a security setting: needs Roman's OK. Evidence: [[src-local-host-security-posture]].
- **C7 (gh token):** switch from the OAuth `gho_` token (repo, read:org, gist) to a fine-grained PAT limited to `claude-library` and needed repos; keep `headersHelper`. Roman's OK needed (credentials). Evidence: rules 15, 18.
- **C8 (untrusted-cwd rule in CLAUDE.md):** "Never start a worker with cwd inside a downloaded or cloned directory; clone into the scratchpad and pass the path as an argument; run Python as `-I`." Evidence: rule 22.
- **C9 (cross-device):** require ask for any `cachyos-run.ps1` script containing `sudo`, `rm -rf`, `systemctl`, `pacman`; log every script sent. Evidence: rule 14; see [[topic-cross-device-agent-control]].

## Open questions
- Does a PreToolUse `ask` decision under bypassPermissions render on the phone via Remote Control, and does it time out? Test with a harmless command before relying on it.
- Is the bot still a member of the Telegram group in `access.json`?
- Whether `--dangerously-skip-permissions` can be replaced by `--permission-mode auto` + deny/ask on this host without breaking unattended jobs (auto mode runs a classifier on every action: cost and latency).

## From Nate Herk / RoboNuggets / Karpathy

Added 2026-11-01 from 549 creator videos (Nate Herk, RoboNuggets, Andrej Karpathy). Practitioner evidence: [demonstrated] = shown working in a video, [opinion] = advice. Weigh below the official/benchmarked sources above; where they disagree see [[src-creators-disagreements]].

- **Enforce never-break rules with hooks, not skill text.** Example: no invoice above a limit without sign-off. Why: hooks run as code regardless of what the model decides. [opinion] (T31; [[src-robonuggets-agent-practice]])
- **Add caution rules and prefer guarded tools.** Ask the agent to amend CLAUDE.md to be more careful about deleting files, and avoid tools without permission and deletion guardrails. [opinion] (T32; [[src-robonuggets-agent-practice]])
- **Use auto mode for safe decisions and permission relay for big ones.** Why: agents no longer stall waiting at a terminal. [demonstrated] (T33; [[src-robonuggets-agent-practice]])
- **Sandbox each agent to specific tools, memory and repo.**  [opinion] (T34; [[src-nate-herk-agent-practice]])
- **Harden every webhook.** Use HTTPS, verify signing secrets, keep credentials in the credential store, and use production URLs only once secured. Why: webhooks are public entry points. [opinion] (T35; [[src-nate-herk-agent-practice]], [[src-robonuggets-agent-practice]])
- **Keep human checkpoints where outputs are probabilistic or hard to reverse.** Review dialogue and prompts, and approve email drafts. Why: some outputs will be off. [demonstrated] (T36; [[src-nate-herk-agent-practice]], [[src-robonuggets-agent-practice]])

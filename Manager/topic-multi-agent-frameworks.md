# Multi-agent frameworks and Claude Code orchestrators: what to steal, what to ignore

Scope: LangGraph, OpenAI Agents SDK/Swarm, AutoGen/AG2/Microsoft Agent Framework, CrewAI, MetaGPT/ChatDev, Google ADK, Strands, Letta, smolagents, Claude Agent SDK, A2A/MCP protocols, and the popular Claude-Code-adjacent orchestrators (ruflo/claude-flow, Gas Town, oh-my-claudecode, claude-squad, Vibe Kanban, container-use, Conductor, CCPM, Aperant, ccswarm, PAL, Ralph Orchestrator, BMAD, SuperClaude). Stats are from `gh api` on 2026-10-29 as recorded in the src- notes. Written by the lead from those notes (the assigned worker was stopped by the usage limit). Patterns themselves: [[topic-orchestration-patterns]].

## TL;DR
- The platform we run on (Claude Code subagents + SendMessage + hooks + skills) already implements the orchestrator-subagent pattern natively. No framework is needed; frameworks matter as sources of ideas (ledger, durable state, guard stages, cost cockpit).
- The vendors of the best-known frameworks are retreating from heavy abstractions: LangChain archived langgraph-supervisor and recommends a plain tool-calling supervisor; OpenAI replaced Swarm with the Agents SDK; Microsoft archived AutoGen for Agent Framework. [[src-repo-langgraph-supervisor-swarm]], [[src-repo-openai-agents-sdk-and-swarm]], [[src-repo-autogen-ag2-maf]]
- GitHub star counts in this space track marketing and prompt packs, not task success: almost no repo publishes success rates versus plain Claude Code. ruflo (80k stars) has documented mocked internals. [[src-repo-ruflo-claude-flow]], [[src-repo-bmad-superclaude-subagent-collections]]
- The only structural idea repeated everywhere that survives scrutiny: isolate every parallel writer (worktree/branch/container) and review diffs before merge. [[src-repo-claude-squad-vibe-kanban-container-use]]
- Protocols: MCP (agent-to-tool) and A2A (agent-to-agent) are both Linux Foundation projects; A2A is for separate services, not for in-process subagents. Claude Code does not speak A2A natively (absence of evidence). [[src-linuxfoundation-a2a-one-year]], [[src-linuxfoundation-agentic-ai-foundation]], [[src-repo-google-adk]]

## Rules
1. **Do not adopt an orchestration framework for the manager; extend Claude Code natively.** Our manager already is an Agent-SDK-style loop (the Claude Agent SDK is the same engine as a library). A second runtime adds an LLM abstraction, state store and failure surface for no capability we lack. Evidence: [[src-repo-strands-letta-smolagents-agent-sdk]], [[src-ccdocs-sub-agents]], [[src-anthropic-building-effective-agents]] ("frameworks can hide prompts and responses"). Confidence: high.
2. **Prefer the pattern the framework vendors themselves now recommend: a supervisor that is just an agent calling specialists as tools.** OpenAI: agents-as-tools when one agent should own the final answer; handoffs only when the specialist should take over the conversation. LangChain: use the supervisor pattern directly via tools for more control over context engineering. Evidence: [[src-repo-openai-agents-sdk-and-swarm]], [[src-repo-langgraph-supervisor-swarm]], [[src-langchain-docs-multi-agent]]. Confidence: high.
3. **Steal the ledger and the guard stage, not the framework.** Magentic-One's orchestrator (task ledger + progress ledger, stall/loop detection) is the best-documented supervisor design; Magentic-UI's ActionGuard (per-action irreversibility class: always-ask / never-ask / LLM-judge) is a good model for confirm-first. Microsoft Agent Framework adds checkpointing and time-travel as first-class features. Evidence: [[src-arxiv-magentic-one]], [[src-magentic-ui-paper]], [[src-repo-autogen-ag2-maf]]. Confidence: med-high.
4. **Durable state on disk is the common thread of the orchestrators that work for long runs.** Gas Town: "work persists in git-backed hooks", persistent worker identity with ephemeral sessions, Beads dependency graph for tasks; Ralph Orchestrator: gates that reject incomplete work + persisted tasks; Cursor's judge-and-restart. For us: a ledger file plus per-job state files. Windows is not a supported environment for Gas Town's full tmux workflow ("use WSL"). Evidence: [[src-repo-gastown-beads]], [[src-repo-ccpm-aperant-ccswarm-pal-ralph]], [[src-cursor-scaling-agents]]. Confidence: med.
5. **Parallel writers need isolation, not coordination.** claude-squad, Vibe Kanban, container-use and Conductor all reduce to one worktree/branch/container per agent and human review of diffs; container-use adds an inspectable command log ("what agents actually did, not just what they claim"). For our host: if two workers must edit the same repo, give each its own git worktree (`isolation: worktree` on the Agent tool) and merge. Licences matter: claude-squad is AGPL-3.0, Aperant AGPL-3.0, Conductor closed and macOS-only. Evidence: [[src-repo-claude-squad-vibe-kanban-container-use]], [[src-ccdocs-sub-agents]]. Confidence: med-high.
6. **Treat star-count leaders as catalogues of prompts, and read the issues.** ruflo: README animated "download counter", benchmarks measuring start-up time and RSS rather than task success, and issues showing `coordination_sync` that "reports a synchronization that never happens" and hooks returning `success` without persisting. BMAD/SuperClaude/wshobson/VoltAgent are persona/command packs. Vibe Kanban is sunsetting (vendor shut down 2026-04), PAL MCP has been stale for 10 months, Aperant is in maintenance with a private rewrite. Evidence: [[src-repo-ruflo-claude-flow]], [[src-gh-ruflo-claude-flow]], [[src-repo-bmad-superclaude-subagent-collections]], [[src-repo-claude-squad-vibe-kanban-container-use]], [[src-repo-ccpm-aperant-ccswarm-pal-ralph]]. Confidence: med-high (README-level plus issues, code not run).
7. **Always-on hook/daemon/MCP surface is a cost.** ruflo's `npx ruflo init` writes `.claude/`, CLAUDE.md, daemon and hundreds of MCP tools; its mods run in-process "with your account's permissions and are not sandboxed". Our manager-setup research already named ambient plugin context as the biggest waste. Evidence: [[src-gh-ruflo-claude-flow]], manager-setup.md. Confidence: high for risk, no benchmark for benefit.
8. **A2A only across service boundaries.** ADK's own rule: use A2A for a separate service, another team, another language/framework or a formal contract; not for internal code organisation, performance-critical calls or sub-agents needing shared memory. Our cross-device agents (`claude -p` over SSH) are closer to "remote job runner" than A2A peers; borrow its task-state vocabulary and polling/idempotency semantics ([[src-a2a-protocol-spec]]), not the protocol. Evidence: [[src-repo-google-adk]], [[src-linuxfoundation-a2a-one-year]]. Confidence: med-high.
9. **MCP's 2026-07-28 spec moves long work to handles and polling.** Stateless core, Tasks extension (`tasks/get`, `tasks/update`), `input_required` results, no SSE resumability, trace context in `_meta`. If we ever expose the manager's jobs as an MCP server, model them as task handles, not streams. Evidence: [[src-mcp-spec-2026-07-28-changelog]]. Confidence: high (spec).
10. **Role-play company frameworks (MetaGPT, ChatDev, CrewAI role/goal/backstory) are the weakest bet.** MAST data: failures concentrate in spec disobedience, repetition, no/incorrect verification; MetaGPT's SOP structure helped system design, ChatDev verifiers did superficial checks; CrewAI's own "production" recommendation is the Flows layer (deterministic events) rather than free crews. Evidence: [[src-mast-why-multiagent-fail]], [[src-arxiv-metagpt]], [[src-arxiv-chatdev]], [[src-repo-crewai]]. Confidence: med-high.
11. **Spec-driven decomposition (CCPM) is a workflow, not an orchestrator.** PRD -> epic -> tasks -> GitHub issues -> parallel worktrees; README gains (89% less context switching, 75% fewer bugs) are unsupported (its own benchmark is 11 checks). The idea (issues as source of truth, explicit definition of done per task) is already in our brief template. Evidence: [[src-repo-ccpm-aperant-ccswarm-pal-ralph]]. Confidence: low-med.
12. **Cross-model review (PAL "consensus"/clink) offers diversity but ships code to third parties.** Debate/consensus does not reliably beat self-consistency ([[src-arxiv-mad-smit-should-we-go-mad]]); on a subscription box with confirm-first rules for external sends, skip. Evidence: [[src-repo-ccpm-aperant-ccswarm-pal-ralph]]. Confidence: med.

## Where sources disagree
- **Framework vendors vs the Anthropic/Cognition line.** Vendors (LangChain, CrewAI, ruflo) sell structure; Anthropic's January/October 2026 posts say fold subagents back unless measured. Neither side publishes head-to-head task-success data against a plain agent; "AI Agents That Matter" argues for exactly that comparison. Follow: measure against the plain sonnet-worker baseline before adopting anything. [[src-claudecom-fold-subagents]], [[src-arxiv-llmcompiler-and-agents-that-matter]].
- **Swarm/hierarchy as scaling answer (Gas Town "20-30 agents", ruflo "queen-led swarms") vs Cursor's finding that coordination, not model count, is the limit.** The scale claims are unmeasured; Cursor's is. [[src-repo-gastown-beads]], [[src-cursor-scaling-agents]].
- **A2A as the inter-agent standard (LF, 150+ orgs) vs Anthropic shipping none of it.** For a single-owner home setup the protocol value is near zero; the vocabulary is useful. [[src-linuxfoundation-a2a-one-year]].

## Applies to us
- No framework adoption. Nothing here should be installed on the host: the failure/attack surface (plugins running with account permissions, AGPL, daemons) is worse than the gain, and the host already has a confirm-first policy that frameworks do not respect.
- Already aligned: nested subagents as tools, SendMessage resumption, hooks.
- Missing and worth stealing: (a) ledger file, (b) per-action irreversibility classes for confirm-first, (c) worktree isolation when two workers edit one repo, (d) a `synthetic`/provenance marker discipline: worker outputs that were not produced by real checks must say so, (e) cost cockpit via a daily digest (see [[topic-observability]]).

## Candidate changes for us
- **C1 (CLAUDE.md, Manager role):** "Do not install or adopt multi-agent frameworks/orchestrators (ruflo, claude-flow, Gas Town, claude-squad, etc.) without a measured comparison to a plain sonnet-worker and Roman's OK. Mine them for ideas only." Benefit: prevents attractive but unsafe installs by workers. Risk: none. Evidence: rules 6-7.
- **C2 (brief template line):** "If two workers must modify the same repo, use `isolation: worktree` for each and have one integration step." Evidence: rule 5.
- **C3 (confirm-first as classes):** replace the prose list with three classes in CLAUDE.md: ALWAYS-ASK (money, send as Roman, publish, delete non-temp data, security/credential/remote-access), ASK-IF-UNSURE (anything irreversible on the Linux machine, network exposure), NEVER-ASK (read-only, temp files, installs of tracked software). Evidence: [[src-magentic-ui-paper]] ActionGuard. See [[topic-agent-security]] for the hook that enforces it.
- **C4 (provenance rule in worker presets):** "Mark any result you did not directly observe as UNVERIFIED in the report." Evidence: ruflo mocked-success issues in [[src-repo-ruflo-claude-flow]]; see [[topic-report-formats-and-verification]].
